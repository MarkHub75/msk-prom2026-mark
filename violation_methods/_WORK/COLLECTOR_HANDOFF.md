## Доказательная картина и главный вывод для рассказа

Исследование обосновывает архитектуру метода: наблюдаемая часть тела/положение на полу → связь с субъектом → предикат T/F/U → подтверждение по source-time → событие с доказательствами и причиной завершения. Универсального «лучшего PPE detector» и гарантированного снижения ложных тревог нет. Условный первый маршрут — доступный простой детектор, явная связь предмета с головой/частью тела, простой трекер, CPU-геометрия и собственные проверяемые правила. Pose/дополнительные crops/ReID/clip/VLM включаются по конкретному дефициту, выигрышу и цене; LinQ gates остаются обязательны.

Сильные первичные опоры:

- **Семантика данных и признаки.** SHWD `person` — отрицательная голова, не full body ([F001](../RAW_FACTS.md#f001)); SH17 `head` не bare head, medical face-mask не industrial respirator, YAML order не Table2 ([F005](../RAW_FACTS.md#f005)/[F007](../RAW_FACTS.md#f007)). Реальные два VOC/два YOLO SH17 и R2PPE JSON инспектированы ([F066](../RAW_FACTS.md#f066)–[F073](../RAW_FACTS.md#f073)); пропуск annotation не visible negative.
- **Pose не универсальный победитель.** Same-detector/same-training comparison [F009](../RAW_FACTS.md#f009): AP keypoint .675 против refitDT .664/direct .663, но APsmall .211 хуже .222/.248. Это узкое опубликованное сравнение, не crowd ownership accuracy и не наш запуск. [F019](../RAW_FACTS.md#f019) даёт реальный steel-plant low-light glove failure и framewise false non-compliance при хорошем среднем F1.
- **Наблюдаемость имеет реальные продуктовые ограничения.** Macroscop, Bosch, Axxon и Domination дают разные size/FPS/angle units, а не одну универсальную границу ([F018](../RAW_FACTS.md#f018)/[F048](../RAW_FACTS.md#f048)/[F076](../RAW_FACTS.md#f076)/[F077](../RAW_FACTS.md#f077)/[F090](../RAW_FACTS.md#f090)). Невидимое лицо прямо допускает неопределённость face-PPE.
- **Промышленная приёмка не сводится к headline accuracy.** Oil India GEM/2026/B/7902194 — первичная procurement chain с конкретными требованиями и спорными/отложенными знаменателями ([F082](../RAW_FACTS.md#f082)–[F084](../RAW_FACTS.md#f084)). Это требование, не достигнутый результат; полный SoW и signed SAT не получены.
- **Временной оператор нельзя выбирать по названию настройки.** Закреплённый Frigate code+same-commit docs и caller-chain ([F085](../RAW_FACTS.md#f085)–[F088](../RAW_FACTS.md#f088)) показывают конкретное статическое расхождение; runtime не проверен. AXIS short-lived означает возраст видимости в изображении, не dwell внутри зоны ([F045](../RAW_FACTS.md#f045)).
- **RGB smoking теперь имеет прямой manual и object-study след, но matched event comparison остаётся открытым.** Domination face→cigarette, DAHD/CDPA cigarette boxes и pinned fusion code [F090](../RAW_FACTS.md#f090)–[F093](../RAW_FACTS.md#f093) не определяют event FP/hour на нашей камере.
- **OVD/VLM/INT8 допускают только условный выбор.** Fixed vocabulary и dynamic prompting требуют разных графов ([F055](../RAW_FACTS.md#f055)–[F057](../RAW_FACTS.md#f057)). Есть operational verifier workflow и прямые CCTV/industrial публикации, однако Kim меняет threshold/objective и теряет precision, Guo доступен только как abstract ([F097](../RAW_FACTS.md#f097)–[F099](../RAW_FACTS.md#f099)). INT8 effects чужих ViT/PeopleNet не предсказывают потерю нашего PPE/pose ([F061](../RAW_FACTS.md#f061)/[F062](../RAW_FACTS.md#f062)).

## Семантика, которую нельзя потерять в связном тексте

**F100 — основной контракт.** Item on/off-target описывает экземпляр вещи. Coverage описывает target bodypart человека. Spare off-body не отменяет надетый approved item; off-body при скрытой голове/лице не доказывает отсутствие защиты. `exists worn approved item` может дать coverageT; `no detected worn item` не даёт coverageF. CoverageF требует видимого отрицательного состояния по согласованной политике.

T/F/U — подтверждение предиката/его отрицания/недостаточность оснований, не confidence bands. Strong Kleene: F∧anything=F; T∧T=T; остальные случаи с U дают U; NOT U=U. PPE rule=`R∧Z∧NOT C`; постоянно действующее правило ношения не должно требовать действия снятия. Smoking rule=`S∧H`; S=U,H=T → U; S=T,H=F → F именно этого rule, smoking при этом остаётся T. RuleF не глобальная безопасность. Negative smoking должен иметь собственный наблюдаемый interval/GT contract; отсутствие сигареты/дыма само по себе не F. Пять ручных контрпримеров в F100 — логическая проверка определений, не benchmark.

**F105–F107/F121 — общий конвейер.** ByteTrack — условный CPU baseline; OC-SORT — второй вариант при nonlinear motion/occlusions; ReID только по event benefit и дополнительному neural budget. ByteTrack `frame_rate` меняет buffer, а не вводит variable dt. Source timestamp/PTS, inference receipt и publish time раздельны. Prediction/reuse/stale не fresh measurement; track ID не личность человека. Передача атрибутов при ambiguity должна freeze/expire, а не заражать нового человека старым coverage.

Lifecycle как предложение: `clear→candidate→active→resolving→ended`, отдельно observation_state (observed/occluded/stale/signal_lost/scene_invalid). `observed_start` не `confirmed_at`; end через observed_compliance/observed_exit отличается от technical end track_lost/stream_lost/rule_disabled/identity_ambiguous. Последнее censored, не «нарушение прекратилось». Unknown не накапливает positive duration и не даёт observed-clear. Cooldown — доставка уведомлений, merge gap — связь эпизодов, dwell — подтверждение; не смешивать с review cutoff или object age.

Стартовый sweep **предлагается**, не взят как норма: confirmation 0/0.5/1/2 s; exit 0/0.5/1 s; gap 0/один ожидаемый интервал/две выборки; N/M 1/1, 2/3, 3/5 с явным denominator/U policy. Если важен быстрый вход, dwell 2 s может быть неприемлемым. Cooldown сначала off для измерения raw duplicates. Подбор на calibration, не test.

Typed declarative rule и event schema в [F107](../RAW_FACTS.md#f107) — **псевдоконфигурация**, не найденный SDK API. Указать camera/scene/rule/model versions, actor/track segments, predicate provenance+freshness, observed_start/confirmed_at/last_observed/end/publish, end reason/censoring, fullframe+part crop+pre/post clip. Одна лучшая картинка не доказывает длительность; старый wearing frame не current wearing. Нельзя собрать «все СИЗ надеты» из несовместимых моментов.

Event validation: actor-aware one-to-one matching, point-crossing onset collar отдельно от interval tIoU, duplicate predictions FP, unmatched GT FN; uncertainty/availability/coverage рядом с precision/recall/FA per negative camera-hour и capture→publish latency. DCASE200ms — пример аудиопротокола, не CCTV-норма. Короткое balanced clip test и ноль FP в нём не доказательство нуля тревог за смену.

## LinQ и optional методы

[F116](../RAW_FACTS.md#f116) — матрица **требований методов**, не supported-ops list. Fullframe detector: f forwards/s; person classifier: f + P×r crops/s; bodypart chain растёт с people/visible parts; tiles K×f(+f); pose/ReID — дополнительные neural inputs; clip model требует timestamped buffer/stride; verifier — candidates/s×frames/call и token generation. Batch может уменьшить submissions, но не вычисление crop images. CPU выполняет geometry/tracking без ReID/association/state machines/typed rules; CPU-постобработка не доказывает соблюдение всех neural requirements.

Четыре gate [F117](../RAW_FACTS.md#f117): export корректен → graph compiles → фактически исполняется на assigned LinQ → сохраняет outputs/detection/event quality. Название YOLO/ONNX/public HPS int8 не закрывает их. Не объявлять attention/pose/3D unsupported без ops/artifact evidence, не обещать mixed precision/QAT/float heads как доступные опции. INT8 сравнивать по slices и events, включая spurious boxes, NMS/track changes, small-object/keypoint drift; чужие ImageNet/PeopleNet проценты не переносить.

OVD fixed vocabulary может перенести text preparation offline, но class order/embeddings/head/graph и повторная подготовка при смене словаря остаются. Dynamic text/fusion — другой workload. OVD «helmet» не wearing relation. VLM допускается optional после отдельного разрешённого execution path и paired E014: baseline TP/FP→accepted/rejected/unverified; timeouts/schema failures не negative; reject-only stage не спасёт upstream misses. Detector+rules — самостоятельный baseline.

## Практические проверки и первые 15–20 минут после кейса
