## Что меняет практический выбор

1. TFA считает K-shot в аннотированных **экземплярах каждого класса**, а не в кадрах. В видео дополнительно нужно считать независимые эпизоды/траектории/камеры. Один человек в десяти соседних кадрах не даёт десять независимых условий переноса (F01–F04).
2. Новый класс и новая камера — разные изменения. TFA исследует base/novel class protocol с богатой base-подготовкой; он не устанавливает, что любой детектор респираторов переносится на новую камеру после десяти boxes (F01–F03).
3. Неразмеченный объект не является подтверждённым фоном. Маска классификационных классов, маска пространственных регионов и исключение полностью unlabeled images — разные интерфейсы. Исправление только одного loss не доказывает исправление objectness/RPN/assignment всего детектора (F05–F09).
4. Federated Loss уменьшает множество участвующих в classification loss классов. Он не находит пропущенные boxes. В проверенной реализации Detic нет аргумента с spatial ignore regions в `sigmoid_cross_entropy_loss`; background RoI получает нули для выбранных foreground classes (F07–F08).
5. Нельзя автоматически обещать неизменный inference после sparse training: Co-mining описывает одну branch при inference; SparseDet использует C-RPN и в основном режиме обе views даже при inference. Его абляция без augmentation сохраняет C-RPN (F10–F12).

### W1-03-S03 — Sampling Techniques for Large-Scale Object Detection From Sparsely Annotated Objects

Yusuke Niitani et al., CVPR 2019, pp.6510–6518. [CVF landing page](https://openaccess.thecvf.com/content_CVPR_2019/html/Niitani_Sampling_Techniques_for_Large-Scale_Object_Detection_From_Sparsely_Annotated_Objects_CVPR_2019_paper.html); [arXiv v2](https://arxiv.org/abs/1811.10862v2), v1 27.11.2018, v2 21.04.2019. Доступ 23.10.2026. CVF PDF open вернул HTTP 403; [arXiv PDF](https://arxiv.org/pdf/1811.10862) прочитан через urllib/PyMuPDF, страницы 3–5, §4.1–4.3, Algorithms 1–2, §5.1. Numeric benchmark improvements здесь не переносим.

**W1-03-F06 [PAPER, S03 §4.1–4.3/Algorithms 1–2].** В proposal-based detector используется per-RoI/per-category sigmoid classification с состоянием ignore для выбранных пар. Part-aware sampling игнорирует part-category classification loss внутри box subject, только если part-category отсутствует в verified categories данного изображения. Нужны verified positive/negative categories, subject boxes, mapping part→subject и spatial condition. Pseudo-label-guided sampling отбирает predictions вне verified categories, исключает overlap с GT и фильтрует по per-class thresholds, подобранным по precision на withheld set; отобранные регионы задают **ignore categories**, а не автоматически новые доказанные GT. Метод отличается от positive pseudo-label mining. Для каски/person это возможная гипотеза spatial prior, но у нас каска может быть в руке, на столе или вне person box; association и нарушение ношения таким prior не доказываются. Специальный loader/loss необходим; обычный YOLO text label не хранит все эти сведения.

### W1-03-S04 — CenterNet2 Technical Report: Federated Loss

Xingyi Zhou, Vladlen Koltun, Philipp Krähenbühl, Joint COCO and LVIS workshop ECCV 2020, LVIS Challenge Track. [Первичный report](https://www.lvisdataset.org/assets/challenge_reports/2020/CenterNet2.pdf). Дата в документе — контекст challenge 2020; точный день/revision PDF неизвестны. Доступ 23.10.2026. Прочитаны §3, §4 Implementation details, Table 1–2, страницы PDF 2–4.

**W1-03-F07 [PAPER, S04 §3].** Для federated LVIS annotations авторы выбирают подмножество классов S: все positive categories плюс случайные negative categories, взвешенные square-root frequency. В опытах |S|=50; binary classification loss считается только на S. Это class subsampling, а не spatial поиск unannotated instances и не проверка отсутствия каждого sampled class. Механизм не является federated learning между устройствами. Если недоразмеченный объект относится к участвующему классу, сам факт subsampling не гарантирует исключения его false-negative penalty; отсутствие отдельного spatial решения принципиально.

### W1-03-S05 — Detic: конкретный Federated Loss в исходнике

[Авторский facebookresearch/Detic](https://github.com/facebookresearch/Detic), HEAD `436cda2a2347df60a7c66daca0e8c59f93dc5e79`, commit 28.08.2023 12:58:22 UTC, установлен GitHub API 23.10.2026. Прочитаны [detic_fast_rcnn.py](https://github.com/facebookresearch/Detic/blob/436cda2a2347df60a7c66daca0e8c59f93dc5e79/detic/modeling/roi_heads/detic_fast_rcnn.py): `sigmoid_cross_entropy_loss`, строки 197–229, `inference`/`predict_probs`, 298–331; [utils.py](https://github.com/facebookresearch/Detic/blob/436cda2a2347df60a7c66daca0e8c59f93dc5e79/detic/modeling/utils.py): `get_fed_loss_inds`, 16–28. README/paper Detic image-level supervision здесь не исследованы; её результаты не приписываются одному FedLoss.

**W1-03-F08 [CODE, S05].** `sigmoid_cross_entropy_loss` строит one-hot GT по RoI, удаляет background column и умножает BCE на маску appeared classes от `get_fed_loss_inds`. Helper включает `torch.unique(gt_classes)` и при нехватке добирает категории `torch.multinomial(..., replacement=False)` по frequency weights. В этом интерфейсе нет проверенной per-image positive/negative/unknown coverage map или spatial mask пропущенных объектов. Mask снижает набор classification columns; она не исправляет proposal assignment и не добавляет missing boxes. Режим inference вычисляет probabilities через sigmoid при `use_sigmoid_ce`; FedLoss sampling там не вызывается. При переходе от softmax trainer к sigmoid изменяется scoring convention — threshold заново валидируется, даже если сам loss является train-time. Это чтение кода, не исполнение.

**W1-03-F09 [INFERENCE из F07/F08].** FedLoss нельзя рекомендовать как универсальный patch для PPE-набора с несколькими классами и random missing boxes. Число 50 из LVIS не переносится на маленький class vocabulary: в проверенном helper нет явного ограничения `num_sample_cats` величиной доступного C, а добор идёт без replacement. Несогласованные параметры могут запросить больше категорий, чем есть; конкретный runtime error не проверялся. Даже корректно уменьшенный subset не превращает unknown в verified negatives и не решает пропуск второго объекта уже positive class. До выбора такой ветки нужны настоящий C, flags, loss/assignment audit и E02.

## Coverage: какие labels можно объединять

**W1-03-F13 [INFERENCE из F05–F12].** Нижеследующая таблица — наша схема данных/решений, а не готовая спецификация конкретного trainer. Её цель — не потерять unknown при преобразовании разнородных источников.

| Состояние source/image/class | Что известно | Чего label не доказывает | Условный путь |
|---|---|---|---|
| Exhaustive для оговорённых классов/ROI/размеров | Все допустимые видимые экземпляры перечислены по policy | Полноту вне ROI, для tiny/occluded/других классов | Обычный supervised loss в пределах policy, единый class mapping |
| Verified absent class | Человек/источник проверил отсутствие в оговорённой области | Отсутствие по умолчанию в кадре без боксов | Разрешить negative loss для подтверждённого class/ROI |
| Verified present + exhaustive instances данного класса | Класс есть, его instances перечислены | Исчерпывающую разметку других classes | Class-aware loss/отдельная задача либо доразметка остальных |
| Positive image label без boxes | Где-то есть класс | Локализацию, число instances, negative регионы | Image-supervised метод с отдельной поддержкой; не подставлять как bbox GT |
| Sparse boxes одного/нескольких классов | Boxes подтверждают конкретные positives | Что остальные регионы — background, даже для того же класса | Доразметка или проверенный spatial ignore/mining/assignment-aware метод |
| Source никогда не размечал класс | Unknown для этого source | Verified absent в каждом его изображении | Preserve source×class coverage; masked training, separate model/task или доразметка |
| Пустой label-файл, provenance неизвестен | Нет записанных boxes | Negative scene; fully reviewed image | Quarantine/audit; не отправлять автоматически как hard negative |
| Ignore/crowd/неразличимый регион | Policy ограничивает достоверное решение | Корректный negative внутри региона | Передать геометрию ignore и её поддержку в loader/assignment/loss/evaluator |

Минимальный manifest: source/version, image/camera/session/episode IDs, timestamp, class mapping и определение класса; для class — present/verified_absent/unknown, instance coverage exhaustive/sparse/unknown, annotation ROI и ignore regions, ограничения размера/видимости, способ верификации. Это предложенные поля; простой bbox export может их потерять. Class-absent source и случайно пропущенный box внутри размечаемого класса требуют разных масок. Сохранение только `class_names` не решает эту проблему.

**W1-03-F14 [INFERENCE].** Пример условный: source A содержит только person boxes, source B — только helmet boxes. Простое слияние и общий closed-world loss могут обучать helmet как negative в A и person как negative в B. Полезные варианты: доразметить небольшой согласованный subset для всех нужных classes; использовать trainer с проверенной coverage-aware поддержкой; либо сохранить отдельные задачи/модели с проверяемым association. Вариант выбирается по сложности и target quality; separate models меняют integration/inference cost и не имеют установленной поддержки LinQ. Отсутствие helmet detection не превращается в GT «нарушение»: видимость и связь с человеком относятся к violation_methods.

## Few-shot бюджет и сравнение

**W1-03-F15 [INFERENCE из F01–F05 и W1-01].** Число labels отчётно следует разложить на изображения, boxes per class, независимые physical episodes/people tracks, камеры/сессии и условия. Число людей не всегда известно и не должно выдумываться. Повторяющиеся views допустимы в training, но не должны проходить через независимый assessment split одной траектории. Сохранять ontology base/novel/known-but-new-domain: если нужный смысл уже есть в weights, это domain adaptation, а не обязательно novel-class discovery.

Базовый контролируемый набор кандидатов — unchanged weights (если нужные классы присутствуют), head-only/частичный fine-tuning, full fine-tuning, либо дополнение качественной разметки с тем же trainer. Точный список trainable tensors устанавливается в W1-02/model_stack; TFA «последний predictor» не равен произвольному `freeze` N слоёв YOLO. Если меняется cosine head, class cardinality, input или cascade, нужно вновь проверять output/export contract. Sample-set seed и optimization seed фиксировать раздельно; сравнивать кандидатов на одних и тех же labeled subsets. Если выигрыш меняет знак при другой независимой группе examples, нельзя продавать его как устойчивое улучшение.

## Предлагаемые процедуры следующей практической волны

### W1-03-E01 — полезна ли малая полная разметка и устойчив ли выигрыш

**Гипотеза/решение:** проверить, даёт ли доступная независимая малая разметка полезное обобщение; выбрать full/head-only/дополнительные labels. **Модель:** model_stack должен назвать repo/commit/checkpoint/hash, class map, фактический head-only interface и export target. При новом классе заранее согласовать predictor expansion и initialization; unchanged checkpoint без класса не становится полноценной new-class baseline.

**Данные/среда:** проверенная ontology; полностью проверенные для нужных классов target images, episode/camera/session metadata; annotation work pool, validation для выбора checkpoint, независимый assessment по группам. Не задаём заранее число кадров/VRAM. Нужны training environment и доступ к licensed data, по необходимости CPU/RTX/cloud после отдельного практического запуска.

**Контроль/действия:** заморозить preprocessing, augmentation, class map, loss, event rules и evaluation contract; создать несколько matched subset manifests по независимым groups, считать instances и scenes отдельно. В каждом subset сравнить предусмотренные режимы с явно записанными trainable tensors, одинаковым checkpoint-selection rule и отдельно указанным budget. Нельзя молча уравнивать epochs, wall-clock и updates: выбрать, какую стоимость сравниваем, и измерить остальные. После первого существенного сравнения повторить на другом sample subset; optimizer seed — отдельный фактор. При выборе доразметки сравнить следующую порцию независимых labels с дополнительным training budget существующего набора, записав human time.

**Метрики:** per-class AP с названным IoU protocol, precision/recall, base/novel AP при осмысленном делении, FP/FN по размеру/камере; paired delta по subsets, event measures отдельно; compute wall-clock/memory/human time измеряются. **Артефакты:** split/subset/annotation versions, sample and optimization seeds, pretrained/checkpoint hashes, tensors frozen/unfrozen, config, selected checkpoint reason, raw predictions, metrics и overlays. **Исходы:** устойчивое улучшение → кандидат для integration; ухудшение base → проверить mixing/баланс без сокрытия регрессии; зависимость от sample selection → расширить независимые labels/ограничить claim; отсутствие выигрыша → audit signal/coverage/domain. **Stop rule:** невалидный split/GT или отсутствие нужного визуального сигнала блокируют причинный вывод; не наращивать прогоны ради удобного seed. **Предел:** небольшой успех не доказывает перенос на новую камеру, event completeness, LinQ или достаточность любого K-shot бюджета.

### W1-03-E02 — сохраняет ли trainer partial-label semantics

**Гипотеза/решение:** не штрафует ли pipeline скрытые positive objects как background; можно ли использовать source mixture без доразметки. **Входы:** один зафиксированный checkpoint/trainer от model_stack, малый полностью проверенный diagnostic набор с несколькими instances одного класса и несколькими classes; оригинальные полные labels; spatial ignore/class coverage metadata. Assessment остаётся полностью размеченным и отдельным.

**Контроль/действия:** до длинного обучения создать три версионные copies train labels: A полные; B скрыт весь один class; C скрыт один из нескольких instances уже present class. Зафиксировать фактический mapping этих регионов на proposals/anchors/queries и loss terms. Сравнить обычный loader и предлагаемый partial mechanism с одинаковым input и assignment logs; отдельно проверить classification/objectness/RPN/regression/normalization, а не только sum loss. Для synthetic test скрытый GT доступен аудитору, но не training branch. Проверить пустой label image и сохранение metadata после export/import annotations. Не объявлять mask working только потому, что loss уменьшился. После correctness audit возможен небольшой controlled A/B/C learning comparison по общей E01; это новый практический шаг, не выполненный здесь.

**Метрики/артефакты:** per-region/per-class assignment, mask и loss contributions; gradients по соответствующим logits при доступности, mapping оригинального GT → скрытого/сохранённого, coverage counts, complete-assessment quality после прогона. Сохранять commit/config/seed/tensor diagnostics и visual overlays. **Исходы:** class mask работает в B, но не C → не использовать как random missing-box solution; loss mask работает, objectness нет → интеграция неполна; loader теряет metadata → исправить путь данных; всё проходит → измерять практическую пользу, не считать её доказанной. **Stop rule:** невозможность сохранить coverage или локализовать false-negative supervision → доразметка/отдельная задача вместо неподтверждённого union. **Предел:** искусственное удаление boxes не воспроизводит неслучайные реальные пропуски tiny/occluded objects; correctness loss не доказывает качество.

### W1-03-E03 — стоимость sparse-method inference и выбор доразметки

**Гипотеза/решение:** оправдана ли интеграция специального SAOD метода относительно маленького полностью проверенного набора. **Входы:** E02 прошёл; candidate pinned implementation, dependencies, weights и допустимые данные; для SparseDet — конкретный C-RPN path и режим views, для Co-mining — подтверждённый single-branch artifact; reference student/output contract. Доступность archive по URL ещё не означает эти входы.

**Контроль/действия:** сначала read/shape trace итогового eval graph и сравнение input/output со стандартной baseline; затем только при фактической совместимости — минимальный inference/export smoke check. Для SparseDet сравнить original/augmented и no-augmentation режимы при неизменных weights; не удалять C-RPN, называя это опубликованной абляцией. Сопоставить sparse-trainer intervention с качественной доразметкой при записанных annotation и engineering costs. LinQ compiler/runtime — отдельный фактический доступ/тест.

**Метрики/артефакты:** graph/operators/input count, число backbone passes, actual preprocessing, peak memory/latency при названной среде, raw detections и paired object quality, conversion logs, checkpoint+export hashes; human/integration time. **Исходы:** unsupported graph/избыточная сложность → simpler fine-tuning с полными labels; совместимость и quality gain → кандидат на LinQ validation; no-aug parity → выбрать простой из проверенных режимов, сохранив C-RPN contract. **Stop rule:** не тратить длительное обучение до подтверждения исполнимого output path; если дополнительная разметка снимает проблему быстрее в измеренной среде, закрыть сложную ветку. **Предел:** smoke check одного runtime не доказывает LinQ, streaming throughput или пригодность тревог.

## Открытые вопросы и адресные передачи

| ID | Что неизвестно / следующее доказательство | Кому и влияние |
|---|---|---|
| W1-03-Q01 | Действительная source×class coverage, hidden instances, ROI и ambiguous labels; annotation policy и ручной audit | datasets: решает, можно ли объединять источники |
| W1-03-Q02 | Поддерживает ли выбранный trainer per-class/per-region ignore во всех affected losses и assignment; точный commit/API | model_stack: E02 до обучения; обычный bbox loader не считать partial-aware |
| W1-03-Q03 | Есть ли отдельные независимые episodes/cameras и полностью размеченный assessment; сколько independent positives | evaluation: K boxes недостаточно для claims о переносе |
| W1-03-Q04 | Нужен новый semantic class или новый domain уже известного; base checkpoint и trainable tensors | model_stack/W1-02: выбрать full/head-only и считать retention |
| W1-03-Q05 | SparseDet split manifests против несогласованного текста; реальные constraints C-RPN и matching dependency versions | Только если ветка выбрана; иначе integration cost/неизвестное достаточно для низкого приоритета |
| W1-03-Q06 | Исполним ли итоговый graph/cosine head/C-RPN, actual shapes/output/postprocess на LinQ | linq_platform/model_stack: training method не устанавливает target execution |

**→ datasets:** F13/F14 и E02: переносить coverage/unknown через conversion; при новом источнике с пустыми labels спросить, проверены ли негативы. Приоритет доразметки — не только новые images, но восстановление пропущенных instances в уже выбранных кадрах.

**→ evaluation/W1-15:** F02/F04/F15: sample-set variance и optimizer variance — разные факторы; matched subsets, base/novel retention и group assessment. Цифра 30 VOC runs не является нормативом команды. Few-shot budget и полнота labels отчётно независимы.

**→ model_stack/W1-02/W1-09:** F06/F08/F09: нужны loss/assignment semantics, а не только наличие `ignore` в конфиге; Niitani pseudo-guided ignore не равен pseudo-positive training. FedLoss class sampling не ремонтирует missing boxes. Проверить interfaces и metadata до запуска; точные training flags для неизвестного trainer не предлагаются.

**→ violation_methods:** F06/F14: containment prior для person/helmet не доказывает wearing relation; отсутствие box не равно нарушение. Unknown/occlusion policy должна согласовываться до разметки negatives.

**→ linq_platform/video_architecture:** F10–F12/E03: Co-mining заявляет один inference branch; SparseDet имеет C-RPN и view dependency. Принять method как training-only можно только после чтения конкретного eval graph; exported model и scoring convention проверяются отдельно.

**→ operator_product/hackathon_strategy:** Few-shot counts без coverage/diversity не подтверждают качество. Специальный loss требует интеграционного времени и фактического исполнимого артефакта; ближайшая полезная работа при unknown coverage — согласованный небольшой fully checked subset, а не обещание качества по «10 кадрам».

## Остаточные ограничения

Ветка установила различия режимов и конкретные опасные переносы выводов; не установила оптимальный бюджет labels, скорость обучения, лучшую архитектуру или допустимую частоту тревог для кейса. Авторские repositories и версии проверены только чтением, не установкой. Ни один PDF benchmark не измеряет производственные камеры команды. Strong candidates остаются условными, а E01–E03 — будущими процедурами. Другие файлы не изменялись.
