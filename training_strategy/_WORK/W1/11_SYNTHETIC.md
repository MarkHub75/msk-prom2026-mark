## Решение и граница применимости

Синтетику стоит рассматривать для конкретного установленного пробела: редкий внешний вид объекта, недостающий фон, диапазон поз/масштабов или перекрытий. До целевого датасета нет основания выбирать её главным способом адаптации. Практически наиболее контролируемый первый кандидат — композиция проверенного целого человека вместе с СИЗ и связями на train-only фоне, если есть корректные masks. Генеративное редактирование состояния ношения требует повторной аннотации: сохранённый prompt или исходный box не доказывает истинность нового label.

Проверка полезности обязательна на независимом реальном holdout. Главный контроль — одинаковые real train images и исходные веса с вмешательством real+synthetic против real-only; нужно отдельно контролировать число updates и exposure реальных примеров. Высокая оценка на синтетическом validation показывает соответствие генератору, а не перенос на камеры. Ни одна из открытых здесь работ не устанавливает качество PPE CCTV, событий курения или исполнение модели на LinQ.

## Факты: что действительно проверили авторы

**W1-11-F01 — опубликованная постановка/измерение, S01 §§III–IV.** Исходный DR — предсказание Cartesian положения геометрических предметов на столе для робота, а не COCO-подобные boxes/PPE states. MuJoCo randomizes текстуры, освещение, distractors, камеру, шум; фиксированная высота стола ограничивает геометрию. Авторы показали перенос simulated RGB → real без real-image pretraining, около 1.5 cm локализационной ошибки и grasping. Эта единица не detection AP. Не переносить её на голову человека или tiny PPE. Точный checkpoint-selection budget и аппаратную стоимость здесь не восстанавливали; работу используем как доказательство принципа в узкой исходной задаче.

**W1-11-F02 — метод, S02 §3.** Copy-Paste использует instance masks двух изображений после scale jitter/flip, вставляет случайный subset объектов; fully occluded annotations удаляются, partly occluded masks и boxes обновляются. Масштабы/совстречаемость могут быть нереалистичны. Это задача instance segmentation с известными masks, не обещание корректного label после прямоугольной вклейки.

**W1-11-F03 — опубликованное измерение, S02 §4.1/Table 1.** Mask R-CNN ResNet50-FPN, input 1024, COCO train 118k images, LSJ: box/mask AP 47.2/41.8 → 48.2/42.4 с paste. Batch 256; обычно random initialization; обучение до прекращения улучшения validation, для LSJ+paste приведено 576 epochs. Сравнивается augmentation внутри большого COCO recipe, не fine-tuning на нескольких CCTV labels. Детальный аппаратный бюджет и независимое повторение нами не установлены. Числа нельзя смешивать с headline Cascade/self-training result или выдавать за ожидаемый gain YOLO. F02–F03 используют один paper, не два независимых подтверждения.

**W1-11-F04 — опубликованное измерение, S03 §4.1/Table 1.** Car boxes: Faster R-CNN Inception-ResNet-v2 pretrained ImageNet, 100k DR images против 2.5k Virtual KITTI; AP@0.5 на 500 случайно выбранных real KITTI images: DR 78.1 против VKITTI 79.7. Отбор объектов: height >40 px, truncation <0.15. Batch 4, NVIDIA DGX Station; photometric/geometric augmentations. Синтетические budgets не равны. Критически: authors stopped training при saturation на названном test set и report best results; это слабее untouched lockbox.

**W1-11-F05 — ограничение/измерение, S03 §4.1–4.2/Fig.6/8.** В этой работе real fine-tuning после synthetic улучшал результат, но DR хуже VKITTI при высоком recall; авторская гипотеза — mismatch структуры/контекста. Рост synthetic size насыщался: примерно 10k с pretraining и 50k без него. Числа относятся к cars/easy-filtered split и указанным detector recipes. Они не обосновывают «сгенерировать миллион» или преодоление tiny-object visibility. Не извлекаем точные значения Fig.6 из смешанного OCR без визуальной сверки.

**W1-11-F06 — ограничивающее опубликованное измерение, S04 §§4.1–4.3/4.5/Table 3.** BlitzNet ResNet50 pretrained ImageNet, input 300, VOC detection/AP при IoU 0.5; cutouts из VOC12train-seg. Table 3: среднее AP первых пяти категорий при отдельном обучении категорий: Base-DA 48.7, Random-DA 48.3, Context-DA 57.5. Это не mAP всех VOC classes. При 25% train images Base/Context 32.5/38.3. Random placement немного ухудшил baseline, context placement помог. Detector Adam; checkpoint rule контекстной модели — divergence train/validation loss. Compute/checkpoint detector для этой строки полностью не восстановлены. Отличие от F02 не разрешается универсальным лозунгом: разные данные, модели, бюджеты и augmentations; для PPE нужен свой controlled comparison.

**W1-11-F07 — метод/ограничение, S05 §§5–6/Table 1.** Работа об instance detection известных бытовых предметов BigBIRD/GMU Kitchen/Active Vision с Faster R-CNN. Авторы используют foreground masks, paste на backgrounds, вариации blending, rotations, truncation и overlaps. Table 1: same-image multi-blend 73.7 mAP против no blending 65.9 в их протоколе. Удаление contour artifacts оказалось существенным. Это распознавание конкретных предметов, а не категории «человек без каски». Сам по себе реалистичный patch не устанавливает person–PPE relation. Число собственных CCTV labels, экономия annotation time, стоимость на RTX4070 и перенос на LinQ данной работой не установлены.

**W1-11-F08 — метод/протокол, S06 §§3–4.1.** X-Paste отделяет генерацию/поиск картинки от получения pseudo masks и фильтрации. Используется StableDiffusion v1.4; несколько foreground segmentation методов, CLIP-guided mask selection/filtering; masks с площадью <5% или >95% отбрасываются. Основной ablation recipe: CenterNet2 ResNet50 pretrained ImageNet22k, 640 input, batch32, 48 epochs, LVIS 100k train/20k val. Это большой исходный labeled dataset и дополнительные instance pools, не бесплатная замена target annotation.

**W1-11-F09 — опубликованная ablation, S06 Tables 2/5/10.** При равном pool size: 300k generated-only → box/mask AP 35.3/31.6; 300k retrieved-real → 36.1/32.0; 150k+150k → 36.6/32.7 на LVIS. Более высокий CLIP threshold не монотонно лучше; quality–diversity trade-off. COCO CenterNet2 R50: 46.0/39.8 → 46.6/39.9, заметно меньший gain. GPU cost и checkpoint selection здесь не установлены. Semantic similarity threshold — не вероятность правильного класса/маски. Все числа — авторов, не наша репликация.

**W1-11-F10 — метод, S07 §§3.2–3.4.** Gen2Det inpaints изображения по исходным boxes/classes; применяет image/detector filtering, separate sampling и background-ignore. После удаления ошибочной annotation сам объект остаётся в картинке, а генератор может создать лишние instances. Поэтому авторы меняют training loss; masks для synthetic не известны и mask loss на них выключен. Копировать исходные masks после inpainting неправомерно. Важная переносимость: это специальный Detectron2 training route, не просто папка новых JPG для любого trainer.

**W1-11-F11 — ограничивающее измерение, S07 Table 2/5, §4.1/Supp.§6.** COCO CenterNet2 box/mask AP: real-only 46.00/39.8, vanilla real+synth 44.35/37.03, полный Gen2Det 47.18/40.44. LVIS Mask R-CNN box AP: real-only 22.29, naive mix20.75, полный24.42. Есть sampling/recipe confound; результат полного пакета нельзя приписать одним картинкам. Авторы отмечают затруднение воспроизведения точного XPaste результата по опубликованным code/configs. Нашего воспроизведения нет. Не используем их параметры как PPE defaults; аппаратный бюджет/выбор checkpoint здесь не восстановлены.

**W1-11-F12 — наблюдение авторского артефакта, S08 README.** Опубликован route generation/text2im.py → segment_methods/reseg.py → filtering/object pool → detector training; нужны внешние foreground models и ручное указание их путей. README использует обновление diffusers/transformers/xformers без полного lock. Наличие авторского code подтверждено; воспроизводимость в текущей Windows-среде и готовая интеграция в Ultralytics не проверены.

**W1-11-F13 — наблюдение авторского артефакта, S09 README.** context_aug содержит контекстную CNN и pipeline выбора мест, извлечения VOC instances и paste; основан на BlitzNet, часть blending borrowed из syndata-generation. Это дополнительный pipeline подготовки, а не встроенная опция любого detector.

**W1-11-F14 — переданный code observation соседней ветки.** В [W1-05](05_AUGMENTATION.md), F06, Ultralytics `8.4.184`, SHA `e6d5fc5918f57d4d39fadb43fc5b2a1aea132ac8`, `ultralytics/data/augment.py:CopyPaste.__call__`: при отсутствии segments операция возвращает исходные labels. В этой ветке код повторно не исполнялся. Bbox-only dataset + `copy_paste` flag не реализует методы F02/F08; требуются masks/подготовка или иной явно реализованный compositor.

## Наши выводы и semantic gate для CCTV

Следующие F15–F19 — инженерные выводы из постановки и F01–F14, не опубликованные PPE measurements.

**W1-11-F15 — источник GT определяет доверие.** Renderer даёт точные координаты геометрии в своей сцене, но только при корректном projection/visibility implementation и совпадении ontology. Copy-paste даёт детерминированное преобразование проверенной маски, но меняет перекрытия. Generator даёт изображение, которому ещё нужны проверенные labels. Detector/VLM/CLIP filter оставляет pseudo-label uncertainty. У всех методов отдельный gate: изображение соответствует классу; геометрия соответствует изображению; состояние/отношение соответствует требованиям задачи. Проверка одного уровня не заменяет другие.

| W1-11-F16: состояние/операция | Допуск и обязательное обновление | Причина отказа |
|---|---|---|
| Paste целого person с PPE | Сохранять person ID, head/PPE masks, отношения; один transform для группы; пересчитать clipping/occlusion | Чужая каска потеряла связь с головой; head/PPE исчезли за новым объектом |
| Paste отдельной каски/респиратора | Проверить контакт, pose, размер, orientation и реальную видимость evidence; повторно присвоить state | Каска над/рядом с головой не означает надета; респиратор на шее не означает закрывает дыхательные пути |
| Remove PPE через inpainting | Переразметить результат и появившиеся объекты; проверить восстановленную анатомию и открытый head/face | Prompt «без каски» не доказывает, что генератор действительно создал видимую непокрытую голову |
| Occlusion головы | Согласовать unknown/ignore policy; менять visible mask/box по правилам annotation | Закрытая голова не становится `no_helmet`; отсутствие видимого PPE не доказывает нарушение |
| Перенос человека в ROI | Пересчитать footpoint/ground-plane relation; учитывать perspective, support surface и scale | Box intersect ROI не равен входу; случайный paste может создать человека без физического пола |
| Smoking | Отдельно проверить предмет, hand–mouth geometry и временную семантику | Вклеенная сигарета не подтверждает курение или соседство с горючим материалом |

**W1-11-F17 — масштаб и occlusion.** До rasterization задать целевой диапазон размера по train-camera observations, после конечного resize/letterbox повторно проверить размер evidence. Маска может быть точной, но исчезнувший в двух пикселях ремень уже не даёт человеку надёжно подтвердить state. Не выдумывать универсальный минимальный pixel size. Хранить отдельно amodal geometry и visible geometry; выбирать bbox convention по target dataset, а не механически использовать visible box каждого paste paper. Для частично перекрытого person annotation state может стать unknown даже при большой видимой доле person bbox.

**W1-11-F18 — контекст и разнообразие.** F02 и F06 дают разные результаты случайного размещения, F09/F11 показывают ограниченную/отрицательную пользу части рецептов. Для object-only detection случайная композиция может ослаблять фоновые shortcut; для отношений «надето» и зон она способна разрушать сам label. Разнообразие считать по исходным людям, PPE assets, позам, backgrounds, cameras и sessions; тысяча вариантов одного cutout — не тысяча независимых случаев. Фон holdout камеры нельзя использовать для генерации, а затем называть эту камеру unseen. Если разрешена adaptation на её unlabelled video, это transductive protocol с отдельным session holdout, явно указанным в отчёте.

**W1-11-F19 — практический выбор по пробелу.** Если нет masks и времени на их проверку, сначала реальная доразметка нужного случая и обычные допустимые transforms; F14 не позволяет получить paste одним флагом. Если есть проверенные cutouts и нужен новый фон — group paste, E01/E02. Если не хватает ракурса, которого нет в cutouts, paste не создаёт новую 3D форму; renderer требует assets/rig/camera и отдельной стоимости подготовки. Если нет достоверных реальных примеров состояния вообще, generator может служить поиском гипотез/инструкцией для аннотатора, но не доказательством определения класса. Без real holdout полезность остаётся открытой, даже если synthetic images выглядят убедительно.

## E-процедуры: предлагаются, не выполнены

### W1-11-E01 — gate labels до обучения

Вопрос: допустим ли конкретный compositor/generator для нашего ontology? Входы: annotation guide с visible/amodal/unknown convention, train-only assets/backgrounds с provenance, реальный input preprocessing, renderer/compositor/generator revision/config/seed. Для generative route нужны отдельные reviewer labels; эстетическая оценка и detector confidence не заменяют человека.

Контроль: оригиналы и их annotations; для group paste — неизменённая исходная группа. Действия: получить небольшую заранее стратифицированную batch по классу, масштабу, pose, occlusion и state; в overlays показать исходные/новые masks, boxes, evidence regions и relations; независимый reviewer проверяет class, geometry, state, missing/extra instances. Проверить также фон: после filtering удалённая annotation не должна превращать оставшийся объект в отрицательный background. Для генеративного редактирования проверять весь кадр, не только исходную область.

Метрики: доли неверного class/state/geometry, extra/missing instances; survival evidence после final resize; ошибки по assets/scale/occlusion, время reviewer на пригодный sample. Артефакты: manifest исходников/деривативов и прав, revisions, seeds, transformed annotations, overlays, reviewer decisions/reasons. Stop rule: воспроизводимая ошибка state/relations, систематическая потеря evidence или неизвестная background-label policy блокируют тренировочный trial; исправить generator/policy или исключить группу. Успех gate допускает ablation, но не доказывает перенос и не гарантирует отсутствие редких ошибок.

### W1-11-E02 — controlled real-only vs real+synthetic

Вопрос: закрывает ли синтетика выбранный реальный failure slice? Входы: подходящий pretrained checkpoint и pinned trainer, один real train split, validation и untouched real lockbox по независимым camera/session/clip groups; verified synthetic из E01. Деривативы наследуют split оригинала. Определить один пробел и заранее critical metric/допустимые regressions с evaluation; численный порог без задания не выдумывать.

Контроли: A real-only с текущими допустимыми augmentations; B тот же real pool + synthetic одного типа. Одинаковые input resolution, исходные веса, classes, optimizer, seed, inference thresholds/NMS и checkpoint selection по real validation. Измерять updates, real-image exposure, synthetic exposure и wall-clock: одинаковое число epochs на увеличенном dataset не означает равный training budget. Основное сравнение фиксирует optimizer-update budget; при выигрыше/сомнении добавить контроль real oversampling до того же real exposure либо matched-wall-clock comparison. Это позволит отличить новую информацию от дополнительных повторов/шагов. Synthetic-only C допустим только как диагностический secondary arm, не обязательная трата.

Метрики: per-class AP/recall, precision при фиксированном рабочем пороге; size/evidence/occlusion slices, target failure slice, clean/background negatives, camera groups; event false alerts на независимом реальном видео при фиксированной event logic. Повторы по seed или независимым группам назначать для решающего неустойчивого сравнения, а не выдавать кадры одной записи за независимые наблюдения. Артефакты: split/asset manifests, config diff, checkpoint/predictions, selection logs, реальные error examples и time/annotation cost.

Исходы: улучшение real critical slice без недопустимой regression → сохранить candidate для export проверки; gain только на synthetic → transfer не подтверждён; regression real/negative cameras → уменьшить долю/исправить контекст или отказаться; gain неотличим от real oversampling → предпочесть более простой путь с учётом затрат. Stop rule: прекратить ветку при broken E01, critical regression или исчерпании выделенного бюджета без подтверждённой real пользы; lockbox не использовать для многократного подбора. Успех подтверждает конкретный dataset/recipe; не доказывает LinQ execution, новую камеру или событийную безопасность.

### W1-11-E03 — локализовать источник синтетического shortcut

Входы: результаты E02, asset IDs, reviewer labels, real difficult examples. Контроль: original real-only model и real validation; действия — диагностически сравнить same assets с разными blending/backgrounds и context-constrained placement, удерживая label/количество samples. Отдельно измерить group paste против вмешательства только в PPE, если второй вариант прошёл E01. Не менять одновременно detector architecture.

Метрики: ошибки по asset/source/background, per-state confusion, частота FP на paste-like textures, evidence visibility; синтетический набор является диагностикой, основное решение остаётся по real validation. Артефакты: парные примеры, provenance, prediction diffs и reviewer причины. Исход: зависимость от контура → править mask/blend; зависимость от camera/background → проверить sampling/context; неверные person states → остановить такой edit и доразметить реальные случаи. Stop rule: не расширять generator pool до устранения систематического дефекта; если одна контролируемая коррекция не улучшает real целевой slice в выделенном бюджете, перейти к реальной разметке. E03 объясняет конкретный failure, не устанавливает универсальный лучший способ blending.

## Открытые вопросы и передачи

- **W1-11-Q01, P0 → datasets / violation_methods:** labels — отдельные PPE objects, person states или events? Каковы правила unknown/occluded, visible/amodal box и связи wearer? Без ontology E01 не может разрешить генеративное редактирование; нужны guide и разобранные реальные примеры.
- **W1-11-Q02, P0 → datasets / W1-05 / model_stack:** есть ли разрешённые masks и person–PPE groups? F14 показывает no-op bbox-only switch. Если masks нет, сравнить стоимость их проверки с прямой target доразметкой. Авторские pipelines F12/F13 существуют, но интеграция/зависимости не проверены.
- **W1-11-Q03, P0 → evaluation / W1-15:** имеются ли независимые real cameras/sessions и достаточные critical-state positives/negatives? Нужен E02; без него нельзя заявить synthetic-to-real benefit. Сохранить статус target video, использованного для backgrounds или настройки generator.
- **W1-11-Q04, P1 → W1-06 / datasets:** какие pixel sizes evidence, occlusion и viewpoints реально отсутствуют в train? F04 не покрывает tiny objects; выбрать один gap до дорогостоящей генерации.
- **W1-11-Q05, P1 → model_stack / W1-03:** поддерживает ли выбранный trainer ignore regions/partial labels, если filtering удаляет annotation, оставляя object? F10 требует loss changes; plain folder merge не воспроизводит Gen2Det.
- **W1-11-Q06, P1 → violation_methods / video_architecture:** нужны ли клипы/tracks? Для них согласовывать pose/camera/lighting/IDs во времени, иначе synthetic frame improvement ничего не говорит о событии; курение и вход в зону требуют отдельной семантики.
- **W1-11-Q07, P1 → linq_platform / model_stack:** data-only augmentation может сохранить detector inference architecture, но E02 candidate нужно реально экспортировать и проверить на LinQ. Ни trainer из papers, ни masks для подготовки не устанавливают поддержанный runtime. Новые input size/cascade или architecture требуют нового целевого пути.

Закрыто на уровне research: первичные доказательства полезности и вреда найдены; задачи и ограничения отделены; доступны versioned author artifacts; для принятия решения нужны target ontology, assets и controlled real E01/E02. Публикационное отсутствие PPE-протокола не является доказательством невозможности синтетики для PPE.
