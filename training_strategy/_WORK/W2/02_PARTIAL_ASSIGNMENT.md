## Ответ и изменение решения

На Ultralytics pin U=`e6d5fc5918f57d4d39fadb43fc5b2a1aea132ac8` штатный detect route не имеет найденного сквозного class-coverage/spatial-ignore интерфейса. Это уже не общий вопрос к model_stack: конкретно установлены читаемые targets, назначение, нулевые class targets, regression foreground и обе end-to-end ветви. В этой цепочке «добавить поле ignore», `mask_gt`, `class_weights`, `overlap_mask` либо отфильтровать class rows недостаточно. [W2-02-F01–F08]

Уточнение удобной рекомендации: **для objectness-free detect случай B (целиком unknown class) действительно можно ограниченно решить классификационной маской**, если все оставшиеся классы размечены исчерпывающе и нет иных affected tasks. Ей не обязательно менять bbox loss: bbox loss уже только на известных positives. Но это custom criterion/data contract, не установленный CLI. Для C (скрытый второй instance present class) image×class mask либо оставляет false negatives, либо лишает модель правильных positives/negatives; spatial mechanism не восстанавливает отсутствующий GT и его localization. В legacy YOLOv5 дополнительно требуется objectness ignore. Не следует одинаково требовать «переписать все losses» для каждой architecture. [W2-02-F05/F07/F09/F12]

Найден ограниченный готовый spatial-ignore route в MMDetection Faster R-CNN, но его проверка опровергла универсальность «framework уже поддерживает crowd»: обычные thresholds отключены, ignore class-agnostic, а при zero regular GT MaxIoUAssigner назначает всё background. Для произвольного B/C безопасный union без дополнительной работы не установлен. [W2-02-F10/F11]

K002: **публичный implementation gap существенно закрыт / область уточнена**. Не закрыты correctness исполнения будущего механизма, реальная coverage данных и полезность обучения. W1-03-E02 остаётся практическим gate, со специфическими observables ниже.

## Новые факты: штатная Ultralytics detect цепочка

**W2-02-F01 [CODE, S03; уточняет W1-03-F13/W1-12-F08].** Детекторный TXT loader читает class + четыре box coordinates. `verify_image_label` требует пять columns, class integer и допустимый range. Нет специального отрицательного class ID для ignore box; обычный `-1` не является поддержанным ignore target. Missing/empty получают одинаковые zero-row arrays при разных scan counters. `result_to_label` сохраняет im_file/shape/cls/bboxes/segments/keypoints/normalized/bbox_format, но не source×class exhaustive/unknown, verified negatives, crowd или ROI coverage. `update_labels_info` превращает geometry в `Instances`; `Format` создаёт cls/bboxes/batch_idx. `collate_fn` может сохранить произвольный дополнительный key как tuple, но **это не consumer coverage**: criterion не читает такие keys автоматически. Следовательно, отсутствие поля в стандартном cache не мешает разработать subclass, но стандартный route не создаёт его и не использует downstream.

**W2-02-F02 [CODE/INFERENCE, S03–S05].** `convert_coco` просто **пропускает `iscrowd` annotations**, оставляя image pixels; пишет только box/segment/keypoint rows. Не передаёт ignore geometry, per-image verified category lists, `neg_category_ids`/`not_exhaustive_category_ids` или arbitrary ROI. `lvis=True` дополнительно пишет список всех images, включая unannotated, но не превращает TXT в LVIS-aware supervision. `Format.return_mask`, `overlap_mask`, `mask_ratio` относятся к instance segmentation masks, а не к missing-label ignore. `classes`, `single_cls`, `cls_remap` меняют выбор/представление категорий или head transfer, не делают неразмеченный class unknown. Если crowd dropped, его область может стать detector negative по F05. Это конкретный опасный путь conversion, не утверждение, что любой COCO-compatible loader теряет metadata.

**W2-02-F03 [CODE, S01/S02].** `v8DetectionLoss.get_assigned_targets_and_loss` читает только `batch_idx`, `cls`, `bboxes` для GT. Preprocess собирает `[B,max_GT,5]`, coordinates → pixel xyxy. `mask_gt=gt_bboxes.sum(...).gt_(0)` — **valid padding mask**, не unknown-region mask. Assignment получает detached sigmoid class scores `[B,A,C]`, detached decoded boxes, anchor points, gt_labels/boxes и mask_gt. Detached assignment не означает отключение BCE/backprop по logits: `pred_scores` далее остаются исходными differentiable tensors. В этой работе backprop не исполнялся.

**W2-02-F04 [CODE, S02].** TAL рассматривает **только перечисленные GT**. Candidate pool: anchor centres внутри GT, причём tiny sides расширяются до `stride_val` вокруг центра; поэтому проверка лишь точек внутри исходного tiny box недостаточна. Alignment = score соответствующего GT class в степени alpha × overlap в степени beta; criterion задаёт alpha=.5, beta=6. Top-k/valid-GT mask задают candidate positives, multiple-GT conflicts разрешаются через overlap, при topk2 дополнительно ограничиваются. `get_targets` создаёт one-hot class score для назначенного GT и обнуляет все columns у non-foreground; затем alignment normalization даёт soft target scores. Скрытый GT не имеет своей строки и не может получить собственные positive/regression targets. На его области anchor может остаться background **или** быть назначен другому сохранённому GT; геометрический регион сам по себе не гарантирует fg=False. Если GT во всём batch нет, early return явно даёт zero target_scores и false fg_mask. Если пусто только одно image смешанного batch, padding mask не даёт ему positives.

**W2-02-F05 [CODE, S01].** Classification BCE считается на **всех** `[B,A,C]`, включая non-fg anchors и non-target classes у positive anchors; class_weights broadcast умножает и negative entries. Denominator `target_scores.sum().clamp_(min=1)`; после этого gains и batch-size multiplier. При target=0 непропущенная BCE-компонента соответствует отрицательному обучающему сигналу для class logit; это аналитическое свойство BCE, а не измеренный здесь gradient. У U Detect нет отдельного objectness channel: `no=nc+4*reg_max`, raw outputs boxes/scores/feats. Поэтому фраза «надо исправить objectness YOLO» неверна для этого head, хотя отсутствие отдельного objectness не устраняет false negatives.

**W2-02-F06 [CODE/INFERENCE, S01/S02].** Bbox CIoU и DFL считаются только на fg indices, с весом sum(target_scores at that anchor) и тем же denominator. При `reg_max<=1` вместо DFL используется normalized ltrb L1; имя gain `dfl` не доказывает наличие DFL. У скрытого GT не появляется отрицательная regression loss на фоне: он **теряет собственное regression supervision**. Но удаление GT может изменить конкуренцию за anchors, target_gt_idx, soft scores, regression targets и denominator для сохранённых objects; нельзя гарантировать численную идентичность их вкладов между A/B/C. Простая scalar post-mask общего loss уже не разделяет эти случаи. Если цель — лишь не penalize unknown class в B у objectness-free detect, сохранённый bbox supervision можно оставить; это не требует выдуманного ignore-box regression target.

**W2-02-F07 [CODE, S01/S04].** `DetectionModel.init_criterion` на U выбирает `E2ELoss` по наличию `one2one_cv2`, иначе `v8DetectionLoss`. Active E2ELoss использует one2many TAL topk=10 и one2one topk=7/topk2=1, один batch для обеих; weighted sum обеих losses, но возвращаемые detached log items относятся **только к one2one**. Initial gains .8/.2, one2many decays до .1; одна исправленная branch не закрывает negative supervision второй. `Detect.forward` делает detached features для one2one при training: её head всё равно обучается своим loss, и one2many продолжает воздействовать на backbone. Legacy `E2EDetectLoss` рядом в файле суммирует topk=10/1 branches, но не является выбранным `DetectionModel.init_criterion` на этом pin. Не выбирать trace по имени существующего класса. YOLO26 YAML задаёт end2end=True/reg_max=1; обычный non-E2E detect 8/11 проходит v8DetectionLoss с DFL при reg_max>1. Семейство/режим конкретного checkpoint всё равно нужно сохранить в E02.

**W2-02-F08 [CODE/INFERENCE, S01–S04].** В проверенном default detect route нет consumers для per-class coverage, crowd/ROI-ignore или `[B,A,C]` loss-validity mask. `get_assigned_targets_and_loss(..., **assign_kwargs)` — extension point, а не готовый ignore interface: forwarding идёт через TAL в `pair_overlaps`, базовый `pair_overlaps` принимает только indices/gt_bboxes/pd_bboxes; произвольное `ignore` не реализует suppression BCE. Штатные useful outputs этого method — fg_mask/target_gt_idx/target_bboxes/anchor_points/stride_tensor и loss totals; **target_scores, per-entry BCE и pre-conflict masks не возвращаются**, поэтому для полного audit нужны instrumentation/custom criterion/assigner. Пересылка metadata отдельно недостаточна. Это отрицательное наблюдение про конкретно прослеженный chain, не доказательство отсутствия всех сторонних partial-label методов.

## A/B/C: targets, negatives и допустимый маршрут

Обозначения: одинаковое изображение с сохранёнными pixels; A — полный GT; B — удалены все boxes класса c (class coverage unknown, остальные classes exhaustive); C — удалён один из нескольких instances c. Выводы ниже — **static trace**, не запуск сравнения. Отсутствие в TXT не позволяет loader отличить B/C от проверенного отсутствия.

| Вариант на U detect | Assignment / targets | Какие negative terms и regression | Штатная mask support | Engineering / допустимый data route |
|---|---|---|---|---|
| **A** | Известные GT участвуют в TAL; fg и мягкие class targets определяются predictions/geometry; не каждый anchor внутри box positive | BCE у всех entries; negatives включают non-target classes. CIoU + DFL либо L1 только fg | Обычная positive/padding handling; partial mask не нужна при действительно exhaustive policy | Обычный supervised training после loader gate; полная разметка определяется рабочими classes/ROI/visibility policy, а не всеми предметами мира |
| **B: весь c скрыт** | Ни один GT class c не существует; column c target_scores=0 у всех anchors этого image. Другие GT могут назначать anchors в его области | Весь column c даёт negative BCE; missing c не имеет regression. Другие classes продолжают обычные losses | Нет image×class unknown consumer | Для objectness-free detect custom `[B,1,C]` validity mask достаточна, чтобы убрать **этот negative column**, при строгих предпосылках B; оставить остальные positives/box supervision. Нужны loader+augmentation+criterion wiring, обе E2E branches, explicit normalization. Иначе полная доразметка или separate task с exhaustive own classes |

Kept targets/normalizer могут измениться | Нет spatial/class-aware unknown consumer | Обычная image×class mask c удалит также правильные positives. **W2-02-F09 [CODE/INFERENCE, S06; architecture boundary].** В legacy YOLOv5 v7.0 `build_targets` сопоставляет только переданные GT с anchor ratios/grid offsets. `tobj` в каждом layer сначала нулевой по всей grid, positive positions получают detached IoU. BCEobj вычисляется на **всей grid**. Classification BCE вычисляется только на matched positives (`nc>1`), со smoothing cp/cn; lbox — только matched positives. Поэтому B/C в hidden-only местах штрафуются прежде всего **objectness**, а не dense class BCE; unknown class также может оставаться negative class entry на positives других known classes. Маска c в BCEcls не убирает BCEobj. Нужны пространственная objectness-validity mask `[B,na,H,W]` на каждом level, positive precedence, осознанное reduction/autobalance и при необходимости per-positive class-validity mask. Нет готового такого аргумента в `ComputeLoss(p,targets)`; targets — обычные `[image,class,xywh]`. Для B без геометрии missing class class-agnostic objectness не знает, где подавлять штраф; отключить все background objectness image можно лишь ценой потери всех достоверных negatives. Скрытый объект не регрессируется, пока отсутствует target. Не смешивать legacy `cls_pw` как BCE pos_weight с U class_weights из W1-04.

| Потребность | Что маскировать/сохранить | Чего это не устанавливает |
|---|---|---|
| B, objectness-free detect | Image×class validity расширить до BCE `[B,A,C]`; известные class positives/negatives сохранить, c unknown исключить; policy denominator явно задать | Нет missing c localization, нет гарантии target benefit; это ещё custom implementation |
| C / class-specific uncertain ROI | Class×anchor validity `[B,A,C]` по преобразованной geometry; **известный positive target имеет приоритет** над generic ignore; известные positive bbox targets не обнулять blanket fg mask | Из knowledge «класс sparse» геометрия hidden object не выводится; prior/pseudo regions могут ошибаться |
| Class-agnostic unknown region | Удалять negative entries в выбранном spatial scope, проверяя конфликт с known objects и valid ROI edges | Грубое удаление всего anchor может отключить правильный person positive из-за unknown helmet внутри person |
| Legacy objectness | Дополнительно level-wise objectness validity и reduction; class mask отдельно | Objectness не class-specific, поэтому class coverage table одна не достаточна |
| Любая композиция sources/augmentations | Маски/coverage должны преобразовываться вместе с images, boxes, ROI и sampler; mosaic требует spatial/source provenance, mixup — явного семантического решения | Один global image×class флаг для composite не сохраняет локальную полноту |

Это **interface requirements, не patch и не готовый алгоритм**. Надо разделять два требования: (1) убрать заведомо неверный negative penalty и (2) научить пропущенный object. Ignore может выполнить первое в ограниченном scope, но не создать bbox regression для второго. Нельзя требовать parity всех assignments A/C без предоставления hidden GT: сравнение assignments должно объяснять изменения, а не считать любое изменение bug.

Проверка удобной class-mask рекомендации дала ограниченно положительный ответ B/U detect и отрицательный ответ её универсальности для C/legacy objectness. «Ни один class mask никогда не поможет C» тоже слишком сильная формулировка: можно консервативно удалить все **negative** c entries и оставить positives, но это другая supervision policy с потерей известных negatives. Её качество неизвестно. Полностью доразметить небольшой subset — конкретная альтернатива, а не claim о всегда лучшем качестве.

## Ограниченный public alternative: MMDetection Faster R-CNN

**W2-02-F10 [CODE, S07–S09].** Существует более длинная штатная цепочка для **известной геометрии class-agnostic ignore**, без самостоятельного написания всей criterion:

1. В CocoDataset `ann.ignore=True` **пропускается**, а `iscrowd=True` становится `ignore_flag=1`. Поэтому generic поле `ignore` и crowd не синонимы.
2. `LoadAnnotations` создаёт `gt_ignore_flags` вместе с boxes; `PackDetInputs` разделяет regular `gt_instances` и `ignored_instances`. `unpack_gt_instances` передаёт вторые downstream как batch_gt_instances_ignore.
3. TwoStageDetector передаёт copies data samples в RPN, обнуляя class labels regular GT для class-agnostic RPN. AnchorHead assignment принимает ignored instances. StandardRoIHead отдельно передаёт ignored instances в bbox_assigner.
4. MaxIoUAssigner с **положительным** `ignore_iof_thr` измеряет IoF priors↔ignore boxes; при default `ignore_wrt_candidates=True` denominator связан с candidate area. Он ставит overlap columns кандидатов с IoF выше threshold в -1. При наличии regular GT это оставляет их assignment ignored=-1; RandomSampler выбирает positives `gt_inds>0`, negatives `==0`, игнорируемые не попадают ни туда, ни туда.
5. RPN AnchorHead оставляет label_weights/bbox_weights нулевыми вне выбранных positives/negatives; bbox weights только positive. RoI BBoxHead строит targets по sampled positives/negatives и regresses positives. Поэтому excluded ignored proposals не дают RoI background classification и не добавляют regression.

**W2-02-F11 [CODE/INFERENCE, S07–S09; counterexample].** Найденный route имеет существенные пределы:

- Base FasterRCNN config v3.3.0 ставит `ignore_iof_thr=-1` **и RPN, и RCNN**. Одно сохранение crowd metadata не включает suppression. Конкретные configuration interfaces: `model.train_cfg.rpn.assigner.ignore_iof_thr`, `model.train_cfg.rcnn.assigner.ignore_iof_thr`; positive значения выбираются/проверяются для geometry, здесь не назначается универсальное число.
- При `num_gts==0` `assign_wrt_overlaps` ставит **все** `assigned_gt_inds=0`; предварительная запись в нулевую по GT размерность overlaps не защищает ignore candidates. Поэтому только ignored regions без regular GT не удовлетворяют ожидаемому ignore contract на этом pin. Это static counterexample из raw 220–269, не выполненный runtime reproduction.
- Ignore использует bbox geometry, не class labels ignored instances; это **class-agnostic**, не per-category coverage-aware suppression. Может лишить correct overlapping object положительных candidates. Box-crossing geometry не равна pixel mask: IoF cutoff не гарантирует suppression каждого окна, захватывающего hidden object.
- Неизвестные coordinates скрытого второго instance не возникают из `iscrowd`: upstream всё ещё должен знать ignore region. Для узкого сценария C, где регион уже известен, прочитанный route условно готов без нового loss при nonempty regular GT и настройке обоих assigners. Для случайно недостающих boxes B/C вообще он не является найденным решением.

**Решение:** не рекомендовать смену framework только ради слова `ignore`. Этот route полезен как bounded candidate для dataset с достоверными ignore boxes и как тест границ future implementation; зависимости/weights/export/LinQ для команды не проверены. Для empty-GT cases требуется иная проверенная реализация, изменение handling или исключение image. Niitani/FedLoss из W1 остаются methodological contrast: per-RoI/per-category verified-label treatment ≠ generic crowd drop; FedLoss не назначает missing instances.

## Уровни готовности и выбор data route

| Маршрут | Paper/документ → implementation | Candidate contract | Target benefit |
|---|---|---|---|
| Полная рабочая разметка subset | Обычный supervised detector; U chain прочитан | Exhaustive classes/ROI/visibility policy + loader gate; нет новых partial fields | Не измерен; сравнить количество/разнообразие labels и quality по W1-03-E01 |
| U B, image×class unknown | W1 обосновал смысл; U mask consumer **не найден** | Нужны custom dataset/transforms/collate + BCE validity, обе branches и reduction audit | Неизвестен; это не готовый training flag |
| U C, spatial sparse | Методологические candidates W1 есть; native consumer не найден | Geometry/prior/mining + per-entry masks + assignment audit; отсутствие hidden box нельзя исправить одним class row | Неизвестен; engineering gate до learning trial |
| MMDet M known ignore boxes | Публичный готовый code chain прочитан | Class-agnostic IoF, positive settings **обоих** assigners, nonempty regular GT; empty case исключён | Не измерен, смена detector и export может быть дороже доразметки |
| Separate tasks | Обычное supervised обучение каждой таксономии | Каждый источник exhaustive для own task; не объединять missing labels в общую head. Missing instances own class всё равно исправлять | Association/inference cost и LinQ support отдельно неизвестны |

## W2-02-E01 — точечное дополнение к W1-03-E02, не новый обязательный trial

**Вопрос/решение:** implementation действительно устраняет выбранный false-negative path B/C, сохраняя known positive supervision, либо следует выбрать доразметку/separate task. **Входы:** checkpoint hash, repo/SHA, loaded head type и reg_max/end2end; оригинальный полностью размеченный diagnostic набор W1-03-E02, versions A/B/C и mapping hidden→original IDs; class coverage/ROI metadata; custom mechanism только если он реально подготовлен отдельной практической работой. Нужны отдельный fully annotated assessment и выбранный training environment; LinQ не нужен для проверки loss, но нужен позже для итогового artifact.

**Контроль:** fixed predictions либо identical forward/checkpoint/input/preprocessing для локализации; сначала отключить composite augmentation явными настройками конкретного pin, затем отдельно проверить каждую планируемую composite transform. Не сравнивать sum loss как доказательство mask correctness. Hidden GT доступен аудитору, **не training assignment**; если production method использует ignore geometry, для этого test geometry должна быть явно передана как собственный вход, а не украдкой восстановлена из auditor GT.

**Дополнительные действия/observables к существующему E02:**

1. Сохранить post-loader/post-transform `cls/bboxes/batch_idx` и coverage/ROI keys с типами/shapes; счётчики missing/empty. Отдельные variants: all-empty batch, одно empty image в mixed batch, only-ignore/no-regular-GT и overlapping known-positive+ignore. Последний нужен для person/helmet geometry, не для доказательства wearing.
2. Для **каждой** U E2E branch записать raw scores/decoded boxes, candidate membership с tiny-box expansion, `mask_pos` before/after conflicts/topk2, `fg_mask`, `target_gt_idx`, `target_scores`, denominator, validity masks, BCE до weighting/reduction и box/DFL/L1 contributions. Logs только one2one недостаточны. Отделить fg assignment другого retained GT от true hidden-only background.
3. Проверить invariants chosen contract: ignored zero-target class entries не участвуют; kept positive class entries и корректные bbox targets не blanket-masked; verified negatives вне unknown scope остаются. Если intentionally conservative policy убирает все negatives c, явно посчитать потерянное support. A/B/C denominator/assignment различия сохранить, не объявлять все различия implementation defect.
4. Для legacy v5 дополнительно layer-wise `tobj`, BCEobj unreduced + validity, class-positive indices и cls targets, autobalance/reduction. Для MMDet дополнительно regular/ignored instances после PackDetInputs, RPN и RoI `gt_inds`, sampled pos/neg, label/bbox weights; обязательно воспроизвести zero-regular-GT counterexample и проверить фактически выбранный replacement/filter policy.
5. В практическом execution этапе E02 проверить gradients соответствующих logits **до zero_grad**, known positive regression и сохранение/reload criterion/config. Zero ignored gradient при ненулевом остальном loss — полезный correctness observable; нынешний отчёт его не измерял. Лишь после passage допустим learning comparison W1-03-E01 с full assessment, matched data/budget/selection и отдельным учётом annotation/engineering time.

**Метрики/артефакты:** named tensor dumps/array shapes, post-transform overlays, per-class/region negative/positive participation counts и loss contributions, gains/normalization, branch IDs, metadata round-trip diff, config/code/data/checkpoint hashes; при execution — gradient diagnostics и optimizer update boundary. **Исходы:** B проходит, C нет → применять только источник с class-level unknown/exhaustive own instances; v5 objectness продолжает штрафовать → механизм неполон; only-ignore fails → фильтр/другая implementation до training; metadata lost → data gate failed; всё проходит → проверить пользу на независимом полном GT. **Stop:** первый необъяснённый false-negative contribution или исчезновение correct positive, отсутствие нужной geometry/coverage; не запускать длинное обучение для компенсации ошибки. **Предел:** искусственное deletion не воспроизводит selection bias tiny/occluded labels; correctness не доказывает качество, event metrics, export или LinQ.

## Оставшиеся вопросы и передача

| Q-ID / тип | Точное неизвестное, влияние и закрытие |
|---|---|
| W2-02-Q01 — case/artifact, P0 | Фактические source×class states, exhaustive/sparse instance coverage, ignore/ROI/visibility policy и original metadata. Уже известно, что обычный TXT не сохраняет их. datasets должен получить originals и ручной audit; определяет A/B/C и допустимость union. |
| W2-02-Q02 — engineering/experiment, P0 | Выбранный trainer/checkpoint и actual criterion/head branches; custom validity mechanism не создан. model_stack получает F01–F09/F12 и E01; закрытие — code/API и execution diagnostics W1-03-E02. Публичный static trace на U не подтверждает локально установленную версию. |
| W2-02-Q03 — experiment, conditional | Полезен ли conservative negative suppression против полной доразметки при одинаковом holdout и измеренном annotation/engineering budget. Public source не устанавливает target gain; только после correctness gate, без обязательного grid. |
| W2-02-Q04 — artifact/experiment, conditional | Если выбран MMDet known-ignore route: реально ли target images имеют regular positives, нужную geometry и согласованные transforms; как поступать с zero regular GT. Проверить pinned configs и E01, затем отдельно export/SDK. Не переносить найденное на все MMDetection assigners. |

**→ model_stack:** минимальный контракт — actual task/head/reg_max/E2E choice; per-image/per-class/per-region validity representation; transformed coordinates; branch-specific target/BCE diagnostics; positive precedence; reduction/normalization; legacy objectness при наличии. У U нет готового найденного consumer, но B objectness-free не требует безусловно переписывать bbox loss. Для multi-task segmentation/pose надо отдельно читать mask/keypoint/semantic terms: detection audit не подтверждает их partial safety.

**→ datasets:** хранить исходные verified categories, instance completeness, crowd/ignore geometry, ROI/visibility thresholds и source IDs; не оставлять единственным артефактом convert_coco TXT. Ignore geometry и «source никогда не аннотировал class» — разные metadata. Доразметка пропущенного instance в уже выбранном image может снять correctness barrier без нового алгоритма.

**→ evaluation:** assessment полный по рабочей policy; сохранить claims ровно в допустимом ROI/visibility scope. Positive loss меньше после удаления annotations не означает улучшение. Artificial deletion audit — correctness diagnostic, не оценка реальной missingness.

**→ автор / очередь W2-12:** K002 больше не широкий public вопрос «как YOLO реагирует на partial»: точные failure paths установлены. Default conditional route — согласованный fully checked subset, либо separate exhaustive tasks; coverage-aware union ставится в очередь только при достоверной metadata и implementation gate. Нет необходимости запускать одновременно class-mask, spatial-ignore и новую detector framework. Неизвестное target benefit остаётся отдельным практическим вопросом.
