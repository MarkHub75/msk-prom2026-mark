# GAPS: что не покрывает контракт и какие допущения сделал мок

Контракт не менял. Сверено с `contract/openapi.json`, `ws.schema.json`, `ws-examples.json` (версия 1.0.0, main `d4709bea`, S1) и `tech.md`. Строка = расхождение или допущение. Владелец: **Б** — бэкенд, **Ф** — фронт (Codex), **Д** — демо.

## Важное до показа

| # | Что | Кому | Что сделал мок |
| --- | --- | --- | --- |
| G1 | У демо-событий `EventDetail.episode = null` (5.2). Кадр доказательства доступен только через `episode.evidence[].url`. Значит, у демо-события экран `/events/:id` не может показать кадр. | Б, Ф | Живые события режиссёра несут синтетический `Episode` (`method: "синтетика: ручная разметка"`, `analysis_id: 0`) с `evidence`. Исторические события — `episode: null`. Флаг `--no-episode` возвращает `null` и у живых. Нужно решение: либо эпизод у демо-событий, либо поле кадра в `EventDetail`. |
| G2 | Сид 8.16: 50 % жёлтых — `confirmed`. По 8.6 это открытый статус, из него жёлтое не уходит само. По 8.8 лента оператора показывает **все открытые** события без ограничения по возрасту. На настоящем бэкенде после `serve --seed` в ленте окажется ~96 старых подтверждённых жёлтых, счётчики `open_yellow` секторов будут ненулевыми. | Б | История мока терминальная: подтверждённые жёлтые доведены через мастера до `resolved` (`confirmed → sent_to_master → master_accepted → resolved`). Лента после `reset` пустая. |
| G3 | В фейковой сцене `demo` бег идёт с 3 по 6 с ролика: подтверждение около 4 с (`hold_s` 1), закрытие на 8 с (`end_after_s` 2). Жёлтое живёт около 4 с после публикации, потом по 8.5 из `new` или `viewed` уходит в `auto_finished`. На настоящем бэкенде оператор должен нажать «Подтверждаю» почти сразу, иначе кнопки пропадут. | Д, Б | Жёлтое открыто, пока ведущий не опубликует красное. `demo next` не публикует красное, пока жёлтое ждёт оператора (`--force` публикует и завершает жёлтое как `auto_finished`, по 8.5). |
| G4 | У настоящего бэкенда нет CORS. Фронт с `VITE_API_BASE=http://127.0.0.1:8000` из Vite на 5173 получит ошибку CORS. | Ф | Против бэкенда — только `npm run dev` (прокси Vite `/api` и `/ws` → 8000, `VITE_API_BASE` пустой) или собранный фронт, который раздаёт бэкенд. CORS есть только у мока. |
| G5 | `Evidence.url` относительный (`/api/evidence/{id}/image`). | Ф | Фронт добавляет `VITE_API_BASE`: в моке картинка на 4010, а страница на 5173. |
| G6 | `view` разрешён только из `new`. Повторное открытие карточки с `view` даёт 409. | Ф | Отправлять `view`, только если он есть в `allowed_actions`. |
| G8 | Хвосты ONNX из `config/models.yaml` (`models/linq/*_tail.onnx`) в `.gitignore` (`models/*`), на этой машине их нет. `LinqBackend` проверяет файл хвоста до любого вызова, в том числе при `SAFEWATCH_FAKE=1`. Итог: в свежем клоне каждая задача `failed` с `model_missing`, событий нет (первый прогон WATCH_LOG, main `8b8acf53`). | Б, Д | Для показа на бэкенде положить настоящие хвосты в `models/linq/...` или, только для фейка, пустые файлы с теми же путями (`FakeRemoteShell` их не читает). `bin/watch.mjs` делает такие заглушки в scratch-worktree и пишет об этом в лог. |
| G7 | Эфир с `loop=true` на бэкенде публикует события сцены заново в каждом цикле (новый `pub_key` на цикл, ролик 20 с). | Д | В моке повторов нет. На бэкенде для показа удобнее `loop: false` или остановка эфира после красного. |

## Допущения мока (контракт молчит)

| # | Что | Решение мока |
| --- | --- | --- |
| A1 | В моке нет эфира и видео. По 8.9 камера без `playing`-эфира — `no_observation (no_source)`. | Камера с флагом `observed` считается наблюдаемой (`normal`). Наблюдаемы 7 из 8, «Камера 4.2 · Верстаки» — нет: сектор 4 показывает «Нет наблюдения: 1 из 2 камер». `broadcast`, `preview_url`, `video_id` — `null`, `freshness_ms` — `null`. |
| A2 | `meta.scenarios` на бэкенде S1 пуст (плагины появятся в S5). | Мок отдаёт 10 сценариев. `running` и `fall` — `active`. `fire_smoking`, `no_harness`, `suspended_load` — `model_missing`, «Модель не подключена». `load_carrying` — `skeleton` с текстом из 8.3. `proximity`, `phone`, `fence_crossing`, `restricted_under` — `skeleton`, «Не включён в демонстрационный контур» (текст мока). Описания, подписи, единицы и диапазоны параметров придуманы моком, значения по умолчанию — из `config/default.yaml`. |
| A3 | Порядок проверок в `event_action` (S7 ещё нет). | Неизвестная `X-Role` → 400; плохой `X-Actor` → 422; плохое тело → 422; нет роли → 400; нет события → 404; действие не своей роли → 403; пара (действие, статус) не из 8.6 → 409; `resolve` с пустым комментарием (после `trim`) → 422. |
| A4 | Тексты ошибок, которых нет в `texts.py`. | 404 события: «Событие не найдено». 409: «Действие недоступно в текущем статусе события». 422 `resolve`: «Опишите принятые меры», `details.field = "comment"`. 501: «Функция недоступна в демонстрационном моке». Совпадают с бэкендом: «Выберите роль», «Имя: до 60 символов», «Неверные данные запроса», «Действие недоступно для этой роли», «Сектор не найден», «Камера не найдена». |
| A5 | `X-Role` на чтении. Бэкенд проверяет её только там, где есть `RoleDep` (карточка события и пишущие вызовы). | Так же: `GET /api/meta` с неизвестной ролью отвечает 200, `GET /api/events/{id}` отвечает 400. |
| A6 | `MasterInbox.recent_resolved`: окно не задано. | Последние 10 `resolved` по времени решения. |
| A7 | `ShiftSummary.shift_id` и `title`. | `day:2026-10-24` / `night:2026-10-23`, «Дневная смена 24.10». Смены из `config/default.yaml`, МСК = UTC+3. |
| A8 | `Notification.id`. | `<event_id>-yellow`, `<event_id>-red`, `<event_id>-master` (как `41-red` в `ws-examples.json`). |
| A9 | `GET /api/events`. | Фильтр дат по `started_at`; сортировка по `published_at` по убыванию; `cursor` = смещение строкой; `limit` 1..200; `q` ищет по причине, названию, камере, сектору, зоне. |
| A10 | Ручная разметка кадра в `HudObject.score`. | `score: 1.0`, тег `manual` «ручная разметка, не нейросеть», `label: "человек · ручная разметка"`. |
| A11 | Живые события мока: `mode=demo`, `is_demo=true`, `provenance.fake=true`, `provenance.backend=null`. На настоящем бэкенде события из эфира будут `mode=replay`, `is_demo=false`. | Фронт не должен строить логику на `mode`/`is_demo`, кроме пометки «демо». |
| A12 | Служебные маршруты режиссёра. | `/__demo/{next,reset,status,ws-drop,fault/*}` на порту REST мока. В контракте их нет, на бэкенде их нет. |

| A14 | Маршруты контракта, которых нет в моке. | 501 `not_implemented` с `ApiError`. Чтения S1 (`/api/sectors`, `/api/cameras`, `/api/cameras/{id}`, `/api/admin/cameras`) отвечают по-настоящему, их запись — 501. |
