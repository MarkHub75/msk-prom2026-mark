# АРГУС — фронтенд Егора

Фронт и бэкенд `safewatch` находятся вместе в `main` после squash-слияния PR #36. Он заменил прежний baseline; отдельная копия `front/final`, соседний worktree или ручная подмена `frontend/` для запуска больше не нужны. Контракт REST — `../contract/openapi.json` 1.1.0, WS — `../contract/ws.schema.json`.

## Стенд для команды и жюри

Подготовьте настоящий пакет и `config/user.yaml` по [docs/DEPLOY.md](../docs/DEPLOY.md), затем из корня репозитория:

```text
docker compose up -d --build
```

Откройте `http://127.0.0.1:8000/?review=real`. Образ собирает этот фронт на Node 24 (`npm ci`, `npm run build`); FastAPI раздаёт `frontend/dist` вместе с API/WS. Host `frontend/dist` не нужен. Production API использует текущий origin, WS — `ws(s)://<тот же host>/ws?role=...`; адреса localhost в Vite proxy относятся только к разработке.

Предпочтительный пакет `argus-real-v2`: четыре реальных ролика и заранее посчитанные LinQ-детекции `fake: false`; fallback — `argus-real` с двумя роликами. При совместимом профиле детектор+поза и `extra: []` задачи используют кэш, LinQ/Jupyter при показе не нужны. Не запускайте `npm run demo` или `SAFEWATCH_FAKE=1` для доказательства настоящих детекций. Происхождение видео: Önal, Dandıl, Mendeley Data, DOI 10.17632/xjmtb22pff.1, CC BY 4.0; атрибуция в пакете.

Настроенный HTTPS-адрес существующего Tuna получают у Марка; в Git его не публикуют. Для проверки нужны реальное видео, кадр/клип, WS `hello` и последующее событие, затем путь оператора и мастера. Статусы конкретной сборки и ограничения — в [отчёте этапа 1](../docs/handoff/upgrade-v3-stage-1.md).

## Локальная разработка

Нужны Node 24 и Python 3.12 с uv. Из корня:

```text
uv sync --locked
npm ci --prefix frontend
npm run build --prefix frontend
uv run --no-sync safewatch serve --seed
```

Открыть `http://127.0.0.1:8000`; остановить host-сервер `uv run --no-sync safewatch stop`. При работающем сервере не выполняйте `uv sync`. Docker на том же порту должен быть остановлен заранее.

Для изменения фронта можно вместо production-сборки запустить `npm run dev --prefix frontend`: Vite проксирует `/api` и `/ws` на host-бэкенд 8000. Открывайте адрес, который Vite напечатал в `Local:`. Для production оставьте `VITE_API_BASE` и `VITE_WS_URL` пустыми: тот же origin.

```text
npm run gate --prefix frontend
```

Гейт: `api:check → lint → typecheck → test → build`. `build` выполняет `tsc --noEmit && vite build`. `api:check` сверяет сгенерированные типы с актуальным OpenAPI; после согласованного расширения контракта — `npm run api:gen --prefix frontend`. Маркер `FRONT_OWNER` отключает старую трассировку путей baseline в `tech.md`, но не проверки API/WS и не этот гейт.

## Отдельные синтетические режимы

`npm run demo:mock` из `frontend/` запускает Vite, Prism 4010 и mock-WS 4011 на примерах контракта. Это проверка экранов, не реальные результаты LinQ. `npm run demo` — исторический helper для отдельного backend worktree и фейка: он не является инструкцией текущего Docker-стенда. Не направляйте публичный Tuna на dev/mock-сервер.

Обзорные fixtures включаются явно параметром `review`, `VITE_REVIEW_MODE` или сохранённым режимом сессии. Для приёмки откройте `?review=real`, убедитесь, что нет полосы обзорного режима, и проверьте реальные запросы к API и WS. `SAFEWATCH_FAKE=1` создаёт синтетические детекции и должен оставаться подписанным фейком.

## Роли

Роль выбирается в шапке, логина нет: REST получает `X-Role`, WS — параметр `role`. Имя сотрудника для действий задаётся в профиле.

| Роль | Экраны |
|---|---|
| Оператор | диспетчерская, сектор, камера с HUD и зонами, карточка события с клипом, захват экрана при красной тревоге; с телефона — `/m/operator` |
| Мастер смены | поручения, карточка, принятие/решение и сводка смены с PDF |
| Охрана труда | журнал, фильтры/CSV, правила камер, аналитика, нарушители, датасет ложных срабатываний |
| Руководство | аналитика, нарушители, существующий калькулятор окупаемости |
| Администратор | камеры/секторы, видео/эфир/калибровка/зоны/правила, система и демо-пульт |

## Демо-пульт (`/admin/demo`)

Пульт показывает пакет и происхождение детекций, камеры с готовыми записями, состояние и позицию эфира. «Проиграть один раз» отправляет `POST /api/cameras/{id}/broadcast` с `loop: false`, «Остановить» — `DELETE /api/cameras/{id}/broadcast`. События создаёт backend-конвейер по проанализированной записи.

Пока backend по умолчанию запускает цикл, события повторяются на каждом круге. Для осознанного показа можно остановить все эфиры, затем выбрать «Проиграть один раз» для нужной камеры. Это ручное управление существующим поведением; полная дедупликация и изменение поведения по умолчанию относятся к этапу 2. Сброса мира через API нет. Старые события сохраняются; новый чистый Docker-показ делают в отдельном именованном томе по DEPLOY, не удаляя host `data/app`.

## Сценарий дымовой проверки

1. Проверьте пакет в «Системе» или `/api/demo/packs`: правильное имя, `backend=linq`, `fake=false`; четыре ролика v2. Дождитесь `done` и `cached=true` у задач.
2. Выберите оператора и сектор 1. Убедитесь, что видео движется, HUD и данные камеры видны. Разрешите звук пользовательским кликом.
3. Дождитесь настоящего красного, откройте доказательство и проиграйте клип. Подтвердите событие; для красного существующий автомат передаёт его мастеру.
4. В роли мастера откройте поручение, примите, укажите меры, завершите. Проверьте состояние на сервере и в журнале.
5. Обновите прямой маршрут, проверьте мобильный viewport и повторите через HTTPS Tuna, включая WS и медиа.

В v2 камера 1.4 публикует красное около 5,2 с, 1.5 — 10,7 с, 1.3 — 17,0 с от начала видео; 2.3 — фон без события. Жёлтых в этом пакете нет. На 1.4 спорна зона оператора у пресса; 1.5 пересекает нарисованную линию, а заголовок про «перелезание» неточен. Эти сцены не доказывают промышленную точность и не заменяют проверку всех сценариев.

## Приложение на телефон (PWA)

- `manifest.webmanifest` собирает `vite.config.ts`; `start_url` — `/m/`, переход к сохранённой роли. Иконки находятся в `public/icons`.
- `public/sw.js` регистрируется только в production. Кэширует оболочку, `/assets` текущей сборки и иконки; `/api` и `/ws` не кэшируются. Без сервера показывается состояние отсутствия связи.
- В профиле есть установка на телефон и разрешение уведомлений. На iOS используется «Поделиться → На экран “Домой”». Системные уведомления идут через `registration.showNotification`.
- Установка требует HTTPS (или localhost). Доступность системного звука/уведомлений зависит от разрешения браузера; её проверяют после пользовательского клика.

## Что считать доказательством

Исторический сид — 240 синтетических `is_demo=1` событий, доступных журналу/статистике. Он не попадает в настоящую операторскую ленту. События эфира реального пакета имеют `is_demo=0`, связанную модель, SHA видео и кадр/клип. Видео — воспроизведение записи по часам сервера, не RTSP.

Интерфейс всех ролей и механизмы правил существуют; качество моделей и полнота восьми сценариев проверяются отдельно. CPU (local) не называется TPU, отсутствие модели отображается честно. Калькулятор v2 — будущий этап 3, текущий экран использует существующий API. Авторизации и живых RTSP-камер нет.
