## Изменение рекомендации [W2-EXPERIENCE-F04, INF]

До W2 предлагалось обязательное ручное действие на каждом шаге. Существование сложностей F03 позволяет проверить альтернативу: краткая классификация эпизода, повторяемые эпизоды одной причины связываются с одной мерой; отдельная проверка результата нужна там, где её требует политика/критичность. Обязательный свободный комментарий к каждой мелкой тревоге и второй reviewer каждого клика пока не имеют эмпирического основания. Не следует добавлять их в must-have только ради «полного workflow».

Для первичной обратной связи достаточно компактной причины/«не могу определить», сохранения контекста и понятного следствия. Уполномоченный куратор проверяет спор/пример для обучения, а не блокирует всякое оперативное оповещение. Управление очередью по повторяемой причине — предложение; оно не доказано ни отзывами, ни невидимым UI Protex.

Предложенная проверка, **не выполнена**: на одной последовательности (истинный эпизод, несколько повторов, неоднозначность, плохая видимость) сравнить обязательную меру+reviewer на каждый эпизод с одной мерой на причину. Сохранить ошибки решений, число незавершённых задач, время активной работы и объяснение участника. Принятый за быстрый клик неверный исход — провал. Не объявлять результаты пяти участников доказательством удобства для завода. Если более тяжёлый путь нужен локальным регламентом, сокращать разрешено только его необязательные элементы.

## Что осталось неизвестным

- Наблюдаемая event card/step sequence Protex, реальный effort и accessibility. Закрытие: доступная запись/публичный help с экранными шагами, затем screenshot-first в рабочем браузере.
- Прямая трудность рабочего, которого снимают, и российского оператора конкретного HSE-пилота. Пользователь G2 административной/ИТ роли не представляет эту группу.
- Требует ли реальный процесс нашего клиента отдельного reviewer и обязательного комментария каждой меры. Закрытие: локальная процедура/полный кейс/эксперт.

Передача CONTRACT: не создавать обязательный reviewer/task/comment для каждого эпизода как «проверенный конкурентами» паттерн. Для MVP минимум — человеческая оценка/сомнение и одна связанная мера, если она нужна сценарию; никакое обещание удобства не выводить из маркетингового feature list.
