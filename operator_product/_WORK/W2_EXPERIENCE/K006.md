Срез доступа 23.10.2026 Europe/Moscow. Новые первичные документы получены search+open; DPA после неуспеха web PDF прочитан локально. Право РФ, практика ХайТэк и настроенный клиентский договор не установлены.

## Итог для критики

**Предложенный исход: область применимости privacy-обещаний сужена; прямая реакция работников остаётся открытой.** У конкретного продукта обнаружено договорное исключение для unblurred QA/training. Поэтому карточка «анонимно» без разделения стадий не обоснована. Не считать blur гарантией отсутствия идентифицируемого оригинала. Прямой рассказ работника/представителя российского видео-HSE пилота не получен; vendor case о сотрудничестве с профсоюзом сохраняет своё происхождение.

## Предлагаемый data flow для нашего MVP [W2-EXPERIENCE-F11, INF]

Это наш контракт-требование, не реконструкция несуществующего доступа к ХайТэк. F05/F06 показывают, почему стадии надо разделять. Наличие отдельного места хранения на каждом шаге — вопрос к architecture, а не требование создавать все хранилища.

| Стадия | Возможные данные и риск | Предлагаемое правило/доступ | Что пока неизвестно |
|---|---|---|---|
| Камера/NVR, исходный RTSP | Оригинал лица, тела, контекста/смены; NVR может записывать независимо | Указанный владелец источника, отдельное право чтения и учёт мест записи | Есть ли NVR/archive; согласованные цели/сроки; кто реально читает |
| LinQ input/job | Кадры/клип до masking могут покинуть площадку при удалённом инференсе | Передача только по согласованному processing path; журнал input_ref/job_ref, регион/получатель, доступ; оригинал не помещать в debug по умолчанию | Где LinQ и input storage; допускается ли unmasked input; срок temp/cache |
| Event media | original_ref и derived_masked_ref различны, overlay не оригинал | В UI указывать тип производной и masking status; оригинал — отдельное полномочие; отсутствие original не скрывать | Может ли upstream предоставить оригинал/клип; неизменность ref/версии |
| Review console | Masked overview снижает видимость, но участок/время могут идентифицировать | Role/site permission; при необходимости justification/journal открытия оригинала; label «маскировано», не «анонимно» | Роли и доступ к распознаванию/идентификации; кому нужен original |
| Messenger/уведомление | Attachment создаёт внешнюю копию вне RBAC консоли; screenshot/forward нельзя гарантированно отозвать | Предпочтение minimal text + авторизованная ссылка; отдельное разрешение attach/export, фиксировать derivative/recipient/channel/purpose; privacy фильтр на export path | Разрешённый сервис/токен/контур/доступ получателя и права отправки изображений |
| Export/report | PDF/CSV может содержать image URL, время/камеру и сведения об авторе | Экспортировать только нужные поля, производную по политике, manifest кто/когда/зачем; контроль origin/retention отдельно | Получатели, допускается ли оригинал и дальнейшее хранение |
| Обращение/апелляция | Контекст работника, спорная идентификация, исправление записи | Сохранить первоначальную оценку и отдельное обращение, не требовать доступа работника ко всем видео; ответственный разбирает и фиксирует версию решения | Кто рассматривает, через какой разрешённый канал, доступная процедура и сроки |
| Feedback/curation/training | Операторская метка и оригинал могут уйти новым лицам/подрядчикам | Feedback не означает consent/export/training. Отдельные eligible_for_curation и approved_for_training с основанием, data lineage, правом reviewer; QA contractor — явный получатель | Разрешено ли обучение, какие кадры/подрядчики/регионы, кто утверждает и удаляет |
| Удаление | Очистка UI не удаляет NVR, cache, export, messenger, backup, dataset | Реестр копий и проверяемое удаление по политике владельца; не обещать cascade без механизма | Согласованный retention каждой стадии/backup/legal hold; право РФ |

Без подтверждения схемы допустимо: «В обзоре показан маскированный кадр; доступ к оригиналу ограничивается отдельно». Недопустимо: «никто не видит лица», «исходник никогда не покидает объект», «система полностью анонимна», «все данные удаляются одним кликом». Даже отсутствие face recognition не исключает узнавания по одежде, времени, рабочему месту или внешнему контексту. Это логическая граница данных, не измеренная атака re-identification.

## Маскирование и проверка СИЗ — предложенная проверка

Для каски, респиратора и других подтверждённых полным кейсом СИЗ взять разрешённые неоднозначные и чёткие примеры каждого ракурса, несколько режимов blur/ghosting и оригинал при допустимом доступе. До просмотра зафиксировать rule definition/качество видимости. Раздельно проверить вход детектора и изображение человеку: detector-before-blur может работать, а reviewer-after-blur уже не различать респиратор. Сравнить human decision/«недостаточно данных», сохранить причины и masked version. Если зона лица скрывает признак респиратора — сузить masking/доступ по политике или отказаться от человеческого подтверждения этого признака по производной. Тест **не выполнен**; нельзя заранее заявить совместимость privacy/recall. Требование обязательного LinQ не меняется: обработка до/после masking требует технической проверки соседями.
