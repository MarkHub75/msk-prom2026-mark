# U09 — Каналы, доставка и эскалация
Дата доступа: 2026-10-23 Europe/Moscow. Каналы не подключались; сообщения людям не отправлялись.

## Решение
До определения площадки считать канал сменным адаптером, а не гарантией контакта с мастером. Для демо нужен журнал попытки отправки и отдельное принятие человеком; резервный путь — диспетчер передаёт по согласованной связи. Конкретный SLA и право голосового вмешательства неизвестны.

## Первичные основания
### W1-U09-S01 — DSSL/TRASSIR, Alarm Monitor
URL: https://confluence.trassir.com/spaces/SCR/pages/6130262/Alarm%2BMonitor . Открыта текущая версия, updated 29.09.2026, автор Александр Акимов, последнее обновление Ольга Селезнева. Локаторы Описание скрипта; Типы реакций; Отправка снимков в Telegram; Express; Max; SMS; Операции с тревожными выходами; Генерация тревоги. Старый https://confluence.trassir.com/pages/viewpage.action?pageId=77922611 открывал version 49, 05.04.2021; выполнен переход current version.
W1-U09-F01 [документация]: скрипт выводит тревожный канал, сохраняет screenshot, отправляет описание/кадр в Telegram (на сервере), Express, MAX, email, SMS, управляет тревожными выходами/СКУД и генерирует инцидент по token. Telegram настраивается числовыми ID; MAX — ID получателей и API token своего бота; Express требует адрес сервера, chat ID и выбранную авторизацию; SMS использует отдельный сервис SMSC.RU с учётной записью. Несколько связанных каналов тревожного входа могут дать несколько сообщений. Документирует конфигурацию, не доставку в конкретном цеху, не право подключать систему оповещения и не измерение эффективности.

### W1-U09-S02 — MAX для разработчиков, Настройка сценариев работы бота с помощью API
URL: https://dev.max.ru/docs/chatbots/bots-coding/prepare . Открыто; живые docs без указанной версии/даты; локаторы вводный блок, Как создать, Отправка API-запросов, Добавление в чаты.
W1-U09-F02 [документация]: требуется верифицированный профиль юрлица, ИП или самозанятого — резидента РФ; пользователям доступен прошедший модерацию бот. Документированы messages/buttons, media uploads и callback-сценарии; базовый host на момент доступа platform-api2.max.ru. Это доступная техническая схема, но у команды неизвестны профиль/токен/модерация и разрешение предприятия. Открытый API не подтверждает работающее подключение за 45 часов.

### W1-U09-S03 — MAX для разработчиков, События
URL: https://dev.max.ru/help/events . Открыто; без версии/даты; локаторы Как получать события, Webhook.
W1-U09-F03 [документация]: для production документ рекомендует/требует Webhook, Long Polling оставляет тестированию; нужны HTTPS и доверенный сертификат, публичный endpoint. HTTP 200 означает успешную обработку endpoint; без успеха повторяются попытки, после восьми часов бот отписывается. Это **входящие события бота**, не обещание восьмичасовой доставки HSE тревоги пользователю и не receipt работника.

### W1-U09-S04 — Telegram Bot API
URL: https://core.telegram.org/bots/api . Открыто; page recent changes Bot API 10.3, 24.08.2026; локаторы sendMessage, CallbackQuery.
W1-U09-F04 [документация]: sendMessage при успехе возвращает отправленный Message. CallbackQuery позволяет обрабатывать действие пользователя на кнопке. Первый ответ не означает чтение человеком; принятие в работу можно реализовать явным действием, связанным с incident ID. API не доказывает разрешение Telegram на предприятии, наличие связи/телефона и актуального сменного адресата.

### W1-U09-S05 — HSE L138, Dangerous Substances and Explosive Atmospheres
URL: https://www.hse.gov.uk/pubns/priced/l138.pdf . PDF открыт, Second edition 2013, pp.86–87, §§413–417.
W1-U09-F05 [регуляторное руководство UK]: предупреждение должно соответствовать риску, давать время/информацию для действия и быть видимым/слышимым во всех затронутых областях; примеры включают звонок, klaxon, свет и intercom/tannoy. При нескольких сигнализациях нужно различать их и обучать реакции. Это про опасные вещества/аварийное оповещение в UK, не российская норма и не доказательство эффективности команды «наденьте каску».

## Следствия для маршрута
W1-U09-F06 [наш вывод]: показывать состояния «создано», «попытка отправки», «ошибка канала», «принято [имя/время]», «действие [описание/время]». Эскалировать отсутствие принятия и отсутствие мер раздельно; повтор не должен создавать новый независимый эпизод. Таймер определяется временем до последствий и регламентом, не дефолтом VMS. Передача по рации диспетчером возможна только после проверки контакта/покрытия/разрешений.

Не найдено первичного доказательства, что у заказчиков «ХайТэк» MAX/Telegram/рация являются утверждённым HSE каналом. Не найдено измерения эффективности автоматического голосового предупреждения по каске на российском производстве. Смежное экспериментальное основание и российский пример инфраструктуры разобраны ниже; не выдавать отсутствие применимого исследования за отсутствие практики.

Предлагаемый тест: на площадке пройти маршрут до мастера с согласованным устройством, состояниями offline/экран заблокирован/нет push permissions/истёк token/сбой сервиса/сменился ответственный; измерить отправку, реальное получение, ACK, действие по отдельности. Для громкой связи — согласованная проверка разборчивости при реальном шуме/СИЗ и соответствия аварийным сигналам; без самовольного включения сирен.

### W1-U09-S06 — Wogalter, Kalsher, Racicot, Behavioral compliance with warnings: effects of voice, context, and location
Safety Science 16 (1993), 637–654; DOI https://doi.org/10.1016/0925-7535(93)90028-C . Издатель ScienceDirect ответил 403. Авторский список https://www.safetyhumanfactors.org/publications/ привёл к PDF https://www.safetyhumanfactors.org/wp-content/uploads/2022/09/61WogalterKalsherRacicot1993-copy.pdf . Веб-читалка отклонила 34,801,662 bytes; локальная загрузка успешна, PDF 18 страниц и текст извлечены PyMuPDF, прочитаны pp.637,641–645,650–652. Локальные артефакты WOGALTER_1993.pdf и WOGALTER_1993_EXTRACT.txt.
W1-U09-F07 [опубликованное измерение]: Experiment 1: 198 участников, примерно половина студенты RPI, половина школьники на undergraduate courses; task — смешивание безвредных веществ, представленных опасными. Измеряли надевание маски/перчаток, а не травмы. Добавление voice к warning повысило compliance в сопоставимых условиях; все анализы с voice дали p<0.0001. Pictorials/strobe не показали значимого эффекта. Это лаборатория, подготовленные участники, неизвестен перенос на промышленный шум, охрану слуха, повторяющийся автоматически сгенерированный голос, каски и русский язык. Основание для гипотезы испытания, не обещание эффекта на площадке.

### W1-U09-S07 — Кубузов, Куренкин, Толпаров (Норникель), Кожиев, Горный журнал №6, 2015, с.93–96
Английский титул: Ways to develop command and communication systems in underground mines of Norilsk Nickel Mining and Metallurgical Company. DOI https://doi.org/10.17580/gzh.2015.06.19 . Открыт полный издательский PDF https://rudmet.net/media/articles/Article_MJ_06_15_pp.93-96.pdf ; прочитаны с.93–96, особенно с.95–96. Русский заголовок частично повреждён при извлечении; английская библиография читается.
W1-U09-F08 [первичное сообщение команды предприятия]: авторы описывают подземные сети/радиосвязь и испытания передачи голоса/данных со смартфонов Android/iOS в режиме абонент—абонент/диспетчер. Пересылка фотографий нарушения с планшета/смартфона сформулирована как будущая возможность; покрытие связано с числом роутеров/считывателей и зоной шахты. Испытание не означает массовый HSE workflow 2026 года и не доказывает пригодность обычного смартфона для взрывоопасной зоны. Практическое следствие: устройство, покрытие и стадия внедрения должны быть установлены отдельно.
