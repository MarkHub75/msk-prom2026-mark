# W2-M — диагностика, session isolation и безопасное восстановление

**K015, K012, K020.** Решение: когда исправлять запрос, когда повторять load/inference, когда заменять worker и что отдавать администратору. Исторический контекст — ночь перед хакатоном23–25.10.2026, пять инженеров,45часов. Новые сетевые чтения выполнены23.10.2026; контроль clock02:10:31 и02:11:58 UTC (05:10:31 и05:11:58 Europe/Moscow), точные HTTP-времена02:11:07–02:11:19 UTC в `W2_M/HTTP_LOG.json`. Время завершения записано ниже отдельно. Онлайн-доступ, SKU и SDK команде по RUN_STATE не выданы; регистрация не выполнялась. Исследовательские scripts читали bytes/source, **SDK/native/device не запускали**.

## Решение и существенное изменение W1

**Не найдено основания назначать любой native exception обязательным поводом для process replacement или считать one-process-per-device ограничением LinQ.** Начинать с одного последовательного владельца session/device полезно как наша управляемая архитектурная политика. Она уменьшает число переменных первого запуска; это не vendor requirement и не доказательство межпроцессной изоляции.

Новое положительное первичное evidence: pytpu15.0.24 содержит **реальный thread-pool example/test**, где один device/program обслуживает несколько отдельных Inference descriptors. В14.7.0 есть исполняемый Python async helper и несколько coroutine на один device в одном процессе. Поэтому фраза W1 «public async/thread API не найден» требует версии: для **современной поставки** контракт не получен; для старой14.7.0 async code действительно есть, а15.0.24 содержит multithreading test. При этом старые примеры не доказывают корректную concurrency: thread test имеет TODO о неверных результатах, async helper не задаёт cancel/timeout и игнорирует result callback. Никакой из них не является инструкцией запускать current Runtime16.18.6 через старый binding.

Current runtime error table/release notes/session guarantees после targeted поиска и live navigation не получены. Это ограниченный пробел в доступных материалах, **не установленные unsupported concurrency/cancel и не отсутствие исправлений**. Документированного current соответствия «код→retry/reload/reset» нет. Поэтому ниже — матрица локализации с version scope и безопасными нашими действиями, а не выдуманный vendor recovery manual.

Credentials, tokens и кадры с ограниченным доступом не включать в публичный packet. Один packet/file на исходный инцидент, retries ссылаются на него и не заменяют исходную ошибку последней.

## Точные недостающие контракты и путь закрытия

1. **Thread/process/session scope:** допустимы ли shared device handle/program между threads, отдельный Inference per thread, несколько processes на device, несколько tenants; как определяется exclusivity и очередь; допускается ли fork после native init. Нужен current reference/sample **с версией** и предоставленная access topology. Успех sample другой версии не ответ. До ответа handles не переносить между processes; каждый own worker открывает свои objects согласно поставке.
2. **Error state machine:** для каждого init/load/submit/completion error какие objects остаются valid, когда можно повторить тот же запрос/создать новый Inference/reload Program/reopen Device. Нужны official code table+recovery guarantees matching Runtime, а не только название exception15.0.24.
3. **Deadline/cancel:** ownership buffers до terminal completion, semantics client disconnect, cancel pending vs executing, acknowledgement, idempotency request submission, cleanup собственного процесса. Нужен current API/SDK reference. Символ submit, Future.cancel и host deadline сами по себе этого не устанавливают.
4. **Cleanup fixes:** исправлен ли generator exception path15.0.24 и как гарантируется native cleanup при exception/init failure/process normal exit. Запросить change/release note либо current source/test. Публичный последний PyPI архив не раскрывает закрытую современную поставку. W2-G fake probe не заменяется дублирующим probe здесь.
5. **Participant recovery:** какие действия доступны участнику, scope (session/device/whole host), занятость другими пользователями, contact/incident protocol. Нужен exact issued environment manual или явный ответ инженера. Наличие install-команды в другом hardware/OS protocol не разрешает её использовать как recovery2026.

Это precise unknown: искались конкретные версии/символы/документы, public navigation прочитана, package bytes доступны, old home недоступен DNS. Нельзя переименовывать пробелы в unsupported или необратимое повреждение.
