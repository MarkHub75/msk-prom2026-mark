# W1-02. Аппаратные продукты LinQ

## Вопрос и главный результат

Какие именно ресурсы и интерфейсы описаны для чипа, PCIe-карты, HPS и серверного комплекса, и какие ограничения из этого следуют для многокамерной промышленной видеоаналитики?

Проверка первоисточников выполнена 23.10.2026 приблизительно с 04:15 Europe/Moscow. Контекст подготовки команды — 45 часов, обязательное исполнение на LinQ, обещанный online-доступ; фактическая модель выделенного устройства, SDK и квоты неизвестны. Аппаратных запусков, компиляции и локальных измерений производительности не выполнялось.

**Практический результат:** существует несколько уровней продукта. LinQ H — чип; HP/HPD/HPQ — PCIe-карты; HPS — 3U-система ускорения; HPC — отдельный ПАК с двумя HPS и внешним сервером. Пиковые TOPS, суммарная память нескольких чипов и память CPU-хоста не взаимозаменяемы. Для HP найдено прямое расхождение официальных документов по 16/32 ГБ и PCIe Gen3/Gen2. Без точного SKU и ревизии нельзя гарантировать ни объём памяти, доступный одной модели, ни пропускную способность.

Полезное неожиданное расширение ветки — публичные руководства /docs: они раскрывают распределение памяти по процессорам и действительные исполнения, чего нет в рекламном /sol. Локальные технические выписки для независимого разбора: [SOURCE_EXTRACTS.md](W1_02/SOURCE_EXTRACTS.md). Полные PDF локально не скачаны из-за TLS ошибок; содержание прочитано через web.open.

## Значимые отдельные выводы и границы

**W1-02-F01 — память нескольких TPU не доказана как единая память одной модели.** Тип inference; статус: вывод из прочитанных S05/S07, не проверено на устройстве. Руководства физически распределяют DDR4 по микропроцессорам. Следовательно, 32/64 ГБ карты и 640 ГБ HPS не дают основания обещать размещение одной модели такого же размера. Неизвестны модель разделения графа, разрешённые сегменты и ограничения компилятора. Сначала надо получить лимит памяти на один исполняемый граф/контекст и отчёт memory planner.

**W1-02-F02 — int8 подтверждён, аппаратный fp16 не установлен.** Тип primary_documentation для int8/перспективы, inference для инженерного ограничения; статус: S08 прочитан. Практический выбор модели должен включать проверку квантования и метрик качества на касках/респираторах. Возможность обучать/экспортировать floating-point модель не доказывает такой же режим исполнения на TPU. Параметры mixed precision, аккумуляторов и поддержка vector operations этой веткой не установлены.

**W1-02-F03 — interface generation имеет несколько уровней.** Тип inference; статус: документы прочитаны. Gen4 вход HPS не делает каждый чип Gen4. Ширина внешнего x16 HPD/HPQ не противоречит x8 отдельного чипа, потому что карта содержит коммутатор. В S04/S06 проза «8 линий» расходится с таблицей x16; это повод запросить топологию, а не рассчитывать throughput по наиболее выгодному варианту.

**W1-02-F04 — 960 и 1920 TOPS относятся разным системам.** Тип vendor_statement + inference; статус: прочитаны S08/S11. ПАК HPC нельзя выдавать за выделенную командe единицу HPS. При online API скрыта ещё одна граница: shared resource, scheduler и лимит одновременных задач. Физическая машина и выделенная квота — разные величины.

**W1-02-F05 — память CPU-хоста определяется выделенной машиной.** Тип inference; статус: S09/S12 прочитаны. Максимум серверной платформы не говорит, сколько памяти установлено, сколько доступно в контейнере и кто хранит декодированные кадры. Для HX разделение LPDDR4/DDR4 раскрыто прямо; переносить эту схему на HPS без документации нельзя.

**W1-02-F06 — 2,3 мс не равно срок обработки кадра детектором.** Тип inference на основании S08; статус: опубликованное заявление просмотрено, собственного benchmark нет. Условия HPS ограничены ResNet-50 batch=1; не указаны входное разрешение, конкретные веса, границы таймера, transfer, preprocessing, quantization и версия compiler. Величина 1,5 мс дана как результат/возможность оптимизации, а не гарантированный режим. Эти числа повторяются у продуктов с разной суммарной мощностью и потому не показывают линейного ускорения одного запроса.

**W1-02-F07 — количество моделей не является количеством камер.** Тип inference; статус: не проверено. До 40 моделей HPS и более 16 GraLinQ — заявления о совместном запуске, без FPS/разрешений/загрузки. Одна модель может обслуживать несколько потоков, один поток — несколько моделей. Для сервиса необходимы профиль на собственной сети и предел задержки очереди.

**W1-02-F08 — декодер не следует считать встроенным в каждый LinQ.** Тип primary_documentation (S08/S09) и inference; статус: документы прочитаны. HPS описывает аппаратные видео-ASIC как дополнительную опцию. В HX присутствует видеоподсистема RK3588; её 6 TOPS NPU не являются TPU LinQ. Для проверки обязательного исполнения нужно привязать измерения к нужному вычислителю.

## Неизвестные и конкретные следующие проверки

**W1-02-Q01, наивысший приоритет:** какая точная модель/SKU/revision, число TPU, installed memory на TPU и CPU, лимит RAM/CPU контейнера, выделенная квота ускорителя? Попросить вывод аппаратного inventory и документ, относящийся к этой ревизии. Без этого таблица выше — карта возможностей, а не спецификация среды команды.

**Q02:** доступна ли память агрегированных карт одной модели или только независимым контекстам? Уточнить максимальный размер графа/весов/активаций, способ multi-chip partitioning и инструменты memory planning. Это влияет на выбор детектора, вторичных классификаторов и число параллельных контекстов.

**Q03:** как разрешаются HP 16/32 ГБ и Gen2/Gen3? Запросить authoritative BOM/РЭ по серийному номеру. При SSH-среде сохранить `lspci -nn`, `lspci -vv` для конкретного BDF; различать capability и negotiated link. Это предложенный эксперимент, здесь команды не выполнялись. При API без SSH запросить эквивалент inventory от инженера.

**Q04:** какие форматы реально поддерживает данный compiler/runtime? Запросить release/version, допустимые dtype входов/выходов/аккумуляторов, quantization pipeline и операторы. Наличие int8 не определяет автоматически signedness, layout или масштабирование tensor.

**Q05:** есть ли в выданном хосте декодер H264/H265, где выполняются resize/color conversion/NMS? Нужны пакет/codec/CPU quotas и network limit. Если доступ — только model API, задать максимальный payload, batch, concurrency и timeout; отсутствие PCIe доступа у команды не означает отсутствия ускорителя на сервере.

**W1-02-E01:** после доступа провести две раздельные серии: (а) чистое выполнение целевого артефакта, (б) полный путь видео. Сначала один поток, затем 2/4/8; измерять steady-state per-stream FPS, p50/p95 задержки, queue depth, host/device memory, загрузку CPU и доступный profiler TPU. Фиксировать разрешение, частоту выборки, batch, dtype, clock/power mode, версии и модель. Никакие цифры FPS заранее не назначены.

**E02:** сопоставить число видимых endpoint с исполнением карты. S05 ожидает два, S07 четыре endpoint 2805:0006 rev 08; это пригодная диагностическая зацепка, не доказательство исполнения модели. Профиль и runtime logs должны отдельно связывать задачу с device ID.

**E03:** проверить устойчивую работу при целевой нагрузке и наличие throttling; сравнить начало/конец достаточно длительного прогона. TDP режима и пиковые TOPS нельзя считать постоянными значениями доступного сервиса.

## Передача оркестратору

Достаточно установлено разделение продуктов и физическое распределение памяти HPD/HPQ. Главное изменение архитектурного ожидания: нельзя планировать одну большую модель исходя из суммарной DDR4 HPS и нельзя переводить ResNet latency или TOPS в число камер. Для критика особенно важны три пары документов: HP S02/S03, HPD S04/S05, HPS S02/S08. Первое уточнение постановщику — точный SKU/ревизия и квота; затем память на граф, clock/power mode и границы выполняемого video pipeline. Следующая волна должна независимо получить PDF бинарники, визуально сверить конфликтные таблицы и установить даты/ревизии, если они есть в metadata или поставочном комплекте.
