## Установленные факты

**W2-08-F01 — original annotation payload, выполнено.** `train.json` содержит 1000 image records и 4491 annotations; `test.json` —29 records и 207 annotations. IDs original categories:1 Coverall,2 Face_Shield,3 Gloves,4 Goggles,5 Mask. Это фактические аннотации, но число image records не является проверкой наличия и декодирования всех 1029 media. Prefix tar содержит сначала annotations, затем images; `PARTIAL_TAR_MEMBERS.json` — только успешно прочитанная начальная часть, не полный directory manifest.

**W2-08-F02 — comparison, выполнено.** Все 29 HF test IDs совпали с original test; все declared width/height и category+bbox multisets совпали после `HFcategory+1→originalcategory`. В HF категории 0–4, original1–5; порядок rows отличается и не подходит как ключ. Ключ — `image_id`. Это сильное подтверждение annotation lineage для test 29; byte identity HF JPEG и original PNG не проверена.

**W2-08-F03 — source inventory gap, выполнена ограниченная проверка.** Original COCO root имеет только `images,type,annotations,categories`; все image records содержат только `file_name,height,width,id`. Полей source URL, photographer, license и root licenses нет. Они не восстанавливаются из HF. Source metadata не найдена также в exact release git tree и списке assets двух releases. Issue6 объясняет условия, но не даёт per-image join. Остаток: metadata могла остаться в другой, не прочитанной части tar/у авторов; нельзя писать «её не существует». Дальнейший массовый media download ради этого не нужен текущему решению. Нужен конкретный source manifest, связанный с numeric image_id, либо адресно полученный авторский metadata artifact.

**W2-08-F04 — mask subtype, выборочно просмотрено.** Заново просмотрены сохранённые HF images1012 (1280×720) и 1013 (1920×1088): соответственно эластомерная полумаска со сменными фильтрами и формованная фильтрующая полумаска. Реально извлечённая original train PNG15 (943×663) содержит плоские медицинские маски на нескольких людях; declared dimensions совпадают. У 15 видимы три человека в масках, но в COCO только две Mask bbox category5 (ids114/115); это конкретный кандидат partial labels, не оценка полноты всего набора. Дополнительно извлечена PNG762: медицинская маска и очки в крупном плане, **actual2246×1498 против declared 1200×1200**. У image_id762 в COCO три Mask boxes, но без корректного coordinate/version pairing их нельзя объявить истинной разметкой наблюдаемого PNG. Этот sample выявил artifact discrepancy, а не ещё одну подтверждённую пару. Все визуальные subtype наблюдения — наша интерпретация формы, не author subtype GT, не сертификация и не проверка плотности прилегания.

**W2-08-F05 — rights correction.** После S04 уже неправильно писать «Apache2.0 установлен только для code, лицензия labels совершенно неизвестна». Авторский датированный ответ распространяет Apache2.0 на annotations. Сохранить LICENSE/notices, citation и changes; photographs остаются отдельным слоем. HF frontmatter unknown относится к датасету в целом и не отменяет более конкретный ответ про labels. Для фотографий без per-image metadata нельзя массово назначить единое commercial permission.

## Решение и следующая процедура

Использовать CPPE-5 как условный donor локализации mask/PPE и как источник кандидатов на собственную subtype разметку. Для industrial respirator создать дополнительный слой: `source_subtype=unknown`, `proposed_visual_subtype` по ручной проверке, `wearing_observable`, `wearing_state`, связь с человеком; правильность сертификации/fit/policy отдельно. Разделять плоскую medical mask, filtering facepiece и elastomeric respirator; авторский класс Mask их не различает. Случаи снятия/смещения и body regions без маски нуждаются в своей целевой разметке, а не в преобразовании всех отсутствующих boxes в отрицательные примеры.

**E-W2-08-01 (выполнено):** bounded Range→stream tar→полные 2 COCO→29row comparison; выводы F01–03, артефакты выше. **E02 (предложено):** получить source manifest для выбранных image IDs, сохранить author/license/source date и необходимые notices, затем разрешать нужное действие для каждого фото; при неудаче заменить фото собственными/организаторскими с явными условиями, сохранив разрешённый annotation tooling. **Q-W2-08-01:** где опубликована per-image Flickr/Google metadata из§3.2 и как numeric ID связан с source? **Q02:** уточнить права и способы получения конкретных respirator-like samples1012/1013. Никаких писем не отправлено. Accuracy, CCTV transfer и LinQ performance этим заданием не измерялись.
