## Что меняет выбор

Открытые данные разделяются как минимум на четыре разных мира: заводское CCTV, строительные камеры/обходы/дроны, промышленные stock/web-фотографии и медицинские/портретные PPE. Для всех них словосочетание «industrial safety dataset» может быть формально уместным, но оно не устанавливает одинаковые viewpoint, scale или ground truth. Для заводского replay/adaptation первыми проверять **SFCHD** и **Önal/Dandıl workplace video**; для разнообразия PPE/body parts — **SH17**; для eyes/face donor — **CPPE-5** после semantic/license audit; для строительных объектов — **Site Object Detection SODA**, если восстановится доступ и условия. Для events нужны реальные интервалы/политики, которых object-box наборы не дают.

## SODA: полезная первичная строительная ветка

**W1-01-F01 — авторский документ S01, §3.1/Table2/§4.** Полное имя SODA здесь **Site Object Detection dAtaset**, а не Small Object Detection dAtasets (SODA-D/SODA-A) и не SODA10M autonomous driving. Категории: `person, helmet, vest, board, wood, rebar, brick, scaffold, handcart, cutter, ebox, hopper, hook, fence, slogan`. Numeric IDs не установлены: XML архив не получен. `fence` не обозначает полигон опасной зоны, `slogan` не задаёт policy, `person` не является PPE compliance attribute.

**W1-01-F02 — документ S01 §3.2/3.3/§4, прочитано.** Авторы снимали реальные стройки, не принимая web crawl как достаточно характерный материал. Использовали UAV, handheld monocular camera и hook visualization video. Из 21863 первичных изображений после cleaning получили 19846; 86% изображений имеют 1920×1080. Video-derived кадры брали every 30 frames, затем вручную удаляли видимые повторы. Это не означает 30 FPS и не гарантирует независимость сцен. В paper §5.2 приведён random 90/10 split: 17861 train и 1985 test. Group IDs по камере/исходному видео не установлены.

**W1-01-F03 — документ S01 §3.3–3.4.** Удаляли blurred/ambiguous images и изображения без targets. Частично перекрытые или неудобные для разметки объекты руководство предлагает опускать. Поэтому набор отфильтрованных положительных сцен не заменяет непрерывный CCTV поток. Это влияет на обучение и оценку occluded helmet/person; нельзя объявить все классы exhaustive вопреки инструкции.

**W1-01-F04 — документ и наше сетевое наблюдение.** Data Availability даёт [VOCv1.zip](https://scut-scet-academic.oss-cn-guangzhou.aliyuncs.com/SODA/2022.2/VOCv1.zip). HTTP Range GET 23.10.2026 вернул 403 AliyunOSS. ZIP не получен; размер, MD5 и LICENSE внутри архива не установлены. Это отказ одного URL в нашем запросе, не общее доказательство закрытости SODA. Слово open-source в статье не заменяет точного условия на использование/перераспространение фото и labels. В прочитанном PDF явной лицензии этих артефактов не найдено.

## Обнаруженные пробелы и роли

**W1-01-F07 — наш вывод из S01–S08.** Среди содержательно изученных сильных кандидатов не установлен единый источник, одновременно дающий industrial respirator subtype, removed/correct state, person tracks, site hazard policy и длинные безопасные периоды видео. Это ограниченный результат нашего поиска, не утверждение об отсутствии таких данных в мире. Лабораторные/складские карточки без первичного протокола не поднимаются в сильные кандидаты только по ключевому слову.

Разделение ролей следует сохранить:

1. **Adapt:** SFCHD и данные организаторов после проверки семантики и прав. Отдельная целевая камера остаётся holdout.
2. **Class donors:** SH17 для PPE/body parts, CPPE для goggles/face shield/broad mask после subtype audit, Pictor для hat/vest с сохранением geometry.
3. **Tracking/events:** Önal как реальный CCTV с новой разметкой policy/events; SARD после документирования ID/FPS/source groups. Строительные действия и заводские нарушения имеют разную семантику.
4. **Calibrate:** отдельные camera/time groups, соответствующие реальному transform и входу LinQ. Нельзя расходовать единственный test на калибровку.
5. **Negatives:** безопасные непрерывные периоды и target hard cases: phone/drink/hand-to-face/carrying helmet/occluded head. Для каждого класса нужна известная полнота и визуальная определимость. Кадр без label не становится negative.

**W1-01-E01 — предложено, не выполнено.** После публикации кейса составить target taxonomy/geometry/visibility matrix. На 20–50 стратифицированных source frames каждого кандидата проверить домен, размер после реального resize, geometry и полноту target labels. Размер пилота предлагаемый, это не проведённое измерение. Результат решает, какие источники брать для адаптации, какие оставить донорами, что доразметить.

**W1-01-Q01:** SODA archive access/license требуют author fallback или metadata. **Q02:** складской/лабораторный реальный CCTV с нужным PPE/event GT пока не установлен; продолжать адресно после сценария полного кейса. **Q03:** есть ли SFCHD/Önal camera/session/date groups для независимого теста? **Q04:** чем отличаются full Pictor-v3 и доступная crowd-only версия?
