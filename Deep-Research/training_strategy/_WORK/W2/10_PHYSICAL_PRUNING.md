## Ответ для решения и outcome K010

**Практический positive route существует на уровне прочитанного кода:** авторский репозиторий Torch-Pruning содержит YOLOv8 example, который заменяет C2f, строит DepGraph, физически удаляет зависимые каналы, восстанавливает качество обучением и передаёт изменённый объект в штатный ONNX exporter. Поэтому K010 «не восстановлен ни один физический detector route» закрывается в части implementation evidence. **Работоспособность pinned комбинации, сохранённого артефакта, качество и LinQ speed остаются непроверенными.** README одновременно даёт совместимый старый Ultralytics pin и предупреждает о поломке примера при обновлении Ultralytics. Это основание оценить инженерную цену, а не назначить pruning обязательным trial.

При наличии меньшего штатного student physical pruning следует держать в условном резерве P2. Сначала нужен факт, что штатный меньший кандидат не удовлетворяет совместным ограничениям качества/target cost, а прошедшая quality gate более крупная модель действительно упирается в model execution. Для продвижения pruning нужны ранний smoke/reload/FP export и подтверждение compiler acceptance новых dense shapes; авторский MAC ratio не заменяет эти факты. [W2-10-F01–F10; W2-10-E01]

## Новые факты: graph, head, recovery и artifact contract

### W2-10-F01 — Versioned positive route ограничен старым YOLOv8

**Тип: primary documentation + code observation, S02/S03/S08.** README закрепляет U, который действительно объявляет Ultralytics 8.0.90; tested environment перечисляет PyTorch 2.5.1 и TP 1.6.1. GitHub tag TP 1.6.1 разрешается точно в T, на котором прочитан код. Script default model — `yolov8m.pt`; он ожидает C2f/Bottleneck/Detect и старые импорты `ultralytics.yolo.*`. Это не route для W1 pin Ultralytics 8.4.184, YOLO11 или YOLO26. README предупреждает: “This example is crashed due to ultralytics upgrade.” Документированный pin даёт разумную точку воспроизведения, но не наш runtime certificate.

### W2-10-F02 — C2f меняется до pruning, веса переносятся по ветвям

**Тип: code observation, S03 `C2f_v2`, `transfer_weights`, `replace_c2f_with_c2f_v2`; S08 `C2f`/`Bottleneck`.** Штатный C2f делает одну Conv→BN→activation с `2*c` выходами, затем `chunk(2,1)` и concat с результатами bottlenecks. В C2f_v2 две отдельные Conv `cv0/cv1`, их выходы проходят тот же chain и `torch.cat`, после которого работает `cv2`. Старый `cv1.conv.weight` делится по output dimension; обе части BN weight/bias/running_mean/running_var переносятся; `cv2` и ModuleList bottlenecks переиспользуются. Shortcut определяется через `infer_shortcut`, groups/n/e восстанавливаются из исходного блока. Так граница split убирается из forward представления до удаления каналов.

**Вывод:** это topology rewrite даже при нулевом pruning. Сначала нужна численная проверка converted-unpruned против original, отдельно от quality loss от удаления. `self.c` остаётся атрибутом, но в новом forward не используется для `chunk/split`; нельзя восстанавливать actual channels только по этому старому scalar. Функция `initialize_weights` в script вызвана для BN eps/momentum и inplace activations; её имя само по себе не означает новое обучение с нуля. Фактическую эквивалентность переноса нами не проверяли.

### W2-10-F03 — DepGraph связывает Conv/BN/branch channels, а не проставляет masks

**Тип: code observation, S04–S07.** `GroupNormPruner` через base constructor вызывает `DependencyGraph().build_dependency(model, example_inputs=...)`. Требуется включённый autograd; build содержит assert против `torch.no_grad()`. Script ставит `requires_grad=True`, dummy input имеет `[1,3,imgsz,imgsz]`. Хотя script перед constructor вызывает `model.train()`, `_trace` внутри TP переключает model в eval и регистрирует forward hooks; graph строится из реально пройденного forward/autograd graph. Этот нюанс следует сохранить в smoke, а не приписывать tracing train-head outputs.

`_build_dependency` связывает output-channel pruning upstream слоя с input-channel pruning downstream и обратное отношение. `get_pruning_group` проходит вызванные зависимости и применяет index mappings. Residual `Add` представляется elementwise node: связанные каналы ветвей удаляются согласованно, иначе сложение нарушает shape contract. Для channel concat `update_concat_index_mapping` вычисляет размеры ветвей и cumulative offsets; downstream index переносится в правильную ветвь, а branch index — в общий concat tensor. Это относится и к C2f concat, и к neck joins в реально traced графе. Нельзя вручную удалить один Conv filter и игнорировать его потребителей.

`Group.prune` вызывает handlers всех связанных операций. `ConvPruner` уменьшает `in_channels/out_channels` и заменяет weight через `index_select` соответствующей оси, bias при output pruning; `BatchnormPruner` уменьшает `num_features`, affine tensors и running statistics. Это **меньшие dense tensors**, в отличие от W1-13-F08/F09 `ln_structured` масок исходной формы. Примеры dependent shapes будущего manifest: Conv `[Cout,Cin/groups,kH,kW]`, BN `[Cout]`, следующий Conv input axis, concat consumer sum-of-remaining-branch-channels. Конкретные удалённые indices возникают только в будущем выполнении; здесь их нет.

**Ограничение:** tracing одного input не сертифицирует все dynamic branches/shapes. Неизвестные операции TP может трактовать как elementwise; это повод осмотреть groups/shape assertions, а не считать любой custom detector автоматически поддержанным.

### W2-10-F04 — Detect исключён из output pruning; head inputs всё равно зависимы

**Тип: code observation + вывод, S03 319–334, S07 base 124–145, S04 `get_all_groups`, S08 `Detect`.** Script добавляет каждый `Detect` в `ignored_layers`. BasePruner разворачивает каждый ignored module в его descendants. Эти модули остаются в dependency tracing: список exclusions не передаётся как `ignored_layers` в `build_dependency`, а применяется при выборе pruning groups. Группы с output pruning ignored module отклоняются. Поэтому исключение головы не означает полную изоляцию от upstream channel changes: входные оси первых head Conv могут сокращаться, сохраняя их output widths.

В U Detect `reg_max=16`, `no=nc+4*reg_max`; terminal box Conv имеет 64 outputs, terminal cls Conv — `nc`, DFL сохраняет свой contract. Training head возвращает per-level raw maps; inference формирует `[B,4+nc,N]` decoded xywh и sigmoid class scores; export возвращает этот tensor без обычного tuple с raw maps. Script не заменяет Detect.forward, число классов не сокращает и semantic class remapping не делает. Preserve `nc`, `names` и class order — отдельная обязательная проверка, не следствие уменьшения backbone.

Особенно опасно слепо скопировать demo на custom data: script **перезаписывает** `pruning_cfg['data']='coco128.yaml'`, а pinned trainer `set_model_attributes` присваивает outer model.nc/names из data. В pruning режиме объект головы переиспользуется, вместо штатной пересборки через `get_model(cfg,nc=...)`. Поэтому custom ontology/head следует согласовать **до** surgery, убрать toy override в будущей контролируемой интеграции и проверить head.nc/terminal shapes/data names совместно. Иначе metadata и реальные logits способны разойтись. Это установленная точка риска, а не воспроизведённая ошибка.

### W2-10-F05 — Criterion и recovery: итеративное удаление, затем supervised fine-tuning

**Тип: code observation, S03 `prune`; S07 `GroupMagnitudeImportance`/constructors.** Используется `GroupNormPruner` с `GroupMagnitudeImportance()`; defaults importance — p=2, mean group reduction/normalizer, а не detection-loss saliency. `global_pruning` не задан и по default False. Regularization/backward demo закомментировано: нельзя объявлять этот example sparse-training recipe только по имени GroupNormPruner. One-step pruner создаётся заново для каждого внешнего шага; доля шага вычисляется `1-(1-target_prune_rate)^(1/iterative_steps)`. Это channel schedule, а не гарантия точной общей доли parameters/MACs или времени.

После `step()` выполняется pre-recovery validation, затем `train_v2(pruning=True, ...)`, reload best и post-recovery validation; точки записываются отдельно. Demo жёстко назначает coco128 и 10 epochs на шаг; CLI defaults 16 steps/target rate 0.5/max_map_drop 0.2 — **sample settings, не рекомендация для CCTV**. Нужны настоящие train labels и independent development validation; toy repeated validation не доказывает target quality. Recovery budget должен учитываться целиком, включая промежуточные validations/saves/export.

### W2-10-F06 — Normal YAML rebuild уничтожает topology; patch сохраняет actual object

**Тип: code observation, S03 `train_v2`, `save_model_v2`, `strip_optimizer_v2`; S02.** Нормальная ветка вызывает trainer.get_model с исходным YAML. Pruning branch вместо этого передаёт `self.trainer.model=self.model`, сохраняя изменённую topology. Таким образом YAML исходной YOLOv8 и plain state_dict недостаточны для reconstruction произвольно изменённых widths/C2f_v2. Возможен отдельный shape-aware constructor, но в этом route его нет.

Custom save кладёт в checkpoint full `deepcopy(de_parallel(self.model))` и EMA object, optimizer state/epoch/best_fitness/args/version. `final_eval_v2` использует custom strip, который выбирает EMA как model, убирает optimizer/ema/updates и делает параметры requires_grad=False, сохраняя full-precision model object. Это вмешательство в trainer lifecycle, не универсальный файл `pruned.yaml`. Оно также означает, что final stripped artifact нельзя объявить exact resume state.

**Python dependency:** C2f_v2 должен существовать по подходящему import path при unpickling. В owner reply S10 автор прямо требует импортировать класс в predict process; без этого сообщался `Can't get attribute 'C2f_v2'`. Будущий reusable artifact должен включать versioned custom module и стабильный module path, а clean-process reload — быть gate до recovery budget. Современные torch.load defaults также нельзя молча переносить на исторический script: код использует full-object load без специально заданного weights_only; нужен фактически pinned environment/reload check, а не обещание совместимости любого PyTorch.

### W2-10-F07 — Export route указан, но пока не проверен артефактом

**Тип: code observation + ограниченный вывод, S03 384; S09.** Example заканчивается `model.export(format='onnx')`; собственного patched exporter в нём нет. Pinned YOLO.export передаёт existing model object в Exporter. Exporter deepcopy→eval/float/fuse, ставит Detect.export/format, делает dry runs и `torch.onnx.export`, input `images`, detection output `output0`. `C2f_v2` не subclass C2f, поэтому стандартный switch на C2f.forward_split его не затрагивает: работает его собственный Conv/concat forward. Это объясняет code-level возможность трассировать modified graph без YAML rebuild; наличие строки export не доказывает успешный ONNX/его parity.

Example не задаёт явные opset/static-dynamic/simplify/input args для итогового export. Pinned exporter использует args и fallback opset, поэтому будущий contract обязан сохранить их фактические значения и graph hash. Не считать ONNX opaque custom Python module: после успешного tracing следует проверить реальные ops/shapes, отсутствие неожиданных Python/custom nodes, output decoding и metadata. Exporter в U содержит закомментированный `onnx.checker.check_model`; внешний smoke должен явно включить graph validation и парный inference. Исторический issue #147 содержит reported mismatch после C2f conversion и ответ о возможной проблеме копирования весов; это ограничивающий lead, не доказательство отказа T/U.

### W2-10-F08 — Early stop demo не откатывает последний плохой шаг

**Тип: code observation + вывод, S03 380–384.** Если `init_map-current_map > max_map_drop`, loop делает break; затем всё равно export текущего model. Видимой загрузки последнего допустимого pruning stage перед export нет. Поэтому не использовать этот early stop как acceptance/rollback contract. Хранить immutable stage candidates и экспортировать явный accepted stage; aggregate mAP gate не заменяет critical class/size gate команды.

### W2-10-F09 — Строка speed up в script является MAC ratio

**Тип: code observation, S03 350–353.** `current_speed_up = base_macs / pruned_macs`, после чего печатается `speed up`. В выбранном example отсутствует соответствующий timed runtime benchmark: нет установленного device/software/input-batch/warmup/sync/timing boundary для этого отношения. README иллюстрирует меньшие tensor dimensions/MACs/parameters, но не даёт здесь воспроизводимый target timing protocol. Поэтому численные mAP/скорость из screenshot и generic TP latency таблицы не используются; CUDA/CPU latency других моделей и тем более LinQ gain не выводятся. Serialized bytes также не измерялись. Это сохраняет W1-13-E03 и уточняет конкретную ловушку имени variable.

### W2-10-F10 — Smaller native student имеет другой integration contract

**Тип: наш вывод из F01–F09 и W1-10-F06/F12/E03, W1-13-E03.** У штатного меньшего detector сохраняются архитектурный constructor, package modules и обычный loader/exporter той версии, которую команда уже проверяет. У physical pruning добавляются custom C2f, channel index/dependency manifest, trainer patches, full-object serialization, отдельная parity conversion и новые dense widths для compiler. KD в W1 при нормальном final unwrap должен оставить стандартный student; pruning намеренно оставляет изменённую topology. Ни один путь не имеет заранее установленного quality/latency ranking на LinQ.

| Условие | Меньший штатный student | Этот physical pruning route |
|---|---|---|
| Исходный artifact | Поддержанный штатный checkpoint/architecture, свой quality baseline | Согласованный trained YOLOv8 checkpoint на U; toy coco128 override нельзя переносить |
| Граф после вмешательства | Штатные widths/modules | C2f_v2 + сокращённые dense dimensions; head output contract сохраняется |
| Recovery | Обычный supervised/KD путь при нужде | Специальный train_v2, повторный supervised recovery каждого принятого stage |
| Serialization | Обычный loader выбранной версии | Full model/EMA objects + доступный custom class; исходный YAML не восстанавливает topology |
| Export | Уже известный штатный route всё равно проверяется | Указан штатный ONNX exporter U, но требуется новый smoke/parity и фактический opset/shape contract |
| LinQ | Неизвестно до compiler/run | Неизвестно; новые widths могут изменить compiler mapping и utilization |

## W2-10-E01 — Будущий bounded smoke → recovery → export gate

Это уточнение pruning части **W1-13-E03**, с reused FP/quant/target parity из **W1-13-E01** и clean artifact принципом **W1-10-E03**. Процедура **не выполнена**. Её цель — решить, заслуживает ли physical pruning дорогого recovery и сравнения с native student; это не grid по pruning ratios.

**Входы:** разрешённый конкретный trained YOLOv8 U checkpoint/hash; TP T и environment lock, установленный smoke environment; custom class source с importable path; согласованные data/head nc/names; train split, development selection split и отдельно закрытый camera/session/episode holdout; native smaller student и непрореженный reference. От linq_platform нужны compiler/import contract, ограничения shapes/opset и затем target access. Критерии quality/runtime и предел engineering budget задаются до trials по полному кейсу; здесь числа не выдумываются.

1. **До surgery:** inventory module tree/keys/shapes/params, nc/names/reg_max/strides, input tensor hashes и raw outputs на representative examples; зафиксировать уже работающий native reference. Проверить pinned imports и путь custom class. Если фактический выбранный detector не U YOLOv8, не выдавать этот script за готовую интеграцию: отдельная port задача только при наблюдаемой необходимости.
2. **Conversion-only gate:** в будущей практике заменить C2f без удаления, проверить eval outputs и AP/critical slices на тех же inputs против original. Отдельно осмотреть BN state, shortcut/group settings. При несогласованности остановить route до pruning/recovery; иначе последующая потеря будет иметь смешанную причину.
3. **Один малый surgery smoke:** autograd включён, выбранный static input; сохранить DepGraph/group listing, root и dependent deleted indices, все changed tensor shapes, concat offsets, residual equalities и head exclusions. Проверить train forward/loss/backward/finite gradients и eval forward; nc/box/DFL outputs не изменились. Выполнить full-object save и clean-process reload с versioned class, сравнить raw outputs. На этом же candidate выполнить FP ONNX export/checker и reference parity; при доступном SDK — ранний compiler acceptance/placement smoke новых shapes. До успеха этих gates большое recovery не назначать.
4. **Recovery comparison:** из одного исходного target checkpoint сохранить unpruned FP continuation control с сопоставимыми labels/updates и pruned recovery, плюс отдельный native smaller student с честно записанным budget/initialization. Нельзя сделать вид, что toy 10 epochs demo — честный оптимальный protocol всех трёх. Данные, resolution, thresholds/NMS, selection objective, разрешённые аугментации и accounting фиксируются; различия budget сообщаются. Stage selection использует development split и immutable candidates, last rejected stage не экспортируется. Holdout не используется для выбора ratio/stage.
5. **Final artifact gate:** reload accepted stage в чистом процессе; экспорт явного artifact/hash с фиксированными opset/input/batch/dynamic/simplify/precision/output contract; повторить W1-13-E01 FP→export→quant/compiler→target. Замерить target model-only latency distribution/peak memory при одинаковом batch/concurrency/inputs/warmup/sync/transfer boundary, placement/fallback, а end-to-end video delay отдельно. Одно ORT совпадение не закрывает target gate.

**Метрики и сохраняемые доказательства:** conversion/reload/export tensor deltas; detection AP с точной метрикой, critical recall/precision по class/size/camera и paired errors; event metrics только при неизменных event rules. Отдельно actual dense tensor shapes, параметров/MACs counting convention, bytes model/package, target latency/memory и полная цена `T_setup+T_recovery+T_validate+T_save+T_export+T_decision` и human minutes. Сохранить hashes inputs/checkpoints/graphs/compiled file, environment/dependency locks, custom module, patched trainer source, pruning history/index mapping, class map/splits, logs/seeds/config/selection rationale, outputs и compiler placement report.

**Outcomes/stop:** conversion mismatch, head contract drift, incomplete group mapping, reload/FP export failure или compiler rejection → остановить до recovery, сохранить native candidate. Recovery нарушает critical quality gate → rollback accepted prior stage/штатный student; не экспортировать rejected current stage по demo break. Меньшие MACs без требуемого actual target результата → не продвигать по speed claim. Pruned проходит quality и target cost с допустимой ценой интеграции → кандидат, сравниваемый с native smaller student, а не автоматически победитель. Успешный bounded smoke ещё не подтверждает качество после полного recovery, редкие камеры, multicamera throughput или LinQ ускорение.

**→ model_stack:** F01/F02/F04/F06/F07 задают конкретный versioned candidate contract: old YOLOv8 C2f_v2, protected head output, full object, patched train/save и штатный exporter U. Проверить conversion parity и clean reload раньше recovery; не выдавать исходный YAML или plain state_dict за topology artifact.

**→ linq_platform/video_architecture:** dense shapes могут уменьшиться, sparse backend не требуется логикой метода. Нужны acceptance/alignment/placement/quant и actual target timings именно transformed graph; F09 исключает использование напечатанного speed up как runtime evidence.

**→ evaluation/datasets:** ontology должна соответствовать уже созданной голове; toy coco128 override опасен. Разнести conversion, surgery, recovery и export deltas; редкие PPE/small-object slices могут ухудшиться при сохранённом aggregate AP. Holdout по независимым группам, recovery continuation control и native smaller comparator обязательны для attribution.

**Краткая передача автору/очереди:** K010 implementation gap содержательно закрыт; найден один author-hosted dependency-aware physical detector route. Новый limiting evidence — старый U pin/сломанная upgrade compatibility, обязательный C2f rewrite и custom serialization, toy data override, MAC speed-up label и отсутствие rollback перед export. Public existence найдено; пригодность actual artifact, recovery quality и LinQ benefit остаются вопросами E01/Q01–Q05. Physical pruning — условный P2 резерв после smaller native student, без обещания выигрыша и без обязательного trial slot.
