## Новые факты: что остаётся после prediction

### W2-04-F01 — Detect Results не содержит полного вектора классов

**Тип: наблюдение кода S02/S03.** `construct_result` масштабирует координаты к исходному изображению и создаёт `Results(..., boxes=pred[:, :6])`. Для обычного detect строка имеет `x1,y1,x2,y2,conf,cls`; `Boxes` разрешает 6 или 7 колонок, седьмая связана с tracking ID. `conf` и `cls` — последние две колонки, `xyxy` — первые четыре. У detect конструктор не получает `probs`, поэтому `result.probs` здесь `None`. Классификационный `Probs` не восстанавливает отброшенные detection scores. `boxes.data` иногда называется raw в docs, но это **raw storage данного Results после postprocessing**, не raw head logits. Нет отдельного background/objectness channel, ROI proposals, complete class vectors или всех locations в этом объекте. W1-10-F15 про token scores GroundingDINO имеет иной interface и не меняет этот факт.

### W2-04-F02 — Полные векторы существуют раньше Results, но это другой контракт

**Тип: код S04/S11.** У `Detect.forward_head` отдельные `boxes`, `scores`, `feats`; `scores` ещё logits. `_inference` применяет sigmoid и соединяет decoded boxes с `nc` scores. При one-to-many decoded output имеет `(B,4+nc,A)`; это не `(B,5+nc,A)`: отдельного objectness или background logit нет. Native non-export forward возвращает `(decoded_predictions, raw_dict)`; export возвращает только выбранный output. У dual head raw dictionary может включать `one2many`/`one2one`, у обычного — непосредственно `boxes/scores/feats`. End-to-end выбранная ветка проходит top-k до выхода decoded prediction. Векторы нельзя извлечь обратно из final `conf/cls`.

**Вывод:** categorical `-sum p log p` для normalized softmax classes здесь не возникает автоматически. Можно отдельно определить Bernoulli uncertainty для независимых sigmoid entries или нормировку по классам, но это разные новые score hypotheses, не вероятность неправильного box. Минимальный route ниже ничего такого не требует.

### W2-04-F03 — NMS path уже удаляет кандидаты до выдачи scalar scores

**Тип: код S05.** `non_max_suppression` берёт первый элемент native tuple, фильтрует locations по `amax(class_scores)>conf_thres`, переводит `xywh→xyxy`, при стандартном `multi_label=False` оставляет лучший класс. Далее class filter, ограничение `max_nms`, class-aware либо agnostic IoU suppression и `max_det`. DetectionPredictor не включает `multi_label=True`. Поэтому снижение `conf` не отключает NMS и не возвращает complete vectors; `iou` не восстанавливает отброшенные class scores. Class filtering применяется к уже выбранному argmax: запрос определённого класса не равен поиску всех locations, где score этого класса превысил floor. `max_nms`/time limit тоже могут ограничивать результат. Финальные boxes описывают retained predictions, а не все возможные гипотезы.

### W2-04-F04 — NMS-free в U означает one-to-one top-k, а не полную плотную сетку

**Тип: docs S10 + код S06/S08/S09; связано с F02/F03.** В проверенном U YOLO26 prediction/validation по умолчанию использует one-to-many+NMS. `nms=False` задаёт native backend `end2end=True` до fusion. Гайд различает экспорт: `nms=None` — raw one-to-many, `True` — embedded NMS, `False` — one-to-one processed output. Нельзя переносить значение флага predict на exported graph: граф уже определяет выходы.

После head top-k e2e branch NMS-функции делает только confidence/class filtering и cap, без IoU suppression. `iou` там не превращается в подавление overlapping boxes. При class-aware top-k возможны разные class entries одного location; это также не complete vector. Индексы e2e filtering относятся к уже сокращённому input, не автоматически к исходным anchors. У YOLO8/11 YAML нет one-to-one; setter предупреждает и оставляет one-to-many. Называние family недостаточно: проверять actual graph/head и аргументы. Fusion может удалить неиспользуемую ветку; для сравнения режимов нужен исходный artifact и корректное пересоздание backend, не смена private flag fused object.

### W2-04-F05 — Embeddings публично доступны, однако не добавляются к обычным Results

**Тип: код S07/S08 и подтверждающие live docs S10.** Native Ultralytics PyTorch `model.embed(source)` проверяет тип модели; default — second-to-last layer. В `_predict_once` указанные feature maps проходят adaptive average pool до image vectors, concatenate и early return при последнем выбранном layer. Predictor при `args.embed` выдаёт tensors и пропускает обычный detection postprocess. Для стандартного «Results плюс embedding» нужны отдельный проход или custom совместное извлечение. Выход зависит от layer ID/channels и preprocessing; это не person/ROI embedding или готовая мера полезности кадров. Public wrapper не поддерживает этот interface для exported formats/чужих модулей. У выбранного checkpoint совместимость ещё не проверена.

### W2-04-F06 — Object features и raw tensors требуют отдельной инженерной границы

**Тип: код S02/S07/S09, наш вывод.** `DetectionPredictor` умеет добавить `r.feats`, если заранее установлен private `_feats`, используя сохранённые indices. Это условная внутренняя ветка, не стандартное поле каждого detection Results. Обычный public `predict` не обещает ROI vectors. Для one-to-many native output custom predictor может перехватить вход `postprocess` до NMS; API принимает custom `predictor` class. Доступ к raw dict, decoding и сохранение индексов — ответственность такой реализации. Для one-to-one pre-top-k vectors нужны native raw head tensors/decoding либо hook до top-k. Не следует использовать training mode ради logits: он меняет поведение модели. Export с already processed output не отдаёт потерянные векторы без нового graph/export. Это адресная потребность model_stack, а не выполненная интеграция.

## Один minimal acquisition contract без изменения архитектуры

**W2-04-F07 — наша предложенная спецификация, не найденный готовый selector и не проверенный выигрыш.** Выбран route `retained-low-confidence + metadata exploration`, использующий только F01. Он конкретизирует arm C существующего W1-08-E01, а не создаёт обязательный новый AL algorithm.

1. **Вход:** разрешённый train acquisition pool, отделённый от dev/lockbox; hashes кадров, camera/session/group IDs, timestamps, source FPS/timebase и заранее определённая единица временного исключения. Checkpoint hash, package U либо вновь прочитанный pin, canonical class map и режим head закреплены. Не строить embedding/selector на lockbox.
2. **Стандартный API:** обычный detect `model.predict(..., stream=True)` с `embed=None`, `augment=False`, заранее выбранными `imgsz/rect`, precision/device/batch, `conf=c_pool`, `iou`, `max_det`, `agnostic_nms`, `nms`. Не выдавать `c_pool` за event operating threshold. Он фиксирует видимую selector выборку; неизвестные значения выбираются в train-only correctness pilot, не по lockbox. Минимально использовать `classes=None`, чтобы class filter дополнительно не скрывал hypotheses; scope labels контролировать отдельно. Для чистоты сравнения все arms используют одинаковую preannotation policy.
3. **Сохраняемый public output:** row per frame, даже если boxes пусты; `frame_id/group_id/time/orig_shape`, все retained `xyxy,conf,cls`, count, model/config hashes и status. Сохранять числа без округления до display confidence. Пустой список, decode/inference error и пропуск frame — разные состояния. `Results.path` для кадров из видео недостаточен как уникальный frame ID. Полные Results с orig_img в памяти не обязательны: переносить компактные записи на CPU и отделять images по manifest.
4. **Явный score:** для непустого кадра `u(frame)=max_b(1-conf_b)=1-min_b(conf_b)`, сортировка по убыванию, ties — закреплённый seed/frame key. Это low-confidence heuristic по retained boxes, **не entropy**. Для пустого кадра `u` отсутствует (`null`), а не искусственные 0/1. Количество boxes и predicted class записываются для анализа density/class bias. Более плотный кадр имеет больше шансов получить один low score; выбранная формула этого не исправляет и требует cost audit.
5. **Очередь:** заранее разделить budget на ranked часть и seeded exploration по camera/session/scene strata. Exploration имеет доступ ко всему пулу, включая high-confidence и no-box кадры; дополнительно обеспечить заранее описанное покрытие no-box stratum, когда он есть. Недостаток empty frames в stratum отмечать, не синтезировать. Доли/квоты — параметры будущего опыта, универсальных процентов нет. Общий temporal cap действует между rank/random/targeted частями и между rounds; dedup не должен слить разные фазы обязательного event.
6. **Human output:** выбранный image/clip размечается полностью для in-scope taxonomy с unknown/ignore по guidelines. Проверять области вне proposals, иначе уверенные пропуски станут background. Score не выбирает только один box для исправления. Причина отбора, минуты просмотра/разметки/QA и итоговая coverage сохраняются; неполная разметка требует отдельно подтверждённого partial-label loader/loss.

Низкий `c_pool` увеличивает число слабых hypotheses и стоимость NMS/сериализации; нет основания ставить его в ноль ради «всех ошибок». `N==max_det` отмечать как **возможную** цензуру, не доказанное число потерянных boxes. E2e top-k может скрыть слабый/редкий класс ещё до `conf` и class filter. Одна фиксированная настройка между rounds делает сравнение интерпретируемым; изменение head/cutoff/preprocessing считается изменением selector bundle.

Общие confident errors и объекты, которых нет в taxonomy, остаются невидимыми ranking. Поэтому metadata exploration — обязательная часть этого предложенного контракта; disagreement тоже не гарантирует их обнаружение. Нет labels → нельзя сообщать, какой arm лучше, по одной привлекательности error gallery.

## W2-04-E01 — Будущий interface/cost gate перед W1-08-E01

**Вопрос и решение:** можно ли использовать минимальный route из F07 без custom inference и несоразмерных затрат? Это небольшое инженерное дополнение к W1-08-E01 pilot; сам equal-human-minutes trial не дублируется и сейчас не выполнялся.

**Входы/доступы:** actual checkpoint/hash и установленный version pin от model_stack; разрешённые train-only кадры разных camera/session, включая empty/плотные/малые объекты; class map, fixed preprocessing/postprocessing и независимый dev/lockbox manifest. Для проверки данных нужен полный ручной просмотр pilot, не только boxes. Среда обычного offline inference; LinQ для selector не обязателен, если кейс это разрешает. Не использовать эти кадры как финальный тест.

**Контроль и действия:** с одним checkpoint/режимом выполнить стандартный predict и сохранять строки F07. Проверить типы/shapes, `probs=None` для detect, координаты overlay в original image, соответствие timestamp/hash и наличие записей no-box/error. Отдельно отметить вероятный cap и warnings. При необходимости проверить NMS/e2e как **разные interfaces**, не ранжировать их quality без labels и не смешивать очереди. Проверить deterministic rank/ties/seeded exploration и temporal cap на сериализованных данных; после reload порядок должен восстанавливаться. Не обращаться к private fields ради выбранного route. Затем измерить pilot scan/serialization и human correction+QA, провести полный missed-object audit selected и exploration кадров.

**Наблюдения:** фактические wall-clock decode/preprocess/forward/postprocess/CPU transfer/serialization/ranking, peak memory/bytes, retained counts и no-box/error/cap flags; минуты поиска/разметки/review; доля дублей и coverage независимых strata. Встроенный `Results.speed` из профилирования S06 не заменяет полный pipeline timer: нет общей гарантии включения decode/queue/serialization и human time. Никаких обещаний минут RTX из имени карты.

**Артефакты:** compact prediction records + schema/version, manifest hashes, package/checkpoint/config, raw timing boundaries, overlays, deterministic ranks/ties/seed, empty/error policy, selected group IDs, human-minute log и coverage audit. Сохраняется также цель score и факт, что это не entropy.

**Исходы:** interface стабилен и стоимость допускает сравнение → arm C W1-08-E01 при равном полном human budget против stratified random; extra inference/custom tensors оказались нужны → сначала оценить их цену отдельно, либо оставить metadata random/targeted; ranking выбирает дубли/непроверяемые outliers → исправить policy на train-only pilot и зафиксировать изменение до основного опыта. **Stop:** mapping/coordinates/provenance нарушены, пропущены no-box records, утечка splits, неразмеченные in-scope objects трактуются как negatives или pilot съедает заранее отведённый reserve — не расширять AL. Нет подтверждённого выигрыша полного времени/качества → не повышать сложность автоматически. **Предел:** успешный gate подтверждает interface и измеренную стоимость конкретного pilot, не преимущество AL, generalization новых камер, правильность event logic или LinQ inference. Training/benefit проверяются исходным W1-08-E01; thresholds отдельно по W1-15-E02.
