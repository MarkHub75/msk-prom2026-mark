Research/access date: 2026-10-23, 19:23–19:27 UTC (22:23–22:27 Moscow). Branch question: which temporal methods have an inspectable checkpoint→preprocessing→video-label contract and could become a host-side reference without claiming unsupported LinQ execution? Decision: prioritize causal MoViNet-A0 Stream only if a neural temporal module is needed; compare against track/pose rules. Keep STGCN++ as a conditional pose-window reference and X3D-XS as a bounded RGB clip reference. Do not put VideoMAE or AVA SlowFast on the delivery critical path. None is tested on LinQ; no models were loaded, exported, trained or executed.

## Decision-bearing findings

**M08-F01 [primary_docs; inference] Causal and buffered-online are different contracts.** MoViNet Stream explicitly uses causal (2+1)D convolution, external state tensors and one-frame updates. In contrast, standard MMAction TSM distributes eight samples across the supplied clip and shifts information both temporal directions; it can run on a trailing window after acquisition, but is not equivalent to a trained unidirectional streaming network. The original TSM online demo is a separate MobileNetV2 hand-gesture/Jester implementation with TVM and explicit supported gestures; do not transfer its Nano GPU >70 FPS claim (excluding I/O) to industrial actions, CPU or LinQ. [M08-S01, S04, S15]

**M08-F02 [primary_docs; artifact_access_checked] MoViNet-A0 Stream is the strongest concrete host candidate.** Exact archive `movinet_a0_stream.tar.gz` returns HTTP200, 15,165,440 bytes. Linked `movinet_a0_stream.tflite` returns HTTP200, **27,141,832 bytes**, whereas the current README labels that link 13 MB. This is an artifact/documentation size discrepancy, not evidence of compression/runtime RAM. README reference construction: `model_id=a0`, `causal=True`, `conv_type=2plus1d`, `se_type=2plus3d`, `activation=hard_swish`, `gating_activation=hard_sigmoid`, `use_positional_encoding=False`, `use_external_states=True`, 600 classes, output states enabled. TFLite export fixes batch1, one frame, 172px; RGB tensor is `[1,1,172,172,3]` **plus state inputs**, not a stateless image classifier. Each output state must feed the matching next input. The 50-frame 172px evaluation refers to accumulated ten-second clips at recommended 5fps, not a required 50-frame input call or guaranteed event latency. Source K600 single-clip top1 72.05 is an author benchmark, not target safety accuracy. [M08-S01, S03]

The model README distinguishes current and `_legacy` stream archives, with architecture changed in 2021 to mobile-friendly (2+1)D. Pin archive content/hash before export; do not mix old checkpoints/current construction. README gives float32 single-core Pixel4 22ms and Xeon W-2135 16ms single-frame A0, while 2022 official blog gives separately quantized A0 int8 4.80ms/3.1MB/65.0% and float16 17.47ms/7.6MB/71.5%. These are different binaries/precision conditions; the directly checked float TFLite is **not** the blog's int8 artifact. Quantized-binary exact current URL/license/metadata remains unresolved. Initialization/reset policy is an application decision: isolate per camera/person crop stream, reset on identity or source discontinuity, and validate long normal→incident transitions. Maintaining cumulative state forever may dilute or retain context; benchmark stream classification is not an onset detector. [inference]

**M08-F03 [primary_docs; artifact_access_checked] STGCN++ is small but its sampling is offline and its data rights restrict immediate use.** Exact MMAction v1.2.0 `stgcnpp_8xb16-joint-u100-80e_ntu60-xsub-keypoint-2d.py` and `...20221228-86e1e77a.pth` are inspectable; checkpoint HEAD200/5,859,545 bytes. Model is RecognizerGCN/STGCN, adaptive graph initialization, residual GCN, multiscale temporal convolution, COCO graph and 60-class head. Pipeline is PreNormalize2D→GenSkeFeat(coco,j)→UniformSampleFrames(100)→PoseDecode→FormatGCNInput(num_person=2). Train/val one clip, test **ten** clips. The 100 samples span the available action's duration; there is no fixed fps/seconds value in this contract. Thus “100 frames at 30fps = 3.33 seconds” would be an invented deployment assumption. README reports joint-only 89.29% xsub, 1.39M parameters/1.95G; do not quote fused four-stream results as this artifact's performance. Filename says 80e but actual tagged config's train loop is **16 epochs** with RepeatDataset times5. Preserve the actual config, not a parsed filename training schedule. [M08-S09, S10]

Skeleton data donor `ntu60_2d.pkl` HEAD200/705,401,771 bytes; not downloaded/unpickled. Docs say dictionary `split` and `annotations`; each annotation has `frame_dir`, `total_frames`, `img_shape`/`original_shape`, `label`, `keypoint[M,T,V,C]`, `keypoint_score[M,T,V]`; COCO V17,C2 versus original Kinect NTU V25,C3. Those representations/checkpoints are not interchangeable. Tagged PreNormalize2D maps x to `(x−w/2)/(w/2)` and y to `(y−h/2)/(h/2)` using img_shape (fallback1080×1920); feeding already normalized coordinates without adjusting this step corrupts input. Joint feature generation includes available keypoint scores; verify the final channel contract during export rather than assuming x/y alone. 2D annotations were generated with Faster-RCNN R50 person detection and HRNet-w32, so substituting another pose extractor changes input distribution. NTU is staged, Kinect multi-view; not CCTV incident localization. Native labels include falling, phone, staggering, but no industrial policy. Original NTU page requires registration/request/release agreement and restricts data to academic/noncommercial research, including redistribution/derivation restrictions. A public derived-pickle URL does not resolve that. [M08-S11, S12]

**M08-F04 [primary_docs; artifact_access_checked] X3D-XS is a useful bounded RGB comparison, with an actual preprocessing discrepancy.** Original PyTorchVideo builder fixes pretrained XS to 4 frames, input_crop_size160; S13/160, M16/224. Official Hub demonstration instead uses XS/S crop182 and M256, with short-side equal to crop. Demo XS temporal rate12 at nominal30fps gives `clip_duration=4*12/30=1.6s`; effective sampled rate about2.5fps. It is not four adjacent30fps frames. Hub scales RGB /255, normalizes mean .45 and std .225, uniform temporal subsampling, short-side resize and center crop. Exact XS checkpoint `X3D_XS.pyth` HEAD200/30,779,313 bytes; loader expects `model_state`, 400-class Kinetics model. Builder says do not modify kwargs with pretrained=True. Consequently freeze one exact recipe and re-evaluate; do not silently combine 182px demo input with 160px model-zoo FLOP/accuracy claims. A trailing 1.6s buffer supports delayed online use, but X3D convolution has no external causal state. Raw float32 4×3×160×160 input is 1,228,800 bytes, **input only**, not RAM estimate. [M08-S02, S05]

**M08-F05 [primary_docs] TSM/TSN offer deployment-friendly 2D compute but no safe shortcut from clip to event.** MMAction tagged TSM config uses 8 segments each clip_len1, frame_interval1, sampled across the full supplied video, 224px crops. Train uses multiscale crop/flip; val center-crop, test TenCrop (80 images per source clip). Thus `1x1x8` is not a fixed8-frame continuous temporal window. Exact checkpoint HEAD200/97,651,119 bytes, listed in artifact inventory. TSN is a useful order-agnostic average-segment baseline: cheaper temporal logic does not make it a reliable motion transition recognizer. TSM improves ordering cues but shifting channels is an operator/export concern and ordinary bidirectional TSM has future dependence within the clip. Host PyTorch CPU reference possible in principle; no FPS, memory or LinQ compiler support was measured. [M08-S04, S06, S15]

**M08-F06 [primary_docs] 3D CNN/SlowFast and VideoMAE remain offline references here.** Concrete AVA SlowFast config is FastRCNN with ResNet3dSlowFast plus 3D RoIAlign and multi-label AVA head (81 outputs including background). It needs full RGB clip **and person proposals**, not just a cropped actor or standalone classification call. Despite filename 8x8x1, pipeline is SampleAVAFrames clip_len32 interval2; slow resample_rate4/speed_ratio4. Tagged sampler explicitly starts at center−32 and ends before center+32, so at30fps last frame is center+30 (1s future) and span62/30≈2.067s; nominal window64/30≈2.133s. Preserving original center semantics adds at least ~1s lookahead plus decode/inference. A trailing-window relabel is a changed evaluation protocol. AVA prep fixes source30fps; reducing observation rate to1fps changes coverage dramatically. [M08-S07, S08, S13]

VideoMAE-B checkpoint is K400-pretrained **recognition** donor, not an industrial anomaly or event detector: HEAD200/173,099,345 bytes. Tagged config is **test-only**, 16 frames interval4, num_clips5, ThreeCrop224, NCTHW, ImageNet mean/std. README table says short-side320, whereas config resize is224: another actual recipe discrepancy. 16x4 nominal30fps spans2.13s (first-to-last2s); test uses15 views, not one causal input. 87M/180G are source model statistics, no CPU/TPU performance guarantee. Original VideoMAE self-supervised masking and small-data transfer claims do not eliminate the need for target labels/fine-tuning or make the fine-tuned classifier causal. Broad temporal convolution/transformer heads are not a fourth deliverable merely because frameworks support them: no exact industrial checkpoint/data contract was established here. [M08-S14, S16]

## Four conditional methods and acquisition/decision contracts

| Candidate | Conditions / event contract | Practical split / stop condition |
|---|---|---|
| 1. Detector/pose/track + timed rules | Preserve timestamped observations and uncertainty; past-only ROI dwell, calibrated motion if geometry exists, posture-transition and motion-evidence history. Use hysteresis and per-episode close/re-arm rather than repeated frame alerts. Baseline for running/fall/immobility; fall requires transition, lying may need a separate prolonged-state rule. | Neural detector/pose only on LinQ **if exact export/device works**; CPU tracker/rules. Timestamp and identity gaps suspend evidence, not prove immobility. No new checkpoint claim in this branch. |
| 2. MoViNet A0 Stream | Exact above causal graph; choose per-scene or person-stream semantics; preserve 5fps-like inputs initially, compare temporal recall and onset latency. Fine-tune action head then selected blocks only if permissioned target clips exist; background/no-event must be represented. | Host TFLite CPU reference, per-stream state budget. On-device conditional on actual LinQ state I/O/operators/compiler. Stop if state handling or target recall fails. |
| 3. STGCN++ joint COCO17 | Pose extractor provenance, normalization, stable person assignment and confidence missingness must match; evaluate 100-sample past windows with explicit seconds and adapted head. [inference] Keep acquisition fps separate from network inference/update fps. Store enough timestamped frames to revisit brief transitions even if NN output is throttled. Define event score timestamp, receptive context, first valid detection and notification time independently; centered-model lookahead must enter measured latency. One incident should create one episode notification and remain visible in the journal. No unconsciousness diagnosis, bbox-overlap-as-meters or weight/effort inference.

## One supported additional hazard: apparent person-directed physical aggression

**M08-F07 [artifact_access_checked; local_test(annotation only); inference] Conditional research extension, not validated production feature.** AVA labels64 `fight/hit (a person)` and76 `push (another person)` are in the actual 60-class evaluation pbtxt (HTTP200,2649 bytes). Validation zip was GET200 downloaded **to memory**, unzipped and parsed locally, 1,611,664 bytes: 243,029 annotation rows, **478 rows of class64 and86 of class76**. These are person-second annotations, not numbers of independent incidents or videos. Example row: video `55Ihr6uVIDA`, timestamp991sec, normalized bbox[.305,.216,.494,.987], action64, person19. Corresponding source identifier URL is https://www.youtube.com/watch?v=55Ihr6uVIDA&t=991s ; **not opened, video availability/content not verified or downloaded**. AVA original page plus MMAction video downloader provide a real video dataset→annotation→SlowFast trained-head path; this is stronger than an image-only “violence detector” lead but still no acquired target video.

CSV is eight scalar columns: video_id,timestamp,x1,y1,x2,y2,action_id,person_id; multiple rows allow simultaneous labels/person tracks. Google original page defines 430 videos (235train/64val/131test),15minutes at1sec annotation intervals, evaluation on included timestamps and exclusions; v2.1 removed duplicate movies and v2.2 adds missed annotations/corrects some extreme-aspect boxes. Exact checked SlowFast weight is **AVA2.1** with author25.80mAP, not AVA2.2; use AVA2.1 split/labels for its published comparison, or explicitly call AVA2.2 a new evaluation. No per-class aggression performance was established. Movie acting/domain shift, close interactions, assisted lifting, balance recovery, friendly contact, tool handoffs and handshakes must be matched negatives. Label “apparent hit/push requiring review”; intent and injury are unobservable.

AVA page explicitly grants dataset CC BY4.0; preserve attribution. Underlying movie/media rights and retrievability are not equated to a blanket clearance to redistribute footage. MMAction Apache2 code is separate from checkpoint publication and source movie rights. Do **not** add a second hazard merely to fill a quota: “heavy carrying” in NTU is already core scenario8 and has no visible mass ground truth; staggering is medically ambiguous and overlaps scenario7.

## Evaluation and unresolved gates

**M08-F08 [inference] Small-data fine-tuning design.** Split by source video/camera/site/actor recording session before generating windows. Keep adjacent and overlapping windows together; avoid random-frame splitting and calibration on test. NTU concurrent three-view captures require the intended cross-subject/cross-view protocol; treat views of one performance as linked if making a custom split. Kinetics CVDF README explicitly warns K400 validation largely overlaps K700 training; never claim independent cross-version testing. AVA-Kinetics includes original AVA videos plus K700 clips and is not automatically an independent holdout from either. Native clip top1, AVA frame-mAP and target event recall/false alerts/hour are different metrics. The directly GET-checked K400 val.csv (HTTP200,810,935 bytes) has header `label,youtube_id,time_start,time_end,split,is_cc`; e.g. first row abseiling,0wR5jVB-WPk,417,427,val,0. These are clip-level source intervals/class labels, not person boxes or industrial onset/offset/policy annotations. The `is_cc` field must not be erased when assembling redistributable source material. The checked K400 video-part list is a real1130-byte metadata list, not acquired videos.

Target evaluation needs episode start/end, actor, scenario/policy status, visibility, “unknown”, camera/source fps and independent annotation adjudication. Report event recall and onset-to-notification latency distribution at a fixed false-alert/hour operating point, plus duplicate counts, missed short transitions and occlusion/identity-reset strata. Use matched normal negatives: walking/fast safe work, bending/kneeling versus fall, resting/maintenance versus immobility, scanner/radio/tool versus phone, authorized locations, near-camera and distant actors. For MoViNet report both cold-start and continuous-prefix conditions; for window methods report stride and accumulated context; for centered AVA model include future acquisition delay.

Remaining unknowns: LinQ model/device/SDK/operators, accepted host/device split, measured RAM including state tensors, binary integrity/full hashes, exact weight-specific license notices, quantized artifact URL, target videos, label budget, local CPU throughput, event threshold/SLA. No inference/export/runtime checker was run. The only `local_test` here is CSV/archive parsing and input-memory arithmetic, not a model or video test.
