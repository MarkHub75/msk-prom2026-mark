# W1 D10 — fall, lying and immobility data: temporal semantics, negatives, acquisition and splits

Research/access date: **2026-10-23**, final clock check **19:24:02 UTC**. Branch question: which source datasets can support a reviewable temporal fall/lying experiment, with actual negatives and grouping, rather than an accidentally inflated frame classifier? No model execution, training, video playback, full video/archive download, access request or outreach was performed. Small annotation CSVs, documentation PDFs, HTML and metadata were retrieved. `local_test` below means parsing those files only.

## Decision

**D10-F01 [inference]** Use **URFD camera 0** for a bounded source-level ingestion/semantics test, **UP-Fall** for a subject-disjoint temporal evaluation when its raw images and labels are obtained, and **Montreal MCF** for confounding-action and view stress tests when use rights are established. All three remain staged indoor data, not a validation set for industrial CCTV. Keep fall event, lying state, and immobility duration as separate targets. None establishes unconsciousness or a safe operational alarm threshold.

**D10-F02 [artifact_access_checked]** A materially useful correction to prior work: Montreal is **not uniformly inaccessible**. The web browsing tool returned an Anubis access page, but ordinary bounded Python HTTPS requests returned the original index and PDFs and genuine ZIP response headers. This is an access-path difference, not evidence that videos were downloaded or inspected. The index includes a 2025 erratum that is essential before transferring time labels across cameras.

**D10-F03 [local_test + primary_docs]** URFD's ADL feature file contains **1,470 lying-labelled rows in 16 non-fall sequences**. Consequently, the row label `+1` cannot be reinterpreted as a fall event. These are an unusually useful, explicitly traceable hard-negative pool. Full findings below.

## URFD: event-negative recordings can contain lying people

**D10-F04 [primary_docs; S01]** URFD has 30 fall and 40 ADL recordings. Camera 0 is parallel to the floor; camera 1 is ceiling mounted and exists only for falls. Images are stored as per-camera PNG ZIPs. Views use nearest timestamps rather than exact synchronized exposure. Feature rows describe a depth-frame posture: `-1` nonlying, `0` transient falling pose, `+1` lying on ground; the documented original posture classification excludes `0`. Dataset licence is **CC BY-NC-SA4.0**, explicitly noncommercial academic; commercial permission is a separate gate. Subject identities and an official subject-disjoint split were not established from this page.

**D10-F05 [local_test; S02]** Parsed downloaded CSVs with Python `csv`, grouping by sequence column. Files have no header; 11 fields: sequence, frame, posture, eight depth-derived features. Counts:

| File | Recordings | Rows | `-1` | `0` | `+1` |
|---|---:|---:|---:|---:|---:|
| falls | 30 | 2,995 | 1,192 | 900 | 903 |
| ADLs | 40 | 8,549 | 6,260 | 819 | 1,470 |

ADLs with `+1`: **adl-10, adl-11, adl-21, adl-22, adl-23, adl-30 through adl-40**. Saved complete per-sequence transitions in `urfall-cam0-adls.csv.summary.json`. Example: adl-10 begins at frame 1 with `-1`, changes to `0` at frame 170 and `+1` at frame 200. Fall-01 changes to `0` at 83 and `+1` at 113. Frame coverage can start after 1 (e.g. adl-01 starts at 6); therefore do not fill omitted rows with a negative label or assume annotation row index equals image frame index. All 30 fall recordings have exactly 30 transient rows; this regularity is a **label-generation audit flag**, not verified physical duration of each fall.

**D10-F06 [inference]** Use original recording category to identify event negatives and row posture to test lying discrimination. Preserve `0` as a temporal state and report performance around it. A static classifier trained only on `-1` vs `+1`, then called “fall detection,” is evaluating a different task. Some ADL `0` labels demonstrate that the transient-code name alone does not establish a true accident. The exact actions in each negative require video review, which was not performed.

Never include camera1-only falls with camera0 negatives in a purported balanced view test: viewpoint becomes correlated with class.

## UP-Fall: dense original state labels and a real person split

**D10-F08 [primary_docs / author_claim; S03]** This is staged data from 17 healthy young adults in a controlled room; falls used a mattress. Two fixed frontal/lateral cameras are about 1.82m high; consolidated sampling is roughly 18.4Hz. Trial CSVs contain timestamps, sensor channels and subject/activity/trial identifiers; PNG filenames are timestamps. Crucially the activity column changes within fall trials among standing, falling and lying; picking-up trials also change state. Fall tags were manually inspected, ADLs tagged from times. Thus **folder activity is not frame truth**. Negative activities include walking, standing, sitting, picking up an object, jumping and deliberate lying. These provide a useful counterexample to “horizontal person = fall.” This paragraph summarizes original conditions, not measured deployment performance.

**D10-F09 [primary_docs; S04]** Storage keys are subject/activity/trial, with a camera image ZIP for each view. Official page declares subject8/activity11/trials2–3 missing. Complete sensor downloads, optical-flow features and raw camera images are distinct products. A downloaded feature CSV or preliminary four-person sensor set does not constitute ready video input. Source page says publicly available and requests citation, but a clear reusable dataset licence covering raw images was **not found in inspected primary material**. Article CC BY status does not itself settle image-data rights.

**D10-F10 [primary_docs; S05]** The 2020 vision competition explicitly defines **train subjects1–12 / test subjects13–17**. Both cameras stay with their subject. Inputs are full frame sequences, not presegmented clips. Its metric builds 3-second windows with 50% overlap, labelled by the most frequent tag, resolving equal counts by the first tied tag. Some subjects have incomplete information. Treat this as a reproducible **historical classification protocol**, not an alarm-latency or industrial-safety SLA.

**D10-F11 [inference]** Retain that person split as the first reproducible protocol, with validation subjects taken solely from1–12. Split before generating windows. The majority label can erase a short fall inside a window; add event recall and time-to-first-alarm evaluated on full timestamped sequences. Do not tune threshold or dwell time on13–17. Camera holdout of the same trial is not independent person/event generalization.

Actual access check for S06: direct URLs `https://drive.google.com/uc?export=download&id=1kq2qhQlzKbsobOUiqA4pRY83hoV3MhBT` and `https://drive.google.com/uc?export=download&id=1XJ61-FQ_2PMoEPdNVK5PblkEbXEetBx1` redirected to drive.usercontent.google.com and returned **HTTP200 text/html**, 2,040 and 2,475 bytes respectively, titled **Google Drive - Quota exceeded**. Local files keep original names but are HTML error responses, not executable Python or a usable ZIP. No retry-bypass, credentials, download API project or account was created. Raw image file-level availability remains unverified, not disproved.

## Montreal MCF: exact temporal corrections and difficult confounds

**D10-F12 [primary_docs; S07]** MCF uses eight wide-angle IP cameras, one actor, staged falls with mattress. Nine interval states distinguish walking/standing, falling, lying on ground, crouching, moving down/up, sitting, sofa lying and horizontal movement. Schema is scenario/reference-camera/start-frame/end-frame/state. Same physical event appears in every camera. Confounds include chair/sofa occlusion, carrying, coat changes and housekeeping; compressed imagery, shadows and reflections are intentional difficulties. Keep every view of a scenario in one partition. A person-disjoint test within this dataset is impossible because it has one subject.

**D10-F16 [artifact_access_checked / unknown; S10]** Original ImViA URL returned404. A third-party upload's CC BY claim cannot grant rights to original videos. ## Split and evaluation contract for this branch

The following are **D10-F18 [inference / proposed experiment]**, not claims of an existing published benchmark:

1. Build a manifest before feature extraction: dataset release, original subject, room/layout, session/date, source recording, physical event, view, source frame/timestamp, label source/revision, parent original and hash. Preserve “unknown subject” explicitly; do not derive actor identity from filenames or face appearance without documented mapping.
2. Group URFD by **fall/adl recording stem**, linking both views and all derivatives. If actor mapping later becomes available, regroup by actor; until then label the result recording-disjoint rather than subject-disjoint. Reserve camera0 for fall-vs-ADL comparisons. Use camera1 only for clearly labelled view analysis.
3. Group UP-Fall by subject for the official split. Keep trial and its two views and all overlapping windows together. Validation comes from training people only. Hold out complete rooms/sites in a later external set because the subject split still shares a laboratory.
4. Group MCF by scenario across all eight cameras. It supports recording/view robustness within one actor and scene. Do not advertise scene/person generalization. Keep scenario23 ambiguous until reviewed and include corrected camera delays and intervals from S08 in the manifest.
5. Keep a source-family registry across OmniFall, URFD, MCF, UP-Fall, pose derivatives, flipped clips, resized images, extracted frames and annotations. A derivative or reannotation is not an independent dataset. Exclude source ancestors of test recordings from training, retrieval exemplars and threshold tuning. Exact hashes plus near-duplicate temporal fingerprints support this audit; they were not computed for video in this branch.
6. Split raw groups first, then generate causal windows. Sliding windows from the same recording never cross partitions. Each output timestamp may use only frames already observed. Preserve chronological timestamps; avoid centred windows and future majority labels for an online result. Report window classification separately if reproducing the competition metric.
7. Evaluate event detection with event recall, false alarms per camera-hour and first-alarm delay distribution. Separately evaluate frame lying precision/recall, episode duration errors and track gaps. Report transitions and occluded intervals rather than silently dropping hard frames. Do not set an acceptable maximum delay without the case owner; no numerical SLA was established.
8. Record negative classes deliberately: controlled lying/down-and-up; kneeling/crouching/bending to pick items; sit/stand transfers; jumping; work on floor; maintenance under machinery; obscured lower body; person entering/exiting; camera motion, frozen stream or lost track. The first classes are source-supported leads above; industrial maintenance, frozen-stream controls and long natural inactivity are **hypothesis / collection needs**, not claimed contents of these datasets.
