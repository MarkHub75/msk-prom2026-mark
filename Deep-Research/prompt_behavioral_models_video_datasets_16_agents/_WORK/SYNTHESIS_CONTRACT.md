# Contract for synthesis roles (not new research)

Read original briefs and CASE_NOTES.md. Six root deliverables only; preserve source and fact IDs with explicit anchors so relative references survive folder moves. No third search wave, no final auditor. New evidence only W1/W2 Medium roles. No root conclusion is mandatory for critic.

## Evidence assembly

Keep distinct: existence of a model family; exact trained checkpoint; binary access; actual download/hash; static parse; model execution; event benchmark; LinQ execution. Code, weights, annotations, source media and redistribution grants are separate. A code permissive license does not automatically clear all five. Conversely do not erase a positive dataset grant merely because public-recording/privacy scope remains unknown.

Every meaningful catalog record: precise identity, direct artifact URL, revision, access observation, schema/tensor/label semantics, source/evidence link, unknowns. Preserve full original evaluation settings beside quantitative results; no synthetic AP ranking. Generic action classes are donors until task/person/time/scene compatibility is shown. A downloaded annotation file cannot establish that source videos are still retrievable.

RAW_FACTS must include detailed methods registry, checkpoint registry, video dataset registry, annotation semantics, model/video/scenario compatibility, negative controls, rights, benchmark/causality, limits, proposed protocols and handoffs. Avoid only a short summary followed by pointers; include substantive branch evidence without copying whole pages.

## Event target schema (proposed, to refine using D15)

Stable fields: source_id + original_sha/revision; parent/session/synchronized-view group; subject/site/camera; media time_base and PTS origin; event_id; subject/ordered pair IDs; scenario literal and policy version; start/end/evidence intervals; observed action versus state; visibility/occlusion/unknown spans; allowed ROI/permit context; censoring at beginning/end; label provenance and annotators/disagreement; train/dev/lockbox role. Keep sparse timestamp action labels distinct from dense temporal intervals. Incomplete labels are not automatically negatives.

Episode matching must be predeclared and one-to-one, class and actor/pair compatible; provide timely recall, all-event recall (including unobservable), observable/eligible subset with coverage, event precision, unmatched alerts per camera-hour, duplicates per GT event, onset/confirmation/notification latency, duration/clear errors and censoring. Choose temporal-overlap/onset tolerance with the team; no invented acceptance percentages. Negative exposure excludes title/outro/frozen/looped frames and synthetic scenes when claiming real-camera FP/hour. Right-censored holds cannot count as completed clear/rearm.

Source clock time and processing wall clock are separate. Full-future interpolation, acausal centered windows, multi-crop/multi-clip voting and postprocessing cannot be called an online causal baseline. A tracker may retain state without emitting a box; no output is not safe/no event. Track identity, person identity and event identity differ.

## Required proposed experiment records

E001 artifacts/rights/input contracts; E002 grouped provenance split and hard negatives; E003 exact CPU/RTX baseline; E004 event-level causal replay; E005 bbox vs tracking vs pose rules vs temporal ablations; E006 1/2/5/native FPS and dropped frames with original PTS (rates here are comparison conditions, not promised sufficient rates); E007 independently controlled geometry/zone policy and uncertain boundary; E008 exact SDK/export/compile/device and quality delta later. Adapt IDs to assembled corpus.

For each include inputs/access, actions, expected observations, decision criteria anchored in case/team requirements, failure modes, saved evidence, what PASS does not prove. No timing or VRAM guesses. Stop rules are logical gates (missing relevant label, unavailable checkpoint, unobservable target, failed target controls, unsupported exact device path), not arbitrary numerical targets.

## Final report usefulness

Eight case rows each need: observable target; static versus temporal requirement; exact method/checkpoint + code/weight status; exact video/labels/access/rights; missing annotation and ready development pack versus actual lockbox; metrics and false-positive/negative controls; camera/FPS/ROI/geometry/window dependence; conditional LinQ vs CPU boundary; first action/stop gate. Additional hazards only when real evidence supports them; do not rename the same generic zone infrastructure as several independent achievements.

Three routes need concrete hypothesis, inputs/outputs, grouped split, metrics, measured-unknown conditions. MVP shortlist based on artifact+video+label+event verification readiness, with reserves and stop-list. Preserve first-hours engineering questions and 3–5 organizer questions, no outreach. Handoffs to named neighboring topics reference what is established and what would change the decision.

Russian report: substantial connected prose and useful comparison tables, no mere list/catalog. English: compact but independently understandable, explicit status labels/F IDs, accurate required YAML, concrete answers. Include actually performed roles, timestamp and case provenance. Date of access ≠ original publication date. Root actual start 2026-10-23T22:12:28+03:00; child completion may cross midnight, record actual date.
