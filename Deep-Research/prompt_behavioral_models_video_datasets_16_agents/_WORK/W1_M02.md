# W1 M02 — Tracking identity, gaps and incident lifecycle

Branch question: which concrete online trackers and artifacts can support stable human/machine episodes through missed observations, occlusion and zone re-entry, without false new incidents or silently merging a different event?

Decision: retain the already proposed pinned direct ByteTrack baseline, but expose association and track state separately from emitted results, and maintain a timestamped incident ledger outside the tracker. OC-SORT is a meaningful motion-only challenger for non-linear motion; BoT-SORT-ReID is a challenger where actual target-camera appearance helps. Neither is a demonstrated industrial upgrade. DeepSORT/StrongSORT add an embedding dependency and GPL code. StrongSORT++ and published BoT-SORT post-interpolation results must be classified separately from causal live-alert results. No tracker or NN was executed here, no industrial video was scored, no training/paid compute/outreach occurred.

The sibling overview and RAW_FACTS were searched first. Prior ByteTrack dt=1, strict TTL and persistent-ledger findings are context, independently rechecked in raw code where mentioned. This branch's new contributions are OC-SORT output suppression and None semantics; BoT-SORT spatial gating of ReID; DeepSORT predicted output ambiguity; explicit offline processing; exact accessible DanceTrack annotation gaps and licenses.

## Findings and exact implementation contracts

**M02-F01 [primary_docs] ByteTrack remains detector-dependent.** S01 `yolox/tracker/byte_tracker.py`, BYTETracker.update: Nx5 means xyxy,score; larger detector output multiplies objectness and class score. Coordinates are rescaled from model image to original dimensions. It associates high confidence boxes first against tracked+lost, then lower confidence against unmatched currently tracked tracks, then handles unconfirmed and new tracks. Low scores are not equivalent to safe behavior evidence. A detector yielding no box for a fully hidden person supplies no visual activity evidence. `Tracked`, `Lost`, `Removed`, plus `is_activated` differ from “incident active.” Default high/low scores and buffer are not calibrated for plant CCTV. The published MOT17 detector training uses CrowdHuman+MOT17+Cityperson+ETHZ; ablation uses CrowdHuman+half MOT17. Thus using the test-model detector on MOT17 training for one's validation leaks detector training. Different models in its zoo have different train/eval conditions.

**M02-F02 [primary_docs, inference] ByteTrack and BoT-SORT share expiry-after-association hazard.** S01 update and S02 `tracker/bot_sort.py` lines203–218,304–342,414–426: frame_rate scales `int(frame_rate/30*track_buffer)`, but loss is counted in update steps. Lost tracks enter association before removal loop checks `frame_id-end_frame>max_time_lost`. Strict maximum identity age needs pre-association expiry using last measured source time/step. Raising buffer can reduce fragmentation but increases opportunity to merge a new similarly located person. Fixed cadence with explicit gap updates is coherent; passing source FPS while only updating sparse selected frames changes real-time TTL. Detector inference timeout, masked region, no-person result and queue drop must remain distinguishable even if all cause an empty tracker update.

**M02-F03 [primary_docs] BoT-SORT-ReID is not arbitrary long-range re-entry matching.** S02 `tracker/bot_sort.py` lines267–275 and304–315: embeddings are extracted from current image crops only when `with_reid`; appearance distances are divided by2, thresholded, and rejected outside an IoU-distance proximity mask; final cost is minimum of geometric and surviving appearance cost. A good visual match outside the spatial gate cannot rescue that pair through the appearance term. ReID does not grant persistent human identity after exit. The second low-score pass is geometric. CMC uses current images and has implementation choices (`files`, `orb`, `ecc`, plus code-supported variants); README's original VideoStab-based GMC files can be precomputed with C++ tools. Measure the actual live CMC choice, do not inherit precomputed-file scores. Main implementation returns active activated tracks and stores tracked/lost/removed separately. Multiclass support does not mean pedestrian ReID weights generalize to forklifts or suspended loads.

**M02-F04 [primary_docs] Original OC-SORT has a sharp None versus empty contract.** S03 `trackers/ocsort_tracker/ocsort.py` lines197–208: documentation requires one call per frame and `np.empty((0,5))` when no detections. `None` returns an empty result before frame_count increments; it is not an empty time step. Defaults constructor lines180–194: max_age30, min_hits3, IoU .3, delta_t3, inertia .2, use_byte=False. Five-column input xyxy+score is rescaled like detector output. Main update output is Nx5 xyxy+ID, not detector score+ID/class. The public-detections update is a different API and can emit head-padding rows; do not conflate adapters.

**M02-F05 [primary_docs, inference] OC-SORT may keep/reassociate an ID while withholding it from output after a gap.** S03 KalmanBoxTracker.predict lines144–157 resets hit_streak when `time_since_update>0`; update bbox resets time_since_update and increments hit_streak (136–140). OCSort.update lines321–328 emits only time_since_update<1 and (hit_streak>=min_hits or startup frame_count<=min_hits). One missed step followed by reacquisition after startup leads to hit_streak1,2 before3, so the old valid identity can be absent from output for the first two returning observations under min_hits3. Deletion is a different test `time_since_update>max_age`. An episode consumer equating “not emitted” with “left/clear” can split one incident even when association itself succeeded. ORU repairs filter state using a virtual trajectory when a later observation arrives; this cannot establish that unsafe action occurred during the hidden gap. The fixed F matrix and delta_t use steps, not seconds. README performance CPU700FPS excludes detector and appearance NN; no LinQ/host throughput measured here.

**M02-F06 [primary_docs] DeepSORT's demo can emit a predicted box with no detection this step.** S04 `deep_sort/tracker.py`: defaults max_age30,n_init3; predict then update; confirmed tracks use appearance matching cascade, recent unmatched use IoU. Track.mark_missed deletes tentative immediately on miss and confirmed only after time_since_update>max_age. `deep_sort_app.py` lines182–198 emits confirmed tracks while time_since_update<=1, including one-step predictions. StrongSORT's demo lines189–204 does likewise. Therefore demo MOT result rows are not a direct list of current measured detections. An adapter must carry matched detection ID, last measured PTS and measured/predicted flags, instead of treating exported rows as fresh evidence for immobility or unsafe proximity.

**M02-F07 [primary_docs] StrongSORT++ is retrospective and can rewrite IDs/boxes.** S05 `strong_sort.py` first run() writes full sequence; optional AFLink then optional GSI read/write same output. `AFLink/AppFreeLink.py` constructor loads whole trajectory file, model.cuda(), and link() constructs global pair cost matrix, links track ends to starts with thrT=(0,30), thrS75, thrP .05, rewrites IDs and deduplicates (frame,id). `GSI.py` interpolates between known left/right observations, fits Gaussian process to whole track, and writes smoothed rows (confidence1). These rows are synthetic, not observations. Default GSI interval20,tau10 are frame-count settings. An exact current implementation needs CUDA for AFLink despite it being described as lightweight; adapting CPU is possible in principle but was not tested. StrongSORT's prepared detections+features+ECC are also a distinct input pathway from live detector+embedder+CMC.

**M02-F08 [primary_docs] Published BoT-SORT test recipe also calls retrospective interpolation.** S02 README tracking MOT17/MOT20 test commands call tools/interpolation.py after inference. Its dti() reads the entire sequence, fills gaps only where future endpoint exists, default CLI n_min5,n_dti20 (function default n_min25 is overridden by CLI), and overwrites unless save_path supplied. write_results_score writes score=-1 for every row, losing the measured/synthetic distinction. Do not use this output as online evidence or assume unmodified published quality is achievable before future frames arrive. Report causal raw results and delayed repaired results separately.

## Episode contract and tests to run next (proposed)

**M02-F11 [inference] Required separation:** physical identity is not guaranteed by tracker ID; `track_uid=(camera,stream_epoch,tracker_instance,local_id)` prevents accidental reuse across resets. Use a separate stable episode_uid and an auditable possible-continuation relation. A track miss transitions evidence to unknown, not automatically safe/clear. Do not extend measured immobility time with predictions. Masked person boxes/hidden feet must retain evidence quality flags. Class-specific trackers prevent person/machine cross-association, but machine motion/proximity still needs appropriate detections and ground calibration.

Allow short-gap continuation only under a documented temporal/spatial/appearance policy; record uncertainty. Ambiguous reappearance by two similar uniformed people must not automatically inherit the old unsafe event. A confirmed visible exit can close zone occupancy; a frame edge miss/occlusion cannot establish exit. If a person leaves and later re-enters, whether it is one persistent hazard or new episode depends on explicit scenario/ROI policy and evidence of clearance. A persistent fall/lying hazard may remain unresolved even while person identity is lost; smoking/phone episodes require current localized evidence. Permanent ID blacklists suppress genuinely repeated incidents. Global camera cooldown merges different workers. Neither is acceptable general deduplication.

Minimal deterministic test proposal (not executed): feed fixed original-coordinate boxes at ordered ticks with a unique detection ID, no ML inference, after initial warmup. (1) OC-SORT20 observed ticks,1 empty,3 identical boxes: assert same internal ID and emitted-return pattern absent,absent,present for min_hits3; compare one None gap to show no age advancement. (2) DeepSORT confirmed track,empty update: assert its demo emits time_since_update1 but measurement flag false; next miss hidden while track still confirmed. (3) ByteTrack/BoT-SORT N+1 empty returns: compare stock association with pre-expiry adapter, assert no over-TTL ID resurrection. (4) two identical-looking tracks cross then one returns in old box: evaluate false merge/episode transfer. (5) stream restart with localID reuse: assert unique epoch and no automatic old episode closure. (6) repeated all-empty/timeout/masked steps: ledger remains unknown and emits no repeated alert. Instrument internal track state, matched_det_id, last-measured tick and emitted rows separately.

Real-sequence next test: use dancetrack0010 GT identity gaps above with actual frames, same detector outputs across ByteTrack,OC-SORT,BoT-SORT, and manually label gap causes. Native20Hz plus deterministic10/5/2Hz thinning, controlled detector misses and ROI masking; compare fixed-time buffers, not identical frame counts. Score ID switches, fragmentation, re-association precision, duplicate event starts, wrong old-event continuations, time to resume measured evidence, and unresolved-gap rate. Safety-event GT must be added; assigning “hazard=true” mechanically to an identity is only an association stress fixture. Evaluate raw causal output before optional interpolation, and prohibit future frames in live scoring.
