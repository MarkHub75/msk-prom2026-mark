# Open decisions and proposed eight-stage experimental roadmap

Topic `behavioral_models_video_data`; context `mosprom-research-v1`. This is a proposal for later authorized engineering, not a record of performed model tests. The two search waves are complete. The collector used saved sources only. P0 means it can block the chosen architecture or invalidate its main claim; P1 means scenario-dependent promotion/quality work; P2 is an optional extension. No acceptance percentage, runtime estimate, rental, outreach or SDK command is invented.

The source evidence and exact artifact identities are in [RAW_FACTS.md](RAW_FACTS.md) and [SOURCES.md](SOURCES.md). All seven critic outcomes are `scope_narrowed`, with closed artifact/clock subcomponents and remaining actual event/device/rights gates in [CRITIC.md](CRITIC.md). A source-read or static PASS does not close an execution question.

## First engineering hours

1. Obtain the issued LinQ device/SDK/compiler/runtime and accepted CPU/device partition; ask for exact input/output/job evidence requirements. This can change the architecture before training.
2. Choose one observable event and obtain permissioned continuous target footage, matched normal/confuser recordings and independent actor/pair/visibility annotations. Reserve an untouched source/session/site lockbox before tuning.
3. Freeze one exact detector→pose/flame model and pre/post chain. For RTMPose, choose SDK1.2.0 RGB/CropResizePad/minSimCC or a separately named validated port; do not mix body7, AIC+COCO, recipe05d8511e and old CPU96154d0b artifacts.
4. Load the existing media/clock fixtures without relabelling their source semantics. Four reviewed fall files cannot test10/30s holds; Charades desk phone cannot test concurrent mobile use while walking; routine warehouse passage is not near-miss GT; Mmodal mist video is unconfirmed.
5. Run a CPU/RTX causal reference only after the artifact/runtime contract is fixed. Keep original PTS and measured/predicted/unknown states. Measure event precision/recall, duplicates and latency before adding a temporal head or training.

## Proposed eight-stage roadmap

Every stage below is **NOT EXECUTED** as a model/event experiment. Saved W1/W2 artifact/media inspections are inputs, not a completed stage. “Pass” means the stated narrow gate, not industrial validation. Team/case requirements supply acceptance thresholds; where absent, report observations and keep the decision open.

### E001 — exact artifacts, rights and input contracts

**Inputs/access:** Canonical checkpoint registry F005 and SOURCES, actual saved full bytes/static schemas, pinned code/config/license records, intended evaluation/demo/deployment use and actual available CPU/RTX environment. LinQ details may still be pending Q001. No rental or large download is implied.

**Actions:** Select one exact route, collect any missing small matching dependencies through authorized access, verify full hashes and external-data files, class maps, training/source versus export identity, runtime versions and notices. Freeze detector→crop→network→decode→original-coordinate contract. For RTMPose use batch1,17actual outputs, SDK1.2 RGB/CropResizePad/minSimCC; do not import the old CPU detector under the recipe name. For fire/forklift preserve opposite numeric maps. Record code/weights/annotations/media/redistribution/consent separately. For MoViNet declare float or modified INT8 and complete43-state interface.

**Expected observations/decision:** Either a complete reproducible manifest with an implementable, permission-appropriate reference, or a precise missing artifact/term/dependency. Pass only if identity, rights for intended use and full input/output/prepost contract are explicit. Stop or narrow the route on unavailable matching checkpoint, missing external tensor, unsupported license use or irrecoverable class/decoder ambiguity.

**Failures:** Similar filename mistaken for equivalent training/export; HTML saved as weights; partial hash represented as full; copied mirror counted independently; code grant extrapolated to all media; runtime support inferred from static schema.

**Preserve:** Manifest with URLs/revisions/hash/source timestamps, access response type/range/full status, external files, package/driver versions, licenses/notices, shape/dtype/class/prepost contract and unresolved rights ledger. **Pass does not prove:** model executes, numerical parity, relevant pixels, event quality, performance or LinQ. Evidence F003–F007/F019; Q001/Q004/Q015.

<a id="E004"></a>
### E004 — causal episode evaluation and notification lifecycle

**Inputs/access:** Frozen E003 reference, E002 dev/test split and operational GT, agreed Q002 deadline/policy, explicit one-to-one matching and uncertainty/censoring rules. Prepare continuous past-only replay, then paced/live measurement for wall latency.

**Actions:** Freeze event confirmation/hold/gap/clear/rearm and actor/pair ledger. Emit one message for one ongoing episode, retain unknown spans and possible continuation separately. Compute class/actor/pair-compatible one-to-one matches; duplicates/unmatched alerts remain errors. Score all-known and observable/eligible recall with coverage, timely recall, event precision, unmatched alerts per reviewed camera-hour, duplicates, onset/first-evidence/confirmation/notification delay, duration/clear error and censoring. Include detector-failed positives in the primary denominator. Perturb the future suffix and confirm earlier outputs unchanged. Test initial lying, brief event, long normal prefix, occlusion, unknown gap, actual recovery, repeat after clear and reconnect. Paced/live run logs processing wall time separately from source time.

**Expected observations/decision:** A reproducible match/error ledger showing whether the chosen observable event meets agreed requirements. Stop on future/GT-boundary dependence, missing-event exclusion, repeated messages, unsafe clear-on-miss or padding counted as evidence. If no operational budget exists, report results without declaring acceptance. Right-censored holds/clear remain unassessable, not success or ordinary miss.

**Failures:** Window accuracy renamed event quality, favorable posthoc match tolerance, same alert matched multiple times, model-driven eligibility, title/outro hours inflating denominators, unpaced replay called live latency, interpolated hidden action claimed observed.

**Preserve:** Frozen policy/matching files, GT version, candidate-match graph and one-to-one decisions, complete alert/track/evidence ledger, censoring/coverage/exposure denominators, causal suffix check and wall/source timing logs. **Pass does not prove:** new-site safety, physical diagnosis, low-FPS robustness or LinQ. Evidence F014–F018; Q002/Q003/Q005/Q013/Q017.

### E005 — targeted method and adaptation ablations

**Actions:** Compare one change at a time with equal detector/input/label/visibility conditions where possible. Measure detector misses separately from pose/action mistakes.
