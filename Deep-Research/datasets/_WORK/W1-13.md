# W1-13 — CCTV, малые объекты и перенос домена

Исследователь A, datasets, первая волна. Дата доступа23.10.2026. Все расчёты ниже аналитические; inference, обучение и измерение качества не выполнялись. Данных целевой камеры организаторов нет.

## Решение

Слово industrial и высокое разрешение сами по себе не делают набор репрезентативным для CCTV. **SFCHD** — наиболее прямой кандидат для factory-camera adaptation с касками/одеждой и сложным освещением; **Önal/Dandıl** — реальное заводское видео для replay и новой разметки событий. **SH17** полезен разнообразием PPE, но stock-photo viewpoint/масштаб требуют отдельной целевой проверки. **CPPE-5** даёт ясные face-protection признаки, включая крупные респиратороподобные изделия внутри `Mask`; это donor, а не доказанный CCTV holdout. **SODA** сочетает близкие и дальние строительные виды, но его cleaning/annotation отбрасывает часть нужных нам трудных случаев.

## Сравнение домена и масштаба

**W1-13-F01 — авторские числа S01.** SH17 собран из Pexels по queries о manufacturing/industrial workers. Максимум8192×5462, минимум1920×1002 — авторские размеры, не наш замер всех images. Заявлено39764 annotations с area<1% image и59025 с area<5%. Процент площади не означает одинаковую ширину/высоту, плотность информации или CCTV distance. Body parts дают много small-area boxes даже на близком фото. Требуется распределение каждого target класса после конкретного resize; сводная доля всех17 classes не отвечает, как выглядит респиратор у дальней камеры.

**W1-13-F02 — документ S02.** SODA:86% images1920×1080; handheld short/long range, UAV, tower crane hook view. Авторы прямо отмечают, что видео с самой высокой точки бывает слишком неясным для разметки малых объектов. Blurred/ambiguous images удалялись, partially occluded/inconvenient objects опускались. Следовательно, даже real-site source имеет selection bias относительно непрерывного потока с плохой видимостью. Random90/10 image split не доказывает перенос на новую камеру.

**W1-13-F03 — документ и полученные metadata S03.** CPPE web/medical: paper Fig3 сообщает средний aspect ratio1.40 и среднее `sqrt(width*height)=946.94pixels`. Последнее не средняя ширина и не размер box. В29 полученных HF test rows есть разные aspect ratios/разрешения. Реально просмотренный id1012 показывает крупное лицо с полумаской; id1013 — крупный torso в белой защите на чистом фоне. Два примера не измеряют частоту таких сцен; они подтверждают существование заметного отличия от дальнего elevated CCTV.

**W1-13-F04 — документ S04 и подсчёт C/W1-03.** SFCHD: surveillance cameras двух химзаводов, около40 scenes, недельный сбор; каждые10 frames при наличии людей. Из примерно40000 captured images получили12373. Сцены indoor/outdoor, тени/сильный свет; есть отдельные `blur_head`, `blur_clothes`. В реально полученном COCO metadata C:11349 images1280×704 и1024 images1920×1080. Paper §3.3 говорит максимум1920×1280; расхождение с конкретным JSON сохранять. Интервал frame sampling не устанавливает FPS. Blurred labels документа связаны с shadows/strong lighting; это не исключительно motion blur.

Paper определяет small objects через площадь<0.12%, а не COCO area<32²pixel. README числа safety helmet small7717/14298 и blurred head small1078/1134 являются авторским распределением по порогу набора, не нашим замером после640 resize. Реальное CCTV делает source приоритетным, но не устраняет camera correlation или license unknown.

**W1-13-F05 — документ S05.** Önal v1:1920×1080,24FPS,H.264, камеры около4м, дневной свет/ночные лампы, две камеры9/14; реальный завод. Авторы отмечают 2D projection ambiguity near walkway. Подходит для perspective/occlusion/temporal replay; не содержит доказанного протокола размеров PPE или industrial respirator labels. Curated1–20с clips отличаются от длинного потока с редкими тревогами.

**W1-13-F06 — наше наблюдение S06, один label member.** SARD `4.txt`, строка2: `helmet 1328 112 1346 127`; последние четыре числа похожи на18×15 xyxy box. Соседний person имеет условный размер53×73. Schema/FPS/видео4 не проверены, поэтому этот пиксельный расчёт условен. Нельзя определять is_small, пока не установлены координаты и размер кадра.

## Прозрачный расчёт resize/letterbox

**W1-13-F07 — наш расчёт, не качество модели.** При letterbox в640×640 scale=`min(640/W,640/H)`. Padding меняет начало координат, но не размер box. Значения ниже не учитывают небольшое округление до целых пикселей.

| Вход / объект | Scale | Размер после resize | Практический смысл |
|---|---:|---|---|
| Гипотетическое CCTV1920×1080, head30×24 | 1/3 | 10×8pixels | FullHD кадр не гарантирует видимость ремней/носа/сигареты. Это иллюстрация, не измеренная камера. |
| Гипотетическое CCTV3840×2160, box30×24 | 1/6 | 5×4pixels | Больший canvas при фиксированном исходном box не улучшает full-frame input. Не утверждается равная физическая дистанция. |
| CPPE HF image1013,1920×1088, goggles279×165 | 1/3 | 93×55pixels | Реальный metadata box остаётся крупным. |
| CPPE HF image1012,1280×720, Mask516×438 | 1/2 | 258×219pixels | Этот donor существенно легче по масштабу, чем гипотетическая30px голова. |
| CPPE HF image1023,600×400, Gloves23×15 | 640/600 | 24.53×16pixels | Upscale не создаёт новую исходную детализацию. |

Не приписывать всему CPPE крупный масштаб по двум JPG. Per-class histogram требует annotations выбранного состава. Из area<1% нельзя вывести единственный размер сторон без aspect ratio.

## Условия person/head crops

**W1-13-F08 — наш вывод.** Crop полезен, когда первичная камера ещё разрешает признак, но full-frame resize его убирает. Для исходного30×24 head в кадре1920wide person crop шириной180px при входе640 условно даст head106.7×85.3 input pixels вместо10×8. Источник по-прежнему содержит только30×24 реальных samples; crop не приобретает новую оптику. Интерполяция или super-resolution здесь не измерены и не доказывают корректность состояния.

Проверять надо ошибки первого stage, обрезанные головы, контекст переносимого PPE, позы, перекрытия, наклон камеры и число одновременных crops. Хороший отдельный head crop не подтверждает весь pipeline. Стоимость crops на LinQ — соседняя platform/model_stack проверка, не полученный здесь факт.

## Программа domain/scale audit

**W1-13-E01 — предложено, не выполнено.** На каждой новой камере сохранить native frame, codec/FPS/timebase, resolution, viewpoint, day/night, compression/bitrate при наличии источника. Разметить person/head/PPE boxes с visibility/occlusion/blur/unknown. По exact transform получить per-class width/height/area/aspect ratio и квантили, сохраняя исходный image ID. Camera/session/source-video IDs не выдумывать: отсутствующее — unknown; восстановленное — inferred с основанием.

**W1-13-E02 — предложено.** Сравнить donor с target по размеру признака, чистоте, высоте камеры, свету, occlusion и домену. Проводить audit раздельно по классам, а не по общей доле small objects. Только target holdout подтвердит перенос; он не участвует в training/calibration. Source-frame groups должны ограничивать утечку между splits.

**W1-13-E03 — предложено.** Hard negatives: обычные/защитные очки; медицинская маска/респиратор; helmet в руке/на голове; hood/hat/голова; телефон/питьё/еда/рука у лица; спина/неразрешимая голова. Для оцениваемых состояний нужна полная ручная разметка и visibility. Нет PPE label не означает negative. Для зоны отдельно фиксировать footpoint visibility и ambiguous projection.
