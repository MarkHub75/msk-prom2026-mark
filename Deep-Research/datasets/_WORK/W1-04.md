# W1-04 — респираторы, маски, очки и защита лица

Исследователь A, datasets, первая волна. Дата доступа 2026-10-23; clock при фиксации результата 03:09:27 UTC / 06:09:27 Europe/Moscow. Получались небольшие metadata, статьи, README и два preview JPG; обучение и полный CPPE archive не запускались.

## Практический ответ

**CPPE-5 — допустимый условный донор объектов `Mask`, `Goggles`, `Face_Shield`, но не готовый источник состояния «снятый промышленный респиратор».** Его статья исключила отдельную respirator category из финальной таксономии. Однако это не означает отсутствия самих респираторов на картинках: реально просмотренный HF test image_id1012 содержит полумаску с фильтрами, размеченную как `Mask`. Отдельные типы masks/respirators и корректность ношения по этим labels восстановить нельзя.

Для промышленного класса требуется целевая небольшая доразметка с разновидностью защиты, box единицей, person association и состоянием visible worn/removed/incorrect/unknown. SH17 имеет полезные body parts и очки/лицевую защиту, но сырые теги и очищенный class map различаются; подробный artifact-разбор B. MaskedFace-Net даёт correct/incorrect медицинского mask в синтетическом крупном face domain и не закрывает промышленный CCTV.

## CPPE-5: точная семантика и геометрия

**W1-04-F01 — первичный документ S01 §3.1, прочитано.** Авторы рассматривали7 категорий и исключили respirator/shoe cover из финальных из-за недостатка богатой разметки/примеров; полный facepiece respirator не входил даже в первоначальный список. Финальные5 категорий — object detection positive boxes; наличие box не задаёт correctness/absence. Определение goggles включает защитные очки; не доказана отдельная метка обычных оптических glasses.

**W1-04-F02 — metadata S02/S03/S04, фактически прочитано.** Между оригинальным README и HF есть сдвиг IDs:

| Original README ID | Original name | HF category ID/name | Геометрия HF |
|---:|---|---|---|
| 1 | Coverall | 0 Coverall | object bbox |
| 2 | Face_Shield | 1 Face_Shield | object bbox |
| 3 | Gloves | 2 Gloves | object bbox |
| 4 | Goggles | 3 Goggles | object bbox |
| 5 | Mask | 4 Mask | object bbox |

HF bbox документирован как COCO `[x,y,width,height]`, float32; координаты в пикселях исходного изображения. В sample1013 `[868,239,279,165]` category3 является goggles box. Эти IDs нельзя переносить в VOC/YOLO без именованной обратимой карты. HF row содержит image_id, image,width,height и objects{id,area,bbox,category}; person association/track/state отсутствуют в schema.

**W1-04-F03 — опубликованные авторские числа S01 §4/Table3.** 1029 images,4698 annotated objects:1197coverall,447face_shield,1343gloves,407goggles,1304mask. Статья описывает медицинский веб-домен, преимущественно Flickr с меньшей долей Google Images; «real-life» и «non-iconic» не означает фиксированную surveillance camera. Авторское утверждение exhaustive annotations касается выбранных5 classes, а не helmet/person/industrial respirator states.

**W1-04-F04 — конфликт версий/protocol, S01 §5 vs S03 Dataset Splits.** HF README и фактические rows подтверждают train1000/test29; S01 текст experiments говорит1029training images и another100testing images. Эти протоколы нельзя смешивать, объявив1129 одним публичным архивом. Полный original tar не скачан; вопрос соответствия100test images открыт. Для HF зафиксировать revision и использовать именно1000/29;29test слишком мал для уверенной отдельной оценки редких PPE states.

**W1-04-F05 — локальный подсчёт S04 только test29.** 29 rows содержат207boxes:Coverall45,Face_Shield17,Gloves61,Goggles32,Mask52. Размеры встречаются от340×736 и410×205 до2000×2000; это список наблюдений этих29, не распределение всех1029. Бокс Gloves23×15 в image1023 и Mask25×28 в image1022 показывают, что даже небольшой раздел не состоит исключительно из крупных объектов. Но долю CCTV-масштаба всего набора мы не измеряли.

**W1-04-F06 — наше визуальное наблюдение S05.** `image_id1012`,1280×720: крупный профиль лица женщины с полумаской, фильтрами и ремнями; единственный label `category4 Mask`,bbox `[369,271,516,438]`. По фото нельзя утверждать конкретную сертификацию/модель защиты. `image_id1013`,1920×1088: человек в белом coverall, goggles и cup-shaped маске, руки у капюшона; HF labels goggles/mask/two gloves/coverall. Следствие: класс Mask объединяет визуально разные изделия; «respirator исключён как отдельный класс» и «есть респиратороподобные изображения внутри Mask» совместимы. Просмотр2images не доказывает состав всех52test Maskboxes.

**W1-04-F07 — документ S01 §3.2/3.3.** Авторы описывают исходные image URL/author/license/MD5 metadata для Flickr и более ограниченное metadata Google Images; двойную независимую разметку с третьим арбитром/верификацией. Наши HF rows не содержат этих per-image source/license полей. Поэтому Apache2.0 кода не переносить автоматически на фотографии. HF front matter `license: unknown`; это точный статус карточки, а не положительное разрешение. Подробнее W1-10.

Получение S02: `dataset.tar.gz`,авторский размер~230MB и MD5 `f4e043f983cff94ef82ef7d57a879212`; README ведёт на Drive и downloader. Мы получили только README/script metadata, HF rows и2JPG; tar MD5 не проверяли. Paper/README/HF карточка — одна авторская родословная, а не три независимых набора.

## Другие доноры и пробел промышленного респиратора

**W1-04-F08 — S06, авторское описание.** MaskedFace-Net строится через деформацию наложенной маски на FFHQ faces. Текущий README:133,783images=67,049CMFD+66,734IMFD,1024×1024,ссылка на OneDrive по19GB для каждой части плюс Drive mirrors. Старый abstract137,016 — другое заявленное состояние; не подменять точную версию. Есть названия correct/incorrect subsets, но это image/face level, не box промышленного изделия. File names связываются с FFHQ metadata. Correct mask — нос/рот в заданном synthetic positioning; это не респираторный fit test и не снятие во времени. Лицензия README BY-NC-SA4.0, исходные FFHQ image licenses неоднородны.

**W1-04-F09 — S07 и передача B.** SH17 содержит `Face-mask-medical`, `Face-guard`, `Glasses`; нет отдельного industrial respirator в17flat classes. Статья описывает `on/off` и glasses safety/vision, но в очищенном release суффиксы могут быть удалены. До исследования raw annotation невозможно обещать корректность ношения или association; точные исходные tags и доступ проверяются W1-02. Базовый flat YOLO label предмета и дополнительный tag — разные артефакты.

SARD sample `4.txt` включает11person/action строк `wear mask(O3d)` (W1-07-F07), но11строк не11независимых событий, а класс действия не тип industrial respirator. Это зацепка, не готовый донор respirator. Сетью искались industrial respirator/goggles dataset,CPPE иface-mask источники; найденные общие карточки без annotation protocol не включены как доказанные источники нужного класса.

## Рекомендованный mapping и доразметка

| Source signal | Возможная роль | Условие / запрет семантической подмены |
|---|---|---|
| CPPE Goggles | class donor защитной eye-region вещи | Уточнить принятую в кейсе грань glasses/goggles; не делать no_goggles из отсутствия box на невидимом лице. |
| CPPE Face_Shield | class donor лицевого щитка | Не эквивалент full-face respirator или medical mask. |
| CPPE Mask | broad face-protection donor | Сохранить исходный label; вручную разделить medical masks/respirators/unknown до exact target merge. |
| SH17 Face-mask-medical | medical-mask donor | Точный industrial respirator target не установлен. |
| MaskedFace-Net CMFD/IMFD | исследование face-crop medical-mask position | Synthetic aligned portrait domain; не holdout CCTV и не industrial fit/correctness. |

**W1-04-E01 — предложено.** Получить оригинальные source/license metadata и небольшую стратифицированную выборку CPPE Mask:filter/cup/surgical,profile/front,distant/occluded. Для каждого сохранить image_id,source_box,visual subtype,visibility,worn/carrying/removed/unknown и связь с человеком. Спорное изделие — unknown,а не уверенное medical/respirator. Оценить межаннотаторные расхождения; только после этого определить, сколько independent source images относится к target protection.

**W1-04-E02 — предложено.** После получения камеры разметить несколько полноразмерных кадров, где protection видна/не видна: уменьшить точно тем же transform,что model input; проверить,остаётся ли отличим нос/ремни/фильтры. Если нет,исход `unknown/insufficient_resolution`,не no_respirator. Person/head crops могут увеличить пиксели входа,но не восстановить отсутствующую исходную деталь. Не выполнять inference/correctness claim по одному крупному web example.
