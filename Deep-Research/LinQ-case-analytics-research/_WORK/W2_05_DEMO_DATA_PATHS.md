K-ID: K005. Собственная веб-проверка: 23.10.2026, Europe/Moscow. Статус: нормативное разделение и условная карта подготовлены; разрешённость конкретных файлов и фактический режим LinQ не установлены. Это адресное исследование выбора демо, не юридическое заключение о всей системе. Реальные видео не загружались, сообщения не отправлялись, контактов не было.

## 1. Решение для команды

Предпочтительный условный путь — короткая собственная постановочная запись с добровольными совершеннолетними участниками, в безопасной обстановке, с заранее определёнными правами на файл, обработку у названных получателей и публичное использование изображения. Запись ещё не создана и согласия не получены. Пока маршрут LinQ не выяснен, подготовить сценарий и комплект разрешений; для открытой ссылки использовать только явно демонстрационные карточки/синтетические метаданные без связи с реальными людьми и предприятием. Работающее выполнение инференса LinQ должно затем проверяться отдельно; макет журнала его не доказывает.

Четыре независимые проверки: (1) право получить и использовать материал; (2) основание обработки людей и данных для выбранной цели; (3) допустимость передачи конкретному внешнему обработчику; (4) допустимость показа конкретной аудитории. Прохождение одной не закрывает остальные. Публичная ссылка на приложение не требует открытия производственного архива. Доступная всем миниатюра и API, отдающий исходный кадр по URL, также входят в проверку публикации.

## 5. Минимальная карта данных до первого внешнего кадра

Это предлагаемый артефакт проверки, он ещё не заполнен фактическими данными. На одну строку — один переход: источник/владелец → отправляющий сервис → endpoint/юридическое лицо-получатель → страна обработки → какие байты и метаданные → назначение → срок/удаление → люди с доступом → основание/документ → разрешённая аудитория результата. Разнести исходник, подготовленный кадр/тензор, результаты модели, миниатюру и журнал. Передача тензора вместо JPEG не доказывает необратимость; её нельзя объявить обезличиванием без проверки возможности восстановления/сопоставления.

Для публичного demo нужен отдельный перечень разрешённых файлов и полей, а не доступ к общей таблице пилота. Проверять также прямые URL, object storage permissions, API и экспорты: скрытие изображения в UI не закрывает выдающий его endpoint. Это продуктовые рекомендации из разделения аудитории (F01,F13), а не установленные дефекты существующего приложения.

## 7. Проверка привлекательных, но не подтверждённых идей

- W2-05-E01: «Размыли лицо — значит разрешено». Опровергающее основание F01: важна косвенная определимость по контексту, а не наличие лица. Одежда/татуировка, бейдж, зона/смена и сопоставление могут сохранить связь с человеком. Это анализ риска, не тест конкретного blur. Неидентифицирующая демонстрация требует анализа всего доступного набора, а не визуальной оценки одного квадрата.
- W2-05-E02: «На GitHub/в открытом наборе всё уже разрешено». F10–F12 обнаруживают условия автора/площадки и права, которые лицензия не передаёт. SH17 особенно неудобен для публичной карточки с обвинительным ярлыком. Не делается вывод, что весь набор незаконен; вывод уже: автоматического разрешения для выбранного пути нет.
- W2-05-E03: «Есть согласие на видеонаблюдение — можно отправить и опубликовать». F03–F07 задают разные цели, роли и права. Содержание существующего согласия неизвестно, а согласие вообще не единственный возможный законный путь.
- W2-05-E04: «Российский ускоритель = on-prem/все базы в РФ». F14 подтверждает лишь онлайн-доступ. Реальная география и логирование должны быть артефактом Q01–Q05.
- W2-05-E05: «Публичный WEB требует открытых кадров работников». Локальная сверка F13 этого не требует. Можно сделать открытое решение на отдельном демонстрационном материале; до разрешений — показать интерфейс с честной пометкой о синтетических данных.
- W2-05-E06: «Только метаданные всегда безопасны». Время, камера, зона и последовательность событий могут идентифицировать человека через сменный график. Для открытого демо нужны вымышленные, не производные от реального работника значения; простое удаление ФИО недостаточно.

## 9. Результат по K005 и передача соседям

K005 закрыт на уровне исследовательского решения: четыре условных маршрута, различие внешней обработки и раскрытия аудитории, первичные нормы в явно обозначенном правовом зеркале, конкретные условия SH17/Pexels, документные зависимости и узкие вопросы LinQ сведены в одном файле. Изменяется решение о демо: выбрать собственную документированную постановку как основной условный материал; не подставлять производственный архив и не считать SH17 готовым публичным pack; разнести открытый demo и будущий закрытый пилот. До получения документов разрешённым в этой работе не объявлен ни один реальный файл.

Для operator_product: карточка для внутреннего решения и карточка открытого демо — разные составы данных; журнал не должен выдавать производственные кадры публичному API. Для video_architecture/linq_platform: запросить фактическую карту endpoint→storage→logs→support; не обещать on-prem и отсутствие внешних копий. Для datasets: SH17 здесь проверен только по опубликованным условиям, не одобрен для публичного использования; проверить исходный файл и права людей. Для hackathon_strategy: ссылка на доступное решение и открытый производственный архив различаются; постановочные/синтетические данные явно обозначать; они не подтверждают точность на заводе.

Остаток локализован: подписанные согласия/поручения/разрешения, права на конкретные файлы, реальная сеть и сервисы LinQ, география, сроки удаления, решения ответственного оператора и допустимый режим показа экспертам.
