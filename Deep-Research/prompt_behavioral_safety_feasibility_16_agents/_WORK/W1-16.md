Дата доступа и исследования: **2026-10-23**. Исследователь W1-16 первой волны. Работа — исследование, без приложения, установки зависимостей, исполнения чужого кода, загрузки весов/видео, экспорта, компиляции и inference. Выполнены новые web search/open, малые GET конкретных исходников и metadata, HEAD точных артефактов и `git ls-remote`. Все smoke tests ниже **NOT_RUN**. Субагенты не создавались.

## Ответ на вопрос команды

Найдено пять практических маршрутов, но **ни один открытый проект не подтверждает всю цепочку до реального LinQ и требуемого одноразового сообщения о нарушении**. Воспроизводимыми на уровне исходных артефактов являются detector/pose → host postprocess/tracker, а правила исходных нарушений, event lifecycle, доказательные фрагменты и измерения надо добавить. «Есть README с красивым demo» слабее точного checkpoint + I/O + исполнимого code path.

Рекомендуемый порядок проверки — сначала один разрешённый LinQ detector и его точный tensor contract; затем пригодные исходные сценарии. Если доступен person-only detector, generic zone — полезный технический fallback и демонстрация инфраструктуры, **не самостоятельная замена ни бега, ни сближения с движущейся техникой, ни перелезания/прохода под оборудованием**. Из тех же tracks можно проверять движение/бег, но скорость проекции сама по себе не доказывает gait. Pose открывает падение с последующей малой подвижностью; двухклассовый forklift/person detector — сближение; COCO person/phone — лишь ограниченный контекстный кандидат; fire/smoke — огонь вне заданной разрешённой зоны, не курение.

Новые относительно простой сводки веток результаты:

- **W1-16-F01 [CODE]** Официальный ONNXRuntime-пример Ultralytics v8.3.0 делает прямой resize, тогда как основной predictor делает letterbox. Это два разных целостных контракта, а не автоматическая ошибка старого примера. Их смешивание без согласованного обратного преобразования ломает bbox, расстояния и зоны. Нужен паритет CPU/export/calibration/device на одинаковом входе [S03–S04].
- **W1-16-F02 [CODE]** Supervision time-in-zone на точном SHA использует внешний пакет `trackers.ByteTrackTracker`, anchor `CENTER`, а не прежний `sv.ByteTrack`; requirements не pinned. Готового lock нет [S01].
- **W1-16-F03 [CODE]** Его `FPSBasedTimer` хранит первый frame ID через `setdefault`, не удаляет запись при выходе ID из зоны; повторный вход включает время отсутствия. `ClockBasedTimer` аналогично хранит первое время. Эти utilities не являются счётчиком непрерывного нарушения или дедупликатором [S02].
- **W1-16-F04 [ARTIFACT/CODE]** Новый fire reference R3-E6 имеет release PT **и готовый ONNX**, publisher hashes, exact export/parity/CPU-benchmark scripts и записи среды. Это более сильный deployment reference, чем один `best.pt`; но корневой LICENSE не найден по прямому URL, права не установлены, а tracking/event/LinQ там не доказаны [S13–S17].
- **W1-16-F05 [CODE]** `distance_calculation.py` Ultralytics считает pixel distance между выбранными bbox centroids. Это не floor distance, не движение погрузчика и не collision predictor [S07].
- **W1-16-F06 [CODE]** Smoking repo содержит несогласованные model paths и разные inference backends: `func.py` импортирует `ov_inference`, хотя отдельный `ort_inference.py` создаёт sessions на отсутствующие в описанном дереве `model/rtdetr-best.onnx`/`model/yolov8n-pose.onnx`; export читает `models/last.pt`. Нельзя получить проверенную цепочку, просто заменив название backend на LinQ [S12].

## R1 — Person detector → tracks → zone / motion scaffold

**Практическая польза:** минимальный backbone и smoke-test для camera/time/event/dedup; условная база для бега, а generic restricted-zone demo только при явном согласовании такого отдельного scope. Source S01–S06; MIT supervision не меняет AGPL модели и не выдаёт video rights.

**Путь:** свой разрешённый MP4/OpenCV BGR HWC + source PTS → согласованный fixed640 letterbox/RGB/FP32 BCHW → точный YOLOv8n → dense detection output → host threshold/class-aware NMS/undo transform → person class0 → ByteTrack IDs → floor-anchor polygon/history → состояние → одна карточка/журнал. Взятый готовый time_in_zone пример работает с Python YOLO outputs; для LinQ заменить только inference boundary, сохранить контракт `xyxy/score/class_id` в original-frame coordinates. Центр bbox из исходного примера для floor-zone заменить обоснованным anchor (обычно bottom-center) и проверить на выбранной сцене.

Ожидаемый стандартный raw output static640 **[1,84,8400]** (4+80), вывод по head architecture из W1-04, не actual exported metadata. I/O names/dtype/layout проверить на реальном ONNX. Host tracker weights не требует. Inference NN должен реально выполняться на LinQ; decode/NMS/tracking/rules могут быть host-side только в согласованной архитектуре. Не передавать уже отфильтрованные scores так агрессивно, чтобы потерять low-score association ByteTrack.

**Минимум → сильнее:** person in defined polygon → calibrated track velocity плюс проверка gait/pose/temporal model для заявленного бега. Скорость в px/s или person-heights/s честно proxy; м/с требуют floor calibration. Быстрая ходьба, перспектива, skateboard/перенос платформой, движение камеры — controls, иначе бег не доказан.

**Smoke R1 (NOT_RUN):** (1) hash weights/video/config, export static640 no NMS с opset, который допускает полученный compiler; (2) CPU PT/ONNX parity на square и non-square кадрах, проверить углы полигона после inverse mapping; (3) те же tensors на реальном LinQ, затем tracker на обоих outputs; (4) человек входит→стоит→выходит→входит вновь; gap/окклюзия/два пересекающихся человека; (5) одна тревога на первое непрерывное episode, новая после подтверждённого reset, lost track не safe. Для running дополнительно ходьба/быстрая ходьба/бег разных направлений и held-out clips. **Стоп:** только bbox/зона без gait/motion evidence не закрывают исходный running scenario; неопределённый device execution не закрывает LinQ.

## R2 — Pose → track history → suspected fall + low motion

Source S04–S06/S09, artifact official pose above. Code v8.3.0, базовые зависимости PyTorch/NumPy/OpenCV/Ultralytics плюс ONNX exporter/runtime; точный transitive lock надо записать после разрешённой установки, здесь не создан. Готовый source path pose postprocessor масштабирует bbox и keypoints, а tracker индексирует results по matched detections. Не отрывать keypoints от соответствующего track при reorder.

**Путь:** BGR MP4+PTS → fixed640 RGB tensor → pose NN на LinQ → host NMS/scale → bbox +17×(x,y,confidence) → person tracker → valid pose history → rapid posture/descent candidate → low posture + low motion confirmation → один episode. Ожидаемый output **[1,56,8400]**, а не84/85: 4+1+51; actual graph не экспортирован. Нос, плечи, таз/лодыжки — наблюдаемые точки, не медицинские параметры. Движение сравнивать в original-frame coordinates с нормировкой на недавнюю высоту человека и ΔPTS; per-frame bbox normalization может уничтожить снижение тела.

**Минимум → сильнее:** один pose CNN+host rules → опубликованный 30-observation TSSTG reference. TSSTG не выбран как обязательный route: W1-01 установил checkpoint link404, неполную root license и legacy stack. Своим GET S09 подтверждена реальная последовательность вызовов; это не download-and-run. Замена AlphaPose на YOLO с 17 joints требует удаления/перестановки joints и проверки distribution shift. Learned classifier не освобождает от post-fall visibility/low-motion state.

**Smoke R2:** (1) exact pose export + raw output parity на 10–20 фиксированных кадрах, затем compiler/device; (2) один разрешённый staged fall с pre/post history и один squat/sit/repair-lying clip; (3) fall+still → одна карточка, fall+recovery → без low-motion escalation; (4) лежащий двигает руками, человек скрывается, camera starts already lying, ID switch — отдельные controls; (5) измерить onset→candidate→confirmation, valid observation duration, event FP/FN/unknown. **Стоп:** нет support 56-channel/keypoint head, нет наблюдаемого перехода/достаточной видимости либо parity нарушен. Fallback bbox может называться low-posture observation, не тем же качеством «падение+неподвижность». Сознание не оценивается.

## R3 — Forklift/person → class-aware tracks → moving-machine proximity

Source S08 для weights, S06/S07 как host references; W1-03 отдельно дал проверенный homography speed example. Baseline checkpoint исторически ultralytics8.0.21+ultralyticsplus0.0.23; не смешивать его вслепую со средой официального v8.3.0. Source export path этой версии: [engine/exporter.py](https://raw.githubusercontent.com/ultralytics/ultralytics/v8.0.21/ultralytics/yolo/engine/exporter.py) — адрес/разбор передан W1-03, повторное открытие здесь не выполнено.

**Путь:** fixed-camera BGR video + PTS → RGB BCHW640 → two-class NN **на LinQ** → host decoded detections/NMS → verify names (ожидается0 forklift,1 person) → раздельная association по классам → forklift image/floor motion gate → person anchor↔forklift footprint/опасная область → temporal proximity episode на **паре IDs** → одно событие. Ожидаемый dense output **[1,6,8400]**, архитектурный вывод, actual model.names/output проверить. Для bbox-only варианта расстояние до проекции bbox/расширенной области — явно 2D proxy. Центры далеко по высоте могут давать неверное расстояние; bottom-center погрузчика тоже не всегда физический footprint.

**Минимум → сильнее:** image-plane proximity + confirmed forklift movement → floor homography, измеренный footprint, relative velocity/TTC. TTC без calibration/quality/trajectory history не обещать. Из generic distance example S07 берём только метод обращения к IDs/overlay, а не готовую оценку безопасности.

**Smoke R3:** (1) resolve rights и checkpoint version, hash, load names, export6-channel, CPU→LinQ raw parity; (2) stationary forklift+near person, moving forklift+far person, moving forklift+near person; (3) взаимное перекрытие, forklift/person ID-switch, движение камеры, выход одного объекта; (4) один alert на непрерывное сближение пары, reset после устойчивого separation; (5) сравнить pixel and calibrated distances на контрольных точках пола, если заявлены метры. **Стоп:** модель/сервис выдаёт только person, нет временного доказательства движения техники, неустойчивые IDs, не решены права weights. Fallback fixed polygon полезен, но исходный moving-machine scenario им не закрывается.

## R4 — COCO person/phone → assignment + walking/work context

**Минимальная нейрочасть повторно использует R1**, class0/person и67/cell phone из S05; вторую сеть не добавлять до подтверждения необходимости. I/O/export/лицензии как R1. S03 — точный ORT code path, который позволяет изолированно сравнить raw/decoded outputs до event rules. Нужно явно выбрать единый preprocessing; phone bbox мало и особенно чувствительно к resize/квантизации.

**Путь:** LinQ detector → host class-aware NMS → person tracks → phone-to-person assignment (overlap/дистанция, конфликт нескольких людей→unknown) → видимая use evidence + движение того же человека или явно заданный рабочий контекст → concurrent temporal condition → episode. Phone in bbox ≠ использование; phone held at hip ≠ texting; person внутри work ROI ≠ доказанная выполняемая работа. Честный scope: «возможное использование видимого телефона при передвижении», с review, только если дополнительные признаки/контроли дают разумное различие.

**Сильнее:** pose hand/ear proximity или HOI talk_on/text_on/read, но это вторая NN/больший compiler risk, и hand-near-face не доказывает телефон. UPT из W1-04 не предпочитается: exact artifact download/экспорт не установлен, другая input normalization и пары proposals. В этой ветке его доступность повторно не подтверждалась.

**Smoke R4:** (1) parity полного outputs и отдельная small-phone subset до/после quantization; (2) свой near-camera staged пакет: ходьба+телефон перед лицом, ходьба+телефон в кармане, неподвижный разговор, телефон в руке у бедра, рация/сканер/бутылка, phone у соседнего человека; (3) phone-use и walking должны пересекаться по PTS, а не просто когда-либо встречаться в track; (4) disappearance телефона не должно немедленно разрешать новый дубликат при следующей детекции; (5) confidence/visibility unknown отдельно от no-phone. **Стоп:** на целевом масштабе телефон не обнаруживается, assignment неоднозначен, detector-only выдаётся за use, нет grounded work context. Fallback person tracks сохраняет infrastructure, но не phone violation.

## R5 — Fire/smoke NN → forbidden-zone rule → region episode; smoking rejected

**A, минимальный:** nano checkpoint rabahdev S11, exact revision/hash/HEAD above. Source inference/export через Ultralytics, но exact package checkpoint сначала инспектировать: модель card не является environment lock. Publisher mapping **0 smoke,1 fire** (передано W1-05; подтвердить model.names). RGB fixed640 FP32, dense output предположительно[1,6,8400], host NMS/undo-transform. Ограничение программы — видимый огонь вне явно заданной разрешённой зоны; smoke отдельно именовать smoke, не подменять fire.

**B, сильнее воспроизводимость deployment:** R3-E6 release S13–S17 уже предоставляет ONNX + hashes + exact export, equivalence и CPU-stage timing paths. Classes **0 Fire,1 Smoke**, наоборот A. Fixed **[1,3,768,768]** FP32; ожидаемый output при обычном two-class head[1,6,12096] — лишь архитектурный вывод, реальная metadata и operators не прочитаны. На LinQ требуется именно detector graph; reference ORT CPU code заменить device call, сохранить letterbox/class-aware NMS/coordinate contract. Опсет17 и большая768 сеть могут оказаться хуже nano для данного compiler. Сначала права и compiler inspection; 44.8MB ONNX доступен по HEAD, но ещё не compiled.

**Путь события:** region detections → temporal spatial association/IoU+zone (личный ID не нужен для пламени) → persistence + forbidden-zone intersection → open incident → updates без новых сообщений → sustained disappearance→close. Не считать каждое меняющееся smoke/fire bbox новым человеком/событием; smoke plume растёт/распадается. Fire и связанный smoke могут быть одним episode, а два удалённых очага — разными. Hysteresis и overlap rules — проектные, требуют controls.

**Smoke R5:** (1) resolve license/metadata/hash, actual names and ONNX I/O; A export либо B published ONNX; (2) CPU and LinQ parity на одинаковых tensors, не переносить готовую publisher CPU equivalence на device; (3) разрешённые изображения/записи flame, smoke-only, пар, пыль, блики/солнце, сварка, жёлтая одежда/экран с огнём; (4) одинаковый видимый fire inside allowed vs outside; (5) один sustained episode, короткая детекционная дыра, два очага, исчезновение и новый очаг. Для видео не создавать опасный огонь ради теста: разрешённый существующий материал либо контролируемая безопасная имитация с честной маркировкой. **Стоп:** неизвестные права/артефакт, false positives на сварке/steam, неподдержанный output6/opset17, контекст зоны не задан. Ни A, ни B **не обнаруживают курение**.

**Smoking rejected как готовый route:** cgr reference S12 полезен как пример pose/crop/evidence counter, но неполон по paths/weights/backend contract. W1-05 установил metadata `last.onnx` с untrained description; это не является доказательством плохого/хорошего качества, зато блокирует молчаливое принятие происхождения. Hand-to-mouth, fire bbox, smoke cloud не заменяют cigarette/use evidence. Нужна отдельная проверенная поставка до включения smoking в основные сценарии.

## Общий LinQ gate и fallback без подмены условий

Это **предложение**, не установленный API. Сначала получить exact device/compiler/runtime/target, доступ, model catalog, допустимые операторы/opset/static shape/layout/precision, где preprocessing/NMS, proof выполнения. W1-13 описывает эти пробелы. Объявить уровни: `source inspected` → `weights available` → `host inference pass` → `ONNX parity pass` → `compile pass` → **`device inference/parity/timing pass`** → `event controls pass`. Ни один предыдущий уровень не сокращает последний.

| Условие выданной среды | Разумное действие | Что нельзя заявить |
|---|---|---|
| Custom ONNX разрешён | Проверить сначала один graph; собственный preprocess/calibration, compiler log, `.tpu`/иной реальный artifact, runtime proof | ONNX200 или ONNX checker≠LinQ PASS |
| Есть только catalog detector | Его exact classes/I/O/hash/license → сценарий с этими признаками; host rules/tracker | Название YOLO family≠наличие phone/forklift/pose |
| Поддержан только YOLOv5s/tinyYOLO3 | Взять **реальный** разрешённый checkpoint/catalog artifact и его собственный decoder; source NN адаптер заменить, event layer оставить | Старый85-objectness decoder не применим автоматически к v8(84/56/6); не выдумывать доступность custom heads |
| Pose/head56 не поддержан | Перейти к подтверждённому detector и другому сценарию, если он пригоден | bbox лежащего человека≠полная замена fall+low-motion |
| Собственный forklift/fire graph blocked | Catalog эквивалентных классов либо убрать соответствующий исходный сценарий; технический zone demo маркировать отдельно | Generic polygon≠moving-machine/phone/smoking violation |
| Реального device/service execution нет | Продолжать host reference и event research, отмечать BLOCKED_DEVICE, запросить рабочий baseline у организаторов | CPU/GPU/mock/записанная vendor demo≠обязательный LinQ inference |

Если API отдаёт уже NMS boxes, не выполнять второй неизвестный decoder; если raw logits — не считать их финальными detections. Нужен manifest реальных выходов и class map. Выходы должны включать нужные channel counts: 84/85-only adapters для 6/56 не подходят.

**W1-16-F07 [передача W1-14, не самостоятельный новый GET]:** после завершения его проверки [W1-14.md](W1-14.md) оркестратор передал exact `linq-cv-bench` commit prefix `3ad1b7`: builder строки 222/261 берёт первый output, runner176–183 рассчитан только на84/85; строка206 содержит Unicode-опечатку имени args. Это ограничения **конкретного примера**, не запрет LinQ на другие heads. Для R2/R3/R5 адаптеры надо проверить/заменить отдельно; R1/R4 также не освобождены от parity и исправления runner. Публичный пример с непригодным decoder не позволяет сделать вывод, что сам accelerator не компилирует модель. Полный immutable SHA/первичные локаторы брать из W1-14; здесь префикс сознательно не выдаётся за полный hash.

## Событие, dedup и минимальная проверка целого маршрута

Предложенный общий state machine: `CLEAR → CANDIDATE → OPEN → RECOVERING → CLOSED`; отдельно `UNKNOWN` по видимости/качеству/обрыву потока. Подтверждать по valid observed PTS-duration/k-of-n с параметрами камеры; prediction-only Kalman frames не копят доказательство. Exit threshold мягче entry для hysteresis. Вход в OPEN создаёт persistent event_id один раз; дальнейшие кадры обновляют evidence/duration/quality. Смена локального track ID не обязательно новое нарушение: осторожный space/time merge, без объединения соседних людей. Reset требует наблюдаемого прекращения условия и отдельного refractory interval. Lost track/stream error не означают безопасный исход.

Event key: R1/R2/R4 `(camera,rule,person episode)`; R3 `(camera,rule,person episode,forklift episode)`; R5 `(camera,rule,spatial incident episode)`. Dedup только по class/time cooldown склеит независимые инциденты; только по local ID создаст дубли после ID-switch. Закрытые события/идемпотентность записи должны переживать UI refresh/retry. Это design, не существующая функция прочитанных demos.

Минимальные сохраняемые поля: source PTS/onset/confirm и wall clock отдельно, camera/zone/rule_version, stable event_id, local track/pair IDs, наблюдаемые признаки+quality/unknown reason, snapshot/pre/post evidence, model URL/revision+SHA256, ONNX/compiled hash, actual input/output contract, runtime/device/precision, status. Representative frame без prehistory не объясняет бег/падение/движение техники. Нужен prebuffer и достаточный postbuffer; максимальный clip размер/retention задаёт команда.

Общий smoke procedure перед выбором двух–трёх сценариев:

1. Зафиксировать маленький legal video/image пакет и development/held-out controls, timestamps/fps/resolution, hashes. Для временного нарушения single screenshot лишь проверка NN, не event test. Использовать свои staged записи с согласием; права данных/видео не следуют из code/model license.
2. Exact weights и environment lock; inspect model.names, actual exported ONNX input/output/ops, static shape, normalization, transform, decoder/NMS. Для custom heads не наследовать COCO assumptions. Не запускать benchmark на всей коллекции.
3. На тех же сохранённых tensors PT→ONNX CPU→реальный LinQ сравнить raw outputs и decoded detections/keypoints; tolerance определить до просмотра итогов. Проверить non-square original images и границы зон. INT8 отдельно проверить на small objects/ключевых temporal признаках.
4. Прогнать целые короткие clips с предложенными controls и deliberately dropped/gapped frames; проверить once-per-episode, reset/re-entry, two simultaneous events, unknown, no phantom alerts on retry. Event-level TP/FP/FN/late/duplicate/unknown и false alerts на время negative видео; не только frame mAP.
5. Сохранить реальные device logs и timings: warmup/cold, device inference p50/p95, transfer/pre/post/track/rules/storage/UI, end-to-end source-age/alert delay, sustained throughput/queue/drop policy. Выделить file playback и live capture; не переносить CPU/RTX published FPS на LinQ. Именно эта проверка решает Go/No-go, а не наличие exporter.

## Что отказано, что неизвестно и передача

**Отказано как готовое end-to-end решение:** time-in-zone без continuous episode reset; centroid pixel-distance как safety distance; TSSTG с недоступным checkpoint как критический путь; smoking cgr как готовая воспроизводимая поставка; детекция phone без action context; видимый smoke как smoking; generic zone как незаметная замена исходного сценария. **Оставлены:** R1 infrastructure/fallback, R2 условный fall candidate, R3 условный proximity, R4 узкий phone reserve, R5 visible fire reserve.

**Наблюдено здесь:** exact raw source availability/code paths, отдельные несовместимые preprocessing contracts, неполный timer reset, custom channel obligations, direct artifact HEAD sizes, HF revision/LFS fire metadata, new fire release/tag/source/scripts/hashes. **Заявлено издателями:** training datasets, model metrics и environment snapshot, license policy; не воспроизведено. **Выведено:** ожидаемые raw shapes, proposed adapters/temporal FSM/controls/приоритеты. **Неизвестно:** actual graph metadata/locally hashed weights, custom model runtime load, все LinQ compiler/device свойства и скорость, качество на заводских камерах, event thresholds, все отдельные video rights, standalone weights license forklift/R3-E6.

Передача соседям:

- W1-14/15 и model-stack: проверить6-channel forklift/fire и56-channel pose наряду с84/85 COCO; сохранить все outputs и не hardcode first output; actual preprocessing/precision. Новый R3-E6 exact ONNX — кандидат на graph inspection, но права и opset17 остаются gate.
- W1-03: distance_calculation generic reference только pixel centroids; motion gate/footprint и pair lifecycle обязательны. Forklift weights rights остаются нерешены.
- W1-01/02: pose tracker reorder и valid observation timestamps; TSSTG 30 observations не автоматически30 одинаково spaced frames после dropped sampling. Running требует gait evidence или явно ограниченного proxy.
- W1-04/05: раздельные mappings: COCO person0/phone67, rabah smoke0/fire1, R3-E6 fire0/smoke1. Разные code/version licenses; smoking repo paths/backend mismatch; R3-E6 новые export/parity sources и live HEAD200 доступны.
- Evaluation/video architecture: re-entry timer, ID-switch dedup, PTS vs clock, pair/spatial incident identity и source-age latency включить в smoke. Собрать legal positive/negative короткие clips, не разворачивать большой benchmark.

**Решающая развилка:** фактический LinQ output contract и один успешный измеренный реальный inference. До него невозможно честно выбрать победителя по «скорости на LinQ»; после него пятичленная карта routes позволяет быстро оставить только те исходные нарушения, для которых присутствуют признаки, права, данные и temporal event evidence.
