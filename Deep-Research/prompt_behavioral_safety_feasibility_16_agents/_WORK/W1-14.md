## Вопрос и решение

Какая конкретная цепочка checkpoint → экспорт → frontend → quantizer → compiler → runtime имеет достаточные основания для первого LinQ smoke-test, и где семейное имя скрывает несовпадающий tensor contract?

**W1-14-F01. Ни один конкретный checkpoint этой ветки не установлен как compiled/accelerator-measured.** Вендор публично называет yolo8/yolo11, но это уровень `vendor family named`. Даже строка pose в презентации LinQ2026, о которой отдельно сообщает W1-15, не определяет ни `yolov8n-pose.pt`, ни RTMPose-t. Готовый ONNX — следующий, отдельный уровень, а не совместимость с LinQ.

**Практический порядок:** сначала точный выданный vendor golden для проверки доступа, затем один собственный static FP32 detector без embedded NMS; после доказанного frontend/PTQ/device path — pose. RTMPose-t opset11 полезен как готовый экспорт, но требует двух выходов и правильного crop preprocessing. YOLOv8n-pose сокращает число сетей, но её 56-channel head не проверен как LinQ artifact. Smoking opset19 и SafetyVision opset20 — готовые ONNX, но более рискованные frontend-кандидаты; низкий номер opset сам по себе не гарантия совместимости.

**W1-14-F02. Публичный готовый YOLOv8 runner нельзя напрямую использовать для наших custom моделей:** он допускает только 84/85 каналов, тогда как smoking даёт7, SafetyVision ожидает17, pose ожидает56. Builder по умолчанию выбирает только первый graph output, поэтому RTMPose с `simcc_x` и `simcc_y` требует явной доработки. Эти ограничения — ограничения примера, **не установленная неподдержка LinQ**. [S03, S04]

| Model compiled | В этой ветке отсутствует | Поддержка всех ops/shapes на выданном SDK |

Условия кейса требуют реальный нейроинференс LinQ с замерами, одно сообщение на нарушение, журнал и GUI/web. Разделение NN на LinQ, decode/NMS/tracking/rules на host — **условная архитектура**, пока организатор не подтвердил допустимую границу вычислений и критерий доказательства. Отсутствие SSH не означает невозможность выполнения, если сервис предоставляет exact model lifecycle и убедительный completion evidence.

## PTQ и runtime: что известно и что требуется

**W1-14-F03.** FP32 внешний тензор не означает FP32 TPU арифметику; int8 железо не определяет внешний dtype. Нужны user↔raw rescale, scales/zero-points, signedness, per-channel/per-tensor, accumulator precision и output dequantization для exact release. FULL/RAW — имена режимов исторического pytpu, а не универсальный bool «float/int8». Текущая ABI и semantics не проверены; исторический пакет15.0.24 не объявлять matching Runtime16.18.6.

Публичный builder свидетельствует о vendor PTQ на исходном floating graph через TF, не о поддержке готового ONNX QuantizeLinear/DequantizeLinear/QAT. Не готовить QDQ как гарантированный обход. Graph import должен пройти прежде выбора calibration thresholds. Guide2025 по соседнему research описывает data-dependent calibration; scope `percentile` и математическая формула не установлены. Не выдавать percentile100 за доказанный max(abs activation).

Calibration для каждого graph/preprocessing отдельно: репрезентативные разрешённые кадры из целевых камер, маленькие люди/телефоны/сигареты, фон, свет/пыль/окклюзии; для top-down pose именно crops с тем же affine/normalize. Сохранить список/hash и фактическое число; calibration и evaluation разделить по видео/эпизодам. 100/500 — варианты бюджета, не доказанная достаточность. Изменение состава/percentile сравнивать по одному после float parity. Fail-closed на TypeError вместо blanket retry, записать requested/effective arguments и thresholds, если API разрешает. На экспортной ветке не начинать QAT до доказанного PTQ bottleneck и supported import path.

## Smoke-test plan — не выполнен

1. **Получить matched environment.** У организатора exact image digest/wheels, framework/compiler/runtime/native/driver/firmware, hardware target, разрешённую NN boundary и выданный golden. Выданный vendor `.tpu` сначала проверяет доступ, не custom model feasibility. Зафиксировать actual operator/opset/IR/shapes/batch API docs. Сайт/guide2025/current benchmark environment не склеивать в одну установку.
2. **Freeze model manifest.** URL+revision checkpoint, exporter code/torch/onnx/onnxslim версии, fp32/static1, layout/names/nc/classes, все outputs, expected geometry. Для первого своего YOLO detector candidate opset13,nmsFalse,dynamicFalse,halfFalse,batch1,imgsz640; opset13 выбран по S02 sample, не по установленному лимиту LinQ. Сначала simplifyFalse; simplification отдельно сохраняет hash/ops/parity. Для pose pin свой exact экспорт, не копировать detection artifact.
3. **Structural gate.** Полное разрешённое скачивание выбранного малого артефакта в будущем; SHA256 сравнить с manifest, external data проверить, ONNX checker/shape inference и полный domains/opset/IR/node attrs/types inventory. Никакой ручной смены opset/IR. Для RTMPose должны сохраниться оба outputs; сделать настоящий static export/специализацию, если SDK требует, а не только header edit.
4. **Float golden.** Три одни и те же подготовленные реальные inputs: positive, hard negative, geometric/channel diagnostic. PyTorch/exported ONNX compare raw outputs с записанными max/mean error и task-level tolerance; exact decoder/NMS affine/letterbox inverse проверять отдельно. Не назначать универсальный numerical epsilon без масштаба output. Нулевой/random input полезен для plumbing, но не качества.
5. **Frontend gate.** На выданной версии импортировать ONNX с явными input/output names, сохранить TF mapping и float outputs если доступно. First unsupported node/domain/opset/attribute — точный diagnostic packet; не делать unlimited fallback по names. `output_nodes` включает оба SimCC outputs, pose channels не отбрасываются. Только успешный import всего graph даёт следующий gate.
6. **PTQ gate.** Калибровать тем же preprocess; сравнить imported float→quantized software golden на task metrics. Сохранить effective API/thresholds/.qm hash и save→load parity. Для pose отдельно оценивать joint coordinate/confidence drift, для cigarette recall малых объектов, для No_Harness false absence при окклюзии. Score thresholds после PTQ фиксируются на tuning set, holdout не подбирает параметры.
7. **Compile gate.** compile batch1 для exact target/preset из поставки; сохранить log, partition/coverage report, graph hash, `.qm`→`.tpu` provenance, tensor descriptions. Успех compile не доказывает отсутствие host fallback и не даёт FPS. Не переключаться наbatch8 до batch1 parity и разрешённых quotas.
8. **Device gate.** Один реальный вход, completion/log/device identification, output copy после completion, сравнение software quantized↔device с exact user/raw contract. Затем конечные positive/negative кадры. FPS отдельно после warmup, cold load отдельно; end-to-end decode/preprocess/queue/inference/NMS/event delay отдельно. `1/FPS` не latency, targetQPS не achievedQPS. Сохранить rejected/stale/drop counts.
9. **Event gate, условно host.** Per-camera/model-version track IDs и timestamps; episode подтверждается по времени, не по числу кадров при пропусках. Для падения нужен переход+низкая поза+неподвижность с controls sitting/lying/work/occlusion; для smoking — person↔cigarette association+zone+temporal persistence с controls телефон/еда/пар; для техники — motion и геометрия, не один bbox. Конкретные hold/cooldown выбрать по размеченному видео, не объявлять2–3s требованием SDK. ACTIVE эпизод даёт один event ID; loss track не мгновенный rearm; exit/clear с hysteresis. Неподвижность не потеря сознания, No_Harness не доказанное отсутствие подключения.

## Кандидаты, отказы и handoff

- **Оставить на первом gate:** официальный detector static640 и поддержанный vendor golden; detector покрывает person/phone/геометрию, не весь behavioral event.
- **Два взаимоисключающих pose пути:** YOLOv8n-pose после собственного graph export либо RTMPose-t после two-output/crop adapter. Не строить одновременно оба до первого успешного compile; число людей влияет на crop-wise latency RTMPose.
- **Smoking/SafetyVision только conditional:** наличие готового ONNX экономит export, но opset19/20 и custom channels требуют собственного adapter. При import block можно повторно экспортировать exact checkpoint на согласованном opset и сравнить numerics; это новая artifact lineage, не downgrade header.
- **Отложить:** PoseC3D, recurrent/transformer action, integrated NMS, dynamic variable-T/multi-person batch до подтверждённой compiler matrix. Не объявлять unsupported: просто нет достаточного evidence для critical path.
