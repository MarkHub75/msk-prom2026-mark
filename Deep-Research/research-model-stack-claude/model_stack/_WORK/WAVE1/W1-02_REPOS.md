## FLASH (находки, важные соседям)

1. **Ultralytics 8.4.184 (последний, 2026-10-22) несовместим по CLI/семантике с большинством гайдов 2024–2025.** `half`/`int8` заменены на `quantize` (с 8.4.80), `end2end` заменён на `nms` (с 8.4.142), причём теперь **по умолчанию `nms=None` = НЕ NMS-free**: даже для YOLO26 экспорт без `nms=False` даёт one-to-many голову, требующую внешнего NMS (W1-02-F06, F07). Команды экспорта нужно фиксировать вместе с версией пакета. → linq_platform, evaluation, training_strategy.
2. **«yolov5s» в LinQ неоднозначен минимум трёхсторонне**: (а) `ultralytics/yolov5@v7.0` — anchor-based, выход `(1,25200,85)` [xywh, obj, cls]; (б) `yolov5su` в пакете ultralytics — anchor-free, split-голова как у YOLOv8, выход как `(1,84,8400)`; (в) master `ultralytics/yolov5` сегодня **зависит от пакета `ultralytics>=8.4.164`**, а в README его 640-px строки ссылаются на anchor-free YOLOv5u. Для воспроизводимого anchor-based «yolov5s» брать только tag `v7.0` (commit `915bbf294bb74c859f0b41f1c23bc395014ea679`) и веса из релиза v7.0 (W1-02-F12..F15). → linq_platform: спросить, какой из трёх подразумевает `yolo5s` на lin-q.ru/tech. Также у Hailo Model Zoo `yolov5s` — вообще v2.0-era `yolov5s_spp` (F31).
3. **Прецеденты NPU сходятся на одном приёме**: вырезать постобработку (DFL-decode, декодирование боксов, конкатенацию box+cls) из графа, оставляя сырые выходы голов (Rockchip, SOPHGO, Qualcomm, Hailo), потому что смесь диапазонов (пиксели vs [0,1]) мешает квантованию. Это гипотеза-кандидат для LinQ, **не доказательство** (F26..F32). Ultralytics 8.4.184 сам не делает этого в основном ONNX-пути (для Hailo он режет граф по именам узлов `.../cv2.i/.../Conv`, `cv3...`, F31).
4. **YOLO26** (ultralytics ≥8.4.0, 2026-01-14): `reg_max: 1` (DFL нет), `end2end: True`, NMS-free one2one голова; нативный RKNN-экспорт в 8.4.184 принудительно отключает end2end (F08). YOLO27 — только анонс «Coming Soon», моделей нет (F04). LinQ заявляет yolo5s/yolo8/yolo11, YOLO26 в списке нет (из CONTEXT §2).
5. **Ultralytics-чекпоинт = pickle полного nn.Module** (ключ `ema`), загрузка по умолчанию `weights_only=False` (F10): весь чужой `.pt` — недоверенный код, и модуль привязан к версии пакета (YOLOX #1906 и yolov5 v7.0: `torch.load` без `weights_only` ломается на torch≥2.6 — F17, F13).

## Резюме для оркестратора

- Зафиксировано состояние всех сильных реализаций (см. реестр §6.1): для каждой есть owner, tag/commit, дата, статус сопровождения и полезные пути.
- Главный стек для воспроизводимости: `ultralytics` **8.4.184** (commit тега `f7dd275e5853801674ca78ef51896617bb5362ba`, PyPI 2026-10-22) для YOLOv8/YOLO11/YOLOv5u/YOLO26; но для сравнения с историческими рецептами нужен ряд «старых» версий (8.0.x для YOLOv8-эпохи Hailo-зоопарка, 8.3.x для YOLO11, 8.3.9/8.2.82 для Rockchip-форков). Версии в разных источниках смешивать нельзя: поведение экспорта (opset по умолчанию, `quantize`, `nms`, end2end) менялось ≥4 раз (F05–F10).
- Для anchor-based «yolov5s» — только `ultralytics/yolov5@v7.0`; master yolov5 — по сути надстройка над пакетом ultralytics (F13, F14).
- Сопровождение: YOLOX заморожен с 2025-06 (последний tag 0.3.0 от 2022), открыты numpy2/torch≥2.6 проблемы (#1904, #1906); mmdetection/mmyolo фактически не развиваются (последние коммиты main 2024-02 / 2023-08); TF OD API объявлен deprecated (README); PaddleDetection 2.9.0 (2026-03-19) живо; torchvision 0.29.1 живо; RT-DETR/D-FINE/DEIM/RF-DETR живы (2026).
- Лучшие NPU-прецеденты (в порядке пользы для нас): `airockchip/ultralytics_yolov8|yolo11` (минимальный патч Detect.forward), `qualcomm/ai-hub-models` (патч головы под int8 + пин `ultralytics==8.4.45`), `sophgo/tpu-mlir` (`output_names` = обрезка по именам узлов), `hailo_model_zoo` (`.alls` + sigmoid на выходных conv + NMS на CPU).
- Главные разрывы: что именно LinQ называет `yolo5s`/`yolo8`/`yolo11` (репозиторий, версия, голова); принимает ли компилятор LinQ вырезанные/мульти-выходные графы, какой opset; влияет ли SiLU (Rockchip-fork yolov5 заменил на ReLU при переобучении — F28). Всё это — только на SDK LinQ (→ linq_platform).
- Запрос эскалации: построчный анализ различий графа между `airockchip/ultralytics_yolov8` (8.2.82) и ultralytics 8.4.184 и перенос приёма на YOLO11/YOLO26 (см. §10).

## 4. Цепочки версий и риски смешения (разбор)

1. **Ultralytics внутри одного major.minor ломает интерфейс.** Три границы: 8.4.80 (`half/int8`→`quantize`), 8.4.142 (`end2end`→`nms`, смена дефолта), и ранее 8.4.8 (появление `end2end`). Скрипты/команды из ноутбуков до этих версий будут молча делать иное (например, `half=True` — deprecated-alias; `end2end=True` — alias на `nms=False`). Фиксировать: `pip freeze` + `ultralytics.__version__` + полную команду экспорта + хеш `.onnx`.
2. **Opset по умолчанию не зафиксирован** — функция от (ultralytics, torch, onnx) — F07. Всегда `opset=` явно (проверить выбор после того, как linq_platform назовёт допустимые).
3. **Чекпоинт ↔ код**: `.pt` содержит pickled-модули (F10); загружать только тем пакетом, на котором обучали или более новым, проверенным; `train_args`/`version` внутри чекпоинта — это источник истины для версии (читать через распаковку zip без unpickle — `py -I -m zipfile -l`; поле `version` лежит внутри pickle, поэтому без загрузки оно недоступно — разрыв).
4. **«yolov5s»**: три различных объекта (FLASH 2). Для каждого — свой вход/выход/голова; сравнивать только внутри одного.
5. **YOLO26**: end2end/NMS-free по умолчанию в yaml (`end2end: True`, `reg_max: 1`), но дефолтный экспорт 8.4.184 → one2many (F06). Для NPU-путей дополнительно auto-disable end2end (F08).
6. **Рекомендуемый вариант единого окружения для сравнения «яблок с яблоками»**: одна версия пакета `ultralytics==8.4.184` + явные `opset`, `nms`, `quantize`, `dynamic=False`, `simplify` (на выбор), и отдельные окружения для `yolov5@v7.0` и YOLOX 0.3.0. Все три — разные venv (SCRATCH).
7. **Fork Rockchip отстают на 2 года** от пакета (8.2.82 / 8.3.9): применять как справочник по приёму, а не как рабочий код для 8.4.184 (Detect изменился: dict-вывод, `forward_head`, `one2many/one2one` — F-источник head.py @8.4.184).

## 5. Противоречия

- **C1** README yolov5 master и релиз v7.0: ссылки «YOLOv5s» открывают anchor-free YOLOv5u (F14) vs релизный v7.0 `yolov5s.pt` anchor-based. Влияет на то, какую голову ожидает компилятор LinQ. Разрешение: спросить linq_platform/выяснить на устройстве; до тех пор готовить оба варианта.
- **C2** Релиз-ноты 8.4.0 («native end-to-end NMS-free», «eliminates the need for NMS») vs 8.4.142+ дефолт `nms=None` (внешний NMS). Не противоречие по версиям, но по ожиданиям пользователей: условия — версия и значение `nms`.
- **C3** Ultralytics-путь RKNN (ONNX с сохранённым decode, нормализацией координат для INT8) vs Rockchip-fork (вырезан decode, DFL, score-sum). Разные приёмы под один NPU; какой из них применим к LinQ — не установлено.
- **C4** Qualcomm `head.end2end=False` («not seen good results») vs Axelera-путь Ultralytics (runtime декодирует NMS-free голову). Показывает, что end2end на NPU — вопрос конкретного toolchain.

## 8. Передачи соседям

- → linq_platform: (а) что значит `yolo5s`/`yolo8`/`yolo11` — репозиторий/версия/голова; (б) допустимые opset; (в) принимаются ли многовыходные/обрезанные графы и какие операторы (Resize, Concat, Sigmoid, Softmax, TopK, NMS, SiLU/HardSwish); (г) pin на версию torch/onnx компилятора.
- → training_strategy: если окажется, что SiLU не поддерживается, прецедент — Rockchip `yolov5` fork с ReLU «только при переобучении» (F28); YOLO26 без DFL (reg_max=1) проще для экспорта; QAT появился в ultralytics с 8.4.143 (`quantize=8` при train, релиз v8.4.143).

- → video_architecture: форма выхода и необходимость внешней постобработки (NMS на CPU) зависят от версии/опций (F06, F09).
