## FLASH

1. **`cls_remap: True` по умолчанию (с v8.4.91)** — при fine-tune с предобученных весов строки cls-head копируются **по совпадению имени класса** (lower/strip) с `names` предобученной модели (`tasks.py` L382). Следствие для PPE: класс `Person` (как в `construction-ppe.yaml`) или `person` в нашей разметке получит инициализацию от COCO-строки `person`; класс `helmet` — от ничего (COCO его не имеет). До v8.4.91 cls-head при совпадении `nc` копировался **по позиции** (потенциально чужие строки). → training_strategy / W1-07.
2. **`names` в ONNX-метаданных хранится строкой Python-dict (`str(dict)`)**, читается `ast.literal_eval`; графы без этих метаданных (например, head-stripped ONNX соседа W1-10) **не несут имена классов вообще** — local_observation. Для LinQ-пайплайна имена нужно вести во **внешнем class_map-файле**, привязанном к sha256 весов. → linq_platform, video_architecture.
3. **Тихие потери данных в Ultralytics**: (a) любая плохая строка метки ⇒ выбрасывается **вся картинка** со всеми объектами (только строка лога «ignoring corrupt image/label»); (b) нет `/images/` в пути ⇒ все метки «не найдены», изображения молча становятся фоном (если вообще ни одной метки — `ValueError` только в train); (c) после аффинного преобразования бокс с видимой площадью <10 % от масштабированного исходного, либо ≤2 px по стороне, молча удаляется; (d) `iscrowd` в конвертере COCO→YOLO пропускается целиком — ignore-регионов в Ultralytics нет. → datasets.
4. **`convert_coco` по умолчанию `cls91to80=True`**: для **пользовательских** COCO-json с `category_id` 1..N даёт `coco80[id-1]`: id 1–11 → тождественно, **id 12 → `None` (падение `TypeError` при записи)**, id ≥13 → **сдвиг на −1** (если ни одной аннотации с id 12 нет — сдвиг молчаливый). Для своих данных всегда `cls91to80=False` и категории 1-based: при `category_id == 0` (например супер-категория в некоторых COCO-экспортах — hypothesis) формула даёт `-1` ⇒ при `cls91to80=False` строка `-1 …` ⇒ картинка отбрасывается как «negative label values», при `True` — `coco80[-1]` = `None` ⇒ `TypeError`. → datasets.
5. **Версионные ловушки в проверках меток** (бисекция тегов, см. W1-08-F09): до **v8.3.66** `assert max_cls <= num_cls` (класс `== nc` проходил проверку и ломал обучение позже); строгое `points.max() <= 1` до **v8.3.163** (с него допуск 1.01); отрицательные размеры бокса отвергаются с **8.4.182**. Если LinQ-стек/команда пинит 8.3.x, проверки слабее.
6. YAML 1.1: имя класса `no`/`yes`/`on`/`off`/`null` в `data.yaml` без кавычек превращается в `False`/`True`/`None` и затем в **строки `'False'`/`'True'`/`'None'`** (local_observation, PyYAML 6.0.3 + логика `check_class_names`). Русско/англо-названия вида `no_helmet` безопасны (подчёркивание).
7. Относительный `path:` в `data.yaml` Ultralytics разрешает **относительно CWD** (затем `DATASETS_DIR`), не относительно папки yaml (`utils.py` L~790). Roboflow-экспорт `train: ../train/images` обрабатывается специальным fallback `data[k][3:]` (L799). `download:` в чужом yaml исполняется через `exec()` (L828) — не открывать недоверенные yaml.

## Резюме для оркестратора

Путь индекса класса и координат в Ultralytics v8.4.184 прослежен полностью: `labels/*.txt` (`cls xc yc w h` нормировано, класс 0-based) → `verify_image_label` (отбрасывает целиком картинку при любой ошибке) → кэш `labels.cache` (хеш пути/размер/mtime + `nc`) → `YOLODataset.get_labels` → `get_image_and_label` (`load_image`: длинная сторона → `imgsz`, `cv2.imdecode` **применяет EXIF**) → Mosaic (канва 114, denormalize по ресайзнутой картинке, clip, удаление нулевой площади) → `RandomPerspective` (афин. матрица, `box_candidates`) → MixUp/CutMix → Albumentations → HSV → flip (класс не меняется!) → `Format` (xywh нормировано относительно итогового кадра, BGR→RGB, uint8 CHW) → `/255` в `preprocess_batch` → loss. `nc`/`names` берутся из `check_det_dataset` (dict int→str, `nc := len(names)`), кладутся в `model.names` (`detect/train.py` L139-143), в `.pt` пиклятся внутри модуля (`yolo11n.pt` — local_observation: 80 COCO-имён внутри pickle), в ONNX уходят `str(dict)` в `metadata_props`, `AutoBackend` возвращает `ast.literal_eval`; `Results.names` = `model.names`.

Главные разрывы/риски (все закрываются проверками до обучения): (1) слияние датасетов с разным порядком `names` — Ultralytics **не проверяет** и не ремапит (кэш хранит только индексы); (2) тихие потери (см. FLASH 3); (3) COCO-конвертер и 1-based id; (4) EXIF/alpha/gray; (5) смена версии Ultralytics меняет строгость проверок; (6) ONNX без метаданных теряет имена. Multi-label («person» и «no_helmet» на одном объекте) формально возможен как **несколько независимых боксов разных классов** (каждый GT — отдельная строка; TAL разрешает конфликт якоря по наибольшему IoU, `tal.py` L361), но не как один бокс с двумя классами; в predict NMS по умолчанию per-class (`agnostic_nms=False`), `multi_label=False`, а в val `multi_label=True` — расхождение режимов важно для интерпретации mAP vs. демо. Ignore/crowd: в Ultralytics нет; YOLOX отфильтровывает `iscrowd` при загрузке; torchvision — только то, что подаёт пользователь.

Написан и проверен на синтетическом датасете с 12 внедрёнными дефектами **аудитор** `W1-08_files\audit_yolo_dataset.py` (PyYAML+Pillow+numpy, без импорта ultralytics, без exec) — готов к запуску на первых же данных хакатона (после получения полного кейса). Статус: «написан и прогнан на синтетике», не проверен на реальных данных.

Не установлено: как LinQ-компилятор/рантайм относится к метаданным ONNX и к формату входа (RGB/BGR, 0–1 / 0–255) — вопрос → linq_platform; какая именно реализация/версия стоит за «yolo5s/yolo8/yolo11» на LinQ — не установлено.

### 2. Цепочка «names → inference»

`data.yaml names` → `YAML.load` (SafeLoader, YAML 1.1) → `check_class_names` (`str(v)`, dict int→str) → `data["names"]`, `nc=len` → `model.names` (+`model.nc`) → EMA → `.pt` (пикл внутри модели, local_observation F20) → `Exporter.metadata["names"]=model.names` → ONNX `metadata_props["names"] = str(dict)` → `AutoBackend.apply_metadata` (`literal_eval`) → `predictor.model.names` → `Results.names`. Ветки: (а) экспортёр с `names` не знает про наши внешние class_map; (б) любой граф, полученный вне Exporter (head-stripped, кастомный экспорт, компилятор LinQ, который может отбрасывать `metadata_props` — не установлено), **не** несёт имён; (в) при нулевых метаданных фолбэк — `class0..class998`.

Рекомендованный контракт для нашей системы (inference): единый `classes.yaml` (id, name, role, `supercategory`, `pairs_with`), id фиксируются один раз; в `data.yaml` обучения дублируется; рядом с каждым весом/ONNX кладётся `class_map.json` + sha256 весов + commit Ultralytics; на этапе демо `names` читается из этого файла, а не из ONNX.

### 3. Слияние датасетов и порядок классов (Roboflow/Kaggle/своя разметка)

Ultralytics не хранит в метках имена; **единственная связь индекс↔имя — `names` в yaml**. При слиянии необходим явный ремап: `(source_yaml, old_id) → target_id` по заранее утверждённой таксономии. Не полагаться на совпадение порядка. Проверка: `audit_yolo_dataset.py DATA.yaml --compare OTHER.yaml` ловит расхождение `names`; после ремапа гистограмма классов должна соответствовать ожиданию (например, число `no_helmet` не может быть нулевым, если источник его содержал). Частые ошибки (код + локальные наблюдения): 1-based id (класс `== nc` отбрасывает изображение в ≥v8.3.66 и **проходит проверку и портит обучение** в ≤v8.3.65, F09); абсолютные пиксели (отбрасывание картинки, F03); неквадратные изображения (нормировка отдельно по w и h — ошибки нет, если нормировать по реальному размеру); EXIF-повёрнутые фото при разметке по неповёрнутым пикселям (F18); PNG с альфой и grayscale (молча → 3 канала); дубликаты строк после слияния (удаляются, но число меток падает); 6-колоночные строки с confidence (картинка выброшена); `.cache` из другого путей/копии.

### 4. Multi-label «person + нарушение»

Три варианта представления (inference по коду, не эксперимент): (1) отдельные боксы-пары: бокс `person` + бокс `head_without_helmet` на голове (малый бокс, чувствителен к фильтру ≤2 px и 10 %-му порогу площади при аугментации); (2) один бокс на человека с классом-состоянием (`person_no_helmet`/`person_helmet`) — проще для метрик, но смешивает идентичность и атрибут и ломает слияние с COCO-`person`; (3) каскад «детектор людей → классификатор атрибута» (граница с W1-13). В любом из вариантов loader видит независимые строки; конфликт якорей между перекрывающимися боксами разрешает TAL по IoU. Для cls_remap (F23): класс с именем `person`/`Person` унаследует COCO-строку, остальные — нет; это полезно как стартовая точка для `person`, и нейтрально для `no_helmet`.

### 5. Различия train / val / predict (кратко, глубоко — W1-11)

- train: `augment=True`, мозаика, аффин в `imgsz`×`imgsz` (int), `pad=0.0`, `rect=False`, RGB/uint8 → `/255`;
- val в тренере: `rect=True`, `LetterBox(scaleup=False)`, `rect_shape` по батчу, `pad=0.5`, бокс не клипуется, `multi_label=True` в NMS, `bgr=0.0`;
- predict: `LetterBox(self.imgsz, auto=same_shapes and args.rect and not scale_fill and (format=="pt" or dynamic), stride=model.stride)` (`predictor.py` L224-243), NMS `agnostic=args.agnostic_nms`, `multi_label=False`; для статического ONNX `auto` отключается — всегда квадрат `imgsz`.
Следствие: mAP из val (rect, multi_label) и поведение демо (letterbox квадрат, single label) могут давать разные цифры.

## Противоречия

1. **Документация vs код: «no txt required» vs «empty txt»**. Doc S06: файл метки не нужен для фона; код трактует отсутствие как `nm`, пустой — как `ne`; оба дают фон. Выбор формата не меняет обучение; влияет только на счётчики лога.
2. **`nc` в yaml**: Roboflow-экспорт содержит и `nc`, и `names`; Ultralytics требует совпадения длины (иначе `SyntaxError`) и в итоге берёт `len(names)`. Если `nc` в yaml устарел после ручной правки `names`, обучение остановится сразу (хорошо), а в YOLOv5 `nc := len(names)` молча (`general.py` L369).
3. **Версионная строгость проверок** (F09): команда, пинящая 8.3.x (где LinQ-«yolo11» мог быть собран), не получает защиты `max_cls < nc` до v8.3.66. Разрешить: зафиксировать версию Ultralytics и прогнать аудитор независимо от неё.
4. **Doc/код для `class_weights`/`cls_remap`**: в `default.yaml` v8.4.184 есть и `cls_remap`, и `cls_pw`; их влияние на fine-tune не измерялось (поэтому сравнения с экспериментами на 8.3.x нечестны).
5. **Roboflow `data.yaml`**: примеры S07/S08 используют `../train/images`; Ultralytics получает путь через fallback; при корректном `path:` fallback не нужен — расхождение зависит от того, лежит ли yaml рядом с папками.
