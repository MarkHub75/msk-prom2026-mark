## Правила второй волны
1. **Твоя цель — изменить картину**: восстановить разорванную цепочку, установить конкретную версию/класс/файл, разобрать реализацию, подтвердить или ограничить сильный вывод. Обязательно попытайся опровергнуть ключевую рекомендацию своего участка и найди условия, при которых она не работает.
2. **Результат**: `ROOT\_WORK\WAVE2\<ID>_<SLUG>.md` (+ `ROOT\_WORK\WAVE2\<ID>_files\` для небольших артефактов). Локальные ID: `<ID>-F01`, `<ID>-S01`, `<ID>-E01`… В файле обязателен раздел **«Статус по K-ID»**: для каждого твоего K — закрыто новым доказательством / уточнено / обнаружено противоречие / осталось неизвестным / потеряло значение, с F-ID и кратким основанием. Шапка — как в CONTEXT §5 (фактическая модель и model ID из своего системного окружения).
3. **GPU-блокировка (RTX 4070 одна на всех)**: перед любым запуском на GPU захвати блокировку атомарно: `mkdir "<SCRATCH>\gpu.lock"` (успех = захвачено; ошибка «exists» = занято — подожди, делая другую работу, и повтори позже; не используй sleep-циклы дольше нескольких минут подряд). Внутри создай файл `owner.txt` со своим ID и временем. Держи блокировку не дольше ~20 минут подряд, освобождай `rmdir /s` (или `rm -rf`) сразу после прогона. Никогда не удаляй чужую блокировку, кроме случая, когда `owner.txt` старше 40 минут — тогда запиши это в свой файл.
4. **Короткие обучения** разрешены только как проверка работоспособности и механизма (минуты, малые наборы: например, `coco8.yaml`, `construction-ppe.yaml` из Ultralytics, небольшие выборки), не как попытка получить продуктовое качество. Длинные обучения и аренда GPU — следующий практический заход.
