# W1-03 WEIGHTS — базовые веса и артефакты (releases, Hugging Face, model zoo)

Роль: исследователь первой волны. Модель: Claude Sonnet 5.5, effort medium. Почему medium: поиск и точная фиксация метаданных артефактов (revision, размер, sha, формат, классы) — объёмная, но в основном каталогизирующая работа.

Сначала полностью прочитай `ROOT\_WORK\CONTEXT.md`. Файл результата: `ROOT\_WORK\WAVE1\W1-03_WEIGHTS.md` (+ при необходимости `W1-03_files\` для json-метаданных).

## Главный вопрос и решение
Где получить базовые (не доменные) веса сильных кандидатов, что это за артефакт (training checkpoint / state_dict / EMA / ONNX / квантованный), на каких данных и с какими классами (в каком порядке) они обучены и каким loader их грузить? От ответа зависит, с какого checkpoint стартовать fine-tune и что использовать как эталон.

## Что сделать
1. Ultralytics: GitHub releases `ultralytics/assets` (теги, имена файлов yolov8n/s.pt, yolo11n/s.pt, yolov5nu/su.pt, pose/cls варианты, новые семейства если есть), размеры и даты; HF-репозитории Ultralytics (например, Ultralytics/YOLO11, Ultralytics/YOLOv8 — проверь фактическое содержимое и revision). Что внутри .pt (по коду сохранения: ключи `model`, `ema`, `optimizer`, `train_args`, `date`, `version`… — помечай как source_code с commit). Допустимо скачать **один** маленький официальный файл (например, yolo11n.pt) в отдельный пустой каталог SCRATCH и посмотреть список содержимого zip `py -I -m zipfile -l` без unpickling; размер и sha256 — вычисленные (local_observation) vs из метаданных.
2. ultralytics/yolov5 releases (v7.0: yolov5s.pt и др.), YOLOX releases (yolox_nano/tiny/s .pth, ONNX-файлы в релизах, если есть), torchvision weights (SSDLite320_MobileNet_V3_Large_Weights, ssd300, fasterrcnn_mobilenet_v3 — URL, transforms, meta categories), TF OD API model zoo ssd_mobilenet_v2 (актуальность ссылок), PaddleDetection PP-YOLOE+/PicoDet (форматы .pdparams, export model), ONNX Model Zoo (onnx/models: какие detection-модели, лицензии, opset), MIT YOLO, RT-DETR/D-FINE (если в карте кандидатов).
3. Person-детекторы: веса, обученные на CrowdHuman или person-only (где лежат, классы, формат).
4. Классификаторы для каскада: torchvision mobilenet_v2/v3, efficientnet_b0, resnet — ImageNet-веса (IMAGENET1K_V1/V2), т.к. часть есть в списке LinQ.
5. Для каждого артефакта: точный источник/URL, revision/tag, имя файла, формат, размер, sha (метаданные vs вычислен), loader (функция/класс), конфиг, classes (число и порядок; COCO-80 vs COCO-91 id mapping в torchvision/TF!), заявленное происхождение данных, inference-only или пригодно для продолжения обучения.
6. Различай: доступный файл / LFS-pointer / gated / битая ссылка / только demo Space.
