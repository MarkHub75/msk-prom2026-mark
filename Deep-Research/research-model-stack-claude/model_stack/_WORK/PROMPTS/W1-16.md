# W1-16 PPE_RESP_SMOKE_ZONE — респираторы/маски, курение, огонь/дым, опасные зоны, падения

Роль: исследователь первой волны (дополнительная ячейка, выделена оркестратором из ячейки 05, чтобы сценарии кроме каски не потерялись). Модель: Claude Sonnet 5.5, effort medium. Почему medium: поисково-каталогизирующая работа по доменным артефактам и способам формулировки нарушения.

Сначала полностью прочитай `ROOT\_WORK\CONTEXT.md`. Файл результата: `ROOT\_WORK\WAVE1\W1-16_PPE_RESP_SMOKE_ZONE.md`.

## Главный вопрос и решение
Для примеров кейса кроме каски — «снял респиратор», «вошёл в опасную зону», «курит рядом с горючими материалами» — какие модельные решения существуют с прослеживаемыми весами/классами/данными, и какие сценарии не решаются одним детектором (требуют pose, трекинга, временных правил, зон)? От ответа зависит, какие сценарии команда сможет честно показать за 45 часов и что потребует сбора данных.

## Что сделать
1. Респиратор/маска: веса и датасеты (face mask detection — с/без маски, mask_weared_incorrect; промышленные респираторы, half-mask, SH17 классы respirator/mask и т.п.). Различай медицинскую маску и промышленный респиратор; лица крупным планом vs CCTV.
2. Курение: веса/датасеты "cigarette detection", "smoking detection yolo", классы (cigarette, smoke, smoking person), размеры объектов, ракурсы; есть ли подходы через pose (рука у рта) + детектор сигареты; публикации.
3. Огонь/дым, горючие материалы: fire/smoke detection веса (классы, датасеты D-Fire и др.), уместность для «курение рядом с горючими».
4. Опасная зона: обычно person detection + полигон + трекинг; найди документированные реализации (Ultralytics solutions: ObjectCounter/RegionCounter/zone, supervision PolygonZone) — версии, контракты (точка привязки bbox: низ-центр?), это часть модельного стека только в той мере, насколько требует модели/трекера.
5. Падение/лежащий человек, отсутствие перчаток/очков — если есть серьёзные материалы, кратко.
6. Для 4–8 содержательных артефактов: repo id + revision, файлы, архитектура/версия, точные class names и порядок с источником, датасет и происхождение, метрики с условиями, лицензия кратко. Не десериализуй неизвестные .pt; ONNX-метаданные можно читать в SCRATCH-venv через `onnx` с `py -I`, если это реально нужно.
