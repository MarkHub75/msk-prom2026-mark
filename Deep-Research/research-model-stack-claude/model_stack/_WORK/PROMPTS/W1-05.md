# W1-05 PPE_HELMET_VEST — готовые доменные веса: каски, головы, жилеты, person

Роль: исследователь первой волны. Модель: Claude Sonnet 5.5, effort medium. Почему medium: основной объём — поиск и прослеживание происхождения доменных артефактов на HF/GitHub/Roboflow/Kaggle; при обнаружении сложной несостыковки классов/форматов — запрос эскалации.

Сначала полностью прочитай `ROOT\_WORK\CONTEXT.md`. Файл результата: `ROOT\_WORK\WAVE1\W1-05_PPE_HELMET_VEST.md`.

## Главный вопрос и решение
Существуют ли готовые доменные веса для касок/голов без каски/жилетов/person, у которых можно установить архитектуру, версию кода, классы (с точным смыслом), датасет, split и метрики — и пригодны ли они как стартовая точка или эталон? От ответа зависит, начинать ли с доменных весов или сразу с fine-tune базового checkpoint на собранном датасете.

## Что сделать
1. Ищи по-английски и по-русски, точными терминами: "hard hat detection yolov8", "helmet yolo11 weights", "PPE detection huggingface", "safety vest", "SHWD", "GDUT-HWD", "Hard Hat Workers", "SH17 dataset", "CHV dataset", "Pictor-PPE", "keremberke hard-hat-detection", "construction-safety", Roboflow Universe "construction site safety", Kaggle "ppe detection", GitHub topics ppe-detection. Проверь HF через API (`https://huggingface.co/api/models?search=helmet` и т.п., сортировка по downloads/likes — но популярность не доказательство).
2. Для 4–8 наиболее содержательных артефактов — глубокий разбор: repo id + revision, файлы (pt/onnx/safetensors), размеры, LFS sha, архитектура и версия библиотеки (из карточки, config, `args.yaml`, имени файла; что подтверждено, а что только заявлено), **точные class names и их порядок** (из `data.yaml`/`config.json`/model card/`names` — укажи источник каждого), смысл классов (helmet vs head vs no_helmet vs hardhat vs NO-Hardhat; person отдельным классом или нет; vest/NO-Safety Vest), датасет и его происхождение (Roboflow workspace/project/version, исходная публикация), ракурс (CCTV сверху vs фото с земли), разрешение, split, опубликованные метрики (и на каком split), лицензия (кратко).
3. Можно ли связать предмет с человеком: есть ли класс person, ассоциация через IoU/содержание, есть ли «head без каски» — это ключевое для сценария «нарушение = человек без каски».
4. Первичные датасеты, на которых строятся многие веса (SHWD, GDUT-HWD, Hard Hat Workers, SH17, Pictor-PPE, CHV): классы, число изображений, источники изображений, статья — коротко, только чтобы проследить веса (полный каталог — → datasets).
5. Не запускай чужой код и не десериализуй неизвестные .pt. Допустимо читать метаданные HF, `config.json`, `args.yaml`, README, тексты yaml; ONNX-файл маленького размера можно скачать в отдельный каталог SCRATCH и прочитать его метаданные (input/output shapes, metadata_props с `names`) только через установленный в SCRATCH-venv пакет `onnx` (`py -I`), если это реально помогает восстановить классы. Зафиксируй, что сделал.
