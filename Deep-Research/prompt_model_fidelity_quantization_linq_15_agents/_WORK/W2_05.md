## K011: completion, FULL/RAW и actual timing scope

### W2-05-F05 — Исторический completion call chain конкретнее общего слова sync

S09 `_bindings.py` L373–425: `sync(inputs, mode=FULL)` выделяет input/output buffers, задаёт user pointers, вызывает native `tpu_run_inference(device,inference,mode.value)`, затем читает output, проверяет `tpu_get_inference_status`, возвращает dictionary. Nonzero run/status превращаются в InferenceError. Python source не содержит отдельного barrier/wait внутри sync; completion должен обеспечиваться контрактом вызываемого native run, а не интерпретацией имени Python метода. C declaration содержит также `tpu_submit_inference` с callback, но один объявленный символ не доказывает доступный high-level async API, используется ли он или его текущие guarantees.

S10 guide2025 с.21 явно описывает `inference.sync` как blocking. S09 packaged ResNet50 test ожидает usable result сразу после sync, но **исходник теста не test result**. PyPI README остаётся смешанным историческим описанием (`iva_tpu`, старые классы/futures), не подтверждением API16. Текущая `.run` ветка S05/S07 не получает blocking semantics из guide `.sync`. Timeout/cancel/retry/reset и thread-safety фактически выданного SDK UNKNOWN. Нельзя заявить завершение через device inventory или return enqueue.

### W2-05-F06 — FULL mode и RAW program различаются; появился конкретный RAW debug dependency

S09 enum L165–169: RAW0, PRE_PROCESS1, POST_PROCESS2, FULL3. `sync` передаёт mode нативной функции; Python не реализует quant arithmetic PRE/POST и не раскрывает место CPU/TPU этих этапов. `_load_inference` передаёт byte pointers, а `_get_inference` для non-raw program интерпретирует bytes через `view(user_dtype)` и reshape(user_shape). Указатель uint8 — адрес байтов, не объявление numerical INT8; `view` не выполняет dequantization.

Отдельно `_is_raw_metadata` L506–518 определяет **RAW program** по отсутствию user_dtype в metadata, а raw output reshapes bytes по ddr_word_len. Это свойство program metadata, не то же, что mode=RAW. Для обычного program просто передать RAW mode ещё не означает, что sizes/reshape/output семантика Python стали raw: выбор размеров/интерпретации привязан к `_program._is_raw`.

**Новый факт beyond W1:** `_converter_to_raw.py` L29–40,76–140 содержит `Codec.encode/decode` с delegation в `tpu_tlm_is.models.iotools.tpu_encode/tpu_decode`; восстанавливает TensorDescription из user/tpu shape/order/dtype, padding, scales, anchor. `convert_to_raw` требует **internal tpu_tlm_is**, переписывает metadata для raw program и возвращает Codec. Без internal dependency выдаёт явный ImportError. Публичный Python пакет поэтому показывает предполагаемый debug route и нужные descriptors; он не содержит здесь арифметику tpu_encode/decode/native processing и не доказывает доступность этого route в выданной VM. Historical hardware mappings в helper ограничены тремя вариантами размеров слов, совместимость с новым target неизвестна.

**Практическое решение:** не делать собственный `astype(int8)` или универсальный scale из byte output; не добавлять второй rescale к user-format FULL output. Запрашивать matching `.tpu` descriptors + codec/native manual; FULL↔documented RAW+codec parity проверять лишь поддержанным текущим механизмом. Наличие старого helper позволяет сформулировать более точный Q02, не объявить current feature supported.

### W2-05-F07 — Timing bug есть и в vendor direct adapter; он не переносится автоматически на MLPerf

S05 L770–793: timer охватывает только `run_once`, decode/NMS после t1; preprocessing/aux preparation до t0; load/probe и COCOeval вне timer. Первый input-name probe может вызвать несколько inference попыток, не включённых в измерение. Значение throughput_img_per_sec поэтому runtime-call throughput при условии blocking run, а не end-to-end FPS.

Warmup default10 images, batch8. На втором batch processed16, в numerator добавляются6 реальных images, но в denominator — время полного8 batch. При N5000 и без ошибок/padding numerator4990, timed calls624 batches =4992 slots. Это **аналитическое следствие кода, не benchmark**; при равном времени full batches относительный коэффициент4990/4992≈0.999599, не измеренная величина ошибки для произвольных timings. При малом тесте N16 коэффициент6/8=.75 — потенциально большой bias. Финальный неполный batch повторяет последнюю картинку до B; полезные completed frames не равны padded slots. Warmup следует исключать целыми batches или измерять точные общие границы; useful FPS считать по реально completed IDs.

S06 performance wrapper использует иной pipeline: native `-s offline -m performance -p program -q qps`, не данный Python timer. Поэтому **нельзя переносить Python warmup defect на vendor presentation или native MLPerf logs без их реализации**. Его Python `is_valid` требует текст VALID и распарсенное Samples per second, но не `returncode==0`; returncode только записан. Existing run directory используется повторно, summary file не удаляется заранее: статически возможна stale-log интерпретация. Это причина требовать свежий run identity, полный raw log/config и successful return code; не установленный факт случившегося неправильного измерения. Нативный warmup/sample denominator/completion этой обёрткой не раскрывается.
