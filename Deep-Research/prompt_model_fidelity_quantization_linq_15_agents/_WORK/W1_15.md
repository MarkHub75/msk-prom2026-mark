## Решение

Первый результат после получения разрешённого доступа должен быть не «TPU виден», а **связанный smoke bundle**: hash входного файла → идентификаторы исходных кадров/PTS → фактические входные tensors → конкретная версия model/artifact → завершённый job → именованные outputs → восстановленные координаты → журнал событий/доставки → доказательство устройства для этого job. Отдельно принимаются качество, полнота обработки, временная пригодность и исполнение нейросети на LinQ. Успех одного не заменяет остальные.

В этой ветке использованы **первичные визуальные наблюдения root**, записанные в [CASE_NOTES.md](CASE_NOTES.md); повторного самостоятельного визуального чтения PDF нет. На с.8 обещаны удалённая VM с LinQ и сервис инференса, на с.13 обязательны видео/тематические изображения, inference на LinQ и замер скорости. Это **требования/заявления кейса**, не полученный здесь доступ. SSH, upload API, авторизация, container/codecs, custom-model deployment, raw outputs и profiling в кейсе не определены. Устный пересказ «CPU+TPU, загрузить файл на сервер» — рабочая предпосылка. Минимальный FPS и допустимая деградация публично не заданы; 1 FPS не считать gate.

Три главных вывода:

1. Руководство H1 описывает локальную tensor→`.tpu`→device→blocking inference цепь; **video/upload service контракт из него не следует**. До выдачи интерфейса нельзя обещать принимаемые кодеки, отправку собственного графа или доступ к сырым тензорам.
2. Свежеполученный pinned linq-cv-bench — сторонний **COCO image adapter**, не готовый server-video runner. Он пропускает нечитаемые изображения, сохраняет только непустые детекции и пишет число запрошенных IDs; такой вывод не даёт полного census. Есть блокирующая опечатка и ограничения custom-классов.
3. Строка `device`/высокий FPS/`.tpu` на диске недостаточны для доказательства TPU. Нужна прослеживаемость конкретного artifact и завершения на целевом устройстве; при закрытом service допустим только явно ограниченный claim с организаторским trace/подтверждением, а скрытое устройство остаётся HOLD.

## Три условных маршрута

Ни один маршрут пока не подтверждён. Выбор определяется выданной инструкцией и capability smoke, а не названием VM.

| Режим | Реально допустимая процедура после выдачи доступа | Граница вывода / когда HOLD |
|---|---|---|
| **Полный SDK + custom models** | Зафиксировать installed versions/device; compile/run только разрешённые custom artifacts; checkpoint→export→quantized→compiled lineage; replay одинаковых tensors на source и target; dumps на доступных границах; затем server video run. Принимаем выбранные shapes/batches/classes, независимо GT и E2E | Отсутствующий float target/intermediate оставляет причинную attribution неполной; наличие SDK не обещает FP32/mixed precision. Custom upload до подтверждения недопустим как факт. Требуются все нейросетевые artifacts, включая pose/ReID/temporal, а не только detector |
| **Ограниченный сервер** | Использовать доступные executable/service/config и разрешённые файлы. Сохранить checksum доступного artifact, version output, stdout/stderr, job IDs; frozen frame или clip replay через существующий путь. Если raw outputs нет, сравнивать canonical boxes/events и GT; попросить готовый trace по выдаваемому интерфейсу, без внешней связи в этом исследовании | Нельзя локализовать quantization/compiler отдельно от скрытых preprocess/decoder. Нет доказательства lineage или device → HOLD соответствующего claim, хотя end-to-end качество можно измерить |
| **Только каталог моделей/готовый сервис** | Закрепить catalog model ID+revision+service version+config, поддерживаемый input, job/result IDs. Выбрать только объявленные классы/сценарии. Проверять black-box качество/время/пустые и ошибочные ответы на независимых clips; использовать supplied reference только при точной версии | Если исходные weights/config неизвестны, **«качество переноса checkpoint→LinQ сохранено» не проверяемо**. Можно утверждать лишь качество конкретного сервиса на corpus. Даже тот же display name pretrained-модели не baseline. Нет source reference → baseline fidelity N/A, не fabricated PASS; device скрыт → proof HOLD |

Во всех режимах neural inference на LinQ обязателен по кейсу. Предлагаемое host распределение: demux/decode, geometric preprocessing, очереди, canonical decode/NMS, tracking/rules/journal — CPU, neural graph — TPU. Это **проектная гипотеза**, а не установленное распределение сервиса. Если NMS встроен в граф, не выполнять повторно; CPU Kalman/rules не равны CPU fallback нейросети. Дополнительные neural pose/ReID требуют своего target proof.

## Контракт данных и журналов для приёмки

Следующие поля — **предлагаемая схема артефактов команды**, не существующий LinQ API. Недоступное поле писать `unknown` с причиной, не заполнять догадкой. Различать `not_applicable`, `not_exposed`, `not_collected`.

- `run_manifest`: run_id, source/candidate IDs, exact source commit/checkpoint/export/compiled hash либо service revision, decoder/preprocess/class-map/skeleton/tracker/rules/config hashes, compiler/runtime/driver/OS реально полученные versions, hardware/device model/ID, capabilities/access restrictions, calibration IDs отдельно от evaluation, shape/batch/dtype/quant parameters, warmup/concurrency/scheduler policy, acceptance-contract ID.
- `media_manifest`: immutable clip_id, original bytes hash+size, supported container/codec/profile/pixel-format/bit-depth/dimensions/rotation/color metadata, time_base/start/time origin, decode library+build+backend, license/provenance, camera/session/epoch, source intervals. Extension `.mp4` не определяет codec/profile. Transcode — новый artifact с hash и source mapping; baseline обязан получить тот же decoded content или сравнение явно confounded.
- `frame_ledger`: clip/stream/epoch/frame_uid, presentation index, original PTS и time_base, effective presentation time, decode status, rotation/color/resize/pad/ROI transform, decoded pixel hash и input tensor hash+name/shape/dtype/layout/range/quant scale+zero point+axis; schedule/enqueue/start/complete/output status и reason. Повторяющиеся PTS требуют уникального frame_uid. Packet DTS не заменяет presentation PTS. Missing timestamps — явная согласованная synthesis policy, не молчаливый `index/FPS` для VFR.
- `job_ledger`: immutable job/model/artifact/device IDs, batch slot→frame_uid, real/padded slots, retry/attempt IDs, submit/start/complete/timeout, output count/schema/hash, transport/service/runtime errors, device-trace link, stale/duplicate/reordered status. Timeout не доказывает cancel; поздний ответ сохранять и не применять повторно. Zero detections — успешный явный `empty`, не отсутствие строки.
- `prediction_ledger`: именованные raw outputs, dtype/shape/finite checks/quant metadata где доступны; decoded boxes/pose/score/class, image coordinates convention и clipping, original W/H, inverse transform, pre/post threshold/NMS settings; rejected candidate reasons. Если сервис даёт только final boxes, raw boundary `not_exposed`.
- `event_delivery_ledger`: camera/epoch/actor/episode/type/zone, evidence frame IDs+PTS, state transitions/reasons, event onset/end uncertainty, created/submitted/received/visible times с clock domain, dedup/retry/ack, payload hash/screenshot/clip path. Evidence не из будущего, delivery не подменять временем file PTS.

Полнота по batch slots сверяется set-wise: каждый scheduled frame имеет terminal status — completed(nonempty/empty), rejected, decode failure, dropped или unresolved. Retries не увеличивают число исходных кадров. Padded копии не превращаются в processed source frames. Для finite fixed run сумма статусов и roster должна замыкаться; unresolved означает незавершённую приёмку, даже если средние метрики хороши.

## Исполнимый acceptance checklist после доступа

Все E-ID ниже **NOT RUN**. Не предлагаются SSH/адреса/порты/upload endpoints. `PASS` только в указанном scope; `FAIL` — нарушенный invariant/согласованный предел; `HOLD` — нет доступа/контракта/доказательства; `INCONCLUSIVE` — недостаточно данных для статистического допуска. HOLD/INCONCLUSIVE не разрешают заявлять полный успех.

### W1-15-E01 — Capability и transfer identity

**Вход:** реально выданная инструкция/учётный доступ, поддерживаемые команды/UI/API из неё, один небольшой лицензированный known-input файл, manifest hash/size; выбранный режим таблицы выше.

**Действия:** выписать ровно поддерживаемые input types/codecs/limits, model selection/custom deployment, invocation/completion/output retrieval, raw outputs/device logs. Через **только документированный способ** передать файл; прочитать размер/hash удалённой копии, если разрешено. Если сервис скрывает bytes, сохранить returned upload/object ID и checksum, либо явно weaker identity evidence. Проверить повреждённый/unsupported file в разрешённом smoke scope: явный отказ, а не «пустое видео успешно». Секреты/токены исключить из bundle.

**Выход/expected checks:** instruction snapshot+version; capability matrix, file identity receipt, unsupported-input error, uploaded model/service revision. **PASS:** выбранный маршрут и identity установлены; **HOLD:** непонятно, какой artifact/file реально обработан. Не доказывает устройство/качество. File-copy метод и конкретные команды не изобретаются.

### W1-15-E02 — Decode, PTS и tensor boundary

**Вход:** E01; короткие CFR/VFR clips с B-frames/rotation и known geometry при наличии поддержки, negative clip, frame roster, source preprocessing contract. Необязательные unsupported варианты фиксируются вне accepted input scope.

**Действия:** снять media metadata, фактический decoded frame census/PTS и decode errors. Локально совпадающие decode bytes не предполагать: сравнить одинаково подготовленные frames/tensors на двух путях, включая channel order, range, interpolation/padding/rotation/color conversion, stride/contiguity при значимости и quant scale. Не применять общий NCHW float32 к сервису без подтверждения. Для file restart назначать epoch; timestamps после seek брать фактические.

Если установлен совместимый **ffprobe**, допустимые диагностические команды основаны на S04, это будущие команды **не выполненные здесь**. Пути ниже — условные локальные имена; `clip.mp4` заменить фактическим разрешённым файлом. Ничего не устанавливать для их исполнения автоматически:

```powershell
ffprobe -version
ffprobe -v error -show_error -show_format -show_streams -of json "clip.mp4"
ffprobe -v error -select_streams v:0 -show_frames -count_frames -show_streams -of json "clip.mp4"
```

**Выход:** media/frame/tensor manifests, hashes, per-frame status; ffprobe — диагностика файла, а не доказательство идентичного production decoder. **PASS:** accepted inputs не теряют/переупорядочивают presentation evidence вопреки policy, tensor contract совпадает. **FAIL:** wrong geometry/color/scale/PTS, silent discard. Если tensors скрыты — HOLD tensor parity, дальнейший black-box GT gate остаётся возможен.

### W1-15-E03 — Реальное устройство и завершение

**Вход:** E02 tensor/clip IDs, конкретный artifact/service revision, разрешённый runtime path и доступные traces.

**Действия:** связать load/deploy record с hash/revision; device identity с session/job; входные frame/batch IDs с output completion. Для подтверждённой соответствующей S01 версии SDK документированная последовательность `Device.list_devices → Device.open → load(.tpu) → inference → sync(input_dict)` даёт blocking path, но это **не команда для неизвестного сервера**. Если фактический adapter вызывает `.run`, проверить documented completion semantics. При async считать время до result readiness/barrier, а не return enqueue. При service нужны job status+completion+device trace, предоставляемые интерфейсом.

**Выход:** source→compiled/service lineage, actual versions, selected physical device, completion record/output hash, execution/partition/profiler trace если экспонируется. В trace отметить CPU portions и все neural artifacts. Отсутствие partition data обозначить, не выдумывать profiler API.

**PASS:** доказательная связка покрывает утверждение «эта нейросетевая inference выполнена на LinQ». **HOLD:** только device inventory, `.tpu` filename, marketing/service label или screenshot загрузки. **FAIL:** другой artifact/backend либо подтверждённый neural CPU/GPU fallback вместо требуемого пути. Высокая загрузка CPU совместима с decode/postprocess, низкая TPU utilization сама по себе не доказательство fallback. Если интерфейс закрыт, trace/письменное подтверждение оператора с job/model IDs — отдельный уровень свидетельства, не собственное наблюдение kernel placement.

### W1-15-E04 — Outputs → геометрия → source/GT comparison

**Вход:** E03 completed output roster, checkpoint/export baseline **только при его точной идентичности**, одинаковые tensors, independent GT frames; frozen decoder/NMS/threshold/class/skeleton map и inverse transforms; известный W1-04 output contract.

**Действия:** перечислить все output names/shapes/dtypes и семантическую границу (logits/raw head/decoded pre-NMS/final detections). Не выбирать первый rank≥3 и не считать 84/85 универсальными. Сравнить dequantized values по фактическим quant parameters, finite masks и per-head errors где доступны. Тем же decoder восстановить boxes/pose в исходном кадре; synthetic known geometry проверяет pad/scale/rotation/clipping. Outputs как множества сравнивать one-to-one по W1-12, не по порядку строк. Source и target независимо оценить относительно GT по classes/small/occlusion/lighting/pose; сохранить unmatched, margin crossings и худшие examples.

**Выход:** raw/canonical predictions+pairing+GT evaluator/version; AP/recall/pose показатели и denominators/slices, Δ и согласованный uncertainty design. **PASS:** W1-12 E01–E03 и заполненные absolute floors/caps/δ. **FAIL:** нарушенный contract/critical invariant/budget. **HOLD:** нет baseline — только GT quality claim; нет допустимых потерь — нет fidelity acceptance. Отсутствие raw не блокирует black-box quality, но запрещает локализацию причин по внутренним tensors.

### W1-15-E05 — Непрерывное видео, tracking/events и file boundaries

**Вход:** golden continuous clips с independent actor/episode GT, short events, occlusion/two persons, continuing episode, re-entry, negative exposure, file boundary/reset, frozen tracker/rules/zones/sampling и event deadlines. Метрики/матчинг — W1-11 и W1-12 E04.

**Действия:** два replay: (A) одинаковые frames/PTS/downstream, меняются только predictions; (B) фактическое service scheduling/queues/drops. Сохранить consumed evidence, state/actor assignments, transitions, source intervals, полный delivery census. Включить empty frame, timeout, duplicated/reordered late result, конец файла и drain. Повтор файла/retry не должен создавать второе уведомление того же job/episode; новый независимый эпизод не должен быть подавлен старым cooldown. Между разными файлами continuity/reset определяется policy, а не автоматически склеенным filename.

**Выход:** timely critical recall по всем GT, FP/duplicates/wrong-person/type/late отдельно, false visible records/source-camera-hour при полном reviewed census; association metrics при релевантности, A-only/B-only episodes. **PASS:** предзаданные W1-11/12 gates, causal evidence и closure. **FAIL:** future interpolation выдана за своевременную тревогу, повтор ongoing incident, новый critical miss, wrong-person, backdated creation. **INCONCLUSIVE:** insufficient groups/critical positives/follow-up. Установка tracker `frame_rate=1` не превращает fixed-dt update в PTS-aware tracking; 1 FPS проверяется по фазам/длительностям, не принимается на веру.

### W1-15-E06 — Performance, clocks, overload и fallback

**Вход:** E05, согласованные allowed load/concurrency/clip roster/warmup/queue/drop/retry policy, named latency boundaries, source→replay clock mapping, доступные resource/profiling logs.

**Действия:** один поток smoke, затем только разрешённая declared concurrency; учитывать upload отдельно, initialization/compile/load отдельно, decode/preprocess/queue/infer/copy/postprocess/event/delivery на доступных границах. Сохранить total elapsed и completed real frames; исключить padded slots из useful FPS; warmup отдельными целыми batches либо точным documented accounting. Сверить requested/scheduled/decoded/processed/dropped/failed/unresolved. Не делить число requested IDs на partial inference time. Нагрузку/отказ устройства искусственно не создавать без разрешённого тестового механизма; допустимы documented validation/rejection/retry checks.

**Время:** для offline file PTS — media clock, wall/monotonic — runtime clock. Из PTS нельзя напрямую вычитать server monotonic/UTC. При paced replay задать anchor `media_pts0 ↔ replay_monotonic0` и speed, считать deadline относительно simulated arrival; при unpaced replay заявлять processing latency/throughput и отдельный media-time causal delay, не live delivery SLA. Межсерверные timestamps без clock mapping/uncertainty не вычитать. Видимый receipt фиксировать на границе получателя; success-only p95 показывать вместе с misses/timeouts/late/unresolved.

**Выход:** completed useful FPS с точным denominator/boundary, stage latencies p50/p95/p99 и n, source/sampled/processed FPS, max evidence gap, input age, drops/reasons, deadline miss rate, queue drain и fallback ledger. **PASS:** quality+timely gates при declared load, completeness и TPU proof. **FAIL:** скрытый backend switch, потеря critical coverage/дедлайна по контракту. **HOLD:** нет mapping/completion/device evidence. Файл обработан быстрее длительности — не доказательство bounded live queues или нескольких потоков.

### W1-15-E07 — Пакет для защиты и decision record

**Вход:** E01–E06, W1-12 acceptance contract, immutable baseline/candidate bundle.

**Выход:** короткая таблица gate/status/scope/evidence; схема фактической цепи с явно неизвестными узлами; model/service/device hashes/revisions; original clip IDs+hash/PTS frame roster; matched/unmatched/drop ledger; paired source/final/GT показатели; event recall/false/duplicate/timing с denominators и пределами; несколько одинаковых кадров source/target/GT с original coordinates, худшие regressions и negative clip; короткий trace completed job на LinQ. Секреты удалить, retained logs не редактировать под успешный сюжет. Видео с нарисованными боксами само по себе не заменяет machine-readable results.

**PASS:** все required gates пройдены в declared scope, любой claim указывает evidence и ограничения. **FAIL/HOLD:** failing/missing required gate. Узкий `PASS(golden fixtures, 1 stream, model revision X)` не расширять на все камеры/модели/нагрузки. Отчёт «не обнаружено новых ошибок на N конкретных эпизодах» не означает population recall=100%. Новый runtime/compiler/model/shape/preprocess/decoder/sampling/policy открывает соответствующие gates заново. Rollback — целый model+preprocess+decoder+rules bundle по W1-12 E06.

## Лестница доказательств TPU и ограничения

Это предложенная классификация свидетельств, не vendor стандарт:

1. **Specification:** кейс требует TPU, vendor обещает поддержку. Доказывает постановку, не run.
2. **Inventory/config:** runtime/version/device перечислен, модель выбрана. Доказывает наличие/выбор, не завершение.
3. **Correlated hardware run:** конкретный artifact/session/device/input/output completion и доступные runtime logs. Основной engineering proof для открытого SDK.
4. **Placement evidence:** compiler/partition/execution/profiler trace покрывает neural graph, включая additional heads/ReID. Позволяет ограниченное утверждение о размещении; device-wide utilization — только corroboration.
5. **Service attestation:** если 3/4 скрыты, supplied job/model/device trace либо подтверждение оператора — косвенное свидетельство с названным происхождением. Нельзя повышать его до собственного hardware observation.

Проверять признаки fallback по фактическому contract: изменился backend/model revision, kernel placement, runtime предупреждение о CPU neural execution, device error→успешный ответ другого neural path. Отсутствие предупреждения не доказывает absence fallback. В проверенном S02 нет явной автоматической CPU neural ветки; **это чтение конкретного файла**, не доказательство отсутствия fallback внутри библиотеки или production service. TLM/TF reference сами по себе не fallback; наличия torch на host недостаточно для обвинения в GPU inference.
