# Сборщик фактов и источников — gpt-6.1-sol/high

Ты отдельная аналитическая роль после W1→fresh critic→W2. Прочитай оба входных файла полностью, PLAN/RUN_STATE/SYNTHESIS_REQUIREMENTS, CASE_NOTES, все15 W1 и все фактические W2, CRITIC и CRITIC_HANDOFF. Получай доказательства из сохранённых материалов, без новых сетевых запросов, субагентов и скрытой третьей волны. Существующие материалы соседних исследований — вторичные и их результаты не наши эксперименты. Корневой каталог — целевая папка, новые конечные каталоги не создавать.

Создай последовательно SOURCES.md, RAW_FACTS.md, OPEN_QUESTIONS.md и дополни CRITIC.md результатами W2. Сохрани исходные замечания и историю; для каждого K: closed/narrowed/contradiction/open/not relevant с основанием и конкретным W2 источником. Не называй документационный вопрос закрытым действительным device test. В _WORK/ID_MAP.md сохрани W1/W2 prefixed S/F→stable S001+/F001+ mapping; по темам соседей одинаковые IDs не смешивать.

SOURCES: содержательно использованные источники, прямые URL/локальные переносимые пути, название/автор, publication/version/commit отдельно от access time, точный locator, evidence type и поддержанные F. Объедини URL дубли с сохранением разных версий и локаторов; несколько чтений одной статьи не независимость. Неизвестные даты/ошибки доступа видимы. Saved snapshots должны иметь provenance; источники с живыми docs/latest не выдавать за pins установленного стека. Сохранённый исходный PDF кейса _WORK/INPUT/CASE_LINQ.pdf и личное чтение root CASE_NOTES — отдельное первичное локальное наблюдение с provenance рендеров. Кейс с.8 обещает VM/сервис, не подтверждает выданный здесь доступ.

RAW_FACTS: подробная инженерная база, не укороченный human report. У каждого F явные assertion, evidence type, S+locator, version/conditions, actual checked scope, limitation, practical implication; наши выводы/предложения выделены. Сохрани значимые точные version-specific literals, hidden defaults, code caveats и противоречия. Не теряй conditions papers/bug reports или превращай их в наши reproduction. Не складывай полные копии чужих страниц. Нужны сравнения stage failure/remedy, method requirements/backend/cost/verification, model schemas/LinQ level, metric units/split/limits; инструкции A–F тематического задания покрываются напрямую или через подробную AUTHOR_HANDOFF.

OPEN_QUESTIONS: приоритетные Q001+ с конкретной неизвестностью, где искали/что известно, причина отсутствия ответа, решение, владелец по функции/способ закрытия (public docs/code/artifact/CPU-test/SDK/device/engineer), связанные F/K/E. Короткая группа немедленных вопросов LinQ. Различай закрываемое поиском и требующее actual grant/model/data. Подробная программа 5–15 E-ID, все PROPOSED/UNRUN: цель/decision, inputs+access, baseline→target stage, будущие sample IDs из frozen manifest (не вымышленные существующие IDs), procedure без invented API, observable outputs/logs/profiler/TPU proof, pre-agreed PASS/FAIL/HOLD/UNAVAILABLE, возможные исходы и что PASS не доказывает. Smoke/regression/event и три приоритетных теста обязательны; избегай огромного дубля веточных E.

По данным: calibration/tuning/independent test и group lineage, finite dataset/cluster limitations. Numerical equality, task quality, event usefulness и actual device proof раздельны; никаких универсальных 1%/1FPS. LinQ/compiler precision/QDQ/mixed support нельзя выводить из ORT/Intel/NVIDIA. Версии 2025guide/2026benchmark/legacy bindings не составляют единую установку. По каждому разрыву после W2 честный Q вместо обещания.

Создай _WORK/AUTHOR_HANDOFF.md: доказательная картина, наиболее важные decisions/unknown/contradictions, условия применения методов, план cheap→expensive и restoration tree, ссылки на F/S/Q/E, handoffs соседним темам. Не ограничивай базу произвольным числом источников/фактов; сохраняй весь decision-relevant материал. В рамках собственной сборки проверь resolve созданных IDs/ссылок/якорей и аккуратность UTF8; отдельную финальную проверочную стадию не добавлять. Правь только свои три финальных реестра, CRITIC dispositions и служебные ID_MAP/AUTHOR_HANDOFF/COLLECTOR_NOTES. Передай counts/paths, K dispositions и ключевые ограничения root.
