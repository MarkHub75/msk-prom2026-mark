## Решение

Сначала проверить контракт конкретной модели и фактически применённую калибровку, затем оценивать PTQ. Сторонний пример LinQ нельзя переносить на custom YOLO nc=1/2/3 без исправления адаптера. В нём есть подтверждённые исходным кодом COCO-зависимые ограничения и отдельная опечатка, способная остановить программу до аппаратного inference. Они не являются доказательством дефекта LinQ SDK.

Основной target-specific риск калибровки: `--percentile` может оказаться только requested, а не effective. Скрипт ловит любой TypeError от calibrate с аргументом и повторяет без него; итоговый build_summary не сохраняет ни percentile, ни retry, ни thresholds. Поэтому «успешно собрано с percentile=X» по этому summary недоказуемо. Перебор percentile до проверки реального API может быть перебором одинаковых default-вариантов или разных состояний после неудачного вызова.

Руководство 2025 документирует полезную fidelity ladder: исходный TF → квантованный TF с его rescale → TLM → TPU. Но его демонстрационная проверка правильного top-1 класса одного изображения слишком слаба для detection/pose/events. Перенести структуру этапов, расширив сравнение до named tensors, декодированных детекций и независимого качества; не переносить два calibration изображения из примера как норму.

## Адресные проверки после получения доступа

Численные tolerance и допустимая потеря quality кейсом не заданы. Exact checks ниже относятся к схемам/артефактам, а numerical gates согласуются с baseline repeatability и W1-06/12. Отсутствующий инструмент получает UNAVAILABLE, не PASS. Предлагаемые поля manifest — **наша схема**, не LinQ API.

**W1-14-E01 — output adapter до аппаратного запуска (NOT_RUN).** Из manifest взять task/head/version/nc/names/output stage/axis/dtype/quant boundary. Подать decoder fixtures nc1/2/3 с уникальными class scores и candidate IDs, в BCN и BNC согласно объявленному варианту; по отдельности final N×6 и pre-NMS C=6, не распознавать их одной эвристикой. При shuffled dict outputs/prototypes требовать те же named outputs; missing name и неизвестный integer encoding должны давать явный отказ. PASS: custom class map сохранена, axes не угаданы, extra channels не попали в classes, Unicode typo устранён в производном коде. NMS повторно не применять, если он уже в модели. Полный decoder contract и tie/cap fixtures — W1-04; результаты их выполнения здесь не заявляются.

**W1-14-E02 — effective configuration admission (NOT_RUN).** На предоставленной среде записать package/native/compiler/firmware/target versions, hash wheel и model/imported graph; изучить установленную сигнатуру и matching docs RegularModel/calibrate. Записать requested и реально переданные percentile/algorithm/axis/shape; не переписывать TypeError в успешный retry. Получить успешный fresh model→calibrate→thresholds→quantize, сохранив поддерживаемое представление thresholds/config и все warnings. Если current API не принимает percentile, это отдельный explicit default-policy run, не результат sweep X. В каждом опыте список input hashes и ordered calibration IDs одинаков. PASS: policy проверяема; UNKNOWN scope отдельно от успешного вызова. Успешный вызов ещё не доказывает, какие численные величины параметр меняет.

**W1-14-E03 — scope/эффект percentile и воспроизводимость (NOT_RUN).** Только после E02 использовать небольшой vendor-supported graph с доступными weights/intermediates, не generic непроверенный API. Сравнить два допустимых значения percentile при одном graph/data; затем один percentile при двух заранее описанных calibration distributions, меняя один фактор. Сопоставить weights, activation thresholds, scales и dequantized outputs. Изменение только weights поддерживает weights-scope для этого опыта; activation thresholds могут зависеть от новых quantized weights, поэтому само их изменение не доказывает direct activation-percentile policy. Нет изменений — возможны неактивный аргумент, отсутствие чувствительных хвостов, округление либо кэш; это INCONCLUSIVE, не доказательство игнорирования. Два fresh повторения одной policy и supported `.qm` save/load в новом процессе без recalibrate проверяют численную воспроизводимость. Hash файла отдельно: сериализация может включать метаданные и меняться без numeric drift. Не обещать threshold portability между графами/SDK.

**W1-14-E04 — numeric boundary ladder (NOT_RUN).** Один frozen float tensor pack с names/shape/layout/range/hash и эталонными outputs. Пары: source ONNX→imported float TF; imported float→quantized reference с документированным rescale; quant reference→TLM если доступен; TLM→TPU user output. Для каждого named output: shape/dtype/finite/minmax, absolute/relative error, per-channel/branch slices и candidate alignment до NMS. Разрывы именовать по реально сравнимой границе; без imported float ONNX→quant ref включает import+quantization. Без TLM quant ref→device включает compiler/runtime, локализация слабее. Получить user/raw sizes/dtypes/scales и native definition FULL/RAW от конкретной версии. Не заменять unknown raw packing на astype(int8), а byte pointer — на numerical dtype. Если доступен supported RAW route, сравнить FULL(user_input) с документированным PRE→RAW→POST эквивалентом. Не требовать bitwise equality FP32 без контракта производителя. PASS: boundary conversions объяснены и нет неконтролируемого первого разрыва; top1 совпадение недостаточно.

**W1-14-E05 — compile/precision preservation (NOT_RUN).** Для одного `.qm` и golden pack сравнить только документированно разрешённые presets/targets/batches. Сохранить tensor descriptions, partition/device и actual compute/storage types настолько, насколько отчёт раскрывает. Не выдавать float dtype контейнера за FP compute, долю INT8 узлов — за эффективность. Для QDQ/QAT или FP island сначала минимальный граф из выбранного семейства и проверка сохранения scales/axis/zero-point/boundaries в compiled representation и raw outputs. Если это невозможно доказать, support=UNKNOWN и обучение по этому пути не начинать. При unavailable report сообщить границу наблюдаемости, не придумывать CLI dump. Successful compile с neural CPU fallback не является скрытым выполнением требования TPU; placement должен быть раскрыт.

**W1-14-E06 — независимый quality gate (NOT_RUN).** На раздельном tuning/test replay использовать те же кадры/PTS, геометрию, class schema, decoder/NMS и frozen thresholds. Раздельно FP export→quant ref→TPU: AP/recall по критическим классам и small/occlusion/dust slices; pose errors при наличии; event recall, wrong-person/late/duplicate, FP per camera-hour. Если raw tensors близки, а detections различны, сначала decoder/NMS/threshold boundary; если dets близки, events расходятся — tracker/rules/state. Подбор score threshold после PTQ — отдельная настройка рабочей точки, а не доказательство восстановления raw quality. Время calibration/preprocess, compile и inference логировать раздельно; backing memmap size не является peak RAM. Схема статистики и допуска — W1-12, temporal propagation — W1-11.

## Что нужно установить у реального target

1. **Q14-01, блокирует объяснение PTQ:** exact quantizer/compiler/native versions, actual signatures, scope/formula percentile, granularity/axis, signedness/zero-point, clipping/rounding/saturation, accumulator и bias types; supported dump thresholds/encodings.
2. **Q14-02, блокирует numeric parity:** user-format/raw-format I/O конкретного `.tpu`/сервиса, где выполняется PRE/POST, batch padding, output names/roles, разрешённые host stages. Отсутствие custom output в стороннем примере не доказывает запрет SDK.
3. **Q14-03, блокирует QAT/mixed precision:** поддерживается ли QDQ/imported encodings и действительно ли compiler сохраняет их; какой официальный train/export recipe; какие FP islands/исключения/precision combinations исполняются на TPU; где возможен fallback.
4. **Q14-04, ограничивает диагностику:** есть ли поддерживаемый quantized reference/TLM/current per-layer extraction и compiler precision/placement report; как открыть intermediate outputs без изменения production semantics/fusion.
5. **Q14-05, блокирует перенос конкретной модели:** выбранный head/task/nc/kpt shape, export flags/opset, operators/attrs/shapes, NMS stage; exact operator matrix выбранного release. Перечень yolo8/yolo11 не является ответом.

Достаточный следующий шаг: получить version-matched build/infer example и один known-good input/output вместе с доступом, затем E01/E02/E04 на выбранной модели. Пока можно подготовить единый output/config manifest и frozen data split; это не требует GPU. Общее PTQ «per-channel weights + per-tensor activations» из W1-07 остаётся **условным кандидатом**, пока Q14-01 не установит, что именно позволяет LinQ. Публичных измерений потери качества для нашего checkpoint на выданном устройстве нет.
