## Точная специализация, стартовые зацепки и ожидаемое решение
### W1-15. LinQ: серверное исполнение из загруженного видео, верификация и доказательства качества

**Главный вопрос:** что команда может реально проверить в предоставленном организаторами окружении и как убедительно доказать корректное исполнение на TPU?

С учётом устного указания о видеофайлах на сервере (без обязательного онлайн-стриминга с ноутбука) исследуй подтвердимые интерфейсы передачи файлов, форматы доступных video inputs, место декодирования, CPU vs TPU responsibilities, сохранение детекций и временных меток, измерения входного и выходного качества, layout и dtype обмена, logging/profiling, признаки fallback, сравнение с golden test clips.

Не придумывай SSH-команды, адреса, порты, API или способ авторизации. Где конкретные детали доступны только через инструкцию постановщика/сам сервер, подготовь **точный acceptance-test checklist**, который можно исполнить после выдачи доступа.

Сценарии выхода:

1. Доступен полный SDK и изменение моделей.
2. Доступен сервер с ограниченными инструментами.
3. Разрешён только готовый инференсный интерфейс/модель.

Это условные варианты до подтверждения. Для каждого покажи допустимую проверку точности и ограничения выводов.

**Результат:** процедура «проверка реальной LinQ infer → восстановление боксов → сравнение с исходной моделью → документирование деградации/отсутствия деградации» и набор доказательств для защиты.
