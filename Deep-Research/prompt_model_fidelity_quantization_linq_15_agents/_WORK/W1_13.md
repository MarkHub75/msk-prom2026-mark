## Решение для команды

**Подтверждён документированный маршрут, но не замкнутый воспроизводимый путь наших весов:** ONNX → `onnx_to_tf` → TensorFlow Graph/GraphDef → внутренняя квантованная модель `.qm` → `Network` → `compiler.compile_` → executable и tensor descriptions → `TpuProgram` → файл `.tpu` → `pytpu` на хосте с LinQ. В guide есть пример ResNet50, а в публичном стороннем repo — код self-build YOLOv8s. Веса, `.qm`, `.tpu`, действующий комплект SDK и журнал успешной компиляции нашего detector здесь отсутствуют [S01, S06–S10].

Перед обучением большого custom detector получить у организаторов **manifest фактически выданной среды + один неизменённый рабочий пример с артефактами + право загружать/компилировать custom weights**. Затем воспроизвести пример, проверить свой статический float export, importer и только после этого расходовать ресурс на обучение/квантование. Это инженерный вывод из незамкнутых звеньев, не ограничение LinQ.

Три существенных границы:

1. Guide 2025, сайт с Python3.8, PyPI-пакеты 2021/2023, сторонний repo 2026 и benchmark Framework2026.8.43 — **разные источники версий**. Они не определяют совместимый комплект автоматически.
2. Сторонний YOLOv8 exporter имеет default opset13, но это выбор автора скрипта, **не максимальный поддерживаемый LinQ opset**. В build формы принудительно статические. Ни symbolic axes в exporter, ни `Optional[int]` в guide не доказывают dynamic-shape TPU execution.
3. Названия YOLO8/YOLO11 в официальном перечне не задают importer/operator/shape/precision matrix для custom weights и custom class count. Нельзя обещать поддержку torchvision detection, DETR/RT-DETR, RTMPose, TFLite или OpenVINO IR по общей фразе «PyTorch через ONNX».

Framework preparation **не требует GPU по приведённому guide**: указан обычный Linux host с CPU/RAM. Но guide не доказывает возможность произвольной cross-compilation на Windows, ARM или без всех закрытых зависимостей. Runtime example перечисляет локальные TPU devices; удалённый сервис не является тем же интерфейсом. Отдельная машина компиляции и машина inference возможны как архитектурный вывод из `.tpu` boundary, но разрешение remote custom upload и совместимость должны быть выданы явно.

## Сценарии доступа и действия без выдуманных интерфейсов

Полный кейс уже найден: `_WORK/INPUT/CASE_LINQ.pdf`; сведения о с.8 взяты из первичного локального конспекта root `CASE_NOTES.md`, без повторного визуального чтения этим агентом. Организаторы обещают удалённую VM с LinQ и inference service. Фактический grant здесь не получен. SSH, REST endpoint, token type, custom model upload, quotas и file upload protocol **в кейсе не определены**. CPU+TPU и загружаемое видео — рабочие предпосылки команды, не установленный API.

| Возможный grant | Что можно реально доказать при получении | Чего недостаточно для custom deployment |
|---|---|---|
| Только готовый inference service | Выполнение перечисленной service model; reproducible inputs/outputs; provider-side version/device evidence, если сервис их отдаёт | Нельзя обещать собственные веса, export/compiler control, raw outputs или layer diagnostics |
| VM + runtime + готовые .tpu | Проверить vendor example и фактическое TPU execution; применять postprocessing/events на host | Нужен framework/compiler доступ либо готовый custom artifact от authorized pipeline |
| VM + framework/compiler/runtime | Строить полный staged route в утверждённом окружении | Нужны operator constraints, compatible package manifest и raw artifacts; root/admin права не подразумеваются |
| Local preparation SDK + remote runtime | Compile на разрешённом preparation host и передать .tpu | Требуется binary compatibility и явно разрешённый upload; не выдумывать SCP/REST команды |

## Точные вопросы инженерам / организаторам

1. Какой grant предоставлен: shell VM, готовый service или compiler pipeline? Разрешены ли custom weights, `.onnx/.qm/.tpu` upload и получение raw tensors? Каков официальный file-transfer/API contract?
2. Каковы SKU/device count, target string, OS/arch/Python, driver/libtpu/pytpu/runtime/firmware и exact wheel/build hashes Framework/Compiler/importer? Какая совместимость `.tpu` между этими версиями? Соответствует ли среда benchmark16.18.6/2026.8.43 или другому bundle?
3. Где exact matched manual/release notes/known issues? Для этой версии `onnx_to_tf` возвращает Graph или tuple, откуда импортируется, какой TensorFlow/ONNX/opset/IR диапазон реально поддержан? Нужен полный lock, а не lower-bound HX web page.
4. Дайте unchanged successful example для конкретного detector/pose, включая **weights hash, exporter version/call, ONNX bytes, QM/TPU, calibration IDs/preprocess, IO descriptors и golden input/output**. Есть ли рабочий пример custom nc1/2/3, а не только COCO80?
5. Какие допустимы dynamic/static dimensions, batches, memory limits и shape-dependent operators? Для Resize/Gather/Reshape/Transpose/Concat/TopK/NMS нужны ограничения по атрибутам и tensor types, а не список сетей. Разрешены ли multiple outputs/custom operations; где decode/NMS выполняются?
6. Каковы numeric contracts inputs/outputs, их quantization parameters; импортируются ли ONNX QDQ/QOperator или QAT encodings? Есть ли mixed precision/node exclusions и какие именно API/limits? До ответа не переносить на LinQ техники W1-07/08/09.
7. Как получить compile report, unsupported-op diagnostics, execution status и признаки CPU partitioning/fallback? Есть ли TLM/hardware-graph tools в выданном bundle и как они соотносятся с actual TPU numbers?

Практический порядок вопросов: grant+manifest+рабочий artifact сначала, конкретный graph/operator issue после float parity. Семейство модели выбирают по **подтверждённому artifact route**, а не по числу названий в Model Zoo.

## Статусы доказательств

- **Marketing/vendor claim:** официальный family list, PyTorch через ONNX, full stack, Cloud TPU/demonstration availability.
- **Documented interface:** S01 ONNX/TF/QM/Network/compiler/TPU boundary и runtime example; точный SDK release не закреплён.
- **Public source example:** S06–S11 — реальные readable scripts с pinned commit. **Полностью публичная executable reproduction с приложенным SDK/weights/QM/TPU/outputs не установлена.**
- **Published third-party result:** S09 автор сообщает завершённые vendor TPU runs и незавершённый segmentation O5; это авторский статус, без изученных raw metric artifacts. Не используем его как свою измеренную accuracy/FPS. S05 — vendor benchmark, иной evidence class.
- **Actual test by our team:** модели/TPU/compile не тестировались. Подтверждены только metadata, HTTP source retrieval и равенство 6 raw files pinned blobs.
- **Unknown/requires access:** конкретная предоставленная среда, custom graph support, operator matrix, formats beyond documented TF/ONNX, numeric scheme details, binary compatibility и remote API.

Пересечения: W1-02 определяет фактический exporter; W1-04 — полный output contract и дефекты custom-nc adapters; W1-07 — effective calibration; W1-08 — QDQ/QAT границы; W1-09 — mixed precision. Их общие APIs не приписываются LinQ. Соседний linq_platform дал полезные leads; его shape/helper probes и аппаратные заявления не присвоены этой веткой.
