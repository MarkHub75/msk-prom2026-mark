## Решение для команды

В fidelity gate следует выделить обязательные срезы по **размеру признака после фактической предобработки**, видимости нужных частей тела, близости к порогам и принадлежности объекта человеку. Общий mAP и стандартный COCO pose summary могут скрыть именно эти потери. Первый приоритет — телефон/сигарета/элемент привязи у нижней границы различимости; второй — wrist/ankle/hip при окклюзии и соседнем человеке; третий — пересечение порогов уверенности, расстояния и угла. Это приоритет анализа последствий, не опубликованный универсальный рейтинг чувствительности INT8-слоёв.

В источниках нет доказательства, что INT8 любого семейства обязательно ухудшает малые объекты сильнее крупных, и нет количественной оценки для неизвестной модели на LinQ. Нужны парные результаты именно нашей цепочки. Если FP32 уже не различает признак или класс отсутствует в head, восстановление precision не решает задачу. Если ухудшение возникает только после преобразования, сначала локализовать стадию и контракт decoder; лишь затем рассматривать calibration, selective precision или QAT вместе с владельцами W1-07/08/09/14.

## Где 0.5–2 pixel становятся изменением события

Ниже **аналитические придуманные примеры**, не кадры и не результаты моделей/LinQ. Пиксели — непрерывные координаты боксов, без integer-inclusive convention. Они показывают механизм, а не ожидаемую величину ошибки.

1. Для двух квадратов стороны `s`, сдвинутых на `d` по обеим осям, `IoU=(s-d)^2/[2*s^2-(s-d)^2]`, при `0≤d<s`. Для `s=4` и `d=0.5/1/2` это примерно `0.620/0.391/0.143`; для `s=8` — `0.784/0.620/0.391`. Таким образом, один пиксель может перевести tiny box через IoU=0.5 при неизменном визуальном классе. Это влияет на оценку matching и на системы, где используется IoU association; не означает автоматически, что событие пропущено.
2. Пусть network resize имеет scale `1/3`. Ошибка 1–2 pixel **в model input** соответствует 3–6 source pixels. Для heatmap дополнительно учитывать stride, crop affine и inverse transform: при stride=4 сдвиг 0.25 heatmap pixel даёт 1 input pixel. У реальной камеры коэффициенты необходимо прочитать из pipeline, а не предположить.
3. Если правило принимает `score≥0.25`, изменения `0.251→0.249` достаточно для пропажи кандидата. Пиксели здесь вообще не меняются. Сохранить score до threshold/NMS: иначе отсутствие объекта ошибочно выглядит как грубая регрессия localization. Порог иллюстративный, не предлагаемый норматив.
4. Две соседние heatmap/SimCC позиции с почти равными значениями могут сменить argmax или превратиться в tie после округления. Например, `0.5001` и `0.4999` при шаге округления `0.01` обе дают `0.50`. Фактический сдвиг зависит от tie ordering, формы peaks и codec. Это условный арифметический пример, не установленный quantizer LinQ.
5. Направление короткого сегмента `(10,0)` после ошибки endpoint `(10,2)` поворачивается на `atan(2/10)≈11.31°`. Для `(100,0)→(100,2)` это около `1.15°`. Поэтому angle rule на foreshortened limb может смениться при небольшом jitter. При ошибках обоих концов ситуация иная; rotation одного сегмента не равна ошибке полного коленного угла.
6. Если signed distance опорной ankle/foot точки до границы ROI меняется `+0.5→−0.5` source pixel, классификация inside/outside меняется. После homography метрическая ошибка зависит от локальной геометрии и плоскости; переносить единый «пиксель→сантиметр» коэффициент нельзя. См. W1-05 и W1-11 для inverse geometry и temporal rules.
7. Phone box может остаться правильным, но wrist другого человека окажется ближе после 1–2 px сдвига. Ошибка возникает в owner/interaction association: глобальный detection mAP может остаться почти тем же, а уведомление уйдёт не тому actor. Проверить person/object/hand связи отдельно.

## Конкретная диагностическая процедура

**E10-1 — отделить отсутствие сигнала/класса от переноса.** Нужны raw camera frames, GT, class map и исходный checkpoint. Для каждого целевого класса проверить семантику, visible evidence и размер после настоящего resize. Сравнить checkpoint/reference на исходном полном кадре и, как отдельный диагностический режим, на crop из исходного разрешения. Ожидаемая развилка: если class отсутствует — исправляется задача/модель; если reference full frame не видит, crop видит — проблема масштаба/контекста; если оба не видят — это ещё не вина precision. PASS для fidelity допускается только на измеренных данных при отдельно показанной абсолютной пригодности. «Одинаково не видят» доказывает parity этого примера, не безопасность.

**E10-2 — paired slices по стадиям.** Freeze исходные bytes/PTS, preprocess tensor, crop affine, thresholds, class order, decoder и sampling. Прогнать одни sample IDs по доступным стадиям checkpoint→export FP32→target graph/reference precision→LinQ target precision. Для каждой пары сохранить raw candidates до confidence/NMS и decoded outputs. Нужны доступ к промежуточным outputs и сведения о dequantization; если интерфейс отдаёт только final detections, локализация причины ограничена. Логировать shared tensor input и source/model coordinate errors отдельно.

Сопоставлять predictions с независимым GT и отдельно друг с другом. Для matched pairs считать coordinate shift/score change; unmatched reference TP→target miss, target-only detections и смены класса учитывать отдельно. Не ограничиваться «пересечением сохранившихся»: survivorship bias скроет пропажи. Вывести `N_reference_TP`, `N_lost`, `N_gained`, recall/AP среза и per-class metrics. Компенсация потерянного события новым TP другого класса не закрывает регрессию. Доверительные интервалы и кластеризацию клипов согласовать с W1-12.

**E10-3 — pose decomposition.** На одинаковых GT/reference person crops сравнить pose networks и codecs; затем повторить полноценную цепочку с их собственными detections/crops. Первый режим изолирует pose/decoder, второй включает ошибки person detector. Для heatmap head сохранить top1/top2 margin, peak position, invalid values и inverse geometry; для SimCC — обе оси, split_ratio, softmax/score settings. Pose confidence не считать физической вероятностью видимости без проверки calibration. Отдельно сравнить critical joints и angle/zone predicates. Expected check: одинаковые raw outputs + разные decoded coordinates указывают на codec/геометрию; одинаковый crop + расходящиеся tensors — на модельную стадию. Само изменение decoder — новая конфигурация baseline, а не доказательство исправления quantization.

**E10-4 — причинный replay событий.** На фиксированной временной сетке заменить только predictions одной стадии, сохраняя tracker/event config. Считать event recall, false alarms, wrong-person, onset delay, duplicates; детальные правила и event matching принадлежат W1-11/12. Затем отдельно проверить actual processing cadence сервера: throughput не равен частоте кадров, действительно дошедших до event engine. Непрерывный источник нужен для false alarms/hour; curated набор hard negatives не даёт эксплуатационную частоту. Если нейросетевые outputs совпадают, а события нет, искать sampling/state/rules; это не доказательство ошибки INT8.

**E10-5 — targeted repair/stop-loss.** Если первый расходящийся переход — preprocess/export FP32, исправить контракт прежде калибровки. Если расходится precision при том же входе, передать sample IDs и raw head diffs W1-07/09/14: репрезентативная calibration, допустимая mixed precision, ограниченная QAT-абляция только при поддержке компилятора. Если baseline слаб, рассмотреть более информативный camera/ROI/input режим или сократить сценарий. Для tiling повторить весь gate, включая latency/merge/actor, поскольку меняется система. Не принимать улучшение, полученное только снижением confidence и ростом ложных тревог. После согласованного короткого бюджета без локализованной причины откатиться к последней принятой конфигурации; неподдерживаемые target precision modes не придумывать.

Все E10-* — **не выполнены**, доступы/артефакты пока отсутствуют. PASS/FAIL необходимо зафиксировать до просмотра final stress results: per-slice допустимые потери recall, лимит critical event misses/false alarms, error/latency margins и минимальную представленность. Численные нормативы в кейсе не даны. Возможен строгий smoke-критерий «нет новых пропусков на заранее выбранных критичных fixtures», но это только regression smoke; он не заменяет статистическую оценку редких событий. ## Ограничения и контрпримеры

- Окклюзия скрывает факты. Видна привязь ≠ доказано крепление к анкеру; не видна тонкая стропа ≠ доказано её отсутствие. Телефон рядом с человеком ≠ доказано использование; wrist у рта ≠ доказано курение. Нужны размеченные interaction/evidence и состояние «недостаточно данных», иначе parity способна сохранить ложную интерпретацию.
- Большой объект у границы зоны тоже может быть чувствительным к одному пикселю. Малый размер увеличивает относительную геометрическую ошибку, но downstream margin часто важнее абсолютного размера.
- Рост precision не создаёт детали, потерянные камерой, blur или resize. Tiling увеличивает пиксельный бюджет модели относительно full-frame resize, но не возвращает невидимый сигнал и может уничтожить контекст взаимодействия.
- Публикации SAHI — drone/satellite; CrowdPose — повседневные человеческие сцены; Robust Detection включает общие/дорожные данные и синтетические искажения. Фабрика отличается optics, fixed viewpoint, СИЗ, дымом, объектами, освещением и частотой событий. Ни проценты улучшения, ни severity, ни ranking моделей прямо не переносятся.
- Общая программа срезов применима к YOLO, torchvision detection, DETR/RT-DETR и heatmap/SimCC pose. Raw tensor layouts, presence/absence NMS, score semantics, coordinate conventions и codec для каждого семейства разные. MMPose decoder нельзя приписать YOLO pose; NMS-проверка не навязывается NMS-free head.
- Без LinQ intermediate tensors не доказать конкретный layer culprit. Без достаточного GT не доказать absolute/event accuracy. Без исполнения и runtime evidence нельзя объявить поддержку tiling/mixed precision или фактическую TPU-работу.

## Открытые вопросы и передача соседям

2. Какие конкретные checkpoint/classes/pose schema/codec? Видимость, confidence и missing keypoints имеют ли documented semantics? Редкие классы действительно обучены?
3. Доступны ли target raw outputs до decoder/NMS? Каковы quant scales, dtype, actual precision и возможность адресного исключения head? Отдать W1-13/14.
4. Какие margins/temporal predicates меняют safety event? Нужны точные owner/interaction/zone критерии и политика unknown. Отдать W1-11, не определять по mAP.
5. Каков минимальный объём независимых клипов на каждый critical slice и допустимый предел деградации? Это решение W1-12/команды при неизвестной частоте и цене ошибок.
