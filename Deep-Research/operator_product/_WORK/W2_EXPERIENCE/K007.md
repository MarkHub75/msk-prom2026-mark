# K007 — feedback не gold label; очередь не выборка пропусков

Срез доступа 23.10.2026 Europe/Moscow, researcher medium. Реальных API-запросов с токеном, исправлений в продуктах и обучения не было. Метки DOC/VENDOR/INF/UNKNOWN — как в K005. W1_U10 уже достаточно обосновал отсутствие автоматического обучения после клика; общий trust/HAI поиск не повторялся.

## Итог для критики

**Предложенный исход: область применения уточнена; контракт предложен, доступность архива/продуктовый missed-event UI остаются открытыми.** Получено различающее первичное основание: в Intenseye customer label и vendor label экспортируются отдельно. API с названием Accuracy показывает sampled alerts, не независимые отрицательные интервалы. Поэтому наша единая «ошибка» не должна переписывать истину, а метрика review — называться recall. Точные последствия Protex feedback ограничены заявлением refinement и неоднозначной областью обработки (K006 F06–F09), не обещанием весов новой модели.

## Предложенный контракт [W2-EXPERIENCE-F15, INF]

Объект `feedback` сохраняет raw мнение отдельного человека/системы; объект `review_result` хранит curated решение. Исходный event, прежняя метка и спор сохраняются. Примеры полей ниже — наша минимальная схема, не API Intenseye и не полученная схема ХайТэк.

| Действие | Исполнитель/вход | Что меняется реально | Что не следует автоматически |
|---|---|---|---|
| Оценить найденный эпизод | Уполномоченный reviewer, event_ref + доступное evidence | Append feedback: actor, time, origin, model/rule/media version, результат, причина | Не получение мастером, не устранение, не gold label и не тренировка |
| Уточнить локальное правило | Владелец правила получает «неприменимо» + ссылку на policy | Отдельная задача проверить ROI/schedule/условие; новое правило публикуется отдельно | Старая детекция не обязана быть неверной; старую rule_version не переписывать |
| Уточнить качество наблюдения | Ответственный за камеру/архив получает «нельзя определить» | Камера/ракурс/видимость в очередь диагностики; событие сохраняет неизвестность | «Нет каски» не подтверждено; отсутствие изображения не true negative |
| Разрешить спор | Куратор с предметным знанием, оригинальные независимые мнения и разрешённый контекст | Curated result+основание; agreement/disagreement, автор и дата; unresolved допустим | Голос куратора не становится безошибочной истиной |
| Подать пропуск | Наблюдатель, camera/time interval, описание; при наличии media_ref | `miss_candidate`, origin=manual, отдельный от потока detector event | Нет количественного recall и доказанной причины «модель пропустила» |
| Передать в обучение | Назначенный data curator после предметного review и проверки прав | `eligible_for_curation`; затем отдельное `approved_for_training`, dataset provenance | Не каждый клиентский feedback и не каждый спорный клип годится для обучения |
| Изменить модель | training_strategy/model_stack + независимая evaluation + публикация/rollback process | Новая model_version, результат проверки и явное внедрение на LinQ | UI success/новая отметка не доказывают улучшение и исполнение на LinQ |

Минимальные результаты review: `подтверждено по доступным данным`; `ошибка детекции/связи объектов`; `правило неприменимо в этом контексте`; `дубль эпизода`; `недостаточно данных`; `спор/на проверке`. Причины не взаимоисключающие там, где одновременно плохой ракурс и неверное правило. `не просмотрено` — отдельное состояние; не равно отрицательному результату. Вместо длинного обязательного текста — короткий структурированный выбор, комментарий опционален, кроме особых процедур/спора. Отдельный куратор не обязан проверять каждую обычную меру до оперативного действия: его обязательность привязана к спорной метке/curation, не ко всему alert path.

Метка «ошибка детектора» требует видимого различимого признака и применимого в тот момент правила. «Модель не видит каску, но я знаю, что работник обычно носит её» — недостаточное основание. Отсутствие события при остановленной аналитике — потеря наблюдения; человек вне видимости — не доказанный пропуск детектора. Последствие каждого выбора видно: «сохранена оценка», «отправлено владельцу правила», «кандидат на разбор», а не «модель научилась».

## Независимый архивный путь [W2-EXPERIENCE-F16, INF]

Условие — разрешённый непрерывный архив, timestamps/версии правил и журнал работоспособности. Короткие event-only clips вроде F05 недостаточны для просмотра интервалов без детекции. Наличие у продукта cloud clips не доказывает наличие независимого архива нашего клиента.

1. Ответственный evaluation заранее фиксирует периметр: camera, период, классы, правило, годные условия видимости, единицу события/границы. Отбирает временные блоки из всего разрешённого архива по заранее заданному воспроизводимому плану, **не по входящей ленте**. Сохраняет sampling frame/seed/вес strata, если они используются; не подбирает «красивые misses» как количественную выборку.
2. Разметчик сначала смотрит выбранный блок без detector overlay и списка alerts; отмечает реальные наблюдаемые эпизоды, сомнения, видимость, outage, scene changes. Допустимость/безопасность исходных действий на видео проверяется по локальному правилу; воспроизводить опасное действие не требуется.
3. Второй предметный reviewer разбирает спорные/контрольные блоки, сохраняет исходные мнения; куратор разрешает или оставляет unknown. Для количественной проверки нужен обоснованный план контроля разметки от evaluation, не формальность «двое согласились».
4. Только после фиксации ручного списка сопоставить с detector output по заранее согласованному event matching. Раздельно учитывать модель, правило, ingest failure, потерю архива/uptime и внепериметровые события. Unknown не принудительно превращать в FN/TN.
5. Передать разрешённые curated примеры в data pipeline с происхождением; тестовую независимую выборку не смешивать с обучением. Нужны независимая проверка новой версии и trace исполнения обязательного LinQ.

Метрики review в MVP: число оценённых/всех полученных; распределение результатов **среди reviewed**; backlog/spor; кандидаты misses отдельно. Они не precision всей системы при selective review и не recall. Даже сплошная разметка выбранного блока устанавливает полноту только в данном периметре/видимости/периоде; оценку распространения/доверительные интервалы определяет evaluation, здесь не вычислялись.

## Вариант без архива и проверки для команды

Без независимого архива сохранить miss candidate с временем/местом/описанием и автором, с прикреплённым разрешённым кадром при наличии; «не подтверждено/материал недоступен» допустимы. Количественный recall убрать. Нельзя считать «0 зарегистрированных пропусков» отсутствием пропусков. Privacy Videoless (F05) усиливает эту границу: аналитика доступна, видеодоказательство недоступно.

Предлагаемый tabletop test, **не выполнен**: (а) каска перекрыта; (б) каска видна, но неверный ROI; (в) опасность кончилась до доставки; (г) наблюдатель сообщает miss без клипа; (д) operator/vendor labels расходятся; (е) камера жива, inference не работал. В каждом исходе проверить, что журнал сохраняет незнание/разногласие/версии, действие имеет владельца, а метрика не меняется на ложный recall. Успешный UI-test не подтверждает обучение.

Узкие поиски Intenseye/Protex/Voxel help, false-positive/missed-event registration не дали открытого пошагового HSE missed-event UI. Найденный патент не принят как работающий продукт; неофициальная копия учебного кейса не использована. Не утверждаем отсутствия функции. Закрытие: официальный help/API write contract или запись разрешённого workflow. Для нашего MVP достаточно явного журнала кандидатов; функциональный импорт архива зависит от видеоархитектуры/прав доступа, а не наличия кнопки.

→ CONTRACT: feedback origin/author/version, unreviewed/null отдельно; independent curated result; исход «недостаточно данных»; original/derived/media readiness. → evaluation: sampling frame вне очереди, FN candidate и outage отдельно, event matching и разметка. → training_strategy/datasets: curation permissions, спорные метки не gold, тестовая выборка отдельно. → video_architecture: доступный архив/clock/uptime; без него убрать recall. → linq_platform/model_stack: новая model_version требует реального execution trace, интерфейс его не создаёт.
