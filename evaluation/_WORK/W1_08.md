# W1_08 — Operating points, calibration and abstention

Prepared 2026-10-23. Scope: industrial video analytics evaluation; no organizer evaluator, target data, LinQ SDK/device configuration or measured model output was supplied. Examples below are proposed contracts and mathematical counterexamples, not measured project results. Source IDs and evidence types are explicit. No acceptance targets are inferred.

## Decision in one paragraph

Select and freeze the **whole delivered-alert policy** on development/validation data independent at the deployment-relevant camera/video/session grouping. Model checkpoint, preprocessing, candidate cutoff, NMS, person association, tracker, calibration, class thresholds, temporal confirmation, unknown handling and cooldown jointly determine that policy. Report held-out person/event recall, timely recall, delivered false alerts per evaluated camera-hour, latency and coverage alongside object metrics. A classifier probability calibrated for one population/unit is not automatically a probability that a timely, correctly associated event alarm is useful. Calibration helps interpret a specified score; it does not specify the operational tradeoff or repair unseen events.

## Supported findings

**W1-08-F01 — Published classification result, not a video guarantee.** Guo et al. define confidence calibration through correctness conditional on confidence; their ECE weights binwise absolute confidence–accuracy gaps by bin occupancy. They fit positive scalar temperature T on validation logits via NLL, using softmax(z/T); this preserves the within-example argmax. Their experiments concern image/document classification. They report temperature scaling often effective, with a Reuters exception; this is not a theorem of calibration on a new camera or event pipeline. [W1-08-S01, §§2, 4.2, 5]

**W1-08-F02 — Documentation.** Scikit-learn separates estimating scores from deciding actions. `TunedThresholdClassifierCV` selects a threshold to optimize a chosen scorer; default balanced accuracy is a software default, not an industrial objective. Its default stratified fivefold CV does not encode camera/session independence. `cv='prefit'` requires separate threshold-tuning validation data rather than reuse of classifier training data. The positive class and scorer parameters must be explicit. [W1-08-S02, §§3.3.1–3.3.1.2]

**W1-08-F03 — Documentation.** A calibrator must see predictions independent of base-model fitting; otherwise confidence is biased. Scikit-learn's CV calibration avoids that fitting reuse, but the caller must choose appropriate folds. Absent classes in training or calibration folds produce problematic probability/calibrator behavior. Brier/log loss combine calibration with discrimination and outcome uncertainty, so a lower loss alone does not establish better calibration. [W1-08-S03, §§1.16.1–1.16.3]

**W1-08-F04 — Documentation and inspected code.** `precision_recall_curve` is binary sample classification, not detection/event matching. At real thresholds it uses score >= threshold, tied scores move together, and thresholds increase. The final (precision=1, recall=0) is a plotting endpoint with no threshold. Code warns and sets recall=1 at all actual thresholds when there are no positive labels; this convention must not become a claim of observed operational recall. See pinned `_ranking.py`, `_binary_clf_curve` lines 882–908 and `precision_recall_curve` lines 1019–1057. Code inspected, not executed. [W1-08-S04, S10]

**W1-08-F05 — Documentation and inspected code.** `calibration_curve` accepts binary positive-class probabilities; default five uniform bins differs from other ECE conventions. Uniform and quantile bins differ. Empty bins are omitted; returning fewer points does not mean those confidence regions were validated. The code uses `np.searchsorted` on interior edges and divides only nonempty bin totals. Explicitly pin boundaries and retain bin counts when implementing ECE rather than assuming the plot returns a complete histogram. [W1-08-S05, S09, `calibration_curve` lines 1032–1070; inspected, not executed]

**W1-08-F06 — Documentation.** Scikit-learn 1.7.2 Brier loss is mean squared probability error. Binary customary scaling is [0,1]; multiclass sum-of-squares is [0,2]. `scale_by_half='auto'` (added in 1.7) rescales only binary cases; `labels`, class column order and positive label matter. Comparisons must record scaling and class set. [W1-08-S06]

**W1-08-F07 — Published counterevidence.** Ovadia et al. evaluate uncertainty on classification distributions with shifts/corruptions and OOD inputs. Their experiments show that calibration on held-out in-distribution examples does not ensure calibration under shift; temperature scaling can deteriorate under shifted data. This directly limits extrapolation from an in-domain calibration plot. Their results do not quantify this project's degradation or establish an alternative model as sufficient for PPE alarms. [W1-08-S07, §§2–4, particularly §4.1 and Fig.1]

**W1-08-F08 — Published formal setting.** Geifman and El-Yaniv define selective classification using prediction f and acceptance g: reject means “don't know.” Coverage is accepted probability mass and selective risk is loss on accepted examples divided by coverage. Their risk-control setting assumes labeled examples sampled i.i.d. from a fixed distribution. Its guarantees cannot be transferred by treating consecutive video frames as independent samples or silently changing the target to delivered events. [W1-08-S08, §§2–3]

**W1-08-F09 — Documentation.** Torchvision 0.23 NMS suppresses lower-score boxes when IoU > the specified threshold, so lowering this IoU threshold increases suppression. Exact score ties may select different boxes on CPU/GPU. This makes ordering, equality cases and runtime version relevant to association and subsequent events; do not conflate NMS IoU threshold with confidence threshold. [W1-08-S11]

## Proposed selection protocol (own protocol; W1-08-P01)

1. **Fix truth and deployment population first.** Define classes, persons, visible/unknown states, zones and episode starts/ends; define event matching, timeliness deadline reference, duplicates and ignore intervals. Decide known-camera future-time versus new-camera evaluation. Preserve grouped independence in calibration, selection and final testing. No legal obligation or protection correctness is inferred solely from image recognition.
2. **Declare the search unit.** One candidate is the complete configuration theta: model/weights and input processing; candidate confidence floor; NMS class mode/IoU/ties/max outputs; person/PPE association and tracking; calibrator and fitting subset; per-class decision thresholds; window measured in seconds or explicitly sampled frames; confirmation, hysteresis, missing-frame reset, cooldown and alert delivery. Record search budget/list and all tried candidates. Retuning any of these after test inspection is another selection round.
3. **Use train/development, calibration, policy-selection validation and untouched test roles.** These may be grouped folds rather than four huge datasets. When data are scarce, grouped nested/out-of-fold fitting can reuse data efficiently while keeping the predictions used to evaluate a choice independent of that choice's fitting. Do not mechanically use random frame CV. Jointly fitting a calibrator and selecting thresholds on one validation set is allowable as development, but that same score is optimistic as final evidence; test remains untouched. Final refitting changes the predictor and requires the frozen calibration/threshold recipe to match that refit.
4. **Fit calibration only for a named target/unit.** Example: probability of absent helmet for an observable GT-matched person's crop versus probability that a post-NMS candidate is a correctly localized helmet. Those targets need different GT and denominators. Event correctness can only be calibrated after defining candidate events, matching, horizon and duplicate ownership. A candidate-event calibrator excludes missed events by construction: separately count all GT episodes and misses. Do not train on GT-oracle person crops and label confidence calibrated for the complete detector pipeline.
5. **Replay continuous validation video for each policy.** Save object/person results for diagnosis, but choose operational settings using the complete event/delivery results. Cached raw predictions are useful only if their retention floor and output cap do not discard candidates needed for an alternative setting. Changing NMS after caching post-NMS detections cannot recover suppressed boxes. Temporal tuning on isolated positive clips cannot estimate camera-hour workload.
6. **Select by stated utility/constraints, not a magical 0.5 or maximum F1.** Owner supplies recall/timeliness priorities and tolerated alert/review workload, or the team reports a validation Pareto table and declares a provisional choice. Example symbolic optimization: maximize timely event recall subject to a specified false-alert rate, minimum analysis/decision coverage and latency requirement; alternatively report all tradeoffs when no constraint is supplied. This is not a supplied numerical requirement. For each class, show denominators and constraints; macro averages can hide a failed rare class. Per-class thresholds are extra fitted parameters and require enough independent relevant evidence; unsupported class-specific estimates remain unknown.
7. **Freeze before test.** Store config/artifact hashes, split manifest, calibrator, code/library versions, exact comparisons (>= versus >), timestamp units, sorting/ties, candidate floor and event matcher. Evaluate once on final target-relevant held-out data. If findings prompt redesign, label the set development and obtain fresh independent evidence or narrow the claim. Failed constraints are reported, not “fixed” by test threshold tuning.

## What to measure and keep in the denominator (W1-08-P02)

| Output | GT and counting unit | Numerator / denominator and boundary rules |
|---|---|---|
| Person state PR | Observable labeled person-times; fixed sampling/weighting, association rule | TP/(TP+FP), TP/(TP+FN). Unmatched persons must appear in complete-chain miss accounting; conditional matched-person scores are labeled conditional. Unknown GT is separately counted, not relabeled safe. |
| Event operating point | GT episodes and delivered alert records under frozen one-to-one matching | TP alerts/(TP+FP alerts); matched GT episodes/all eligible GT episodes. Duplicates consume delivered workload and matching policy determines FP. Timely recall requires qualifying matched delivery within declared deadline. |
| Workload | Reviewed continuous eligible camera-time | Delivered false alerts / evaluated camera-hours; also all delivered alerts/hour and review requests/hour. Record coverage/dropped time to prevent “improvement” by processing less. No camera-hour inference from class balance of selected clips. |
| Reliability/ECE | Named binary outcome or multiclass top-label correctness and held-out score unit | For bins B: ECE=sum |B|/N * abs(mean probability - outcome fraction). Dimensionless [0,1], or percentage points if multiplied by 100. State bin edges, top-label/classwise target, N and per-bin counts; empty bins contribute no observations, N=0 is unavailable. |
| Brier | Fully labeled score units, explicit binary or multiclass convention | Binary sum (p-y)^2/N; dimensionless [0,1]. Label unknown is excluded from this labeled-outcome computation but its count/coverage remains visible. N=0 unavailable; prevalence and weighting must match comparison. |
| Abstention | All eligible person decisions or camera-time under the chosen unit | Coverage=accepted/all eligible; conditional error=errors among accepted/accepted. Zero accepted => conditional risk unavailable, coverage zero. Also report total positive episodes detected, missed or unobservable and review burden. |

With no positive GT episodes, recall and timely recall are **not estimable** from that stratum. With no delivered predictions, operational precision is undefined, not evidence of perfect precision; workload can be zero with positive eligible exposure. Zero exposure leaves rate undefined. Pooled counts weight busy cameras/classes more; show pooled and per-camera/per-class counts rather than implying a macro average is pooled precision. Sampling weights must reflect the intended population; weighting frames does not create independent episodes.

## Failure cases and exact boundary tests (own inference/examples; W1-08-C01–C08)

- **C01, frame calibration does not multiply across time.** Construct 100 equal-length tracks of ten frames, all scored 0.9 for a violation. Ninety tracks truly violate throughout; ten are persistently wrong (e.g., occlusion). Frame predictions are exactly calibrated at 0.9. Requiring three consecutive scores leaves 90% of event decisions correct, not 99.9%. Independence of repeated evidence was never supplied. Longer persistence also delays true detection and can remove short GT episodes. Python arithmetic executed locally; no classifier was run.
- **C02, perfect crop classifier cannot recover absent persons.** If all provided crops are correct but the person detector misses one dangerous episode entirely, crop calibration/reliability remains excellent. No crop score exists for that missed episode, and the complete-chain event recall decreases. Likewise a correctly detected helmet belonging to the neighbor gives wrong person ownership despite object correctness.
- **C03, calibration without usefulness.** A constant probability 0.01 on a population with exactly 1% positives is calibrated, with binary Brier 0.0099. At threshold 0.5 it detects none. Low aggregate ECE/Brier is not a recall requirement. Conversely, a coarse bin can hide subgroups with opposite calibration gaps; rare-camera errors contribute little pooled mass.
- **C04, prevalence sensitivity.** Hypothetical binary decisions with TPR=0.9, FPR=0.01 have precision 47.62% at 1% prevalence and 8.26% at 0.1% prevalence: TP share pi*TPR divided by pi*TPR+(1-pi)*FPR. This calculation holds fixed class-conditional decision behavior, not probability calibration after shift. It is neither a project estimate nor a camera-hour false-alert conversion.
- **C05, no object implies unknown or negative evidence?** Hidden head, frame loss or missing person cannot automatically mean absent PPE. A low “helmet present” score is not by itself a calibrated “helmet absent” probability. A three-way violation/safe/unknown contract needs truth for visibility and a declared action for unknown; rejecting uncertain negatives can hide true violations if excluded from recall.
- **C06, selection changes population.** Calibrating all person crops then filtering by detector score/NMS/visibility changes the retained set. Calibrating event candidates before changing temporal merging/cooldown changes both positive meaning and candidates. Recheck reliability for the actual selected policy. A single-label softmax's unchanged argmax does not imply unchanged thresholded detections or alert timestamps; multiclass temperature scaling need not preserve rankings of a class score across different samples.
- **C07, equality and time.** Include scores exactly at threshold, IoU exactly at NMS cutoff, tied scores, one score just above/below after export, onset exactly on deadline, exactly K confirmations, variable frame intervals, dropped frames inside a window and cooldown expiry equality. Specify whether unknown pauses, resets or expires persistence. Count a policy's confirmation/delivery time separately from GT onset. Sliding windows based on received frame count can represent different physical duration under load.
- **C08, abstention is an action.** Unknown GT, model rejection, OOD flag and unavailable video are distinct reasons. Route review requests separately from violation alarms; a human review queue has workload/latency too. A high-confidence threshold cannot guarantee catching novel hazards or shift: OOD may be confidently wrong. Do not inherit selective-classification i.i.d. guarantees for correlated videos or changed cameras.

### Additional temporal-selection boundary (W1-08-C09; own inference)

A frame-score PR sweep assumes fixed scored samples. A full alert policy can change the samples themselves: raising a threshold may remove an early trigger, shift confirmation later, alter episode merging or free a cooldown slot for a later alert. Delivered false-alert counts and timed event matches therefore need not vary monotonically with confidence threshold. For example, if a true early trigger starts a shared cooldown that suppresses two later spurious triggers, removing the true trigger can allow those spurious triggers (depending on cooldown duration and spacing). This is an intentionally policy-dependent counterexample, not a recommended global cooldown design. Recompute event records/matching for every joint configuration rather than apply `precision_recall_curve` to a fixed list and assume it simulates temporal replay. Maintain separate per-class and per-person cooldown contracts if those are the intended semantics; freeze and test cross-class/person interference explicitly.
