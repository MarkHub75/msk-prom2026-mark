## Exact COCO bbox contract

### Inputs, units and parameters

**W1-02-F03 (S01–S03 code):** Initialize explicitly with `iouType='bbox'`; default constructor type is `segm`, so relying on default is a different evaluation. `bbox` is `[x,y,width,height]`, with continuous rectangle extents: `bbIou` computes intersections from x+w/y+h, without pixel-inclusive `+1`. Coordinates must be restored to the GT image coordinate system after resize/letterbox. This code path does not establish a robust validation or clipping policy for invalid boxes. Do not assume normalized values, xyxy, negative dimensions or wrong class IDs will be diagnosed helpfully.

Detection results carry `image_id`, `category_id`, bbox and confidence `score`. `loadRes` asserts detection image IDs belong to the GT image set and assigns detection IDs; its bbox branch derives detection area as width×height. GT `area` comes from annotations, not recomputation here, and can be segmentation area even in bbox evaluation. Therefore changing GT area conventions can change AP by size without changing bbox IoU.

**W1-02-F04 (S01 Params):** Defaults: ten IoU thresholds 0.50, 0.55, …, 0.95; 101 recall samples 0, .01, …, 1; category-aware evaluation (`useCats=1`); caps `[1,10,100]`; area ranges in squared image pixels: all `[0,10^10]`, small `[0,1024]`, medium `[1024,9216]`, large `[9216,10^10]`. The tests use `< lower` or `> upper`, so boundaries 1024 and 9216 occur in both neighboring bins. This is exact code behavior, not the common informal disjoint-bin description. “Small” is not a physical-size claim or universally appropriate industrial-camera stratum.

### Per-image matching

**W1-02-F05 (S01 evaluate/computeIoU/evaluateImg):** Matching occurs per selected image and category, separately for every IoU threshold and area range. Detections are sorted descending by score with stable mergesort and capped at the largest maxDets. For each score-ranked detection, a greedy scan finds the highest qualifying IoU among available GT, favoring nonignored GT over ignored GT. A normal GT can be consumed only once at each threshold; crowd GT may match multiple detections. This is not a global Hungarian assignment. Qualifying comparison is effectively `IoU >= threshold`; threshold initialization uses `min(t,1-1e-10)`. Equal-IoU candidates can replace an earlier candidate because only strictly lower overlap is skipped. Equal score order inherits input order within images; accumulated ties inherit image concatenation order (evaluation image IDs are uniqued/sorted). Preserve output ordering for exact reproducibility.

**W1-02-F06 (S01/S03, unusually important):** `_prepare` first reads/defaults a GT `ignore` field, then immediately overwrites it with the value of `iscrowd` (or false if absent). Thus `ignore=1, iscrowd=0` does **not** provide an arbitrary ignored region in this pinned bbox implementation. Later `computeIoU` directly indexes `iscrowd`, so normal bbox annotations should supply it. Area-range exclusion adds `_ignore` independently. A detection matching ignored GT is ignored; an unmatched detection outside the current area range is ignored. Ignored detections contribute neither TP nor FP; ignored GT is removed from the positive denominator. Crowd overlap is intersection / detection area rather than ordinary intersection / union (`bbIou`), allowing several contained detections to be absorbed by one crowd region. Do not encode every ambiguous PPE annotation as crowd without an explicit semantic policy and compatibility test.

### Accumulation, denominators and summary

**W1-02-F07 (S01 accumulate):** For each category/area/cap, retained detections from all evaluated images are concatenated and globally sorted by confidence, again stable mergesort. Nonignored matched detections count TP; nonignored unmatched detections count FP. Cumulative recall = TP / number of nonignored GT; cumulative precision = TP/(TP+FP+machine-spacing). This is pooled per-class ranked detection evaluation, not the average of frame-level precision values. No true-negative count exists in this AP calculation.

Precision is replaced by its right-to-left monotonic envelope. At each recall sample, `searchsorted(..., side='left')` takes the first achieved recall at or above that sample; unattainable recall samples retain zero. AP is the arithmetic mean of these 101 sampled precision values, then mean over selected IoUs and valid categories for the requested area/cap. It is not simply precision at score .5 or exact integral over all unique recall breakpoints. AR uses the final attainable recall for each IoU and averages valid entries; AR@100 is not a deployed thresholded recall.

**W1-02-F08 (S01 empty cases):** If a category-area setting has zero nonignored GT over the evaluation image set, precision/recall remain sentinel -1, even when there are detections. Summary excludes values <= -1. Consequently a class absent throughout the test can yield no AP penalty from its false predictions; separately report its FP count and exposure. If that class has GT somewhere, predictions on its negative images are pooled FPs and can affect AP. If GT exists but detections are absent, AP and recall are zero. An image-category with neither GT nor detection returns `None` and adds no TN benefit. All-crowd GT similarly has no positive denominator. An all-empty **result list** is an additional loader problem: S02 indexes `anns[0]` and will raise rather than directly construct empty predictions. A harness must explicitly support the no-prediction case and test its wrapper.

**W1-02-F09 (S01 summarize):** Standard bbox summary is 12 numbers: AP@[.50:.95], AP50, AP75, AP small/medium/large, AR@1/@10/@100, AR small/medium/large at 100. Values are fractions on [0,1] before display scaling. Frameworks may show percent [0,100]; record units. Main summary AP uses default helper cap=100, while several other entries index `params.maxDets[2]`. `summarize` explicitly assumes defaults: editing cap list/thresholds and trusting unchanged headline labels can give invalid or empty summaries. For custom settings explicitly select and label tensor entries instead of assuming the standard printed vector remains meaningful.

**W1-02-E02 (own inference from formulas, not run):** A correct xyxy box `[10,20,30,40]` mistakenly passed as xywh becomes rectangle x=10..40, y=20..60 rather than x=10..30, y=20..40. Its size, IoU and size stratum change despite an apparently plausible JSON. Swapped category mapping yields unmatched GT and wrong-class detections; an out-of-evaluation category can instead be filtered out. Validate IDs against the manifest rather than assuming contiguous zero-based IDs.

**W1-02-E03 (own inference from matching, not run):** A real but unannotated helmet, predicted correctly in a fully scored noncrowd region, becomes FP unless it accidentally matches another compatible GT. It does not establish that the visual detector is wrong. On an image declared empty, every retained evaluated-category prediction is unmatched; whether that means a valid negative test or annotation omission is external truth-contract evidence.

**W1-02-E04 (own inference, not run):** For 101 noncrowd positive instances of one class in one image, cap=100 limits maximum recall to at most 100/101 even with otherwise perfect detection. Cap is per image-category for default useCats=1; it is not a global video or per-second cap. Candidate generation, NMS and model output truncation can impose lower caps before the evaluator sees detections.

## Relevant evaluator differences

**W1-02-F10:** Official VOC2012 §3.4.1 states that from 2010 AP integrates the monotonic precision envelope at unique recall changes; the earlier VOC method samples eleven recall levels. This differs from COCO's 101 samples and ten-IoU headline. S05's pinned `voc_ap` implements both variants. Its `voc_eval` uses pixel-inclusive xyxy area with `+1`, strict `ovmax > ovthresh`, global class confidence sorting with `np.argsort` without specified stable kind, and a `difficult` mask excluded from positive count. Detections on a best-matching difficult GT are ignored. It selects the highest-overlap GT first and counts a repeat best match as FP; it does not search for an alternative unused GT the way COCO's candidate scan can. Consequently even “AP50 with the same boxes” can differ because of coordinates, equality, difficult/crowd handling, ranking ties, and assignment—not only interpolation. The official document and this implementation should not be conflated as one pinned artifact.

No framework-specific “fast COCO equivalent” or model-library mAP is assumed equivalent without a versioned implementation check. No organizer evaluator or installed package was supplied, so exact future official metric compatibility remains unknown.
