# LinQ: рабочий доступ рядом с Happ

Доступ к LinQ проверен 24 октября 2026 года.

Открыть Jupyter: http://127.0.0.1:8888/
Вход: учётная запись Jupyter, выданная организаторами.

Подключить после перезагрузки или обрыва: дважды нажать Connect-LinQ.cmd.
Отключить только туннель LinQ: дважды нажать Stop-LinQ.cmd.
Хранить оба CMD-файла рядом с LinQ.ps1.

Рабочая схема:
Этот компьютер -> SSH на ноутбук Матвея -> его OpenVPN -> hackathon.lin-q.ru:80.
Туннель слушает только 127.0.0.1:8888 и использует ранее настроенный SSH-ключ.
Happ остаётся включённым на SAMARKAND VLESS. Для туннеля его настройки не менялись
(правило для OpenVPN, добавленное раньше, описано ниже).

Условия:
- Ноутбук Матвея включён, подключён к этой локальной сети и к OpenVPN LinQ.
- Его текущий адрес: 192.168.1.31. При изменении адреса его нужно исправить в LinQ.ps1.
- На этом компьютере доступен существующий ключ %USERPROFILE%\.ssh\linq_matvey.
- Туннель работает в фоне. После перезапуска компьютера запустить Connect-LinQ.cmd.

Что проверено:
- GET / через туннель перенаправляет на страницу входа JupyterHub и возвращает HTTP 200.
- Учётные данные Jupyter из локального .env принимаются: открывается /hub/home.
- Пользовательский сервер Jupyter уже запущен. Вычисления и ноутбуки при проверке не запускались.
- HTTPS на внутреннем порту 443 отвергается; рабочий сервис отвечает по HTTP на 80.
- Данные идут по существующему SSH-туннелю, затем по OpenVPN Матвея.

Прямой OpenVPN на Windows пока не подключён:
TLS-рукопожатие успешно завершается, затем сервер закрывает соединение.
На Arch у Матвея работают те же OpenVPN 2.7.8, OpenSSL 3.6.5 и профиль с теми же сертификатами.
Несовместимость этих версий не подтверждается. Причина отказа после TLS требует серверных логов
или согласованной проверки без параллельной сессии. Ограничение одной сессии остаётся гипотезой.
Работающий VPN Матвея не отключался и не менялся.

Что уже подготовлено для прямого OpenVPN на Windows (пригодится со вторым логином):
- Установлены OpenVPN Community 2.7.8 (профиль в %USERPROFILE%\OpenVPN\config\) и
  OpenVPN Connect 3.9.0 (профиль импортирован из secrets/linq/Hakathon.ovpn).
- Happ → Настройки → «Настройки прокси для приложений» → режим «Прямое подключение для
  выбранных приложений», в списке: OpenVPN\bin\openvpn.exe и из OpenVPN Connect —
  agent_ovpnconnect.exe, ovpnconnector.exe, OpenVPNConnect.exe. Без этого соединение до
  83.220.57.3 уходило через Happ и сервер не отвечал вовсе.
- В конфиге auth-nocache: после обрыва Connect снова спрашивает пароль
  («Required credentials are missing» — просто подключиться заново).
