# LinQ VPN: настройка на Windows рядом с Happ

Состояние на 2026-10-23. Секретов в документе нет: `.ovpn`, логин и пароль лежат в `secrets/linq/` и `.env` (оба в `.gitignore`).

## Что известно о сервере

- OpenVPN-сервер `83.220.57.3:1194/TCP` — MikroTik RouterOS (клиентский сертификат `Hackathon-common` выпущен RouterOS, CA `hackathon-CA`).
- Конфиг уже split-tunnel: `pull-filter ignore redirect-gateway`, `route 10.0.114.0 255.255.255.0`. Весь остальной интернет остаётся на Happ.
- Jupyter: `hackathon.lin-q.ru` → `10.0.114.30` (резолвится только через DNS VPN; узнано на Linux-машине с поднятым VPN).
- Клиентский сертификат общий на всех; логин/пароль — на команду.

## Что поставлено на Windows

| Компонент | Версия | Зачем |
|---|---|---|
| OpenVPN Community (GUI) | 2.7.8 | первый вариант; профиль в `%USERPROFILE%\OpenVPN\config\Hakathon.ovpn` |
| OpenVPN Connect | 3.9.0 | клиент из инструкции организаторов; профиль импортирован из `secrets/linq/Hakathon.ovpn` |

Оба MSI скачаны с официальных адресов, подпись OpenVPN Inc. проверена, у Connect SHA256 сверен с release notes.

## Правило в Happ (обязательно)

Happ (Xray TUN) перехватывает весь трафик, и соединение до `83.220.57.3` уходило за границу — сервер его сразу сбрасывал (0 байт ответа).

Решение: Happ → Настройки → «Настройки прокси для приложений» → режим **«Прямое подключение для выбранных приложений»**, в список добавлены:

- `C:\Program Files\OpenVPN\bin\openvpn.exe`
- `C:\Program Files\OpenVPN Connect\agent_ovpnconnect.exe`
- `C:\Program Files\OpenVPN Connect\ovpnconnector.exe`
- `C:\Program Files\OpenVPN Connect\OpenVPNConnect.exe`

Остальные приложения (включая доступ к Claude) по-прежнему идут через Happ. После правила TLS-рукопожатие с сервером проходит.

## Почему VPN на этой машине пока не поднимается

Симптом в обоих клиентах одинаковый: TCP открывается, сервер присылает сертификат, через ~1 с соединение закрывается (`Connection reset` / `NETWORK_EOF_ERROR`), до `Control Channel` дело не доходит.

Проверено и исключено:

- маршрут через Happ — обойдён правилом выше;
- версии TLS/шифры (`tls-cert-profile insecure`, RSA/DHE-наборы) — без изменений;
- срок и подпись клиентского сертификата — в порядке (до 2027-02-17, RSA-2048, sha256);
- логин/пароль в `.env` совпадают с выданными организаторами;
- сеть — тот же Wi-Fi, на котором VPN работает у Матвея (Arch Linux).

Наиболее вероятная причина: **тот же логин уже подключён на ноутбуке Матвея**, а MikroTik пускает одну сессию на логин и молча рвёт вторую. Подтвердить можно, только отключив его сессию на минуту.

## Варианты

1. **Второй логин от организаторов** — тогда OpenVPN Connect на Windows заработает напрямую, всё остальное уже настроено.
2. **Через ноутбук Матвея (выбран на хакатон).** SSH-ключ `%USERPROFILE%\.ssh\linq_matvey` добавлен в его `authorized_keys`. Туннель запускается вручную в отдельном окне:

   ```powershell
   ssh -i $env:USERPROFILE\.ssh\linq_matvey -N -L 127.0.0.1:8888:10.0.114.30:<порт> <user>@<ip_матвея>
   ```

   Порт уточнить у Матвея: с его машины `http://hackathon.lin-q.ru/` на `:80` не ответил за 10 с.
3. **OpenVPN в Docker** — не решает проблему одной сессии на логин; имеет смысл только со вторым логином.

## Как переподключиться (когда будет свой логин)

1. Happ не выключать; правило из раздела выше должно быть на месте.
2. OpenVPN Connect → профиль `83.220.57.3 [Hakathon]` → Connect → логин/пароль (вставлять копипастом).
3. Конфиг содержит `auth-nocache`, поэтому после любого обрыва Connect снова спросит пароль («Required credentials are missing» — это нормально, просто подключиться заново).
4. Проверка: `route print` — `10.0.114.0/24` через адаптер OpenVPN, маршрут по умолчанию через Happ не изменился; `Test-NetConnection 10.0.114.30 -Port 80`.

## Напоминание

На ночь отключить сон компьютера (Параметры → Система → Питание), иначе VPN и туннели отвалятся.
