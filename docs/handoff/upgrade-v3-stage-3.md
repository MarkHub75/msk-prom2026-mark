## 2. Что реализовано

- **`src/safewatch/calculator.py`** — одно чистое ядро без БД, сети и часов. Арифметика точная (`Fraction`): `ceil` не видит шума float, деньги округляются только на выходе (до копеек), нагрузка, ядра и месяцы — до 6 знаков.
  - Нагрузка К6: `load_of` (A95 через `scipy.stats.binom` с доводкой по CDF, `Top(k)` по delta, id по возрастанию; `idle`, `surge` с резервом `q = min(reserve, N)`; detector-only stride; CPU inclusive/split).
  - Подбор К7: `select` — ограниченный точный перебор `combos`, бюджет 2 млн комбинаций, иначе 409. Разбиение на ступени: CAPEX → серверы → платы → лишние чипы → id. Неизвестная цена не ноль: такие платы исключаются, иначе `technical_only`. При неизвестной цене сервера сначала минимизируются серверы.
  - Инвентарь: `provided`, `estimated` (план текущих камер), unresolved.
  - Деньги К8: три уровня, правило `0 × null = 0`, поддержка от CAPEX, электроэнергия `Вт/1000 × ч × тариф` только добавленного оборудования, выгоды с переключателями.
  - TCO, ₽/камера/мес, срок окупаемости (больше 36 месяцев остаётся числом), оба порога, 5 ступеней, кривая 5…500 (greenfield, тот же движок).
  - Evidence К5 со стабильными ключами; статусы `ready`, `estimated`, `partial`, `empty`.
  - Валидация К3/К4/К10; legacy-адаптер К12.
- **`services`**:
  - `calculator_defaults` (async): тела и пресеты из конфига, каталог моделей по `config/models.yaml` (вес только у подписанных, у остальных `null`), источники конфига и свои (`argus_linq_artifacts`, `argus_linq_jobs`, `argus_journal`).
  - Замеры: активность — медиана по камерам доли кадров детектора LinQ `fake=0` с человеком `score ≥ high_thresh`, один артефакт на камеру и видео. Файлы читаются в `to_thread` с кэшем по артефакту, id — хэш содержимого. Пропускная способность площадки и RTT — по задачам LinQ, события — по журналу.
  - `_system_groups`: модели по включённым правилам камер. Нет модели → `missing:<класс>` с неизвестным весом и `SCENARIO_MODEL_MISSING`; для правил «любой из классов» достаточно одной модели.
  - Разбор тела: v2 строгий и закрытый, legacy прежний. Роль проверяется до тела, расчёт идёт в `to_thread`.
- **`api`**: формат выбирается по `?format=legacy|v2`, тело читается сырьём. OpenAPI: тело и ответ `anyOf`, у параметра `format` есть enum. Ответ сериализуется своей моделью: v2-поля не теряются. `export.pdf` → 501 `not_implemented`.
- **Конфиг** `calculator_v2` (`config.CalculatorV2Config`, строгие типы запроса): значения К9, источники К11, рыночные ориентиры, подписи и источники полей. Владелец меняет их в `config/user.yaml` без кода.
- **Фронт** (минимально, дизайн не трогал):
  - `schema.d.ts` перегенерирован;
  - в `api/types.ts` добавлены алиасы v2;
  - новый `api/calculator.ts` — типизированные `rolloutLegacy/scaleLegacy/rolloutV2/scaleV2` с дискриминацией по `format`;
  - `Calculator.tsx` вызывает `rolloutLegacy/scaleLegacy` (2 строки);
  - `fixtures/calculatorV2.ts` — пример К14.1 для тестов;
  - `V5.test.tsx` получил поле `v2`.

## 5. API delta для Егора

1. `GET /api/calculator/defaults` → новое обязательное поле `v2: DefaultsV2`. Тела форм: `v2.rollout`, `v2.scale`, пресеты — `v2.presets[].rollout`. Справочники: `models`, `boards`, `sources`, `market`, `measurements`, `limits`, `notices`, `features`, `system_profile`.
2. Расчёт: `POST /api/calculator/rollout?format=v2` (роль `management`) и `POST /api/calculator/scale?format=v2` (`management`/`admin`), тело — целиком отредактированное `v2.rollout`/`v2.scale`. В коде — `rolloutV2(body)` / `scaleV2(body)` из `frontend/src/api/calculator.ts`, они возвращают уже суженный `ResultV2`. Без `?format=v2` работает прежний legacy.
3. «По вашим камерам»: `cameras = {source: "system", camera_ids: null, include_seed: false}`. «Подставить активность»: скопировать `measurements[key=activity_share].value` и `.id` в `load.activity_share` / `load.activity_measurement_id`; при ручной правке доли id сбросить в `null`.
4. Графики: ступени — `result.steps[]` (5 штук, `available=false` у трекера); кривая — `result.scale_curve.points[]` (7 точек, подпись `scale_curve.note`: greenfield, не добавочные расходы). Три уровня — `result.tiers[]`: строки `capex_lines`/`opex_lines`/`benefit_lines`, итоги, `payback`, `severe_threshold`, `board_price_threshold`.
5. `null` + `status`: `null` означает «нет данных / неприменимо», причина — в `reason` и `missing[]`; `0` — известный ноль. Статус результата `ready`/`estimated`/`partial`/`empty`; `warnings[]` и `missing[]` — `code` и русский `message`.
6. Ошибки: 422 `validation`, `details.field` — точное поле без `body.` (например `load.activity_share`), `details.reason` — код К10. Для query — `field: "format"`. 409 `calculation_limit`, 400/403 — роль.
7. Capabilities: показывать трекер, PDF и офлайн-экономию только при `features.tracker.available` / `features.pdf_available` / `features.offline_economy != null`. Сейчас всё выключено, PDF отвечает 501.
8. Убрать из живого расчёта локальные формулы `calculatorEconomics.tsx` (`INDUSTRY_RATE`, `breakEven`, `tierReduction`) и `calculatorExample.ts`. Пороги, рынок и подсказка Росстата приходят с сервера (`tiers[].*_threshold`, `market`, `assumptions`/`sources`). Пример К14 допустим только как подписанный статический пример.
9. Отличие от примера К14.1: ключи evidence моделей — `catalog.models.<id@version>.work_units`, а не `catalog.models.detector.work_units`. Это необязательное поле справки, схема та же. В `models` живого ответа перечислены все модели реестра, у неподписанных `work_units: null`.
