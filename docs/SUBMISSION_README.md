# АРГУС — видеоаналитика промышленной безопасности на LinQ

Открой#Моспром 2026 · кейс ООО «ХайТэк» · инференс на российских ИИ-ускорителях LinQ.

АРГУС смотрит записи заводских камер и находит опасные ситуации: бег у техники, человека в опасной зоне, падение и неподвижность, телефон в опасной зоне, пересечение ограждения, проход под опасной зоной. Он поднимает тревогу оператору, передаёт её мастеру смены и ведёт журнал для охраны труда.

```text
запись камеры → детекции людей и поз на LinQ → треки и эпизоды → правило сцены → одно событие → оповещение → журнал
```

- **Бэкенд `safewatch`** (Python 3.12, FastAPI, SQLite): видео, задачи анализа, LinQ, правила, события, WebSocket. Источник истины — [`tech.md`](tech.md), контракт — [`contract/`](contract/) (1.1.0).
- **Фронт** (React + Vite) — [`frontend/`](frontend/), пять ролей, тексты на русском.
- **Модели:** YOLOv8n 640 (люди) и YOLOv8n-pose 640 (позы): программы `.tpu` для LinQ и ONNX-хвосты, [`config/models.yaml`](config/models.yaml); без LinQ — тот же YOLOv8n на CPU (onnxruntime).

## Запуск

### 1. Из `main` с демо-пакетом — рекомендуется

Нужны Node 24 и Python 3.12 с [uv](https://docs.astral.sh/uv/). Ключи LinQ и VPN не нужны: детекции уже посчитаны на LinQ TPU и лежат в демо-пакете.

```sh
git clone https://github.com/MarkHub75/msk-prom2026-mark.git argus
cd argus
uv sync
npm ci --prefix frontend && npm run build --prefix frontend
```

Демо-пакет `argus-real` (47 МБ: два реальных ролика с завода и детекции LinQ TPU, `fake: false`) лежит в релизе **[demo-argus-real](https://github.com/MarkHub75/msk-prom2026-mark/releases/tag/demo-argus-real)**. Распакуйте `argus-real.zip` в корень репо, чтобы получилось `data/demo/argus-real/manifest.json`, и укажите пакет в `config/user.yaml`:

```yaml
demo: {pack: data/demo/argus-real}
```

```sh
uv run safewatch serve --seed
```

Открыть http://127.0.0.1:8000, роль «Оператор» → Сектор 1 → Камера 1.3. На ~17-й секунде ролика приходит красная тревога «Опасное сближение с техникой»; дальше — сценарий показа ниже. `serve --seed` создаёт ещё 4 сектора, 8 камер и 240 исторических событий для журнала и аналитики; камеры сида без видео честно показывают «Нет наблюдения».

Эфир крутит ролики по кругу, и тревога повторяется каждые ~20 с: перед показом нажмите «Администратор → Демо → Остановить все эфиры» и запускайте сценарий кнопкой «Проиграть один раз».

Без демо-пакета: `SAFEWATCH_FAKE=1 uv run safewatch serve --seed` — фейковый инференс, рамки синтетические (интерфейс подписывает «Демо · синтетические детекции»); свои ролики — «Администратор → Камеры → Настроить → Видео». С настоящим LinQ: `.env` по образцу `.env.example` (`INFERENCE_BACKEND=linq`, ключи `LINQ_*`, SSH-туннель к Jupyter); на CPU — `INFERENCE_BACKEND=local` и ONNX-модели по [`tools/linq/README.md`](tools/linq/README.md). Проверка окружения: `uv run safewatch doctor`.

Режим разработки фронта с горячей перезагрузкой: `npm run dev --prefix frontend` (прокси `/api` и `/ws` на :8000), подробности — [`frontend/README.md`](frontend/README.md).

### 2. Docker — ветка `build/docker`

```sh
git clone -b build/docker https://github.com/MarkHub75/msk-prom2026-mark.git argus
cd argus
docker compose up --build
```

Открыть http://127.0.0.1:8000. Compose включает `SAFEWATCH_FAKE=1`, `.env` не нужен. Сборку проверяет CI (`.github/workflows/docker.yml`). Фронт в этой ветке — версия 2026-10-24 20:38, без демо-пульта и телефонных экранов; актуальный фронт даёт способ 1.

### 3. Публичное демо в браузере — ветка `front/pages`

Статическая сборка фронта со сценарием «жёлтое → красное → мастер → журнал», который целиком живёт в браузере: ни бэкенда, ни установки. Адрес после публикации:

**https://markhub75.github.io/msk-prom2026-mark/#/operator**

Сценарий и кадры заготовлены вручную (ручная разметка, не детекция модели); экраны аналитики, «Системы», настройки камер, загрузки и экспорта отвечают «Недоступно в статическом демо». Workflow `Pages` на каждый push в `front/pages` собирает сайт и прогоняет Playwright-смоук (зелёный 2026-10-24). **На 2026-10-24 GitHub Pages в репозитории не включён** (`gh api repos/MarkHub75/msk-prom2026-mark/pages` → 404), поэтому адрес пока не открывается. Включить может владелец: Settings → Pages → Source → GitHub Actions, затем перезапустить последний `Pages` по `front/pages`. Инструкция — `frontend/src/static-demo/README.md` в ветке.

## Роли

Логина нет: роль выбирается в шапке, каждый запрос несёт заголовок `X-Role`, сервер проверяет права по нему.

| Роль | Что делает |
|---|---|
| Оператор | диспетчерская по секторам, монитор камеры с HUD и зонами, очередь тревог; красная тревога захватывает экран; подтверждает событие или отклоняет как ложное; с телефона `/m/operator` (тревоги, камеры, смена), установка на телефон |
| Мастер смены | поручения на телефоне: «Принял, иду» → «Принятые меры» → «Решено», смена |
| Охрана труда | журнал с фильтрами, CSV и PDF-отчёт, правила по камерам, аналитика, нарушители и бригады, датасет ложных срабатываний |
| Руководство | аналитика по неделям, калькулятор окупаемости |
| Администратор | камеры и секторы; настройка камеры: видео, эфир, калибровка, зоны, правила; «Система»: бэкенд инференса, замеры LinQ, демо-пакеты; демо-пульт |

## Сценарий показа (~3 минуты)

Подготовка (способ 1 с демо-пакетом): дождаться, пока «Администратор → Камеры» покажет записи; в «Демо» проверить строку пакета и нажать «Остановить все эфиры» (после обработки бэкенд сам запускает эфир по кругу, и события копятся); в шапке ввести имя сотрудника («Указать имя»).

1. **Оператор → Диспетчерская.** Секторы, камеры, очередь тревог. В ленте только события эфира.
2. **Администратор → Демо → «Проиграть один раз»** на камере с нарушением: запись идёт как живая камера, события публикует конвейер в момент, когда эпизод «случается» в эфире.
3. **Оператор.** Событие появляется в очереди, красное захватывает экран. «Подтвердить» (клавиша 1) — событие уходит мастеру. Карточка: доказательный кадр с рамкой, клип, «почему» (правило и измерения), история эпизода.
4. **Мастер (телефон или узкое окно).** «Открыть и принять» → «Принял, иду» → «Принятые меры» → «Решено».
5. **Охрана труда → Журнал.** Событие со всей историей и мерами; CSV, PDF. **Аналитика** и **Руководство** — тренды по неделям на сидовых данных (подписано «включая демо-данные»).
6. **Администратор → Система.** Бэкенд инференса и его проверка, задачи с замерами (кадр/с, RTT p50/p90), демо-пакеты и откуда их детекции.

Без бэкенда тот же сюжет проходит статическое демо (способ 3) кнопками сценария.

## Честный статус LinQ

**Что запускалось на LinQ.** Детектор YOLOv8n 640 и поза YOLOv8n-pose 640 скомпилированы в программы `.tpu`; постобработка — ONNX-хвосты на CPU сервера. Доступ — Jupyter LinQ через SSH-туннель; площадка общая (~37 команд), поэтому RTT включает очередь и сеть, а не только ускоритель. Живые прогоны:

| Прогон | Детектор | Поза |
|---|---|---|
| 14:52, проверка адаптера | ~12,4 кадр/с, RTT p50/p90 ~290/~380 мс | ~12,7 кадр/с |
| 20:05, сборка демо-пакета `argus` (S17) | 7,2 кадр/с, RTT p50/p90 495/693 мс | 9,0 кадр/с, RTT p50/p90 399/564 мс |
| 25.10 01:25, демо-пакет `argus-real`, ролик 20,8 с (261 кадр, шаг 2) | 10,6 кадр/с, RTT p50/p90 308/420 мс | 10,5 кадр/с, RTT p50 297 мс |

Детекции прогонов S17 и `argus-real` лежат в демо-пакетах: показ с пакетом использует их без обращения к LinQ, шапка и «Система» подписывают его «детекции LinQ». Те же замеры (кадр/с, RTT p50/p90, загрузка, всего) показывает «Система» по каждой задаче.

**Что не получилось.** Два ночных прогона (S2, R5) LinQ не ответил: у очереди `input` было 0–1 консьюмер вместо 16, обработано 0 кадров. В часы нагрузки RTT p50 доходил до ~10,6 с на запрос; таймауты и повторы задач рассчитаны на это. Живого потока камер через LinQ не было.

**Что в репозитории.** Программы `.tpu` и ONNX-хвосты в git не лежат, демо-пакет `argus-real` — в релизе (способ 1). Без них:

- `SAFEWATCH_FAKE=1` — фейковая оболочка LinQ: рамки и треки сгенерированы и на кадре не обязаны совпадать с человеком; интерфейс показывает «Фейк-режим» и «Демо · синтетические детекции»; замеры на «Системе» тогда от фейка, а не от TPU;
- `INFERENCE_BACKEND=local` — тот же YOLOv8n на CPU (onnxruntime): им показан «живой» кусок финала;
- пакет, собранный на фейке (`--allow-fake`), подписан «фейк» в шапке, в демо-пульте и на «Системе».

**Прочая синтетика.** 240 исторических событий сида (`is_demo`, фильтр «Демо-события») — для журнала и аналитики, в ленту оператора не попадают. Публичное демо и сценарный мок `demo/checkpoint` — ручная разметка, подписано на экране. «Эфир» — повтор загруженной записи по часам сервера, не живой RTSP.

**Сценарии.** Работают 6: бег, опасное сближение, телефон в опасной зоне, падение и неподвижность, пересечение ограждения, проход под опасной зоной. Огонь и курение, страховочная привязь, подвешенный груз ждут моделей с нужными классами; переноска груза — заготовка.

**Не сделано.** Живые RTSP-камеры; авторизация (роль — заголовок). Экраны калькулятора, датасета ложных срабатываний, нарушителей, паспорта камеры и PDF сводки смены есть.
