# Развёртывание Argus

Основной фронт Егора и бэкенд `safewatch` находятся вместе в `main` после PR #36. Docker сам собирает production-фронт и раздаёт его с API и WebSocket на порту 8000. Для подготовленного репозитория сборка и запуск — одна команда:

```text
docker compose up -d --build
```

Подготовка ниже нужна до первого запуска. Результаты фактической приёмки конкретной версии — в [отчёте этапа 1](handoff/upgrade-v3-stage-1.md).

## Машина и исходники

- Windows 10/11 с Docker Desktop и Linux containers либо Linux с Docker Engine и плагином Compose. Проверьте `docker version` и `docker compose version`.
- Docker Compose **2.24+**: используется необязательный `env_file` с `required: false`.
- Для первой сборки нужен интернет: образы Node 24, Python 3.12 slim, uv и зависимости из lock-файлов. Python, Node, uv и системный ffmpeg на хосте для Docker-запуска не нужны.
- Оставьте запас места под образ, build cache и Docker-диск. Для этого стенда ориентир подготовки — не менее 20 ГиБ свободного места на диске Docker; фактический расход зависит от уже имеющихся слоёв. Перед сборкой проверьте свободное место и `docker system df`. Не используйте Purge, перенос VHDX или общую очистку томов как часть запуска.
- Порт 8000 должен быть свободен. Если его занимает именно прежний host-сервер Argus этого checkout, остановите его `uv run --no-sync safewatch stop`. Команда сверяет PID и время создания; произвольный процесс по номеру порта не останавливайте.

```text
git clone https://github.com/MarkHub75/msk-prom2026-mark.git
cd msk-prom2026-mark
```

В существующем checkout сначала сохраните свои незакоммиченные изменения; обновляйте его обычным `git pull --ff-only`. Не создавайте второе приложение в пустой папке и не заменяйте вручную `frontend/`.

## Настоящий пакет

Предпочтителен готовый **`argus-real-v2`**: четыре заводских ролика, четыре камеры, детектор `det-yolov8n@640-ap9999` и поза `pose-yolov8n@640-ap9999`. Архив и отчёт передаёт команда; на ноутбуке Марка это `D:\to-egor\argus-real-v2.zip` и `README_argus-real-v2.md`. Сначала прочитайте отчёт и убедитесь, что пакет закончен. Распакуйте архив в пустое место, затем поместите готовую папку в `data/demo/`, не перезаписывая пакет параллельного агента.

Запасной **`argus-real`** доступен в [GitHub Release `demo-argus-real`](https://github.com/MarkHub75/msk-prom2026-mark/releases/tag/demo-argus-real). В ZIP уже есть корневая папка `argus-real/`; распаковывать нужно в `data/demo/`, а не в `data/demo/argus-real/` повторно. На другой машине без командного архива v2 используйте этот пакет и соответствующий путь в конфиге.

Итоговая структура:

```text
data/demo/argus-real-v2/manifest.json
data/demo/argus-real-v2/ATTRIBUTION.txt
data/demo/argus-real-v2/videos/...
data/demo/argus-real-v2/artifacts/*.jsonl
data/demo/argus-real-v2/artifacts/*.summary.json
data/demo/argus-real/manifest.json       # запасной пакет
```

Видео: Önal, Dandıl, «Video Dataset for Safe and Unsafe Behaviours», Mendeley Data, DOI **10.17632/xjmtb22pff.1**, **CC BY 4.0**. Сохраняйте `ATTRIBUTION.txt`; подпись при показе: «Видео: Önal, Dandıl, Mendeley Data, CC BY 4.0». Детекции заранее получены на LinQ; воспроизведение кэша не является новым замером TPU.

## Конфиг контейнера

Скопируйте `config/docker.example.yaml` в `config/user.yaml` в UTF-8 без BOM. Если файл уже существует, сохраните его и внесите только нужные изменения; не заменяйте настройки владельца целиком. Для готовых реальных пакетов профиль такой:

```yaml
data_dir: data/app
server:
  static_dir: frontend/dist
demo:
  pack: data/demo/argus-real-v2
  autoload: true
pipeline:
  target_analysis_fps: 12
  detector: det-yolov8n@640-ap9999
  pose: pose-yolov8n@640-ap9999
  extra: []
```

Для запасного пакета замените только путь на `data/demo/argus-real`, используя отдельный том по инструкции ниже. Не пишите короткое имя `argus-real-v2` и Windows-пути `D:\...`: внутри Linux-контейнера корень приложения — `/app`.

Конфиг загружается рекурсивно: `default.yaml → user.example.yaml → user.yaml`; неизвестный ключ останавливает запуск. Compose монтирует `config/user.yaml` в `/app/config/user.yaml` **только для чтения**. Файл исключён из build context и не запекается в слои образа. Отсутствие файла — ошибка подготовки, Compose не создаёт вместо него каталог. После редактирования файла выполните `docker compose up -d --force-recreate`: это заново подключает файл и перечитывает настройки без пересборки образа.

Указанный профиль покрывает детектор COCO и позу. `pipeline.extra: []` здесь выбран явно: у пакетов нет артефактов дополнительных моделей. Активная модель, отсутствующая в кэше, может запустить обычный инференс. Каска, респиратор, огонь и другие классы не становятся работающими от монтирования файлов моделей; неподтверждённые модели не добавляйте ради списка сценариев.

## Окружение и секреты

`.env` в корне **необязателен** для показа кэша. Без него настройки дают `INFERENCE_BACKEND=linq`, `SAFEWATCH_FAKE=0`; `LINQ_*` для этого показа не нужны. Если `.env` уже есть, убедитесь, что он не включает фейк и ненужный локальный инференс. `SAFEWATCH_FAKE=1` предназначен для явно обозначенной синтетической разработки, а не для демонстрации настоящего пакета.

Compose передаёт существующий `.env` в окружение процесса, но не кладёт файл в образ. `LINQ_JUPYTER_URL` больше не заменяется безусловным значением в Compose: значение из `.env` сохраняется. Приложение читает переменные процесса раньше собственного dotenv-файла; в контейнере dotenv-файла нет. Простая установка переменной в shell хоста не передаёт её автоматически в сервис, если её нет в Compose-конфигурации; для постоянной настройки используйте `.env`.

Для **новой** обработки видео на LinQ нужны действующие `LINQ_*` и доступ к Jupyter. Если используется SSH-туннель ноутбука, контейнеру может потребоваться явно заданный в `.env` `LINQ_JUPYTER_URL=http://host.docker.internal:8888`; это отдельный режим, не условие cache-only демо. Не выводите `.env`, полный environment, `docker inspect` с окружением или развёрнутый `docker compose config` с секретами.

## Запуск и проверка

Из корня подготовленного checkout:

```text
docker compose up -d --build
docker compose ps
docker compose logs --tail 100 safewatch
```

Откройте `http://127.0.0.1:8000/?review=real`. Параметр отключает сохраняемый фронтом режим обзорных fixtures. Production API работает от текущего origin; WS использует `/ws?role=...` и `wss` под HTTPS. Vite, Prism и mock-WS на 4010/4011 для стенда не запускаются.

Healthcheck использует Python `urllib.request`, curl в slim-образе не нужен. Но `healthy` подтверждает только `/api/health`, а не успешный импорт. Проверьте отдельно:

1. `/api/demo/packs`: имя `argus-real-v2`, `backend: "linq"`, `fake: false`, `cameras: 4`, `videos: 4` (у fallback — по 2).
2. `/api/jobs`: задачи пакета `done`, метрики обеих моделей `cached: true`; в «Системе» нет незавершённого инференса и ошибок.
3. Камеры **пакета** с роликами видны и воспроизводятся. Всего камер больше: `serve --seed` создаёт ещё 4 сектора, 8 камер и 240 исторических `is_demo=1` событий. Они допустимы в журнале/статистике, но не доказывают LinQ и не заполняют настоящую ленту оператора.
4. У события есть кадр, клип играет и перематывается; HUD соответствует сцене. Через DevTools видны WS `hello` и последующее событие/обновление, без localhost, mixed content и mock-данных.
5. Роль «Оператор»: подтвердите реальное красное событие. Оно передаётся мастеру; мастер принимает, вводит меры и решает; событие со всей историей находится в журнале. Разрешение звука даётся пользовательским кликом.

H.264-копия при необходимости создаётся имеющимся `imageio-ffmpeg`, с `yuv420p`, faststart и дополнением нечётных сторон. Клип — окно видео, отдельный файл на каждое событие не создаётся. Исходный SHA и детекции остаются связанными с исходником.

## Данные и повторные старты

Compose использует именованный том `argus_data` с фактическим именем **`argus-upgrade-v3-stage1-data`** по умолчанию, смонтированный в `/app/data/app`. В нём SQLite с WAL, uploads, кэш, анализы и доказательства. Старый Windows-каталог `data/app` не используется, не импортируется и не удаляется.

`./data/demo:/app/data/demo:ro` и `./models:/app/models:ro` доступны только для чтения. Для кэша файлы моделей не исполняются; они нужны при обычной новой обработке. Создайте папку `models/`, если её нет.

```text
docker compose restart safewatch
docker compose down
docker compose up -d
```

Эти команды сохраняют тот же именованный том и решения людей. Повторный `--seed` и импорт того же имени не создают новые камеры и задания. Замена содержимого ZIP под прежним именем **не обновляет** импорт автоматически: существующий `demo_packs.name` пропускается. Зоны, калибровки и правила существующей камеры импорт тоже не перезаписывает.

Для осознанного нового демо используйте **новое имя тома**, сохранив старый. В PowerShell, после `docker compose down`:

```powershell
$env:ARGUS_DATA_VOLUME = 'argus-demo-new-20261025'
docker compose up -d
```

Имя должно быть новым: проверьте `docker volume ls`. Используйте то же значение при дальнейших Compose-командах или сохраните `ARGUS_DATA_VOLUME` в локальном `.env`. Это переменная Compose для имени тома, не YAML-ключ приложения. `docker compose down -v`, удаление host `data/app` и общая чистка томов не являются командами запуска.

## Изолированное переключение на fallback

Остановите контейнер `docker compose down`, сохраните копию своего `config/user.yaml` вне Git, замените `demo.pack` на `data/demo/argus-real`. Задайте ранее не использованное имя тома, например `ARGUS_DATA_VOLUME=argus-fallback-20261025` (в PowerShell — через `$env:ARGUS_DATA_VOLUME`), затем `docker compose up -d`. Проверьте имя пакета и две камеры по шагам выше. Не импортируйте fallback поверх рабочего v2-тома: имена двух камер совпадают.

Для возвращения остановите fallback командой `docker compose down`, восстановите конфиг v2 и **точное прежнее имя** тома, затем `docker compose up -d`. Так сохраняются решения, зоны и настройки обоих показов. Переключение конфигурации не требует пересборки фронта.

## Существующий Tuna

Для публичного стенда нужен существующий стабильный хост Tuna аккаунта команды. Адрес и токен не публикуются в Git, README или сторонних проверяющих сервисах: настроенный адрес берут у Марка либо из локальной конфигурации/консоли Tuna. Новые хосты для этого запуска не создаются. Этот раздел задаёт процедуру; фактический статус подключения и проверки смотрите в отчёте этапа 1.

Цель туннеля — локальный порт Compose **8000**. Если существующий туннель уже смотрит туда, достаточно заменить прежний host-сервер контейнером; туннель не нужно пересоздавать. Если он остановлен, запустите сохранённое подключение с прежним хостом. Сервис Феди из ранней инструкции — исторический вариант, не текущий стенд.

Через существующий HTTPS-адрес проверьте главную страницу и прямой `/operator`, REST с `X-Role`, видео/перемотку, кадр и клип, WS `hello` и реальное событие, затем путь оператора/мастера/журнала. В DevTools соединение должно идти на `wss://<тот же адрес>/ws?role=operator`. HTTP 200 без доставки WS недостаточен для готовности. Локальная запись времени проверки, ID контейнера и image ID связывает публичный запрос с проверенной Docker-версией; ограниченный URL хранится только в локальной передаче.

## Ограничения и ошибки

- V2 демонстрирует два вида правил на трёх камерах с красными событиями; жёлтых нет. Камера 1.4 показывает оператора у пресса в спорной зоне; на 1.5 заголовок про «перелезание» неточен для пересечения нарисованной линии. Это не доказательство промышленной точности всех восьми сценариев.
- Пока `broadcast.loop_default: true`, каждый круг создаёт новые события. В пульте администратора можно остановить эфиры и осознанно запустить «Проиграть один раз». Полная дедупликация и проверка мерцания/ложного красного — этап 2.
- Пакет отсутствует или импорт сломан: сервер может быть healthy с одним синтетическим сидом. Проверьте путь `manifest.json`, импорт в логах, SHA видео, модели/версии и `/api/demo/packs`. Исправьте подготовку и перезапустите; не включайте фейк для сокрытия ошибки.
- Контейнер завершился: `docker compose ps -a`, затем `docker compose logs --tail 100 safewatch`. Не публикуйте чувствительные строки логов.
- Порт занят: установите владельца процесса. Штатный stop предназначен только для host-сервера этого checkout; чужие процессы не завершайте.
- LinQ недоступен: настоящий совместимый кэш продолжает работать. Новое видео требует живой обработки и может честно завершиться ошибкой; старые кэшированные результаты не являются детекциями нового файла.
- Образ не собирается из-за места: проверьте конкретный диск и `docker system df`; сохраните чужие данные. Не удаляйте все Docker-тома.

После изменения исходников обновите checkout и снова выполните `docker compose up -d --build`. Команда собирает фронт из `frontend/package-lock.json` и Python из `uv.lock`; host `frontend/dist` не используется.
