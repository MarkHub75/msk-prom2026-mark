## FLASH (для соседей)

1. **Экспорт: `torch.onnx.export` по умолчанию в torch >= 2.9 — это dynamo/`torch.export` (dynamo=True), а Ultralytics 8.4.184 принудительно ставит `dynamo=False` (TorchScript) при torch>=2.4.** Любой иной код экспорта (YOLOX, свои скрипты) на текущем torch (2.14.1) идёт другим путём, чем Ultralytics: другая декомпозиция графа, opset по умолчанию 20 (а не 18), IR 10 (а не 8). → W1-10, → linq_platform. (W1-09-F06, F26, F27)
2. **YOLOX `tools/export_onnx.py` не работает на текущем torch**: вызывает `torch.onnx._export`, которого в torch 2.14.1 нет (local_observation: `hasattr(torch.onnx,'_export') == False`; открытый issue Megvii-BaseDetection/YOLOX#1907). Плюс #1906 (`torch.load` weights_only=True с torch>=2.6) и #1904 (numpy 2.x в VOC-eval). Требуются локальные патчи или pin старого torch. (W1-09-F18..F21)
3. **YOLOX requirements.txt пинит `onnx-simplifier==0.4.10`, который не ставится на Python 3.13/Windows** (sdist, сборка падает на «Getting requirements to build wheel», local_observation). Для YOLOX использовать `onnxslim` или `onnxsim>=0.5`, либо `--no-onnxsim` в export. (W1-09-F22)
4. **Python 3.13 / torch 2.14.1: ONNX Runtime 1.31.0 грузит модели только с opset <= 26 и IR <= 13** (local_observation); onnx 1.23.2 по умолчанию пишет IR 14 / допускает opset 28. Модель, собранная `onnx.helper.make_model` без явного ir_version, не откроется в ORT 1.31 (проверено на минимальном графе). Ultralytics принудительно срезает IR до 10 (только если >10). (W1-09-F11, F07)
5. **PyPI-колесо torch на Windows — CPU-only** (124 МБ для cp313 win_amd64, local_observation по метаданным PyPI); CUDA-сборка только через `--index-url https://download.pytorch.org/whl/cu126|cu130|cu132`. Вариант `pip install ultralytics` без индекса на Windows даст CPU-torch. (W1-09-F15)
6. **mmdet/mmcv реально нереалистичны на новом torch/Windows**: mmcv 2.2.0 на PyPI только sdist (компиляция CUDA-ops), prebuilt-колёса openmmlab только Linux x86_64, torch<=2.4.0, cu118/cu121, Python<=3.12; mmdet 3.3.0 при этом имеет `assert mmcv < 2.2.0`. (W1-09-F24, F25)
7. **Хост-машина (предположительно ПК команды) уже готова к обучению:** RTX 4070 12 GiB (cc 8.9), драйвер 610.88 (CUDA UMD 13.3), Docker 29.9.2 с runtime nvidia, WSL2 Ubuntu 24.04 видит GPU, nvcc 12.4.131, Python 3.13.9/3.12. Свободно на C: ~70 ГБ (93% занято) — риск для colossal-колёс и датасетов. (W1-09-F30, F31)

## Резюме для оркестратора

- Ядро стека (Ultralytics 8.4.184 @ e6d5fc5, torch 2.14.1, onnx 1.23.2, onnxruntime 1.31.0, onnxslim 0.1.98, numpy 2.5.4, Python 3.13.9) **разрешается и ставится без конфликтов** на хосте (pip check: «No broken requirements found»). Это local_observation на CPU-колёсах torch; GPU-колесо cu126 также установлено и работает на RTX 4070 (F31).
- **Экспорт Ultralytics проверен локально, на случайных весах из yaml** (yolo26n.yaml, yolo11n.yaml; CPU, simplify=True): `export success`, opset 18, IR 8, 15 типов операторов (Conv, Sigmoid, Mul, Split, Add, Concat, MaxPool, Reshape, Transpose, MatMul, Softmax, Resize, Slice, Sub, Div), вход `images [1,3,640,640]`, выход `output0 [1,84,8400]`. Это доказательство перехода «экспорт проходит» для данной конфигурации, **не** для предобученных весов и **не** для LinQ.
- Главное расхождение окружений: **Ultralytics (TorchScript, opset 18, IR 8) vs остальные пути (dynamo, opset 20, IR 10)**. Training- и export-окружение должны быть версионно идентичны по torch/onnx/onnxslim, иначе меняется граф. Рекомендация — один зафиксированный lock-файл на обе роли (env E1/E2 ниже).
- Что нужно LinQ-компилятору (opset, IR, допустимые операторы, динамические оси, постобработка в графе или вне) **не установлено**; список вопросов → linq_platform ниже. До ответа безопасный выбор — статические формы (`dynamic=False`), явный `opset=` в диапазоне 11–18 как гипотеза совместимости, Resize/Softmax/Sigmoid/MatMul как операторы на проверку.
- Каждая стороннюю модель-цепочку стоит ранжировать по «цене окружения»: Ultralytics (pip, без компиляции) << YOLOX (патчи + необязательное C++-расширение на Linux) << PaddleDetection (numpy<2, Python<=3.12, Paddle-колёса с отдельного индекса, совместимость Paddle 3.x не документирована) << mmdet (mmcv compile, version assert). Для 45 часов реалистичны только Ultralytics и (с патчами) YOLOX.
- Машина команды: список диагностик в разделе «Диагностика машин»; на хосте уже получены значения (F30). Для ноутбука и облака — неизвестно.
- Новый риск: **CUDA 13**-колёса PyPI (Linux) тянут `cuda-toolkit==13.0.3` и `nvidia-cudnn-cu13==9.24.0.43` (минимум драйвер >=580 по NVIDIA release notes); для облачных GPU со старым драйвером использовать `cu126` (драйвер >=560.28/560.76 по таблице совместимости).

## Порядок диагностики машин команды (список проверок, без допущений)

На каждой машине (ПК, ноутбук, облачный GPU) записать в таблицу:
1. ОС и сборка: `ver` / `uname -a`, `cat /etc/os-release`; для Windows ещё `wsl -l -v`.
2. GPU/драйвер/compute capability: `nvidia-smi --query-gpu=name,driver_version,memory.total,compute_cap --format=csv`; полный `nvidia-smi` (поле CUDA UMD Version = максимум, поддерживаемый драйвером).
3. CUDA toolkit (нужен только для сборки расширений, не для pip-колёс): `nvcc --version`; (Windows) также компилятор MSVC `cl` в Developer Prompt — нужен для mmcv/любых CUDA-расширений.
4. Python: `py -0p` (Windows) / `python3 --version`; наличие `uv`, `conda`, `git`, `docker`: `where`/`which`.
5. Docker с GPU: `docker info | findstr /i runtimes` (ожидается nvidia), тест `docker run --rm --gpus all <образ> nvidia-smi` (команда стандартная для NVIDIA Container Toolkit; образ выбрать позднее).
6. Torch (после установки): `python -c "import torch; print(torch.__version__, torch.version.cuda, torch.cuda.is_available(), torch.cuda.get_device_name(0), torch.cuda.get_arch_list())"`.
7. Ресурсы: ОЗУ, свободное место на диске (на хосте — 70 ГБ), `where`/доступ к интернету и к pypi/download.pytorch.org/hub.docker.com/github (в зале хакатона может быть ограничен — заранее собрать wheelhouse: `pip download -d wheelhouse ...`).
8. Версии ключевых пакетов: `pip freeze > env-<роль>.txt`, `pip check`.
9. Консольная кодировка Windows: `python -c "import sys; print(sys.stdout.encoding)"`; при cp1251/cp866 запускать экспорт с `PYTHONUTF8=1` (F27).
10. Права/ограничения: может ли ПК ставить драйверы; антивирус/прокси.
