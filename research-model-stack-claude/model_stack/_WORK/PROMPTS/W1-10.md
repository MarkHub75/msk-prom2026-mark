# W1-10 EXPORT_ONNX — exporter, ONNX-граф и потенциальная переносимость

Роль: исследователь первой волны, одна из самых сложных подтем. Модель: Claude Opus 5.5, effort medium. Почему Opus: нужно согласовать архитектуру, код exporter и реально получаемый граф при разных параметрах (opset, dynamic, simplify, nms/end2end, imgsz, batch), найти операции на границе будущего компилятора и не перепутать свойства графа с ограничениями устройства — несколько несовместимых промежуточных форматов и много условных веток.

Сначала полностью прочитай `ROOT\_WORK\CONTEXT.md`. Файл результата: `ROOT\_WORK\WAVE1\W1-10_EXPORT_ONNX.md`; небольшие артефакты анализа (списки операторов, json с формами, логи экспорта) — в `ROOT\_WORK\WAVE1\W1-10_files\`. Сами .onnx и веса — только в SCRATCH (не в ROOT).

## Главный вопрос и решение
Какие ONNX-графы реально получаются из сильных кандидатов при значимых параметрах экспорта, какие в них операции/формы/выходы, где находится decode/NMS, и какие варианты графа наиболее вероятно потребуются для int8-компилятора LinQ (с явным уровнем основания)? От ответа зависит, какой граф мы понесём на LinQ первым, какой держим запасным и какие вопросы зададим постановщику в первые часы.

## Что сделать
1. Код exporter Ultralytics (зафиксируй версию/commit): `ultralytics/engine/exporter.py` (`Exporter.__call__`: подготовка модели — `deepcopy`, `eval`, `fuse`, установка `m.export=True`, `m.format`, `dynamic`, `end2end`, `max_det`; `export_onnx`: `torch.onnx.export` параметры, opset по умолчанию и `get_latest_opset`, `do_constant_folding`, input/output names, dynamic_axes, `simplify` через onnxslim, `nms=True` — как реализован (в графе или обёрткой), `half`, `int8` для ONNX?, metadata_props), `ultralytics/nn/modules/head.py` (что меняет `export` в `Detect`, разные format-ветки — например, для tflite/edgetpu/imx/rknn/hailo — зафиксируй какие есть и что делают: это прецеденты NPU-дружественных правок).
2. **Локальный эксперимент (разрешён и желателен):** создай venv в `<SCRATCH>\venv-W1-10`, установи CPU-сборку torch (`--index-url https://download.pytorch.org/whl/cpu`), `ultralytics` (зафиксированная версия), `onnx`, `onnxruntime`, `onnxslim`. Скачай официальные COCO-веса (минимум `yolo11n.pt`, `yolov8n.pt`; при возможности `yolov5nu.pt`/`yolov5su.pt`) в отдельный каталог SCRATCH с официального release URL. Выполни документированные экспорты (`yolo export model=... format=onnx ...` или Python API — укажи источник синтаксиса) в вариантах: по умолчанию; `opset` явно (например 11/12/13/17 — какие реально проходят); `simplify` вкл/выкл; `dynamic=True`; `imgsz` 640 и неквадратный (например 384x640); `batch` 1 и >1; `nms=True` (если поддерживается для ONNX в этой версии). Для каждого графа сохрани в `W1-10_files\`: inventory операторов (op_type → count), opset/IR, входы/выходы с формами/dtype, metadata_props, размер файла; лог экспорта. Скрипт-анализатор пиши в `<SCRATCH>\scripts-W1-10\`, запускай `py -I` (или python из venv с `-I`) с путём к .onnx аргументом. Запусти ONNX Runtime CPU на одном и том же кадре (например, `ultralytics/assets/bus.jpg` из пакета) для проверки, что граф исполняется и формы совпадают с ожиданием — помечай как local_observation, а не как перенос на LinQ.
3. Опиши, где в графе: Resize (mode, coordinate_transformation_mode), Concat, Split/Slice, Reshape/Transpose, Softmax+Conv в DFL, Sigmoid, Mul/Add/Sub декодирования anchors (константы!), MatMul/Softmax attention в C2PSA (YOLO11), MaxPool SPPF, NonMaxSuppression/TopK/Gather (если nms=True). Проанализируй вариант «граф без decode» (выход сырых голов по трём масштабам), как его получают NPU-fork'и (W1-02 собирает прецеденты: airockchip, hailo и т.д.) — и что тогда обязан делать CPU. Почему для int8 опасно склеивать box-координаты (в пикселях, до 640) и class-scores (0..1) в один тензор — как гипотеза/известная проблема других NPU с источниками, не как ограничение LinQ.
4. YOLOX `tools/export_onnx.py` (`--decode_in_inference`, opset, `-o`), YOLOv5 (v7.0) `export.py` — кратко по коду; torchvision ssdlite — экспортируемость (известные проблемы с postprocess в графе).
5. Официальная документация `torch.onnx` (какая версия docs/stable на сейчас; TorchScript vs dynamo exporter; какой использует Ultralytics), ONNX operator spec для ключевых операторов (версии opset).
