# W2-L SMALL_OBJECTS_MEMORY — малые объекты, P2/imgsz-варианты, активационная память против 16 МБ

Модель: Claude Sonnet 5.5, effort high. Почему: shape inference и аналитика по многим графам и вариантам входа; новых межформатных неизвестных нет, но нужна аккуратная интерпретация. Закрывает K018.

Прочитай `ROOT\_WORK\CONTEXT.md`, `ROOT\_WORK\CONTEXT_WAVE2.md`, в `ROOT\CRITIC.md` — K018. Опорные: `W1-01_FAMILIES.md` («Малые объекты», F34), `W1-10_EXPORT_ONNX.md` (6.3, скрипты), `W1-14_METRICS.md` (F11, F12, F25), `W1-13_CASCADES.md` (§3.1–3.4), `W1-12_QUANT_LINQ.md` (E3), CONTEXT §2 (16 МБ on-chip). Читай FLASH `W2-K_DATA_AUDIT.md` (размеры боксов) и `W2-F_REAL_FINETUNE.md`.

Результат: `ROOT\_WORK\WAVE2\W2-L_SMALL_OBJECTS_MEMORY.md` (+ `W2-L_files\`).

## Что сделать
1. Пиксели: для типичных камер (1920×1080, 2560×1440, 1280×720) и imgsz 640/960/1280 — размер головы/каски в пикселях модели по распределениям construction-ppe (W2-K) и SH17 (W1-14-F25 / W2-K); сопоставление со stride 8/16/32 и receptive field; доля объектов < 8 px, < 16 px.
2. Экспорты (venv-W1-10): `yolov8n-p2.yaml` / `yolo11n-p2`/`yolo26-p2` (если есть yaml — веса из официальных частично переносятся? `Transferred N/M`), yolov8n и yolo11n при 960 и 1280; инвентарь, число узлов, число якорей A.
3. ONNX shape inference: размер каждой активации, максимальный и суммарный (int8 байты) по слоям для каждого варианта; пиковая «живая» память при последовательном исполнении (оценка); attention-матрицы при 960/1280; сравнение с 16 МБ on-chip **как гипотеза** о тайлинге/выгрузке в DDR компилятором, не как установленное ограничение.
4. Альтернативы: тайлинг кадра (SAHI-подобно) vs больший imgsz vs каскад с кропом — арифметика вызовов и пикселей.

Попытайся опровергнуть: «640 недостаточно для касок на CCTV» — при каких дистанциях/разрешениях 640 хватает.
