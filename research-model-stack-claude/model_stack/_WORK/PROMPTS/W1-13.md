## Главный вопрос и решение
Какие практичные альтернативы и дополнения к единому детектору реально реализуемы (с кодом, весами, контрактами), когда они нужны для нарушений кейса (связь предмета с человеком, временной контекст, жесты), сколько моделей и преобразований это добавляет на LinQ/CPU? От ответа зависит архитектура модельного пайплайна (1 модель vs 2–3) и что выносится на LinQ.

## Что сделать
1. Каскад person → crop → классификатор/детектор: какие классификаторы (torchvision mobilenet_v2/v3, efficientnet_b0, resnet — часть в списке LinQ; Ultralytics `-cls` модели) — контракт входа (размер, нормализация ImageNet mean/std vs /255), как обучать классификатор в Ultralytics (`ultralytics/models/yolo/classify`, формат папок), экспорт. Как вырезать (паддинг, верхняя треть bbox для головы), батчирование вырезок переменного числа (динамический batch на NPU — вопрос → linq_platform).
2. Pose: Ultralytics `yolo11n-pose`/`yolov8n-pose` (17 COCO keypoints, порядок, `kpt_shape`, `flip_idx`; выход Pose head в export-режиме — форма), применение: локализация головы для каски, кисть у лица для курения/снятого респиратора, падение. Веса, классы, лицензия кратко. RTMPose/MMPose как альтернатива — кратко.
3. Трекинг: Ultralytics trackers (`ultralytics/trackers/byte_tracker.py`, `bot_sort.py`, `cfg/trackers/*.yaml` — параметры track_high_thresh и т.п., ReID в BoT-SORT), supervision ByteTrack, временные правила (N кадров подряд, гистерезис) — что в модельном стеке, что — в video_architecture. Трекер выполняется на CPU — контракт входа (детекции xyxy+conf+cls).
4. Зоны: point-in-polygon по низу bbox (Ultralytics solutions / supervision PolygonZone) — кратко, ссылки на код.
5. Open-vocabulary/VLM как инструмент подготовки данных/teacher: YOLO-World (ultralytics, `set_classes`, экспорт с фиксированными классами в ONNX — граф содержит CLIP-эмбеддинги константами?), YOLOE, Grounding DINO, OWLv2, Florence-2, SAM2 для авторазметки — лицензии кратко, требования GPU, качество по PPE — только по источникам. Не утверждай их инференс на LinQ.
6. Мультиголовые варианты: один детектор с классами person/head/helmet/vest vs два детектора; ассоциация предмета с человеком (IoU/вложенность/ключевые точки).
