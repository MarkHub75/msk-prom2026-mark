# W1-02 REPOS — канонические репозитории, версии, fork

Роль: исследователь первой волны. Модель: Claude Sonnet 5.5, effort medium. Почему medium: преимущественно установление владельцев, релизов, тегов, коммитов и истории — точный, но не глубоко аналитический поиск. Сложный анализ изменений fork, влияющих на граф, — запрос эскалации.

Сначала полностью прочитай `ROOT\_WORK\CONTEXT.md`. Файл результата: `ROOT\_WORK\WAVE1\W1-02_REPOS.md`.

## Главный вопрос и решение
Какое конкретное состояние кода (repo + tag/commit + pip-версия) нужно брать для каждой сильной реализации, чтобы config, checkpoint и exporter были согласованы, — и какие fork полезны (особенно NPU-ориентированные модификации экспорта)? От ответа зависит, какие версии команда зафиксирует в экспериментах и не смешает ли незаметно версии.

## Что сделать
1. ultralytics/ultralytics: текущая последняя версия на PyPI и GitHub (точный номер, дата, commit тега), ветвь релизов 8.x (или новее), когда появились YOLOv8, YOLO11 (и YOLO12/YOLO26, если есть), изменения формата checkpoint и exporter между версиями; CHANGELOG/releases; какие модели поддерживаются в текущей версии. Зафиксируй SHA `main` на момент проверки.
2. ultralytics/yolov5: последний tag (v7.0?) и состояние ветки; отличие «yolov5s» (anchor-based, репозиторий yolov5) от «yolov5su» (anchor-free, в ultralytics) — по первичным материалам. Это важно: LinQ заявляет `yolo5s`.
3. Megvii-BaseDetection/YOLOX: последний tag/commit, активность, известные проблемы с зависимостями.
4. PaddlePaddle/PaddleDetection (релиз-ветки, PP-YOLOE+, PicoDet), open-mmlab/mmdetection и mmyolo (состояние сопровождения в 2025–2026), pytorch/vision (версия, где ssdlite320_mobilenet_v3_large, ssd300_vgg16, fasterrcnn_mobilenet), tensorflow/models (TF OD API, ssd_mobilenet_v2 — состояние), WongKinYiu/yolov7, yolov9, WongKinYiu/YOLO (MIT), THU-MIG/yolov10, NanoDet, RT-DETR (lyuwenyu/RT-DETR), D-FINE/DEIM/RF-DETR — кратко для тех, что фигурируют как кандидаты.
5. NPU-ориентированные fork и экспортные модификации как прецеденты (не как доказательство для LinQ): airockchip/ultralytics_yolov8 (и аналоги для yolo11), rknn_model_zoo, hailo_model_zoo, OpenVINO, Ascend, Qualcomm AI Hub, NXP eIQ, Sophgo/TPU-MLIR, Axera и т.п. — что именно они меняют в голове/выходах (например, удаление DFL/decode из графа, разделение выходов box/cls, замена SiLU на ReLU), с commit и путями файлов. Это прецеденты того, что может понадобиться для LinQ.
6. Изменения интерфейсов, ломающие воспроизводимость: переименования аргументов export, формат `names`, смена opset по умолчанию, зависимость от версий torch. Issues/PR с привязкой к версии.
