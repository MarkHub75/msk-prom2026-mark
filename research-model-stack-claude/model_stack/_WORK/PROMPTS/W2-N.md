## Что сделать
Для 4–6 модификаций (сначала CPU-экспорты в venv-W1-10, затем короткие обучения по GPU-блокировке):
1. SiLU → ReLU (через YAML `activation:` — проверь, что действительно применяется), YOLOv8n и YOLO11n;
2. YOLO11n без C2PSA (Identity с сохранением индексов) и/или YOLOv8n как «YOLO11 без attention»;
3. YOLOv8n-голова с `reg_max=1` (без DFL, как у YOLO26) без attention;
4. `forward_split` vs Slice (Split в графе) — что даёт экспорт;
5. Resize nearest → ConvTranspose/иное, если документировано;
6. (опционально) YOLO26n без attention.
Для каждой: YAML, экспорт, инвентарь операторов (что исчезло/появилось), `Transferred N/M` от официальных весов, короткое дообучение на construction-ppe (одинаковые эпохи/imgsz) против немодифицированной модели — **как оценка порядка потерь**, без претензии на итоговое качество; время эпохи.
Итог — таблица: оператор-риск → замена → изменение графа → перенос предобучения → цена переобучения (часы на RTX 4070) → когда применять (какой ответ SDK её требует).

Попытайся опровергнуть: «замена SiLU→ReLU дешёвая» и «удаление C2PSA почти бесплатно».
