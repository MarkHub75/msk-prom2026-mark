# Финальная презентация

Тринадцать слайдов для технического и бизнес-жюри: проблема → решение → роли → путь реакции → аналитика → настройка → технологии → реальный кадр LinQ → надёжность → пилот → честная готовность → команда. Прежний восьмислайдовый каркас сохранён рядом; промежуточная версия12слайдов — в исторических evidence.

В PPTX каждый слайд — один PNG1920×1080. Заметки докладчика остаются текстовыми: короткая речь, технические оговорки, вероятный вопрос эксперта и честный ответ. UI взят из предоставленного пользователем вложенного архива Downloads(2).zip; его не рисовали и не генерировали. Синтетические заводские кадры взяты из ChatGPT Images trailer-kit пользователя и помечены как иллюстративные. Выноски, тонкие рамки, макеты устройств и типографика наложены детерминированно. Фрагменты UI имеют точные crop-координаты в evidence/composition.json; исходные изображения сохранены целиком и проверяются поSHA256.

Логоблок задан единожды в scripts/compose.py: крупное «АРГУС» и меньшая подпись «под надзором». Переиспользован на обложке и в финале, как запрошено в структуре. Родные названия/логотипы внутри настоящих скриншотов сохранены. Имена команды получены от пользователя, должности не выдумывались.

Слайд9 — предоставленный пользователем ARGUS_linq_tpu_frame0.png: реальная промышленная камера из Mendeley и сохранённые выходы LinQ, а не синтетика трейлера. Изображение шире16:9 и показано целиком на всю ширину, без обрезки, перерисовки и искажения пропорций. Текст докладчика вставлен дословно. Авторы датасета, DOI и CC BY4.0 — в заметках и [ATTRIBUTION.txt](exports/ATTRIBUTION.txt). Слайд подтверждает отдельное аппаратное исполнение; промышленное качество и обработка целого ролика им не заявляются.

69тестов frontend подтверждены новым запуском front/final в отдельном runtime.352backend — по отчёту main.45с — включённая настройка;18FPSCPU и замер45.2с не подтверждены и исключены. Пропускная способность LinQ записи не выдаётся за задержку тревоги. Числа аналитики из UI — demo,не заводские метрики. План пилота и on-prem/API поставки — гипотезы.

Использован штатный Presentation Craft1.0.0 и неизменённый HRE1.1 OS. craft/capture.html — только поверхность измерения готовых PNG; выступать следует через PPTX/PDF. Передача картинок в DOM не создаёт скрытой текстовой подложки ради critic. Растровый текст проверяется отдельно; findings сохраняются.

Воспроизведение: prepare.py фиксирует Git/архив и шрифты; compose.py рисует12PNG; story.py создаёт заметки,контракт и экспортные утилиты; exports.mjs экспортирует PPTX через существующий PptxGenJS, pdf-preview.py — PDF. После финального редактирования нужно заново экспортировать и проверить PowerPoint, затем выполнить OS capture.mjs в новую evidence-папку и создать новую review-ревизию. Не перезаписывать замороженный review.
