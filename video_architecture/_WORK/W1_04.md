## V07: контракт состояния потока (наш проект, не LinQ API)

**W1-04-F14 [INFERENCE].** Actor per camera — логический единственный владелец temporal state, accepted watermark, health, активных candidates. Это coroutine с mailbox либо worker process с несколькими независимыми camera state objects; процесс на каждую камеру не обязателен. Stateless inference обслуживает общий scheduler, results маршрутизируются обратно полным ключом. Согласуется с соседним `_WORK/W1_03.md` (сообщение корня: request/result key, transforms, latest per camera, bounded inflight/deadlines); соседний файл не редактировался и не является независимым сетевым доказательством этой ветки.

Псевдо-API модулей:

```text
FrameSource.next() -> FrameEnvelope | StreamStatus
InferenceAdapter.submit(InferenceRequest) -> Future[InferenceResult]
CameraState.apply(OrderedResult | Gap | EpochReset) -> [EventMutation]
EventRepository.commit(mutations, outbox_records) -> durable_commit
NotificationDispatcher.deliver(outbox_record) -> attempt_result
MediaStore.resolve(camera,epoch,media_interval) -> evidence_reference/status
```

Крупные frames/clips не идут durable event bus. Передаём ссылки/компактный envelope, а image payload лишь выбранным transport. Shared-memory pool требует ownership/lifetime: слот не перезаписывать до окончания потребления, либо сделать immutable copy на admission. Frigate slot protocol не даёт бесплатного zero-copy по интернету.

**W1-04-F15 [INFERENCE].** Минимальная идентичность/время:

| Поле | Семантика |
|---|---|
| schema_version | Версия нашего контракта |
| camera_id | Стабильный logical source, не IP/pad/session |
| stream_epoch | Новый UUID/generation при reset/fresh session; не переиспользовать0 после restart |
| frame_id | Возрастающий uint64 в epoch; назначить на decoded frame до sampling, чтобы gaps видны; не счётчик completed inference |
| pts,time_base | Исходные integer presentation timestamp и rational seconds/tick, если доступны |
| media_time_ns | Нормализованное presentation time в epoch, ns; может быть null; original PTS сохранить |
| timestamp_source | camera_pts/file_pts/host_decode_monotonic/estimated; fallback явно маркировать |
| captured_at_utc | Только при известной source clock привязке; иначе null |
| received_at_utc | Наш host receive/decode time, не exposure timestamp |
| ingest_monotonic_ns | Только duration в одном clock domain; domain/run id отдельно |
| width,height,transform_id | Оригинальная geometry и обратимость resize/letterbox/ROI |
| request_id,model_revision,preprocess_revision | Корреляция и воспроизводимость |

Ключ `(camera_id,stream_epoch,frame_id)` обязателен и в result. Track id при наличии scoped как camera:epoch:local_track_id. Event_id отдельный неизменный UUID; retries используют тот же UUID; event_revision возрастает, чтобы UI не заменил новое старым update. Semantic candidate fingerprint согласовать с violation_methods; transport dedup не решает повторное аналитическое распознавание того же эпизода.

**W1-04-F16 [INFERENCE].** Разделить presentation/decode order, admission order, arrival order remote results. Frame_id назначается после decoder reorder, не на packets/DTS. Минимум45ч: максимум1inflight на camera, несколько cameras параллельно. Это упрощает порядок, но FPS одной камеры ограничен roundtrip+service. Для большего FPS — bounded reorder buffer.

Outstanding order хранить из **реально отправленных** ids, не ожидать last+1: sampling пропускает номера. Ready map ограничена; head completed/timeout продвигает watermark; timeout создаёт Gap и освобождает ожидание. Старые epoch, duplicate request, result ниже applied watermark, results после live deadline — reject из state update с метрикой. Не применять frame103, потом101. Offline replay допускает иную late policy, отдельный режим.

**W1-04-F17 [INFERENCE].** Gap не отрицательная детекция. Temporal delta считать по media_time; потеря2s не означает2s доказанного отсутствия каски. Передавать Gap(start/end,reason,known_count,duration_or_unknown) и coverage. Короткий gap может сохранять candidate с неполным coverage, длинный — interrupted/unknown, а не safe/resolved. max_gap_s зависит от сценария/FPS и принадлежит violation_methods/evaluation. При VFR/неизвестном PTS нельзя переводить skipped count в секунды фиксированным FPS.

**W1-04-F18 [INFERENCE].** RTSP reconnect, seek/file loop, decoder restart, source replacement, backward PTS discontinuity создают новый epoch, если непрерывность нельзя доказать. Сериализовать StreamReset(old,new,reason). Outstanding старого epoch obsolete, reorder buffer очистить, volatile tracking/candidates сбросить, активные events завершить interrupted по договорённости. Model/preprocess/rule revision или geometry change — явная state invalidation соответствующей части. После crash восстановить incidents/outbox, создать новый epoch/run и warmup; bbox не checkpoint opaque tracker. Полный checkpoint/replay требует versioned state и обычно избыточен за45ч. UI различает ingest alive/inference alive/delivery backlog; frozen overlay не свежий результат.

## V08: шина и хранение

**W1-04-F19 [INFERENCE].** Два разных потока: frames/results с bounded loss ради freshness и подтверждённые event mutations с durable commit/retry/dedup. Process Queue/asyncio mailbox не durable после reboot. WebSocket — projection, DB — source of truth. После browser reconnect snapshot из DB+cursor replay; live update может потеряться.

| Вариант | Первичное основание | Ограничение/решение45ч [INFERENCE] |
|---|---|---|
| Mailbox + SQLite outbox | Транзакционная local DB, ограничения F24 | Рекомендуемый минимум, один DB writer, небольшой dispatcher |
| Redis Streams | Consumer groups/Pending/XACK/XAUTOCLAIM | Если Redis уже нужен/знаком; events/control, не raw video; persistence/retention/reclaim всё равно настраивать |
| Core NATS | Ephemeral at-most-once | Live status подходит; единственный durable alert channel — нет |
| NATS JetStream | Persistence/replay/durable consumers/ack, pull batch/expires | Хорошая альтернатива Redis при знакомом NATS; выбрать один broker |
| MQTT5 | QoS/session state/retained per topic | Интеграция IoT/HA, не замена incident DB; QoS2 не атомарный внешний effect |
| Kafka | Partition log/replay, producer idempotence/transactions | Новый cluster не окупается для нескольких demo cameras; взять только готовый infrastructure/experience |

**W1-04-F20 [DOC].** Redis XREADGROUP since5.0 делит сообщения между consumer group members, Pending хранит unacked. XAUTOCLAIM since6.2 меняет ownership idle pending. ### Transactional outbox и side effects

**W1-04-F25 [INFERENCE].** Одна DB transaction: event mutation с unique(event_id,event_revision), outbox unique(event_id,event_revision,destination), commit. Dispatcher отправляет, пишет attempt/result/delivered marker. Если receiver поддерживает idempotency key — стабильный ключ. Broker publish подтверждать publisher ack нужного режима, но повтор между acceptance и local marker возможен. Consumer inbox/dedup тоже durable.

| Crash point | Восстановление | Чего не обещать |
|---|---|---|
| До commit | Нет event/outbox; volatile candidate мог исчезнуть | Что каждый увиденный frame сохранён |
| После commit до send | Outbox pending, retry | Мгновенная доставка offline recipient |
| После send до delivered marker | Возможен duplicate send | Exactly-once внешнего effect без idempotency |
| Consumer effect до broker ack | Redelivery, inbox/unique предотвращают повторный DB effect | Что broker ack включает внешнюю transaction |
| Broker недоступен | DB alert существует, outbox backlog, health degraded | «Нарушений нет» при выключенном transport |

При нескольких dispatchers не держать row lock/transaction во время network timeout: lease/claim timestamp или короткая transaction SKIP LOCKED и отдельный completion. На45ч один dispatcher. Bounded retries+error/dead-letter, чтобы poison payload не остановил все alerts. Update не получает новый event_id. Clip ready — новая revision того же event; alert не ждёт post-event video.

### multiprocessing/asyncio

**W1-04-F26 [DOC].** multiprocessing subprocesses обходят обычный CPython GIL; Queue сериализует передаваемые objects. asyncio.to_thread снимает blocking с event loop; CPU-bound Python обычно не ускоряет из-за GIL, исключение native extensions с release GIL. Конкретный OpenCV/SDK path нельзя объявлять всегда освобождающим GIL без проверки. S17/S18.

**W1-04-F27 [INFERENCE].** asyncio — network/RPC/timeouts/mailboxes/API/dispatcher. Decode — subprocess/process либо thread с измеренным stall. CPU-heavy Python — process/native vectorized после измерения. Blocking LinQ SDK изолировать worker process, если свой код разрешён; API-only — async client с cap. Thread safety/multiprocess runtime LinQ неизвестны. Не наследовать native runtime/CUDA handle автоматически fork; spawn-compatible init и handle внутри worker, importable worker, main guard облегчают Windows/Linux. Большие images в multiprocessing.Queue копируются; shared memory лишь после измерения, с bounded pool/ownership/cleanup. Stop/drain protocol, watchdog, force terminate только recovery: принудительное завершение может портить queues/locks.
