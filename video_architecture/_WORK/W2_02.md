## Решение

**W2-02-F01 INFERENCE.** Для заявляемого соответствия event→original segment выбрать одного владельца demux на камеру/профиль: те же encoded access units идут в decode и indexed remux. MediaMTX1.21.2 — relay. Отдельный native recorder остаётся альтернативой, но его нельзя считать сопоставленным независимому PyAV decoder по UTC filename. Реализация своего remux не выполнена и её простота за45ч не доказана: ранний gate E01 обязателен. Если gate провален, честный scope cut — snapshot анализируемого кадра, native archive с mapping unknown; не «точный клип».

Новая находка: fMP4 v1.21.2 содержит custom `mtxi` с recorder StreamID, SegmentNumber, DTS, NTP. Это сильнее filename UTC, но не содержит source/decoder epoch. Native playback export эту UserData не сохраняет. Оригиналы и manifest нужны отдельно.

## Проверенный MediaMTX механизм

**W2-02-F02 DOC/CODE S01/S02.** `recordSegmentDuration` — minimum, не maximum. H264 recorder ждёт IDR перед созданием DTSExtractor, сохраняет PTSOffset=`u.PTS-dts`, IDR как sync. Новая граница в Track.write только при next sync sample и `nextDTS−segment.startDTS >= segmentDuration`. Long GOP делает2s setting длиннее2s; stalled source/нет следующего keyframe означает отсутствие конечного close bound. Отрицательная duration next DTS clamp0; sample с отрицательным basetime отбрасывается. Drift NTP vs DTS больше±5s вызывает reset/error; tolerance5s не означает accuracy5s. Контролируемый H264 B0/GOP≤1s — проектная fixture; произвольная камера требует GOP проверки. MediaMTX не создаёт отсутствующий IDR.

Проектная native configuration, не запущена:

```yaml
pathDefaults:
  record: yes
  recordFormat: fmp4
  recordPartDuration: 1s
  recordMaxPartSize: 50M
  recordSegmentDuration: 2s
  recordDeleteAfter: 0s
```

`0s` deletion допустим только с работающим bounded janitor. Part size cap — RAM part, не весь disk cap; превышение возвращает error. При проверенном GOP≤1s target2s даёт условно около2–3s segment при continuous input/bounded I/O, не unconditional SLA.

**W2-02-F03 CODE S03.** mtxi v0: StreamID16bytes, SegmentNumber uint64, DTS int64 в ns (Go duration), NTP int64 UnixNano. Init tracks дают Timescale, sample parts — relative BaseTime/PTSOffset. StreamID=`uuid.New()` при recorderInstance.initialize, а не source/decoder generation; segment sequence локальна format. mtxi не содержит original RTP SSRC/packet IDs/raw PTS/time_base/event ID. DTS уже после depacketization/codec extractor. Равенство PyAV raw timestamps и mtxi.DTS не установлено.

**W2-02-F04 CODE S04.** Create hook: MTX_PATH, MTX_SEGMENT_PATH, RTSP_PORT, regex G1…; complete добавляет MTX_SEGMENT_DURATION в seconds. Нет PTS/start NTP/StreamID/SegmentNumber/decoder epoch. External command Restart:false, не durable ack queue. Control APIRecordingSegment содержит только start; recording=name,segments; list=itemCount,pageCount,items. Для mtxi нужен parser исходного файла. Create вызывается после os.Create ДО writeInit: это не readable/complete file. Complete callback вызывается при успешном File.Close, даже если ранее closeCurPart/writeDuration сохранили error: hook не заменяет validation/coverage.

**W2-02-F05 DOC/CODE S05/S06.** Native `/list?path&start&end` принимает RFC3339, отдаёт start/duration/url (возможно concatenated/clipped timespan). `/get?path&start&duration&format=fmp4|mp4` — download/remux primitive, не durable export job. MPEGTS в seekAndMux возвращает unsupported. FindSegments Start декодируется из recordPath filename, а не mtxi.NTP; startOffset также filename-based. Subsequent offsets с mtxi используют DTS difference. Concat mtxi требует same StreamID+consecutive SegmentNumber; legacy без mtxi — tracks ID/timescale/type и wall tolerance±1s. Output init передаёт Tracks, не UserData: экспорт теряет recorder mtxi provenance. Разрыв прерывает склейку; HTTP200/успешное открытие файла не доказывает полное окно. После начала ответа ошибка только логируется. Leading samples/negative offset не являются frame-accurate reencode trim; requested и actual decoded coverage различать.

**W2-02-F06 DOC/CODE S07.** Default useAbsoluteTimestamp:false заменяет incoming absolute time системным. True требует source absolute timestamps: ToStream пропускает packet без PacketPTS; с true начальные packets без PacketNTP warning+skip. RTCP sender reports дают RTP/NTP pair+clock rate, но не гарантируют правильные camera clocks/эквивалентность независимых readers. Filename UTC не exposure time; event PTS нельзя сравнить с segment DTS без composition/reorder offsets.

**W2-02-F07 CODE/DOC S01/S03/S06/S08.** fMP4 part сначала marshal в memory, потом Write; segment close переписывает duration header и Close. Явного File.Sync в этих функциях нет. Docs last-part-loss/RPO — documented normal flush цель, не проверенная power-loss guarantee на неизвестной ФС. Playback при header duration0 пытается вычислить duration из parts; это recovery primitive, не atomic snapshot растущего файла. Policy: open segment не complete, не копировать растущий original как финальное evidence. После crash complete moof+mdat prefix может стать recovered partial derivative с own hash/coverage; damaged original сохраняется. Close deadline истёк → partial/failed.

**W2-02-F08 CODE S08.** Cleaner удаляет segments по filename Start до now−deleteAfter, не учитывает incident pins/jobs/close state. Независимые native cleaner и custom pin DB создают гонку. Выбрать одного janitor либо сохранять closed originals в отдельный evidence store до expiry. Hardlink сохраняет occupied blocks до последнего link, это не бесплатное место.

## Same-demux mapping: контракт с ограничениями

**W2-02-F09 CODE/INFERENCE S09.** PyAV example назначает packet.stream и mux, пропускает flush packets dts=None. mux_one вызывает packet._rebase_time(output_stream.time_base), меняя timestamps/time_base. Original values фиксировать ДО mux; один mutable Packet не передавать конкурентно decode/mux без copy/reference/lifetime strategy. Frame.pts/time_base — presentation timestamp; frame.dts — DTS packet, вызвавшего возврат frame, не надёжный identity того же image. B reorder/delay/flush нарушают 1packet=1frame. Наличие timestamps/контракта desired sampling time не доказывает mapping.

Минимальный проект — сначала H264 video-only, один профиль. Audio/VFR/H265 расширять после fixture:

1. Demux owner создаёт source_generation при open/reconnect/подтверждённой discontinuity. Packet row: packet_seq, original demux pts/dts/rational tb, codec/extradata hash, random-access, received_monotonic, gaps. RTSP demux PTS могут уже быть FFmpeg-normalized; label `ffmpeg-demux`, не raw RTP.
2. До изменения stream/mux фиксируется index. Encoded recorder создаёт recorder_generation и unique segment IDs, начинает на independently decodable IDR, закрывает на suitable IDR после target. Для decoder сохраняется separate packet ref/copy с исходной stream association. Queue overflow/mux error → recording gap; decode может продолжать, evidence partial.
3. Decode назначает decoder_generation, seq каждому yielded frame. Frame media time выводится из frame.pts×tb в source_generation, проверяется против indexed access-unit PTS/codec reorder. Не время текущего demux loop и не completion now. Duplicate/missing frame PTS → ambiguous/unknown, пока нет явной codec correlation. Flush frames тоже индексируются. Min/max span не доказывает отсутствие внутренних holes.
4. Event содержит IDs реально analyzed frames, rational times и onset uncertainty. Desired slot не evidence time. Mapping uncertainty отдельно от certainty violation.
5. Segment close: flush/trailer/bounded write; independent validation sample PTS/decode boundary/keyframe, output tb/rescale offset; hash финальных immutable bytes. Availability commit только после validation. Pending intent до публикации, после crash reconcile. Close/rename не гарантируют fsync/power-loss (K008).
6. Resolver выбирает camera+profile+source_generation, затем segments по presentation spans для [start−pre,end+post], плюс random access dependencies. Проверяет gaps/generation/codec change/coverage. Complete только при доказанном полном покрытии; partial с gaps либо unavailable/unknown mapping. Hook arrival/UTC filename для выбора не используются.

## Finite evidence policy

**W2-02-F10 INFERENCE.** Finite pre-roll невозможен при unbounded arrival delay. History row может прийти поздно; live state принимает только fresh same-generation; complete evidence только при наличии actual indexed coverage в finite acceptance. Late result не возвращает удалённый original.

Проектные начальные bounds, не требования кейса/не LinQ SLA:

| Bound | Значение | Превышение |
|---|---:|---|
| A_live от frame local receipt | 2s | Reject live apply, late history; не sensor latency |
| L_evidence от самого раннего требуемого anchor до durable pin request | 20s | unavailable:late_evidence; оставшийся материал только partial |
| requested pre P / post Q | 5s / 5s | Проверить actual coverage |
| segment target S / verified IDR max gap G | 2s / ≤1s | Нет bounded G → нет close guarantee |
| close wait C после target postroll | 4s | Closed covered segments + partial:close_timeout |
| job wall deadline J | 30s | Terminal partial/failed, release temporary pins после commit |
| finite chunk window | ≤10s media | Длительный incident — серия jobs; не один unbounded job |
| ongoing manifest rollover R | 60s media | Child part того же incident, chunks независимо завершаются |
| per-incident retained media quota | 10min либо byte cap, что раньше | Stop evidence expansion; metadata incident продолжается, coverage_truncated |

L считать от EARLIEST anchor: долгий dwell означает, что start старше last analyzed frame. Можно provisional-onset заранее pin finite window; иначе старое начало partial. Postroll ждёт progress И monotonic deadline, stalled media не ждётся бесконечно. Job10s+post5+close4 помещается в J30 при bounded dispatch/validation; при превышении terminal partial. Global concurrent jobs/count/bytes также конечны, фактические caps после disk inventory.

**W2-02-F11 INFERENCE.** Условный ring envelope:

`H >= P + L_evidence + S + G + C + maintenance_margin`.

Пример5+20+2+1+4+3=35s, выбрать H40s проектно. Условия: bounded input progress/I/O/G, mapping receipt→media проверен. Для separate recorder неизвестный offset требует дополнительной measured uncertainty. После durable admission future pin intent защищает postroll, не надо всё время расширять H на Q. Если future pins не реализованы, добавить Q/job envelope либо route не удовлетворяет контракту. Writer stall большой ring не исправляет.

`B_ring >= sum(max_bitrate_i/8 × H_i) + GOP_overshoot_bytes + open_part_buffers + FS/index_reserve`, плюс отдельный global B_evidence. Average bitrate недостаточен. Диск/битрейт неизвестны — число камер из40s не следует. Конечный byte cap имеет приоритет над обещанием полного окна.

**W2-02-F12 INFERENCE: lifecycle/low-space/recovery.**

1. Admission транзакционно сохраняет requested interval/generation, existing refs, finite future range, reserved bytes, deadline. DB commit failure не pin success; boundary K008.
2. pending→waiting_postroll→waiting_close→validating→complete|partial|failed|unavailable. Gaps/generation/deadline дают terminal reason. Event/notification не ждут clip.
3. Persisted pins: owner/refcount/max lifetime/bytes; terminal job передаёт finite-TTL manifest. Manual hold тоже имеет owner/expiry/cap. Shared refs dedup, quota по unique retained bytes.
4. Low space: удалить expired unpinned/temporary failed derivatives; reject new jobs/extensions; завершить pending partial по доступному coverage. Не удалять молча pinned originals. Reserve для metadata/status. При исчерпании остановить recorder с recording_unavailable:disk_full; live inference по возможности продолжить. Snapshot тоже bounded.
5. Crash: scan files↔index, open intents→recovering; hooks не источник истины. Validate hash/header/sample coverage; orphan index с unknown provenance, missing refs→partial. Stale jobs terminal по persisted deadline; tails quarantine/recover-prefix. Refcounts пересчитать из durable jobs/manifests до deletion. Process kill/reboot/power-loss/disk-loss разные guarantees; здесь не проверены.

Шаги: log original packet pts/dts/tb до mux, frame pts/tb после decode, output sample index; запросы по analyzed IDs, independently decode originals/сверить watermark. Inject decoder-only/recorder-only restart, reconnect/reset/UTC jump/duplicate/missing PTS, loop continuous/reset, known-domain wrap и main/sub negative. Метрики: wrong-original/loop/generation, missing requested frames, max grid error, detected gaps. Сохранить versions/configs/hashes/mtxi/manifests/packet-frame trace/watermark. Pass:0 false complete; unresolved mapping всегда unknown/partial. Fail→snapshot/archive cut. Pass не доказывает arbitrary camera/codec/RTCP, LinQ или power-loss.
